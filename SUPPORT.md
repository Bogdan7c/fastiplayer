# Support

Fastiplayer is Linux-first, active development / pre-alpha software maintained by one core maintainer. There is no guaranteed response time or commercial support service. Start with the [build guide](CONTRIBUTING.md#clone-and-build-on-linux), [known limitations](README.md#current-limitations), and [media compatibility matrix](docs/web-media-compatibility-matrix.md).

| Need | Route |
| --- | --- |
| Reproducible bug | Search existing issues, then use the [bug report form](https://github.com/Bogdan7c/fastiplayer/issues/new?template=bug_report.yml) |
| Concrete feature proposal | Search the roadmap/issues, then use the [feature request form](https://github.com/Bogdan7c/fastiplayer/issues/new?template=feature_request.yml) |
| Usage question or exploratory idea | [GitHub Discussions](https://github.com/Bogdan7c/fastiplayer/discussions) |
| Suspected vulnerability | Follow [SECURITY.md](SECURITY.md); GitHub Private Vulnerability Reporting is enabled, with fallback instructions there if the channel is unavailable |

Use [Discussions](https://github.com/Bogdan7c/fastiplayer/discussions) for questions and exploratory ideas, and consult the [documentation index](docs/README.md). Use the feature form only when the idea is concrete enough to describe a user problem and expected behavior.

Bug reports should provide the exact revision, OS, CPU/GPU, driver/Mesa/libva versions, input type, codec/profile, reproduction steps, and sanitized logs. Write `unknown` or `not applicable` with a reason when a field cannot be determined. A small authorized reproduction is more useful than an inaccessible private streaming link.

Never post private or signed media URLs, credentials, cookies, authorization headers, or unreviewed configuration/crash dumps. Scrub screenshots and logs as well as prose. Do not attach copyrighted or private media without permission, and do not post suspected exploit samples publicly.
