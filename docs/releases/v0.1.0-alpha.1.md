# Rustiplayer v0.1.0-alpha.1 — draft release notes

**Local draft, not published.** This prepares Rustiplayer's first public development release: **Linux-first · source-only · active development / pre-alpha**. It is not a production-readiness or stable-API announcement. No release date or tag has been created by this document.

## Release scope

Rustiplayer is a Rust-first native media player focused on hardware decoding, GPU rendering, and explicit ownership across media pipelines. It integrates native libraries and drivers; it does not claim an entirely Rust multimedia stack.

Verified capabilities, within the recorded media and hardware profiles:

- Local video playback through VA-API hardware decoding or FFmpeg software decoding and WGPU/Vulkan rendering.
- GPU HDR → SDR tone mapping, including the recorded AV1 10-bit P010 to SDR BT.709 path. This is not native HDR display output.
- Native progressive HTTP(S)/FTP(S), HLS VOD/live/DVR, DASH VOD/live/DVR, and static Smooth Streaming/HDS profiles. Web-page extraction can use optional system `yt-dlp`.
- Audio playback, seeking, stream selection, source reopen/recovery, playlist import/export and persistence, and playback-position restore within accepted profiles.
- Runtime settings application and diagnostics, with explicit owner boundaries and controlled reconfiguration.

The [N15 acceptance report](https://github.com/Bogdan7c/rustiplayer/blob/main/docs/native-web-ingress-n15-acceptance.md) records 11 successful source rows reaching the presentation/audio startup gate and two profile exclusions. Its real-hardware evidence and hermetic consumer tests have different scopes. The [compatibility matrix](https://github.com/Bogdan7c/rustiplayer/blob/main/docs/web-media-compatibility-matrix.md) defines the accepted profiles; these are not universal codec, website, or GPU guarantees.

## Build from source

This release is planned as a GitHub **prerelease with generated source archives only**. No portable binaries, AppImage, Flatpak, or Windows installer are promised. Archives become available only after publication.

Use the [clone/build and contributor checks](https://github.com/Bogdan7c/rustiplayer/blob/main/CONTRIBUTING.md#clone-and-build-on-linux) and [README quick start](https://github.com/Bogdan7c/rustiplayer/blob/main/README.md#quick-start). The pinned primary toolchain is Rust 1.96.0; MSRV is checked separately at 1.92.0. Linux builds need the documented native development dependencies; playback requires Vulkan and the appropriate runtime drivers.

Read the [architecture](https://github.com/Bogdan7c/rustiplayer/blob/main/ARCHITECTURE.md), [documentation index](https://github.com/Bogdan7c/rustiplayer/blob/main/docs/README.md), and [changelog](https://github.com/Bogdan7c/rustiplayer/blob/main/CHANGELOG.md). These draft links target `main` so they do not pretend that a release tag exists; publication preparation should pin them to the verified release revision/tag.

## Known limitations

- Linux is the primary platform. Windows native application support is planned; macOS is outside the roadmap through 1.0.
- Vulkan rendering is required even with software decoding. No production CPU rendering fallback exists. VA-API support depends on the exact device, driver, codec/profile, and frame-import path.
- Native HDR display output is not implemented; HDR-monitor acceptance has not run.
- A native subtitle engine and published subtitle compatibility matrix remain roadmap work. Manifest subtitle descriptors do not prove playback.
- DRM, RTSP/RTP/MMS, RTMP wire playback, and private live extractor state are outside the supported profile. Smooth Streaming/HDS are static VOD only.
- N15 excludes its avc3/HE-AAC/TTML HLS row and a DASH row with unrepresentable aspect metadata. Page extraction depends on compatible system `yt-dlp`, its environment, upstream extractors, and server behavior.
- The UI remains under development and contains Russian text; redesign and localization are planned.
- Cross-source queue evidence does not qualify every windowed UI Next transition. See N15 for the exact consumer boundary.
- T480s runtime capture and performance evidence remain pending. N15 ingress experiments are not whole-player startup, power, battery, or VLC benchmarks.

Media and network manifests are untrusted input. Review the [security policy](https://github.com/Bogdan7c/rustiplayer/blob/main/SECURITY.md) before reporting suspected vulnerabilities. [Support](https://github.com/Bogdan7c/rustiplayer/blob/main/SUPPORT.md) separates bugs, proposals, questions, and security reports. Discussions and Private Vulnerability Reporting are planned for S12 and are not claimed active in this draft.
