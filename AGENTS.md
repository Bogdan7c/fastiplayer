## Локальная проверка через SonarQube

SonarQube установлен локально для проекта `rustiplayer` и доступен по адресу `http://127.0.0.1:9000`.
Проектный ключ: `rustiplayer`.
Dashboard проекта: `http://127.0.0.1:9000/dashboard?id=rustiplayer`.

По моему запросу проверить проект через Sonar:
1. Не записывать токен в файлы, историю команд или конфиги; использовать только переменную окружения `SONAR_TOKEN`.
2. Если sandbox блокирует доступ к `127.0.0.1:9000`, запускать скан с escalation и `SONAR_USER_HOME=/tmp/rustiplayer-sonar-user-home`.
3. Запускать анализ из корня репозитория командой `SONAR_USER_HOME=/tmp/rustiplayer-sonar-user-home scripts/sonar-local-analysis.sh`.
4. После успешного scanner-run дождаться обработки background task в SonarQube; scanner печатает ссылку вида `/api/ce/task?id=...`.
5. Issues смотреть через UI dashboard или Web API SonarQube, но сначала группировать проблемы по rule/severity/file, искать общую причину, а не чинить симптомы по одному.
6. Перед исправлениями сверяться с Context7 и code_index, затем править код, запускать релевантные тесты/`cargo clippy`, повторять Sonar scan и проверять, что issues действительно исчезли.
7. Если Sonar предлагает спорное изменение архитектуры, публичного API или поведения, остановиться и обсудить решение перед правками.
