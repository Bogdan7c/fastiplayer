# Video FFmpeg Build Tooling

## Vendored FFmpeg по умолчанию (2026-10-20, решение владельца)
- Зачем: программный декодер не должен зависеть от системного FFmpeg (кейс владельца: NVIDIA без VA-API + «какой угодно» системный FFmpeg → раньше плеер падал до `main` при смене soname или молча оставался без декодера при FFmpeg < 8.1).
- Решения владельца: свой FFmpeg по умолчанию и собирается вместе с бинарём; исходники скачиваются и проверяются по SHA-256; `.so` рядом с бинарём (не static); системный FFmpeg остаётся флагом `system-ffmpeg`; механизм — патч `ffmpeg-sys-next`.
- Цепочка:
  1. First-party crate `crates/ffmpeg-vendor` (workspace member, `links = "fastiplayer_ffmpeg_vendor"`). `build.rs` берёт архивы FFmpeg 8.1.3 + dav1d 1.5.4 (`src/sources.rs`: версия, URL, SHA-256; офлайн через абсолютные пути в `FASTIPLAYER_FFMPEG_ARCHIVE`/`FASTIPLAYER_DAV1D_ARCHIVE`, сумма проверяется всегда). dav1d собирается meson-ом статически с PIC, FFmpeg — минимальный LGPL (`src/build_options.rs`: `--disable-everything`, декодеры h264/hevc/vp8/vp9/libdav1d, только avcodec+avutil, shared, без -march=native/-ffast-math, `--build-suffix=_fastiplayer`). Штамп-отпечаток в `OUT_DIR/fastiplayer-vendored/ffmpeg-prefix/` пропускает пересборку. Метаданные: `prefix`, `link_libraries`, `runtime_lib_dir`, `runtime_libraries`, `license_dir`. Логи шагов: `OUT_DIR/fastiplayer-vendored/logs/`. Нужны tar, patch (GNU, с 2026-10-28), curl, meson, ninja, nasm, make, pkg-config; кросс-компиляция отвергается.
  2. Патч `crates/ffmpeg-sys-next-patch` (фича `fastiplayer-vendored` = optional dep ffmpeg-vendor): берёт prefix и `link_libraries` из DEP_FASTIPLAYER_FFMPEG_VENDOR_*, линкует `avcodec_fastiplayer`/`avutil_fastiplayer`, bindgen по `prefix/include`. Детали — `mem:dependency-patches/core`.
  3. `video-ffmpeg`: фичи `ffmpeg` (код FFI; сама по себе = системный FFmpeg через pkg-config/FFMPEG_DIR) и `vendored-ffmpeg` (= ffmpeg + патч + dep ffmpeg-vendor). `links = "fastiplayer_video_ffmpeg"`; build.rs пересылает метаданные ffmpeg-vendor в app-egui (cargo отдаёт DEP_* только прямым зависимым). Зависимость на ffmpeg-vendor — прямой path, не workspace (guardrail: `ffmpeg-vendor` в FFMPEG_FORBIDDEN_DEPENDENCIES, разрешён только video-ffmpeg).
  4. `app-egui`: `default = ["vendored-ffmpeg"]`, `system-ffmpeg = ["ffmpeg"]`; фичи аддитивны — при обеих побеждает vendored. `build.rs` копирует soname-файлы + лицензии в `target/<profile>/lib/` (profile dir = 3 уровня вверх от OUT_DIR), `rerun-if-changed` на скопированные файлы, `rustc-link-arg-bins=-Wl,-rpath,$ORIGIN/lib`.
- Почему суффикс `_fastiplayer`: без него бинарь слинковался с системным `libavcodec.so.63` — `/usr/lib` от других зависимостей стоит в путях поиска раньше нашего. Уникальное имя исключает подмену и при линковке, и в рантайме.
- Тесты/cargo: `cargo test`/`cargo run` находят .so через LD_LIBRARY_PATH (cargo добавляет link-search внутри OUT_DIR); прямой запуск — через RUNPATH. `cargo install` не поддерживается (нет lib/).
- Проверка: `ldd target/release/fastiplayer` → `libavcodec_fastiplayer.so.62 => .../target/release/lib/...`.
- Обновление FFmpeg/dav1d (security): правка `crates/ffmpeg-vendor/src/sources.rs` (версия + SHA-256, сверенный с подписью/опубликованной суммой) и ожидаемых версий в `video-ffmpeg/tests/ffmpeg_runtime_probe.rs` (`vendored_ffmpeg_probe_reports_the_pinned_libraries_not_the_system_ones`).

## Патчи исходников FFmpeg (gles2-renderer сессия 13, 2026-10-28, решения 83 и 87)
- Unified diff в `crates/ffmpeg-vendor/patches/<unpacked_directory_name>/NNNN-*.patch` (сейчас `ffmpeg-8.1.3/0001-libdav1d-direct-rendering.patch`: DR1 у libdav1d). Политика — чистый `src/source_patches.rs` (общий с build.rs через `#[path]`; его тесты подключены `#[path = "source_patches/tests.rs"]` — иначе rustfmt не находит вложенный модуль): `ALL_SOURCE_PATCHES`, `patches_for(source)`, `gnu_patch_arguments(dir, file, PatchPass::{DryRun, Apply})` = `-p1 --fuzz=0 --forward --batch --no-backup-if-mismatch`, `patch_fingerprint_lines(crate_root)`.
- Наложение — `build_support/source_patching.rs`: после `unpack_archive` (всегда распаковывает заново), до configure; dry-run → apply; провал dry-run = `VendoredBuildError::SourcePatchDoesNotApply` (имя, версия, путь, хвост лога), нет файла = `SourcePatchMissing`. GNU `patch` — в `REQUIRED_BUILD_TOOLS` (7 инструментов), в apt CI и README.
- SHA-256 каждого патча в `build_fingerprint` (теперь `Result`). В `build.rs` `cargo::rerun-if-changed=patches`: любой `rerun-if-*` (уже был `rerun-if-env-changed`) выключает сканирование всего пакета — без этой строки правка патча не будила build script.
- Inventory: `[[source_patch]]` в `docs/dependency-patches.toml` (sha256, target_version, migration_checklist); `scripts/check-dependency-patches.py` сверяет сумму, версию с `sources.rs`, каталог версии, регистрацию в `source_patches.rs` и сирот на диске.
- Обновление FFmpeg: кроме `sources.rs` — перенести патчи в каталог новой версии и пройти чек-лист миграции записи.
- Тесты: `cargo test -p ffmpeg-vendor` гоняет настоящий `patch` (строгость, отказ при сдвиге контекста и повторе, наш патч на нетронутом `libdav1d.c` из проверенного архива `OUT_DIR/.../downloads`).

## Старый скрипт
- `scripts/tooling/build-ffmpeg-lgpl.sh` (FFmpeg 8.1.1 shared в `target/fastiplayer-ffmpeg/<version>`, без SHA-256 и без dav1d) обычной сборкой не используется; оставлен для `system-ffmpeg` со своим prefix-ом (`FFMPEG_DIR`/`PKG_CONFIG_PATH`). README tooling помечен.

## Тесты
- `cargo test -p ffmpeg-vendor` — политика: SHA-256 (FIPS-векторы, подмена, отсутствие), LGPL/переносимость configure, allowlist декодеров, суффикс, static PIC dav1d, soname-фильтр.
- `cargo test -p video-ffmpeg --features vendored-ffmpeg`: probe на закреплённых версиях; `tests/av1_software_decode.rs` — фикстура `tests/fixtures/av1/testsrc2-160x90-10frames.ivf` (generate.sh, libaom): все 10 кадров декодируются без GPU; ignored-тест (Vulkan) доводит первый и последний AV1-кадр до WGPU submit/release. Общий WGPU-стенд — `tests/support/wgpu_acceptance.rs` (его же использует `vertical_seek_wgpu.rs`).
