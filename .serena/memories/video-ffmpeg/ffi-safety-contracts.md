# FFmpeg FFI safety contracts (Session 14B, 2026-07-11)

Дополняет `mem:core` и `mem:video-ffmpeg/software-design`.

- Raw `AVCodecContext`/`AVFrame`/`AVPacket` и `ffmpeg_sys_next` остаются только внутри `crates/video-ffmpeg/src/ffi`. Integration guard `crates/video-ffmpeg/tests/raw_ffi_boundary.rs::raw_ffmpeg_types_stay_inside_ffi_module` запрещает прямой `ffmpeg_sys_next` вне `ffi` и public raw-type exposure.
- `CodecContext` — exclusive mutable owner и намеренно `!Send + !Sync`. `FfmpegDecoderWorker` теперь конструируется внутри `ffmpeg-video-decoder` thread closure; через spawn boundary проходят только neutral channels/handles/config. Сам codec открывается позднее на этом же owner thread через `Configure` command. Не возвращать `unsafe impl Send`, не добавлять Mutex ради trait.
- `OwnedAvPacket` остаётся `!Send + !Sync`: allocation, timestamp mutation, send/unref/free выполняются на decoder owner thread. После `av_packet_alloc` wrapper создаётся сразу, поэтому `av_new_packet` error освобождает allocation через единственный Drop path. `av_new_packet` обеспечивает `AV_INPUT_BUFFER_PADDING_SIZE` zero padding; packet ownership остаётся у caller при `avcodec_send_packet`.
- `OwnedAvFrame` имеет только доказанный `Send`, но не `Sync`: exclusive refcounted frame один раз перемещается из decoder owner thread в immutable `AvFrameHostPlanarOwner`. После publication wrapper не предоставляет mutable access; отдельный host owner имеет обоснованный `Sync`, а raw frame owner — нет. FFmpeg AVBuffer reference/unreference thread-safe. `av_frame_ref` clone владеет отдельной ссылкой; `unref` сохраняет reusable frame allocation; Drop вызывает `av_frame_free` ровно для своего allocation.
- `CodecContext::open` сразу после `avcodec_alloc_context3` создаёт единый RAII owner, содержащий raw context и boxed immutable `FormatNegotiator`. Все последующие ошибки (extradata, thread budget conversion, options dictionary, `avcodec_open2`, unused options) идут через один Drop path. Drop сначала синхронно вызывает `avcodec_free_context`, пока callback `opaque` state ещё жив, затем Rust освобождает boxed negotiator. Это не позволяет callback пережить state.
- Extradata выделяется `av_mallocz(extradata_len + AV_INPUT_BUFFER_PADDING_SIZE)`, payload копируется, padding остаётся нулевым, затем ownership передаётся `AVCodecContext`; освобождение происходит только в `avcodec_free_context`.
- Runtime loader загружает libavutil раньше libavcodec. Rust local drop order выгружает libavcodec раньше libavutil. `libloading::Symbol` остаётся внутри helper call и не переживает соответствующую `Library`.
- Compile-time trait guards находятся в unit tests `ffi::{codec_context,frame,packet}`. Deterministic post-allocation negative test: `post_allocation_validation_error_releases_codec_context_and_extradata`.
- Матрица проверки: `cargo test -p video-ffmpeg --no-default-features`; `cargo test -p video-ffmpeg --features ffmpeg`; strict Clippy отдельно для обоих режимов; raw boundary integration test. Installed runtime probe остаётся `#[ignore]` в обычном suite и запускается отдельно: `cargo test -p video-ffmpeg --features ffmpeg --test ffmpeg_runtime_probe -- --ignored --exact installed_ffmpeg_runtime_probe_reports_available_runtime`.
