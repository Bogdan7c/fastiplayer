# Frame Server Timeline Hover Intent

- S24 wires the real timeline pointer-hover stream in `app-egui` without decode/executor work. This is the durable handoff for future HoverPreview/SeekLanding predecode sessions.
- Visual widget boundary: `crates/app-egui/src/ui/timeline.rs` emits `TimelineInteraction { actions, hover_intent, display_position }`. `TimelineAction` remains command-oriented only (`Seek`/live scrub routes); hover is a separate `TimelineHoverIntent::{Target(TimelineHoverTarget), Clear}` so it cannot accidentally enter `PlayerCommand` mapping.
- Pointer API invariant: pure hover uses egui `Response::hover_pos()`; click/drag/live scrub still use `Response::interact_pointer_pos()`. Seekable timeline only: non-seekable timelines emit no hover intent. Pointer down, drag, click, lost focus, active drag, and active live scrub emit/produce clear rather than hover target.
- App boundary: `crates/app-egui/src/ui/player_controls.rs` forwards hover as `ControlAction::TimelineHover`; `crates/app-egui/src/state/ui_runtime.rs` coalesces all hover actions for one egui/app frame through `TimelineHoverFrameCoalescer`, latest target wins, with no debounce delay and no config knob.
- App-owned state: `crates/app-egui/src/timeline_hover_intent.rs` owns `TimelineHoverIntentState`, the placeholder visual preview slot, and test-observable invisible prepare/visual presentation outcomes. It intentionally does not build `TimelineHoverPrepareTarget` yet because source/backend/track/generation guards are not safely owned at this S24 boundary.
- Config invariant: `CommittedConfigSnapshot::hover_preview_enabled()` controls only visual placeholder presentation. `hover_preview_enabled=false` still emits/stores the invisible prepare target intent. Device incapability must not suppress S24 intent; real typed pressure/unavailable/current-target degradation belongs to S25+ decode/predecode execution.
- Player invariant: timeline hover sends no `PlayerCommand`, does not call services/player directly from the widget, does not publish `PlaybackState::Scrubbing`, and must leave paused/stopped snapshots observable as `Paused`/`Stopped`. Real hover decode/render/materialization, shared prepared branch consumption, and leave grace remain later sessions (S25/S28A).
