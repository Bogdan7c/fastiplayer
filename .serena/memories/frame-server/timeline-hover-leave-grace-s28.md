# S28 Timeline Hover Leave Grace

- `app-egui` owns hover/focus leave grace in `crates/app-egui/src/state/timeline_hover_leave_grace.rs`. It is pure UI runtime state over `Instant`/`Duration`: start grace on timeline leave, cancel on re-enter, expire once during normal UI frame processing, or cancel immediately for non-timeline controls/actions/hotkeys and passive primary pointer presses that are not tied to a timeline target/seek. There is no background thread or persistent queue.
- `TimelineHoverIntentState` remains pure and does not know timers. `Clear` removes the semantic active target and visual slot; a later target after clear emits a fresh invisible prepare intent. `hover_preview_enabled=false` still disables only visual preview/materialization and never invisible prepare.
- On leave, `AppState` immediately cancels the active `TimelineHoverPrepareController` span with `TimelineLeft`. This preserves the invariant that grace is UX retention only: it does not extend decode range, dependency span, or prepare window coverage. Grace delays only release of already prepared hover-owned working-set entries.
- `hover_leave_grace_ms` is persisted config with default 500 ms and valid range `0..=500`; `0` means immediate release on leave only, not disabled hover/predecode. Re-enter before expiry preserves entries by cancelling pending release; expiry/non-timeline action release entries exactly once.
- `frame-server-core::TimelineHoverPrepareWorkingSet::release_hover_owned_entries_for_session_end(reason)` is the neutral owner boundary for session-end cleanup. It clears primary hover entries and recent-superseded entries, returns separate counters, and relies on `VideoFrameLease` drop for release-once semantics. Pressure release order remains separate and unchanged: `release_one_for_resource_pressure` still releases recent-superseded first, then lower-priority primary byproducts, never the protected current target.
- `player-core::PlayerTimelineHoverPrepareHandoff::release_hover_owned_entries_for_session_end(reason)` exposes the cleanup boundary to `app-egui` without letting app code access working-set fields. Promoted SeekLanding resources are protected because promotion removes them from hover storage; they remain player transaction-owned until commit/cancel/audio-failure/demote-back.
