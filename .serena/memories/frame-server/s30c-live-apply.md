# Frame Server Live Apply

- `[frame_server]` committed settings route is live-applied through `AppRuntimeRoute::FrameServer`.
- Since 2026-07-03, frame-server persisted/runtime settings are only live-scrub related: `live_scrub_enabled`, `live_scrub_decode_mode`, and `live_scrub_max_hz`. Hover preview/predecode settings, prepare slots, leave grace, network hover throttle, budget settings, and recent-superseded settings were removed.
- `fastiplayer-settings::FrameServerRuntimeSettingsUpdate` carries the persisted `fastiplayer_config::FrameServerConfig` snapshot and a `PlayerRuntimeSettingsUpdate::frame_server_policy` payload built with `PlayerWorkerConfig::frame_server_config_from_app_config`.
- `player-core` owns the session/worker policy update via `PlayerRuntimeSettingsUpdate::with_frame_server_policy(...)`, `PlayerRuntimeApplyGroup::FrameServerPolicy`, and `PlayerSession::apply_frame_server_policy_config(...)`. App/settings code must keep using the worker request/reply boundary; do not mutate `PlayerSession.frame_server_config` directly.
- Live scrub mode/max-Hz changes during active drag remain diagnostics-only through deferred live-scrub snapshots; active gestures keep their pointer-down route. There is no hover cleanup, hover network throttle, primary-slot reconfigure, or recent-superseded reconfigure path anymore.
