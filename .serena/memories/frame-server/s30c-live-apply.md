# S30C Frame Server Live Apply

- `[frame_server]` committed settings route is now live-applied through `AppRuntimeRoute::FrameServer`; it is no longer S30B commit-only.
- `rustiplayer-settings::FrameServerRuntimeSettingsUpdate` carries both the persisted `rustiplayer_config::FrameServerConfig` snapshot and a `PlayerRuntimeSettingsUpdate::frame_server_policy` payload built with `PlayerWorkerConfig::frame_server_config_from_app_config`.
- `player-core` owns the session/worker policy update via `PlayerRuntimeSettingsUpdate::with_frame_server_policy(...)`, `PlayerRuntimeApplyGroup::FrameServerPolicy`, and `PlayerSession::apply_frame_server_policy_config(...)`. App/settings code must keep using the worker request/reply boundary; do not mutate `PlayerSession.frame_server_config` directly.
- `app-egui::AppState::sync_committed_config_snapshot` owns app-side live effects: `hover_preview_enabled=false` clears only visual hover preview/materialization; invisible prepare remains active. Network hover throttle-only changes call `TimelineHoverPrepareController::update_network_hover_prepare_throttle` without invalidating source context or in-flight latest-only jobs. Live scrub mode/max-Hz changes during active drag remain diagnostics-only through the existing deferred snapshot; active gestures keep their pointer-down route.
- Primary prepare slot shrink/grow goes through `PlayerTimelineHoverPrepareHandoff::reconfigure_hover_prepare_primary_capacity_protecting`; current hover target is protected when available, and grow only changes future admission. App chooses the active primary slot knob by current backend class: FFmpeg software uses `software_hover_prepare_window_slots`, hardware/no-backend uses `hover_prepare_window_slots`.
- Recent-superseded shrink/grow is neutral in `frame-server-core`: `TimelineHoverPrepareWorkingSet::reconfigure_recent_superseded_budget(...)` releases oldest over-budget recent entries by resource path and never evicts primary hover entries; grow does not refill.
- S30D hover budget capability/admission diagnostics remain out of scope; fixed-too-large backend budget handling must not be faked in S30C.
