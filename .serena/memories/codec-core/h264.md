# codec-core H.264

- `codec-core` now has a platform-neutral H.264 adapter module (`crates/codec-core/src/h264.rs`) with no VAAPI/cros/WGPU dependencies.
- Public H.264 APIs include `parse_avc_decoder_configuration_record`, `H264Packetization::{AnnexB, AvccLengthPrefixed { nal_length_size }}`, `h264_nal_units`, `h264_access_unit_to_annex_b`, `probe_h264_packet_keyframe`, `h264_sps_metadata_from_*`, and codec-neutral registry helpers `probe_video_packet_*_with_codec_private`.
- v1 policy accepts only H.264 ConstrainedBaseline/Main/High, 8-bit 4:2:0, and maps confirmed SPS metadata to NV12 zero-copy requirements. High10, 4:2:2, 4:4:4, MVC/Stereo/unsupported profiles return typed rejections.
- H.264 keyframe probing treats IDR slice as decode-start; SPS/PPS-only access units are valid but `NotKeyframe`; malformed/incomplete packets are recoverable `Uncertain`, not fatal by default.
- AVCC/AnnexB conversion is explicit. SPS/PPS injection is caller-selected via `H264ParameterSetInjection`; the adapter does not hide lifecycle policy.
- Focused coverage lives in `codec-core` unit tests for synthetic `avcC`, AnnexB/AVCC framing, SPS requirement refinement, unsupported variants, and VP9 regression guard tests remain unchanged.
