# codec-core H.264

- `codec-core` now has a platform-neutral H.264 adapter module (`crates/codec-core/src/h264.rs`) with no VAAPI/cros/WGPU dependencies.
- Public H.264 APIs include strict `parse_avc_decoder_configuration_record`, in-band-aware `parse_avc3_decoder_configuration_record`, `H264Packetization::{AnnexB, AvccLengthPrefixed { nal_length_size }, AvccLengthPrefixedWithInBandParameterSets { nal_length_size }}`, `h264_nal_units`, `h264_access_unit_to_annex_b_into`, legacy wrapper `h264_access_unit_to_annex_b`, `probe_h264_packet_keyframe`, `h264_sps_metadata_from_*`, and codec-neutral registry helpers `probe_video_packet_*_with_codec_private`.
- v1 policy accepts H.264 Baseline/ConstrainedBaseline/Main/High, 8-bit 4:2:0, and maps confirmed SPS metadata to NV12/host-planar requirements according to the selected backend contract. Ordinary Baseline is a distinct exact profile and must never be aliased to ConstrainedBaseline or Main. High10, 4:2:2, 4:4:4, MVC/Stereo/unsupported profiles return typed rejections.
- H.264 keyframe probing treats IDR slice as decode-start; SPS/PPS-only access units are valid but `NotKeyframe`; malformed/incomplete packets are recoverable `Uncertain`, not fatal by default.
- `parse_avc_decoder_configuration_record` accepts canonical `avcC` reserved bits and noncanonical MP4 muxer records that zero those reserved bits; only the meaningful low bits drive `nal_length_size` and SPS count. This keeps otherwise playable H.264 MP4 files from being rejected as `UnsupportedVideoCodec`.
- AVCC/AnnexB conversion is explicit. SPS/PPS injection is caller-selected via `H264ParameterSetInjection`; the adapter does not hide lifecycle policy. `h264_access_unit_to_annex_b_into` writes into a caller-owned `Vec<u8>`, clears it before writing, preserves capacity, leaves it empty on error, and avoids the intermediate NAL-list allocation used by `h264_nal_units`.
- Focused coverage lives in `codec-core` unit tests for synthetic `avcC`, AnnexB/AVCC framing, SPS requirement refinement, unsupported variants, and VP9 regression guard tests remain unchanged.
- Session 27A first decomposed the former mixed `crates/codec-core/src/h264.rs`: at that stage the facade owned avcC/NAL packetization, Annex-B conversion and keyframe probing; `crates/codec-core/src/h264/requirements.rs` owns SPS/RBSP parsing and accepted profile/bit-depth/chroma/color policy; codec-local characterization tests live in `crates/codec-core/src/h264/tests.rs`. The S27 YouTube fix adds public typed `H264ProfileIndication` / `UnsupportedH264ProfileIndication` plus `h264_profile_from_indication`, reused by yt-dlp codec tags, avcC and SPS refinement. `profile_idc=66` with constraint-set evidence maps to ConstrainedBaseline; otherwise it remains ordinary Baseline.

## S42 Wave C2 byte-stream boundary (2026-08-27)

- `crates/codec-core/src/h264.rs` remains the public facade and owner of `avcC`/`avc3` parsing, SPS/PPS presence contracts, typed packetization and SPS requirement projections.
