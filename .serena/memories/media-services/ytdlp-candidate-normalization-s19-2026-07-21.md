# S19 generic yt-dlp candidate normalization (2026-07-21)

- `service-ytdlp` owns deserialization of public serialized yt-dlp format fields, request-material reconstruction and provider-specific normalization. `web-media-core` remains the neutral owner of identities, parsed/raw protocol-container-codec values, layouts and static rejection vocabulary.
- Public entry point: `resolve_yt_dlp_candidate_snapshot_with_config`. Process parsing is shared through the generic bounded/cancellable `resolve_yt_dlp_candidate_document_with_cancellation<T>`, so the existing metadata path keeps its behavior.
- Every `formats[]` row maps to exactly one visible `YtDlpCandidateEntry`: accepted candidate or typed rejection. Duplicate IDs, unknown/profile-excluded metadata and unsupported request requirements remain visible; normalization never builds a Cartesian product.
- Ordinary selected muxed/video-only/audio-only results use the selected top-level format as their only request component. Only a validated compound merge may use exact `requested_formats` components. Component roles are explicit `Muxed | Video | Audio`, not positional.
- Identity contract: snapshot-local candidate ID + immutable extraction generation + source-bound semantic identity. Exact selection accepts only the same source/generation/inventory. Cross-generation recovery uses semantic identity plus exact stream layout; missing or ambiguous matches are typed failures.
- Request material is service-owned schema v1. It represents URL/manifest, concrete fragments and base URL, inline HLS, headers, cookies, extra segment/key query parameters, HLS AES and declarative RTMP fields. request_data, impersonation, downloader/private live state and other non-reconstructible requirements are typed rejections. Debug/summary output never exposes URLs, headers, cookies, inline manifests, keys or payloads.
- Descriptor mapping preserves raw and parsed protocol/container/codec identities, numeric metadata and HDR hints. A narrow HLS-only compatibility rule accepts S00's ext=mp4 + container=mpegts serialization; the same pair is a conflict for progressive transport.
- `web-media-core::ContainerIdentity::consistent_family` recognizes only proven refinement pairs: ISO-BMFF+fragmented ISO-BMFF, Matroska+WebM and FLV+F4F. Other disagreements remain typed conflicts.
- The checked-in S00 target corpus (13 rows) normalizes successfully, including MP4/WebM/M4A, muxed/separate/video-only/audio-only and HLS/DASH fragment variants. Focused tests live in `crates/service-ytdlp/src/candidate/tests.rs`.
- Current boundary limitation: S00 does not serialize a subtitle descriptor schema, so candidate subtitle lists stay empty. The new snapshot API is not yet wired into app playback; later composition/open milestones consume it instead of bypassing ownership.
