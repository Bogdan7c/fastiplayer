# S34 — Static DASH VOD production profile (2026-07-24)

## Ownership and runtime flow

- `dash-mpd-core` is the pure static MPD schema/profile owner over the single `bounded-xml-reader` boundary. It keeps BaseURL inheritance, finite Periods, Representation identity/bandwidth/dimensions, SegmentTemplate duration/Timeline, SegmentList and SegmentBase ranges. Dynamic MPD, ContentProtection and unsupported/ambiguous required constructs fail closed.
- `service-ytdlp` owns pinned `http_dash_segments` request material. Serialized fragments are valid only as one leading initialization row followed by bounded media rows with finite positive durations; generator/private state is excluded. It projects headers/cookies/segment query into S21T without concrete HTTP/demux/player deps. DASH secret scope is the authoritative MPD/fragment directory plus exact origin/secure gate; cross-origin redirect stripping remains monotonic.
- `web-media-dash` owns static VOD planning/readiness. Inputs are exact manifest-backed MPD or exact serialized fragments, never fallback between them. `DashVodHttpContext` distinguishes manifest/single-serialized/separate-serialized contexts; separate serialized video/audio retain independent request contexts. Only proven fMP4/WebM, muxed/single/separate and exactly aligned bounded Period/component timelines are admitted.
- Concrete demux parsing is reused through the injected `demux-api::DemuxRegistry` and existing S28 Symphonia fMP4/WebM factories. `web-media-dash` does not parse container packets.
- `app-egui::web_media_dash_open` is the composition owner. It maps the exact normalized candidate, enables `TransportFamily::Dash` only now that the runtime exists, rejects live DASH as S35, prepares everything before the existing strong install barrier, and passes only a ready demuxer plus neutral seek port to `PreparedMedia`.

## Receipted seek boundary

- `demux-api` owns `ProgressiveAsyncSeekHandle`: bounded request/receipt queues, monotonic IDs, runtime-generation fences, supersede/cancel/stale outcomes, and worker-side reopen/scan. Player-owner never blocks on network/parser seek.
- `player-core` knows no DASH types. `PreparedMedia::with_worker_receipted_demux_seek` installs an `Arc<dyn PreparedDemuxSeekPort>` before commit. Session stores exact media-instance + seek-generation + request-id + requested-demux-target fences, suppresses demux reads while pending, drains stale receipts, and enters the existing final seek commit only for an exact successful authoritative result. Failed/cancelled/superseded/stale/mismatched receipts never publish position.
- Rebuild, startup and normal queue-owned open paths propagate the port before the same Ready/authorize/Installed barrier. Legacy prepared media remain synchronous.

## Evidence and limitations

- Hermetic fixtures cover BaseURL/template duration/timeline/list/base addressing, init/ranges, ambiguity and exact dimensions, serialized roles/context, component alignment, multi-period transition, cancellation/malformed boundaries, fMP4 playback/receipted seek, and actual ordered WebM runtime readiness.
- Live/dynamic DASH, DRM/ContentProtection, ABR switching, subtitles and unproven containers remain out of S34 and fail closed.
