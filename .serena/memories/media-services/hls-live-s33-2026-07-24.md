# S33 — HLS live/DVR (2026-07-24)

## Итог

- S33 добавляет explicit HLS live/DVR поверх S31/S31L/S32 без новых `DemuxReadEvent` и без HLS-знания в player-core.
- Live admission fail-closed: `service-ytdlp::YtDlpLiveIntent` строится только из public serialized `is_live/live_status`; отсутствие `ENDLIST` само по себе не превращает VOD candidate в live.
- `hls-playlist-core` сохраняет `EXT-X-MEDIA-SEQUENCE` и `EXT-X-DISCONTINUITY-SEQUENCE`, валидирует initial/refresh live profile; LL-HLS-specific tags остаются typed incompatible.

## Owners и boundaries

- `web-media-hls::live` разбит на `open`, `refresh`, `snapshot`, `timeline`, `demux`, `av`; central S32 owner files не получили live orchestration.
- Каждый live media segment (+ действующий fMP4 MAP) открывается отдельным inner demux. Это HLS-private заменяемая стратегия, которая сохраняет exact segment -> packet/RAP provenance без расширения generic demux/container API.
- Segment-local track IDs стабилизируются; `TracksChanged { duration: None }` публикуется только при фактическом изменении `TrackInfo`/config. Separate A/V seek/replacement готовится offside и коммитится атомарно.
- Refresh main и selected alternate AUDIO имеет независимые RFC cadence/deadlines: changed playlist ждёт target duration, unchanged — half target; reload выполняется только для due rendition, main/audio snapshot и public timeline коммитятся атомарно.
- Refresh generation/sequence/temporal overlap fenced. Retained identity обязан сохранять URI/range/duration/key/MAP; rollback, gap без overlap и mutation typed-fail до state publication.

## DVR и seek

- `HlsLiveTimelineCoordinator` публикует существующий S31L `DynamicMediaTimelinePort`; player-core API не менялся.
- Public DVR range — пересечение выбранных renditions, retained admitted segment identities, реально наблюдённого packet coverage и decode-safe audio/RAP anchors. Manifest EXTINF window только ограничивает расчёт и напрямую не публикуется.
- Expired evidence удаляется немедленно; target не clamp-ится. Пустое доказанное пересечение публикует live without DVR. Live остаётся `duration=None` и не получает persistent resume position.
- Segment-scoped timestamp mapping и rolling evidence принадлежат HLS runtime; ENDLIST на refresh прекращает polling и даёт explicit EOS только после drain retained segments.

## Endpoint/key lifecycle и secrets

- Пользователь выбрал transparent endpoint refresh: 401/403/404/410 manifest, segment/init или key ресурса даёт secret-safe typed single-flight signal.
- Во время refresh demux возвращает existing `TemporarilyUnavailable`; app-owned `HlsEndpointRefreshPort` выполняет bounded fresh yt-dlp extraction, exact semantic rematch и создаёт следующую transport generation. Fresh manifest/transport/snapshots публикуются атомарно; stale generation игнорируется.
- Segment evidence сужается только после доказанного refreshable HTTP expiry, а не после произвольной demux/crypto/cancel ошибки. Key cache очищается при accepted manifest/live-edge или transport-generation change; одинаковый key URI не переносит stale bytes между generations.
- Raw locator/manifest/segment/key URL, headers, cookies и payloads не входят в Debug/errors/signals. Redirect/query/cookie policy остаётся S21T/S31-owned.
- Drop live runtime делает cooperative cancellation + condvar wake и не join-ит blocking network/yt-dlp worker на player-owner; detached worker завершается на существующей cancellation/I/O boundary.

## App integration

- `app-egui::web_media_hls_refresh` владеет yt-dlp re-extraction/rematch adapter-ом; `web_media_hls_open` только компонует exact runtime material.
- `PreparedYtDlpWebMedia` несёт optional timeline port. Normal open, startup и settings rebuild устанавливают его через `PreparedMedia::with_dynamic_timeline` до Ready/Installed barrier; service finite duration подавляется для live.
- Recoverable pre-barrier failure не мутирует current playback; queue/player ownership и CommitMustFinish остаются прежними.

## Focused proof

- `crates/web-media-hls/tests/live_runtime.rs`: hermetic HTTP tests для segment/key/manifest expiry recovery, typed secret-safe rematch failure, nonblocking drop/cancel, ENDLIST drain, sliding seek expiry, fMP4 MAP/discontinuity config change/stable IDs/durationless TracksChanged.
- Pure owner tests в `crates/web-media-hls/src/live/{snapshot,refresh,demux}.rs`: retained RAP evidence, sliding eviction, mutation/race rejection, independent cadence, single-flight expiry и key cache generation.
- Parser/live intent/app barrier tests: `crates/hls-playlist-core/tests/parser.rs`, `crates/service-ytdlp/src/candidate/tests.rs`, `crates/app-egui/src/media_open/preparation.rs`.
- Final affected verification: Rust 1.96 all-target tests PASS (`app-egui` 842; `web-media-hls` 52; parser 17; service-ytdlp 55; web-media-adaptive 18), strict Clippy `-D warnings`, MSRV 1.92 affected check, fmt, toolchain policy, refactor guardrails and `git diff --check` PASS.

## Known limitations

- LL-HLS parts/blocking reload/delta updates/rendition reports/preload hints remain outside profile and typed incompatible.
- No ABR/variant switch, subtitle playback, private yt-dlp live generator state, DRM, RTSP/RTP/MMS or eager whole-DVR probing.
- Segment-scoped inner demux trades one TS/fMP4 parser open per normal HLS segment for exact provenance; LL-HLS sub-second parts are excluded, and profiling may later justify a provider-neutral provenance boundary only if multiple adaptive protocols need it.
