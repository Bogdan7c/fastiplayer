# S32C — HLS VOD seek и production integration (2026-07-23)

## Итог

- S32 завершён для VOD master/media playlist: muxed/separate alternate AUDIO, MPEG-TS/fMP4, MAP, exact/implicit byte ranges, discontinuity, ENDLIST, AES-128 initial profile и decode-safe seek.
- `app-egui::web_media_hls_open` — composition boundary между exact yt-dlp candidate evidence, `web-media-hls`, concrete TS/fMP4 registry и существующим media-open Installed barrier. До доказанного initial `TracksChanged` player/current source не мутируются.
- Subtitle renditions сохраняются как bounded secret-safe descriptors в installed web configuration; URI/reference не попадают в UI/state, fetch/decode/playback не реализуются по контракту S32.

## Seek/lifecycle boundary

- `demux-api::ProgressiveDemuxer` разделён на owner (`progressive.rs`) и worker (`progressive/worker.rs`), чтобы central module не раздувался. Worker выполняет blocking source/demux operations вне player owner и публикует generation-fenced events.
- Decode-safe seek отменяет/суперседит старую работу, реконструирует нужный HLS epoch с ближайшей безопасной границы, сбрасывает stale buffered output и публикует только пакеты актуальной generation.
- Для separate A/V используется HLS-owned `TransactionalHlsAvDemuxer`: оба component replacements готовятся offside и коммитятся вместе; ошибка/отмена одного component не публикует половинчатое состояние.
- Stale read/seek failure после supersede не завершает новый progressive worker. Cancellation причины остаются типизированными.

## Deferred codec open (ContentProbe + TracksChanged)

- `HlsMuxedCodecDeferred` → main `ContentProbe` реализуется через `probe_component_container` (не Missing).
- App `prove_deferred` ждёт initial `TracksChanged` до capability prove на media-open worker.

## Secret forwarding (CDN siblings)

- yt-dlp HLS path scope = directory плейлиста (не file path `index.m3u8`).
- Каждый HLS resource fetch: `with_secret_forwarding(http.resource_secret_forwarding_for(&target))` — out-of-scope CDN → `Suppress`, без расширения origin scope.
- См. `mem:media-services/generic-site-open-2026-07-27`.

## Master/audio selection

- Variant и alternate AUDIO выбираются только по exact validated evidence; DEFAULT/AUTOSELECT не являются скрытым fallback.
- Смешанная/неоднозначная topology и tie fail-closed до player mutation. Два независимых HLS manifest resources в `StreamLayout::Separate` пока typed-rejected; поддержанный separate path — alternate AUDIO внутри одного master playlist.
- `DemuxRegistry::open_probed` возвращает реально content-probed container; HLS component intent и track-shape validation проверяют exact audio/video topology.
- RFC `CHANNELS="2/JOC"` теперь разбирается владельцем grammar в `hls-playlist-core`: модель хранит raw descriptor и `NonZeroU64` primary count. Пустой parameter typed syntax-rejected, атрибут у non-AUDIO typed structure-rejected. App передаёт `NonZeroU16` channel-count evidence, runtime не сравнивает сырой descriptor и не дублирует parser.
