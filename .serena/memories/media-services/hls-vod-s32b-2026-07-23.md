## Итог

- `web-media-hls::prepare_hls_vod` выполняет blocking manifest orchestration только на media-open worker-е и возвращает uninstalled `HlsVodOpenResult` с deferred nonblocking demux runtime, duration и bounded subtitle rendition descriptors.

- S32B не меняет app/player/PreparedMedia и остаётся `NotSeekable`; decode-safe seek и production commit barrier принадлежат S32C.

## Composition/demux boundaries

- `HlsVodOpenRequest` получает injected `Arc<DemuxRegistry>`; `web-media-hls` normally зависит только от neutral `demux-api`, а concrete `mpeg-ts-demux` и `symphonia-demux` остаются composition-owned (dev dependencies только для hermetic fixtures).
- `DemuxRegistry::open_required_container` content-sniff-ом доказывает exact caller-required container и typed возвращает `UnexpectedContainer`; generic `open` semantics не менялись.
- `HlsComponentContainerIntent` требует explicit per-component TS/fMP4 evidence. Наличие MAP никогда не угадывает container: fMP4 требует MAP, TS+MAP поддержан и content-proven.
- Each discontinuity/MAP-change epoch открывает новый ordered demuxer, публикует `TracksChanged` и remap-ит stable public track IDs/timestamps в монотонную global VOD timeline. Symphonia не заставляют игнорировать discontinuity; TS existing ordered semantics reuse.
- Separate audio/video проходит existing `CompositeAvDemuxer` с caller-owned lead policy. Required component failure remains fatal before initial track publication.

## Adaptive resource boundary

- `web-media-adaptive::AdaptiveHttpContext::fetch_resource_blocking` — provider-neutral generation-fenced blocking-worker API for manifest/media/init/key resource, reusing S31 HTTP session, retries, redirects, cookies, cancellation and bounds.
- `AdaptiveResourceQueryApplication::{ApplyScopedReplacement, MergeScopedAddition, BypassScopedQuery}` distinguishes existing provider replacement, pinned HLS merge on every authorized redirect hop, and exact hls_aes URI bypass.
- Same-origin redirect reapplies scoped merged query; cross-origin monotonically strips headers/query secrets. MAP uses media-segment scope; normal keys use key scope with service-projected segment fallback; external `hls_aes.uri` bypasses key query.
- `service-ytdlp::YtDlpHlsRequestMaterial::project_scoped_queries` is the single projection into `SecretRequestContextBuilder`; HLS runtime does not retain a duplicate query string set.

## Planning/crypto/runtime invariants

- Manifest/profile/selection/container/range invariants are checked before deferred runtime publication.
- Explicit range uses checked offset/length; implicit range requires prior range of same composed resource; overflow and missing base typed rejected.
- Each epoch source lazily fetches bounded MAP/media/key resources on the progressive demux worker, never player-owner.
- Key cache is epoch-local/current-source scoped: same declaration across MAP/segments fetched once, rotation replaces, NONE clears, stale generation/epoch cannot reuse. Key/plaintext zeroize.
- Inline key suppresses fetch; external key must be exactly 16 bytes; invalid key/padding/container/required component failure occurs before first public `TracksChanged`. S32C must wait for this event before player mutation.
- Subtitle renditions stay descriptors-only; no fetch/decode/playback.

## Дополнение 2026-08-05 — exact media-tail restart для grouped VOD seek

- Историческая строка выше про `NotSeekable` относится к состоянию S32B. Текущий finite grouped HLS VOD поддерживает progressive seek через private restart boundary, не меняя общий `Demuxer` API и не дробя normal playback на segment-scoped epochs.
- `PlannedResource` присваивает media resources стабильный `HlsSegmentRestartCoordinate` внутри каждого discontinuity/MAP epoch. `HlsEpochPlan::restart_tail` восстанавливает нужный MAP/init и suffix от выбранного media segment, сохраняя исходные URL/range/AES key source/IV и исходный `timeline_start`.
- `HlsEpochSource` регистрирует half-open spans только после успешного fetch/decrypt в координатах plaintext виртуально склеенного ordered input-а. Init gaps не считаются media; offset вне span не угадывается.
- Neutral `Packet::byte_offset` здесь означает точное начало packet/sample в логическом input конкретного backend-а. Это provenance, а не самостоятельное доказательство seek point, RAP или достаточности init.
- Seek index хранит первый audio/video anchor на пару `(epoch, restart_segment, kind)`, а не каждый AAC packet. Поэтому bounded capacity расходуется по segments/kinds и не замерзает на длинном первом сегменте.
- UI preview атомарно pin-ит точное решение для worker-а. Повтор того же request использует pinned anchor даже если индекс вырос; другой request может выбрать свежий anchor. Это сохраняет latest-only/cancellation семантику без увеличения timeout/cap.
- Replacement открывает только exact suffix, но сохраняет original epoch timestamp origin. Новый demuxer обязан реально выдать packet того же kind и global PTS, что anchor; лишь после этого replacement commit-ится. Missing provenance, span gap, budget exhaustion и несовпадение packet-а fail closed.
- Track IDs/topology остаются стабильными на обычных границах segments; `TracksChanged` по-прежнему относится к реальной epoch/config boundary.
- Functional regressions: long grouped TS с tiny index использует production-equivalent `DecodePointBefore`, проверяет forward/back seek, отсутствие refetch segment 0, стабильную topology и последовательную публикацию video RAP + audio после landing. Если TS demux выдаёт audio раньше закрытия video PES, bounded replacement scan удерживает только audio с PTS >= RAP и replay-ит его после доказанного keyframe; incomplete/corrupt PES остаётся ошибкой владельца `mpeg-ts-demux`. Encrypted fMP4 проверяет exact MAP + AES-128 key/IV restoration, forward/back tail restart и exact landing.
