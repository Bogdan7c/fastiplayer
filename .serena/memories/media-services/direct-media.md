# Direct Media Service

- `service-direct-media` is the generic direct media URL opener. It must stay neutral: no `player-core`, no UI, no renderer/backend, no YouTube candidate/capability semantics.
- v1 URL policy: only absolute `http(s)` URLs whose URL path has explicit `.mp4`, `.mkv`, or `.webm` extension. Query/fragment do not count for extension detection. IP URLs with supported extension are allowed; IP/hostname URLs without supported extension are typed unsupported. `rtsp`, HLS `.m3u8`, DASH `.mpd`, unsupported extensions, missing host, and parse failures are typed startup/open errors. No `HEAD`, Content-Type mapping, or byte sniffing in v1.
- Open flow: `Url` parse/classify -> `SourceRuntimeConfig::from_network_config` -> `HttpRangeSource::open` -> require `source_core::Seekability::Seekable` -> wrap in `media_prefetch::PrefetchingByteSource` using network prefetch fields -> `SymphoniaDemuxer::from_byte_source_with_options(extension_hint, source_label, demuxer_options)` -> `DirectMediaOpenResult` with demuxer/tracks/duration/seekability/source label.
- Error taxonomy lives in `DirectMediaOpenError`: invalid/unsupported URL, source config, prefetch config, demux config, Range/source error, non-seekable source, demux/probe error. Worker unavailable remains an `app-egui` delivery error, not service crate state.
- `app-egui::startup_media` owns CLI routing: YouTube hosts via `service_youtube::is_supported_youtube_url()` go to capability-aware YouTube startup; other `http(s)` or authority-style URLs go through `service-direct-media`; non-URL arguments remain local file paths. `app-egui` converts `DirectMediaOpenResult` to `PreparedMedia::from_external_label(...)` before sending it to `PlayerWorker`.
- Focused coverage: `cargo test -p service-direct-media` covers URL policy, non-Range rejection, and local Range 206 H.264 MP4 open through Symphonia; `cargo test -p app-egui` covers CLI routing; `cargo test -p service-youtube` covers YouTube host allowlist and existing YouTube paths.
