# S32A — HLS VOD parser/request/AES foundation (2026-07-23)

## Итог

- Новый pure crate `hls-playlist-core` — единственный bounded RFC 8216 parser/model owner для HLS master/media документов. Он не знает HTTP, yt-dlp, crypto, demux, player или UI.
- `playlist-io` теперь использует shared parser только как S05 classification adapter; network HLS всё ещё возвращает `AdaptiveManifestReference`, local HLS остаётся typed unsupported, runtime не зависит от `playlist-io`.
- Новый `web-media-hls` пока содержит только initial VOD profile и project-owned AES-128/key-state boundary. Network fetch, demux, seek и app integration остаются S32B/S32C.
- `service-ytdlp::YtDlpRequestMaterial::hls_request_material()` публикует borrowed intent-named validated HLS material без concrete HTTP/crypto dependency.
- `source-core::HttpRequestTarget::merge_extractor_query_parameters()` additive и сохраняет pinned yt-dlp merge semantics; existing `with_query_override()` replacement semantics не менялись.

## Parser/profile contract

- Strict UTF-8/NFC/no-BOM/control/line-ending/header/case/whitespace/duplicate grammar и named document/line/segment/variant/rendition/attribute budgets.
- Owned model сохраняет master variants, AUDIO/SUBTITLES rendition descriptors, media sequence, exact durations/references, MAP, byte ranges, discontinuity, key declarations/state, ENDLIST и safe metadata evidence.
- Unknown syntactically valid tags/attributes ignored per RFC. Known unsupported initial-profile semantics typed rejected separately from structural parsing: LL-HLS, SAMPLE-AES/non-identity key format, I-frame paths, SESSION-KEY, alternate VIDEO/closed captions, START, output protection, unsupported protocol version, DEFINE/content steering, EVENT playlist.
- Structural validation включает positive TARGETDURATION, exact decimal rounded EXTINF <= target без float/overflow, single-use/dangling BYTERANGE/DISCONTINUITY, rendition group/name/default/autoselect/reference invariants. ENDLIST may appear anywhere per RFC 8216 §4.3.3.4 and is not treated as lexical EOF.
- AUDIO `CHANNELS` сохраняется как raw descriptor и типизированный positive primary count; malformed slash parameters и `CHANNELS` у non-AUDIO rejected владельцем parser grammar. Runtime не должен повторно разбирать этот атрибут.
- `validate_vod_profile` requires ENDLIST and optionally proves fMP4 MAP presence; concrete container selection remains S32B.

## Exact yt-dlp request material

- Inline `hls_media_playlist_data` is a typed zero-manifest-fetch state; base resolution always uses selected format `url`, never `manifest_url`.
- Segment query material is used for segment and MAP merge. Key query falls back to segment query when absent.
- `hls_aes.uri` replaces the manifest key URI after resolution and bypasses key-query merge; inline `hls_aes.key` suppresses key fetch; `hls_aes.iv` is left-zero-padded to 128 bits.
- Overrides only affect an active AES-128 declaration. Request secrets use redacted Debug and zeroizing storage.

## AES-128 boundary

- Audited dependencies: exact `aes 0.9.1`, `cbc 0.2.1`, `zeroize 1.9.0`; pure Rust, no native/build dependency. Audit: `docs/dependency-audit-s32a-hls-aes-2026-07-23.md`.
- Only METHOD=AES-128 with absent/`identity` KEYFORMAT. Key file/inline key exactly 16 bytes.
- CBC/strict PKCS#7, explicit IV or media-sequence as zero-padded 128-bit big-endian, fresh CBC chain per resource.
- KEY rotation and METHOD=NONE reset are atomic. Encrypted MAP requires explicit IV. Key/plaintext/request secret buffers zeroize on drop.
