# S35 — Strict DASH live/DVR production profile (2026-07-24)

## Ownership and integration

- `dash-mpd-core` owns bounded parsing and validation of the checked-in dynamic MPD timing contract over the existing `bounded-xml-reader` boundary. It does not perform I/O or own refresh/player state.
- `web-media-dash` owns dynamic SegmentTemplate+SegmentTimeline planning, UTC synchronization, availability math, multi-Period selection, refresh ordering, endpoint continuity, packet/seek timestamp mapping and the S31L live timeline adapter. Static S34 entrypoints remain separate.
- `app-egui::web_media_dash_open` and `web_media_dash_refresh` own composition, immutable yt-dlp semantic refresh anchor, monotonic extraction/runtime generations, scoped HTTP material, endpoint re-extraction/rematch, and installation before the existing strong barrier. `player-core` remains DASH-free and consumes only the existing neutral S31L timeline/receipted seek boundaries.

## Supported dynamic timing contract

- Clock synchronization accepts only `UTCTiming` scheme `urn:mpeg:dash:utc:direct:2014`. The direct UTC sample is corrected using the local request midpoint (`after - floor(RTT/2)`); missing/unknown clock models, regression and arithmetic overflow fail closed.
- Required dynamic inputs are `availabilityStartTime`, positive `minimumUpdatePeriod`, `publishTime`, and positive `suggestedPresentationDelay`. Refresh deadline is measured from manifest fetch start. A strictly newer `publishTime` may commit; equal/older publishes are ignored without moving the authoritative deadline or snapshot.
- Dynamic media addressing is only inherited `SegmentTemplate` with `SegmentTimeline`. `$Time$` substitution uses the raw timeline `S@t`; presentation time is `Period.start + (raw_time - presentationTimeOffset) / timescale`. Nonzero PTO, `r=-1`, explicit/derived Period timing and multi-Period live are supported with checked arithmetic.
- Timeline gaps, overlaps, segments crossing the Period boundary, ambiguous timing, and missing required period bounds are typed `DashLiveProfileExclusion`/`ProfileExcluded`; no approximate window is invented.
- `timeShiftBufferDepth` limits history; when absent, history begins at `availabilityStartTime`. Effective `availabilityTimeOffset` is the inherited checked sum and defaults to zero. `availabilityTimeComplete` is accepted only when absent/default true or explicit true; false/partial/chunked/other LL-DASH semantics are excluded.
- Live edge is the latest fully available selected segment boundary minus `suggestedPresentationDelay`, additionally constrained by the strict MPD timing window and actual decode-safe media evidence. A/V availability is the intersection of the selected Representation timelines; no union or single-track approximation.
- Representation continuity across refresh requires the same selected semantic contract. Endpoint refresh stages HTTP fetch, parse, plan, continuity and snapshot construction before one runtime-state commit. Immutable semantic identity is separate from monotonically allocated extraction/transport generation; stale or failed refresh never partially mutates authoritative runtime state.
- Cancellation and shutdown are generation-fenced and cooperative; endpoint refresh, manifest refresh, segment readiness and live timeline publication cannot commit after cancellation.

## Explicit exclusions and limitations

- `availabilityTimeComplete=false`, partial/chunked segment availability, other LL-DASH semantics, SegmentList/SegmentBase/duration addressing for dynamic MPDs, MPD Patch, DRM/ContentProtection, ABR switching, subtitles, and unknown clock/timing models return `ProfileExcluded` or the corresponding typed fail-closed error.
- A segment that crosses a Period boundary is excluded until a separate decode-only preroll/discard boundary exists; S35 does not weaken playback/seek ownership to approximate it.
- This is a deliberately narrow checked-in profile, not a claim of full MPEG-DASH ecosystem support.
