# symphonia-demux H.264

- `TrackInfo.codec_private` remains the only public storage for H.264 `avcC`; no second avcC field was added.
- Internal `track_mapper::TrackEntry` now carries `codec_private` copied from Symphonia `CodecParameters::{Video.extra_data, Audio.extra_data}` so packet mapping can use codec-private state without changing `media-core::Packet`.
- `packet_mapper` calls `codec_core::probe_video_packet_keyframe_with_codec_private`; H.264 MP4/MKV packetization is inferred inside `codec-core`, not with ad-hoc demuxer byte-prefix checks.
- Real fixtures confirmed through `crates/symphonia-demux/tests/h264_fixtures.rs`: `<MEDIA_DIR>/h264-720p-baseline-no-bframes.mp4`, `<MEDIA_DIR>/h264-720p-main-bframes.mp4`, `<MEDIA_DIR>/h264-720p-high-bframes-aac.mp4`, and `<MEDIA_DIR>/h264-720p-high-bframes-aac.mkv` expose `codec_private` parseable as `avcC` and produce codec-aware `Keyframe`/`NotKeyframe` classifications without `Unknown` for valid packets.
- `cargo test -p symphonia-demux --test h264_fixtures` and `cargo test -p symphonia-demux packet_mapper::tests` are the focused checks for this integration. Full `cargo test -p symphonia-demux` also passes after the legacy VP9 WebM test helpers were repointed from missing `test-assets/test.webm` to existing `test-assets/VP9/test.webm`.
