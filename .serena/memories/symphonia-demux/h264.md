# symphonia-demux H.264

- `TrackInfo.codec_private` remains the only public storage for H.264 `avcC`; no second avcC field was added.
- Internal `track_mapper::TrackEntry` carries `codec_private` copied from Symphonia `CodecParameters::{Video.extra_data, Audio.extra_data}` so packet mapping can use codec-private state without changing `media-core::Packet`.
- `packet_mapper` calls `codec_core::probe_video_packet_keyframe_with_codec_private`; H.264 MP4/MKV packetization is inferred inside `codec-core`, not with ad-hoc demuxer byte-prefix checks.
- Root cause for MP4 B-frame release microstutter was upstream `symphonia-format-isomp4` 0.6.0 ignoring `ctts` and `trun` composition offsets: MP4 H.264 B-frame packets reached `media_core::Packet.pts` as decode-order timestamps. The workspace now replaces `symphonia-format-isomp4:0.6.0` with `crates/symphonia-format-isomp4-patch`, which parses composition offsets, keeps demux packet/read order on DTS, builds Symphonia packets with presentation `pts` and explicit decode `dts`, and preserves seek actual timestamps on the DTS/stts timeline.
- Demux invariant for MP4 H.264 B-frames: packet byte/read order remains decode/container order; `Packet.pts` is presentation time and may be non-monotonic in packet order; `Packet.dts`/decode fallback is monotonic. Player/decoder/scheduler must not sort decoded/present queues to compensate for MP4 timestamps.
- The waterfall MP4 `<MEDIA_DIR>/h264-4k30-bframes.mp4` has two noncanonical MP4 quirks that must stay accepted: zeroed reserved bits in H.264 `avcC`, and a `ctts` version 0 atom containing signed two's-complement composition offsets such as `fffffc17` (-1001). `crates/symphonia-format-isomp4-patch/src/atoms/ctts.rs` treats high-bit v0 offsets as signed to avoid `2^32 / timescale` PTS wrap (about 178957 seconds at 24k tbn). Without this, player-core sees frames around `178957xxx ms`, scheduler waits for that front frame, and playback appears stuck after the first frame.
- Real fixtures confirmed through `crates/symphonia-demux/tests/h264_fixtures.rs`: `<MEDIA_DIR>/h264-720p-baseline-no-bframes.mp4`, `<MEDIA_DIR>/h264-720p-main-bframes.mp4`, `<MEDIA_DIR>/h264-720p-high-bframes-aac.mp4`, `<MEDIA_DIR>/h264-4k30-bframes.mp4`, and `<MEDIA_DIR>/h264-720p-high-bframes-aac.mkv` expose `codec_private` parseable as `avcC` and produce codec-aware `Keyframe`/`NotKeyframe` classifications without `Unknown` for valid packets. The waterfall MP4 is a regression fixture for zeroed `avcC` reserved bits and signed `ctts` v0 offsets without wrapped PTS. The same test file also covers MP4 B-frame PTS/DTS separation and no-B-frame PTS/DTS alignment.
- Focused checks: `cargo test -p symphonia-demux --test h264_fixtures`, exact local patch unit test `cargo test -p 'path+file://<REPO_ROOT>/crates/symphonia-format-isomp4-patch#symphonia-format-isomp4@0.6.0' ctts --lib`, `cargo test -p symphonia-demux packet_mapper::tests`, and full `cargo test -p symphonia-demux` when touching demux timing/seek behavior.

- S27 Baseline update: `track_mapper` maps Symphonia `CODEC_PROFILE_H264_BASELINE` to exact `H264Profile::Baseline`; ConstrainedBaseline remains separate. Demux does not guess one profile as another, while SPS/avcC refinement stays owned by `codec-core`.
