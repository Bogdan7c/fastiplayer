# symphonia-demux H.265

- `TrackInfo.codec_private` remains the only public storage for HEVC `hvcC`; Session 3 did not add new `TrackInfo` fields for HEVC packetization or parameter sets.
- `track_mapper` already maps Symphonia `CODEC_ID_HEVC` to stable container id `V_MPEGH/ISO/HEVC` and maps Symphonia HEVC Main/Main10 profile hints into `VideoProfile::H265` when available. The iPhone QuickTime fixture `<MEDIA_DIR>/ios-hevc-main10-aac-4k60.mov` is covered by a demux boundary test: it should open as two supported tracks, HEVC Main10 video with non-empty `hvcC` plus AAC audio.
- `packet_mapper` now routes HEVC packets through `codec_core::probe_video_packet_keyframe_with_codec_private`, so MP4/MKV length-prefixed HEVC packets with parseable `hvcC` can become `PacketKeyframe::Keyframe`/`NotKeyframe` instead of `Unknown`.
- The local `symphonia-format-isomp4-patch` parses MP4 `stss` sync sample tables and `MoovSegment::ts_sample()` uses them to move video seek targets back to a sync sample. This is required for iOS/QuickTime HEVC MOV `DecodePointBefore`: without `stss`, seek can start on a non-keyframe inter-frame even when a nearby sync sample exists. Regression coverage: `crates/symphonia-demux/tests/h265_fixtures.rs::h265_ios_mov_decode_point_before_seek_starts_on_sync_sample` using `<MEDIA_DIR>/ios-hevc-main10-aac-4k60.mov`.
- `hev1`/weak-file path is intentional: incomplete but parseable `hvcC` can prove length-prefixed packetization while VPS/SPS/PPS arrive in-band; this must not be treated as malformed by default.
- Codecs without a keyframe adapter remain recoverable as `PacketKeyframe::Unknown`; HEVC is no longer part of the “codec without keyframe adapter” regression set. Focused check: `cargo test -p symphonia-demux packet_mapper --lib`.
