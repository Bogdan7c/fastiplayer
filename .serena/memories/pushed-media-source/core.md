# pushed-media-source — источник «сегменты извне» и «файл по запросам байтов» (сессии 03a/03b/03c моста, 2026-10-29/30)

Crate `crates/pushed-media-source`: куски, которые кто-то другой приносит по полосам (у браузера — MSE `SourceBuffer`, любая нарезка, посреди боксов), → один `media_core::Demuxer` для `player-core`. Нейтрален к браузеру (решение 90): протокол моста, WebSocket, player-core и config в зависимостях запрещены guardrail-ом `PUSHED_MEDIA_SOURCE_ALLOWED_DEPENDENCIES` (anyhow, bytes, demux-api, media-core, mpeg-ts-demux, source-core, symphonia-demux, thiserror, tracing) + тест в `scripts/tests/test_check_refactor_guardrails.py`, crate в списке cargo-machete `scripts/ci-checks.sh`. План/решения: `user/browser-bridge/` (90–98), отчёты `results/03a.md`, `results/03b.md`; контекст моста — `mem:browser-bridge/core`.

## Механизм 03a («сортировщик»)
- `framing/` — сканер ТОЛЬКО заголовков: fMP4 init=`ftyp`+`moov`, медиа=`moof`+`mdat`; WebM init=EBML+`Segment`+`Info`+`Tracks` (размер `Segment` → «неизвестен»), медиа=`Cluster` (неизвестного размера → известный при конце); TS — 188-байтовые пакеты. Пределы по ЗАГОЛОВКУ. `abort` = `reset`.
- `episode` — один существующий демуксер на один init (`DemuxRegistry::open_required_container` в `ProgressiveDemuxer::new_deferred`, sniff = байты в трубе). `EpisodeKey` = контейнер + init (по идентичности принятого сегмента) + смещение: новый init, `changeType`, смена `timestampOffset` → новый эпизод.
- `lane_demuxer` (сторона плеера, `next_event` не блокирует): `track_identity` (стабильные публичные ID), смещение к `pts/dts` И `track_pts/track_dts` (FFmpeg берёт время из них!), кадр < 0 выбрасывается, видео ждёт ключевой (`random_access`). `episode_seam` (03b): при смене эпизода БЕЗ перемотки пакеты ≤ последнего выданного времени выбрасываются (видео — до ключевого после шва), перемотка сбрасывает шов — иначе замена «внахлёст» отдавала время назад.
- `stream`: `pushed_stream(policy) -> (PushedStreamWriter, PushedStreamOpener)`; `poll_open` неблокирующий → `OpenProgress::Ready(OpenedPushedStream { demuxer, live_timeline: Option<DynamicMediaTimelinePort> })`; одна полоса как есть, видео+звук — `CompositeAvDemuxer`. Первая ошибка побеждает (`StreamState`); `failure_class()` → ProtectedContent/UnsupportedMedia/UnparsableMedia/InputMisuse. `Drop` писателя без EOS доигрывает принятое. `protection`: `encv/enca`, `ContentEncryption` → отказ.

## Полка 03b (решение владельца 95, «как MSE buffered»)
- `framing/timing/` — время коробки из заголовков: fMP4 `tfhd/tfdt/trun` (+`trex`, `mdhd` timescale, cto v0/v1) → presentation-время; WebM `Timecode`×`TimecodeScale` + i16 блоков, `BlockDuration`/`DefaultDuration`×лейсинг. `SegmentTimingContext::from_initialization` раз на init, `media_segment_timing` → `SegmentTiming::{Timed(TimedSpan), Untimed}` (TS). `TimedSpan { span: MediaTimeSpan, end: SegmentEnd::{Exact, Estimated{certain_end}, Open{certain_end}} }`: у WebM без длительностей конец последнего блока оценивается шагом между двумя последними блоками дорожки, единственный блок → Open (дотягивается до следующей коробки, ≤ `SHELF_OPEN_TAIL_REACH` 2 с); замена сравнивает только достоверные диапазоны. Время — i64 мкс до `timestampOffset` (`shifted_by`), полуоткрытый, floor через i128, вся арифметика checked (враждебные 0xFF… → `TimeOutOfRange`). Ошибки → `FramingError::Timing` → UnparsableMedia. Игнорируются: `elst`, Opus `CodecDelay` (до ~7 мс).
- `stream_buffer.rs` (`StreamBuffer`: один `Arc` на поток, `Mutex<BufferState>` с полосами `BufferedLane { timeline: Timed|Untimed, shelf: LaneShelf, feed: LaneFeed }`; подмодули `seek`, `live`, `eviction`, `position`), `shelf.rs` (`LaneShelf`: записи по началу {span, ChargedSegment, EpisodeKey, Delivery::{Waiting,Fed}}; пересечение > `overlap_tolerance` 10 мс → новая заменяет старые), `feed.rs` (`LaneFeed`: `FeedCursor { certain_end, reach }`, бегущий эпизод, mailbox), `mailbox.rs` (эпизоды с эпохой перемотки; устаревшие отвергаются/пропускаются; флаг backlog).
- Правило подачи: ждущая запись подаётся, если начало ∈ [курсор − 10 мс, курсор + `max_contiguous_gap` 100 мс]; первая коробка задаёт курсор; прошлое/за дырой — только на полку (плеер ждёт: `TemporarilyUnavailable` → Buffering); коробка «внахлёст» через курсор — новый эпизод (+ шов). Курсор назад — ТОЛЬКО перемоткой. Нет места в mailbox (`MAX_PENDING_EPISODES_PER_LANE` 4) → запись ждёт на полке, подача догоняет на следующем append, `note_playback_position` и со стороны плеера (`try_catch_up_feeding`, `try_lock`, не блокирует); фатальный `TooManyPendingEpisodes` остался только для TS.
- Замки: buffer → mailbox/pipe/live publisher → ledger; сторона плеера берёт buffer только в seek/seekability/try_catch_up; ничего не ждёт и не join-ит под замком (`ProgressiveDemuxer::drop` только сигналит), выброшенные эпизоды уничтожаются после снятия замка.
- Учёт (`intake.rs` `ChargedSegment` = Arc байтов + заряд леджера): заряд один раз при приёме, освобождение с последней копией (полка/труба/ключ/текущий init) — без двойного счёта; труба леджер не трогает. Потолок `max_held_stream_bytes` 256 МиБ = всё, что держит поток. Выселение: окно позади (конец ≤ min(позиция − behind, курсор)); при потолке — сыгранное старшее первым, пропуская сегменты, ещё лежащие в трубе (`is_shared`); не помогло → `IntakeLimitExceeded` (страница-враг). Полосы, ждущие цель T, выселяют вне [T − behind, T + ahead]. `changeType` timed→TS отпускает полку целиком.
- `monitor.rs` `PushedStreamMonitor` (Clone+Send+Sync, `writer.monitor()`): `note_playback_position(Duration)` (после перемотки отчёты дальше `page_seek_match_tolerance` 250 мс от цели игнорируются до близкого, не дольше `STALE_POSITION_WINDOW` 1 с), `buffer_status() -> BufferStatus { buffered_ahead, intake: BufferIntake::{Accepting, Full} }` (конец непрерывного прогона, покрывающего позицию, минус позиция; min по timed-полосам; до первого отчёта позиция = начало первой поданной коробки; Full при ahead ≥ окна ИЛИ held ≥ `BUFFER_FULL_AT_CEILING_PERCENT` 75 % потолка — иначе 4K за 120 с умирал о потолок), `take_page_seek_request() -> Option<PageSeekRequest { target }>` (последняя побеждает, берётся один раз), `held_segment_bytes()`.
- `earliest_common_start() -> Option<Duration>` (03e): самое позднее из начал полок timed-полос (`LaneShelf::earliest_start`, `StreamBuffer::earliest_common_start`); `None` — какая-то полоса пуста или нет timed-полос (TS); время < 0 → 0; ничего не меняет (тест `monitor_tests.rs`). Нужен процессу моста: старт нового поколения там, где есть данные всех полос.
- Окно: `PushedSourcePolicy::with_buffer_window(BufferWindow { ahead, behind })` (ahead > 0, иначе `ZeroBufferAhead`); `recommended()` = 120/30, пользовательское значение — config `[browser_session]` (решение 96, приложение маппит). `buffer_full_at_held_bytes()`.
- `end_of_stream`, потом байты — снова открывает вход на ВСЕХ полосах (MSE), `InputAfterEnd` удалён.

## Перемотка 03b (`stream_seek.rs`, `stream_buffer/seek.rs`, `page_seek.rs`)
- Синхронный путь player-core (без seek-порта): `PushedStreamDemuxer::seek_with_request` на ходу владельца сессии — допустимо, потому что не блокирует (доказано тестом `seek_never_waits_for_an_episode_thread_blocked_on_its_pipe`). Одно решение на поток: все timed-полосы держат T → полка (страницу не трогаем); иначе одна просьба странице.
- Полоса: бегущий эпизод закрыт, ждущие изъяты с новой эпохой, курсор сброшен, «ждём T»: на полке — подача с записи, содержащей T (или начинающейся ≤ 100 мс после T), новый эпизод, видео ждёт ключевой; вне полки — приходящее до T ложится на полку, не подаётся. `requested_position = from_duration(T)`; `actual` = начало записи на полке, вне полки — T (player-core `DecodeForwardToTarget` прячет раннее видео и режет звук — доказано тестом). Вне полки состояние плеера `Scrubbing`/`Seeking` (не Buffering), `SeekTimeout` через 10 с. После `Ended` перемотка садится на паузу — приложение шлёт Play. После EOS цель ≥ начала последней коробки → садимся на последнюю (иначе вечное ожидание).
- Правило 5 — позднее вступление (03e, 2026-10-30, коммит 9201d931): полоса без данных у цели вступает со своего первого сегмента ПОСЛЕ цели, если другие полосы держат цель и непрерывно покрывают время до начала этого сегмента (`shelf_late_join.rs`: `LateJoinWindow`, `LateJoinCandidates::{AnyOnShelf, ArrivedSinceSeek}`; `ShelfEntry.arrival` + `LaneShelf::note_seek`). Данные полосы внутри куска опор раньше точки вступления — дыра посреди полосы, вступления нет, просим страницу. Вне полки точка вступления — только сегмент, принятый после перемотки. Пересчёт на каждом принятом сегменте любой полосы (`resume_lanes_awaiting_target`); решение «на полке / просить страницу» учитывает правило; `LaneSeekState::AwaitingTarget { target, late_join }`, ответ плееру не позже цели. Раньше: перемотка по полке назад туда, где звука нет, висела в `Scrubbing`; после перемотки вне полки звук, начатый > 100 мс после цели, не подавался вовсе. Тесты: `src/stream_late_join_tests.rs`, `shelf_tests.rs`, `tests/seek_into_lane_gap_to_frame.rs` (по полке, вне полки, «Twitch»).
- Страница сама: `writer.note_page_seek(T)` в порядке провода → следующая перемотка плеера к ≈T (допуск 250 мс) просьбу НЕ шлёт.
- Seekability: любая TS-полоса → NotSeekable; Finite → Seekable; Unknown → UnknownTimeline; Live → LiveWindowUnavailable (в live-режиме игнорируется). Длительность и seekability снимаются при сборке `PreparedMedia` (YouTube шлёт `duration_changed` до `source_buffer_added` — проверено вживую).
- Live: `Live` при открытии → `dynamic_media_timeline`: live edge = конец общего покрытого прогона вокруг позиции, DVR = этот прогон, join = начало первой поданной; перепубликация на приёме/позиции/перемотке; `duration()` = None; live-ли — решается при открытии.

## Файл по запросам байтов (03c, `src/range_file/`, решения 100–104)
- Для `<video src>` (обычный MP4/WebM): `pushed_file(PushedFilePolicy, RangeRequestIds, Arc<dyn RangeRequestNotifier>) -> (PushedFileWriter, PushedFileOpener, PushedFileRequests)`. Каждый диапазон просится наружу (`take_requests() -> Vec<RangeRequest{id, offset, length: NonZeroU32}>`, notifier `range_requested()` зовётся БЕЗ замков); байты — `accept_range_bytes(id, offset, &[u8]) -> RangeBytesVerdict::{Accepted, StaleDropped}`, итог — `finish_request(id, RangeOutcome::{Completed{ResourceSizeReport::{Known,Unknown}}, Failed(RangeFailure::{Network,Http,ResourceChanged,OutOfRange})})` (нейтральные зеркала протокола). Зависимость `media-prefetch` разрешена guardrail-ом.
- Модули: `ids` (`RangeRequestIds` — общий на СЕАНС счётчик u32 с 1, исчерпание = ошибка; `standing_of(id) -> RangeIdStanding::{Issued, NeverIssued}`), `retry` (паузы 0,5→8 с, бюджет, прогресс обнуляет; своя копия — `HttpReconnectSchedule` в source-core pub(crate)), `policy` (`MAX_RANGE_REQUEST_BYTES` 16 МиБ = договор протокола; запрос = min(кусок prefetch, 16 МиБ); `MAX_TOP_LEVEL_BOXES` 256), `state` (чистая логика под одним замком: сверка, повторы, выдача), `core` (`FileCore` Mutex+Condvar, опрос отмены 10 мс), `source` (`RangeFileSource: ByteSource`), `layout` (обход верхних боксов MP4 до открытия: `encv/enca` через `protection.rs`, moov в конце без размера → `UnsupportedFileLayout`, checked_add, `moov` ≤ size−offset), `opener` (поток: первый запрос 0..initial chunk → размер → layout → `PrefetchingByteSource` → `pushed_demux_registry().open`), `sealed_end` (`SealAwareDemuxer`), `writer`.
- `poll_open() -> FileOpenProgress::{Pending, Ready(OpenedPushedFile), Failed}`; ПЕРВЫЙ вызов запускает поток и выдаёт первый запрос. `OpenedPushedFile { demuxer (ОТКРЫТЫЙ БЛОКИРУЮЩИЙ, обёрнут SealAwareDemuxer), seekability: FileSeekability::{Seekable, ForwardOnly}, content_length, lifecycle_cancellation }` — приложение оборачивает `media_source_open::progressive_player_demux::into_player_demuxer(..., lifecycle_cancellation, prefetch)`.
- Сверка (страница — враг): активный запрос — рамки строго подряд, без лишних байтов; недобор только на конце файла; размер не меняется (и Known↔Unknown); неизвестный конец не «плавает»; номер выше последнего выданного → нарушение; номер ниже первого этого потока / отменённый / повторённый → `StaleDropped` молча (отменять запросы протокол не умеет). Payload ≤ 1 МиБ проверяет протокол, не источник. Обрыв (Network/Http) после последнего байта: размер известен → Completed, иначе повтор продолжения. Unknown + `OutOfRange` ровно на конце последнего ответа → EOF. Классы `PushedFileFailureClass::{ProtectedContent, UnsupportedMedia, UnparsableMedia, InputMisuse, SourceUnavailable}`.
- `seal()` (вкладка ушла; Drop писателя = seal): полученное доигрывается, чтение за ним → Ok(0); флаг `read_cut_by_seal` ставится ТОЛЬКО при чтении, обрезанном seal до настоящего конца → `SealAwareDemuxer` превращает ошибку демуксера в `EndOfStream` (иначе плеер вставал в `Failed` на 0,72 с при данных до 2,3 с: ядро на ошибке демуксера выбрасывает прочитанное впрок — общий бэклог п. 24). Без флага ошибки проходят как есть. После seal `accept_range_bytes` → `Err(WriterSealed)` (не нарушение).
- Память: окно prefetch + один запрос (≤ 16 МиБ). Запросы строго последовательные (круг на кусок); перемотка ждёт конца текущего запроса; молчащая страница ограничена только seal/отменой; WebM `ContentEncryption` в файле не проверяется; `moov` при известном размере скачивается дважды.
- Тесты: `tests/file_ranges_to_frame.rs` (+ `support/range_page.rs`, `support/progressive_file.rs`), фикстуры `file-h264-aac-moov-end.mp4`, `-faststart.mp4`, `file-vp9-opus.webm`, `file-h264-cenc.mp4` (4 с, 25 к/с, 100 кадров; `generate.sh`); модульные `range_file/*_tests.rs`, `state_tests/`.

## Ограничения (2026-10-30)
- Смена качества/кодека: с 03d (2026-10-30) — эстафета в player-core (`mem:player-core/track-description-handoff-03d`), строгие тесты `stream_changes_to_frame.rs` (все 20 кадров, звук без тишины, звук далеко впереди → `Ended`). Симулятор звука `tests/support/simulated_audio.rs` считает `mid_stream_silence` (тишина после старта до последнего сэмпла) и `discarded_audio` (уничтоженный ТЕКУЩИЙ выход теряет недоигранный буфер, как настоящий; заменённый выход при смене формата — нет).
- TS-полосы линейны: без полки, перемотки, вклада в «полон». Open-конец WebM: настоящая дыра < 2 с после одиночного кластера проскакивается. Ни одна полоса не держит цель (страница шлёт коробки > 100 мс после T) — ждём до `SeekTimeout`; страница не переслала поздний сегмент, который уже лежит в её собственном буфере, — эта полоса ждёт до `SeekTimeout`. Фрагмент без ключевого в начале → посадка на следующем ключевом (может быть после T). После EOS перемотка в большую дыру посреди полки снова открывает вход и просит страницу. Длительность, пришедшая после сборки `PreparedMedia`, не подхватывается. `remove()` страницы не исполняется (техническое решение 03b: выселяет сама полка, приложение только считает). Кластер WebM неизвестного размера — со следующим элементом.
