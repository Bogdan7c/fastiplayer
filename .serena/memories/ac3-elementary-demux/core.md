# ac3-elementary-demux — сырые `.ac3` / `.eac3` / `.ec3` (2026-10-16, пакет D)

## Роль и границы
- First-party container owner сырого AC-3/E-AC-3 elementary stream-а (без контейнера). Отдельный crate по образцу `flv-demux`/`mpeg-ts-demux`: Symphonia не получает второй parser, `mpeg-ts-demux` владеет только TS.
- Framing только через `ac3-syncframe` (`locate_syncframe`, `parse_syncframe_header`, `scan_access_unit`); декодер не знает. Guardrail `AC3_ELEMENTARY_DEMUX_ALLOWED_DEPENDENCIES` = ac3-syncframe, anyhow, bytes, demux-api, media-core, source-core, thiserror, tracing; crate в `REQUIRED_ROLE_CRATES`, `WORKSPACE_CRATE_DIRECTORIES` (ci-checks), ARCHITECTURE.md.
- Публичный API: `Ac3ElementaryDemuxFactory::new(Ac3ElementaryDemuxOptions)` (container `ac3-elementary`, ext `ac3`/`eac3`/`ec3`, MIME `audio/ac3`/`audio/eac3`, вход SeekableBytes + StreamingBytes; ordered segments → typed `UnsupportedInput`), `Ac3ElementaryDemuxer::open(DemuxInput, CancellationToken, options)`, `AC3_ELEMENTARY_CONTAINER_ID`, `Ac3ElementaryDemuxOptions` (pub поля `Ac3ElementaryLimit`: read_chunk 64 KiB, initial_scan 256 KiB, max_resync 1 MiB, max_leading_tag 16 MiB), `Ac3ElementaryDemuxError` (Cancelled, UnsupportedInput, SourceRead(#source SourceError), StreamRead(#source io), NoAccessUnit, LeadingTagTooLarge, SyncLost{resync_start_offset, discarded_bytes}, UnrepresentableTimeBase, NotSeekable, SeekTargetUnavailable, SeekRollbackFailed).
- Модули: `probe` (доказательство по содержимому), `leading_tags` (ID3v2, synchsafe + footer), `framing` (чистый `next_framing_step` → AccessUnit/Skip{OrphanSyncframe|LostSync}/NeedMoreData/TruncatedTail), `reader` (буфер + абсолютные смещения над ByteSource/ByteStream), `timeline` (`ByteRateEstimate`, `StreamTimeline`), `demuxer`.

## Инварианты
- Probe: кадр ровно в начале (после ≤4 ID3v2-тегов, тег целиком в sniff) + цепочка из 3 корректных заголовков подряд (или до конца буфера при ≥1 целом кадре) → `Exact`. Это сильнее Symphonia `Signature` для ID3 → `mpeg-audio`, поэтому `.ac3` с ID3 выигрывает. Мусор ≤4096 байт перед цепочкой → только `HintOnly` и только при согласном extension/MIME (кадры AC-3 лежат подряд и внутри MKV/MP4-lacing — любой контейнер с сигнатурой перебивает). Оборванный первый заголовок → `Rejected(Truncated)`.
- Поиск синхронизации (старт, seek, потеря) принимает кадр, только если сразу за ним корректный заголовок или конец потока (ложные 0x0B77). Locked: битый заголовок → Skip 1 байт + Searching + warn; отброшенное подряд > `max_resync_bytes` → typed `SyncLost` (offset начала дыры). Orphan dependent → пропуск.
- Пакет = основная программа AU (substream 0 + dependent-ы; программы 1–7 не идут в декодер), codec id `A_AC3`/`A_EAC3` по bsid первого AU (как TS/Symphonia), channels = presentation count, sample_rate первого кадра, time_base 1/rate, NotKeyframe, `byte_offset` = начало AU. Track list не меняется посреди потока (смену формата обрабатывает decoder + player-core output rebuild). bsid 9/10 (AC-3 half/quarter rate) принимаются с 2026-10-17: частота и длительности пакетов по `fs >> (bsid − 8)` (тест `packets.rs::half_rate_bsid_9_ac3_has_halved_sample_rate_and_doubled_frame_duration`).
- Время: PTS = накопленные сэмплы (точно). Дыра посреди потока сдвигает часы на оценку потерянных байт (иначе хвост играл бы раньше своей позиции). Длительность и seek — по «байт на сэмпл» = сумма длин AU / сумма сэмплов в окне открытия (НЕ полный скан: bounded). Точно для постоянной длины кадра (48/32 кГц); 44.1 кГц (длина чередуется на слово) — оценка, после далёкого seek-а PTS может уйти на несколько кадров (для звука без видео незаметно).
- Seek (все режимы одинаково — каждый AU decode point): позиция = data_start + bytes_for(target) − (avg AU − 1) → проверенный поиск вперёд → AU не позже цели; если оценка дала PTS > цели — до 4 откатов на средний AU, затем начало данных. За концом → последний целый кадр. Ошибка → откат (reposition на прежний offset), `SeekRollbackFailed` если и откат упал. Не seekable вход → `NotSeekable` без изменения позиции. Seekability = seekability source-а; duration None без content_length.
- Конец: оборванный последний кадр/мусор в хвосте → warn + чистый EOS, все целые кадры отданы. Отмена: token проверяется перед каждым чтением; `Interrupted` из stream-а повторяется, только если token не отменён (адаптеры переводят Cancelled в Interrupted).

## Композиция
- Local: `media-source-open::local_media::open_local_demuxer_from_source` регистрирует factory третьим (Symphonia, MPEG-TS, AC-3); `SUPPORTED_LOCAL_MEDIA_EXTENSIONS` += ac3/eac3/ec3.
- Web/direct HTTP/FTP (пакет G, 2026-10-16): `web_media_core::ContainerFamily::Ac3Elementary` (токены ext/container `ac3`/`eac3`/`ec3`), `media-source-open::web_media_demux_registry::WebDemuxComposition::new` регистрирует factory третьей (после Symphonia и FLV), маппинг `AC3_ELEMENTARY_CONTAINER_ID → Ac3Elementary`; `new_hls` её НЕ регистрирует. `web_media_open::runtime::demux_hints` даёт `("ac3-elementary", "ac3")` для yt-dlp кандидатов этой family. Classification прямых ссылок следует registry (`supports_extension` для Seekable+Streaming) → `.ac3/.eac3/.ec3` URL-ы стали direct. MIME в descriptor: `audio/ac3`, `audio/eac3`, `audio/vnd.dolby.dd-raw` (используются только как hint при мусоре впереди; direct-путь MIME hint сейчас не передаёт).
- E2E прямой HTTP: `media-source-open/src/direct_progressive_open/ac3_elementary_tests.rs` — loopback Range origin → `classify_direct_media_url` + `open_direct_media` → фоновый ProgressiveDemuxer → тоны 5.1 по lanes; seek через seek port (посадка на кадр 7, 224 мс); сервер без Range → forward-only, 1 GET, без seek port; classification `.ac3/.eac3/.ec3` vs `.ac4`.
- `playlist-discovery` пробует только Symphonia → для raw AC-3 (как и TS) нет статического snapshot-а длительности в плейлисте.
- `codec_core::AudioCodec` не расширялся: production-потребителей нет, канон — строки `A_AC3`/`A_EAC3`.
