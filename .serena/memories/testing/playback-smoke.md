# Runtime Playback Smoke Acceptance

- Optional local acceptance script: `scripts/playback-smoke.sh`; it is NOT a CI/pre-PR gate and `scripts/pre-pr-checks.sh` should remain unchanged.
- Modes: `--mode full` runs FFmpeg probe tests, release `app-egui` build, and the full playback scenario matrix; `--mode software-only` runs probe tests, release build, and FFmpeg software playback scenarios; `--mode probe-only` runs only `video-ffmpeg` focused probe tests plus the existing ignored real-runtime probe. Media modes require explicit paths: `full` needs `--vp9 <file> --av1 <file> --h264 <file>`; `software-only` needs `--vp9 <file> --h264 <file>`. The script never searches `test-assets/` or assumes a filename.
- Common checks: `bash -n scripts/playback-smoke.sh`, `scripts/playback-smoke.sh --help`, and `scripts/playback-smoke.sh --mode probe-only`. No mode/path selection prints `NOT RUN: missing selection` and exits 0; an explicitly requested media mode with a missing required path prints the same status and exits nonzero. Full local acceptance uses explicit selected paths.
- The script runs release playback under `timeout` with isolated per-scenario `XDG_CONFIG_HOME` and stderr/stdout logs under a temporary directory. It sets `player.start_paused = false` in the isolated config so CLI media actually plays.
- Scenario matrix in `full`: auto+VP9 Profile 0 4K60 expects `Selected video pipeline` plan `vaapi-dmabuf-wgpu`; auto+AV1 4K60 expects backend reselection evidence and plan `ffmpeg-host-upload-wgpu`; software+H.264 MP4 4K60 expects FFmpeg host-upload and no start-code/InvalidData errors; hardware+AV1 4K60 expects `PlayerEvent::FatalError kind=UnsupportedVideoCodec` with a stream-oriented reason (`native hardware output не поддерживает AV1...`) and no software fallback; software+VP9 Profile 0 4K60 stress expects FFmpeg host-upload with no resource-table-full and no nonzero `drops_decoder_starvation` summary.
- Positive playback scenarios reject known fatal regressions: `InvalidData`, `Error parsing OBU data`, `No start code`, `resource table is full`, `Decoder thread disconnected`, panic text, `UnsupportedRenderFormat`, missing render resources, and app-level `PlayerEvent::FatalError`.
- `app-egui` logs an app-level fatal marker from `record_worker_events`: `PlayerEvent::FatalError` with `kind` and `message`, so typed rejection is machine-checkable from stderr.
- Missing/too-old FFmpeg remains covered by unit/fake probe tests plus the ignored real-runtime probe; no runtime env override was added.
- Playback-rate S39 remains a manual release acceptance matrix; automated tests do not replace CPAL/DAC and visual continuity checks. For `<MEDIA_DIR>/av1-4k60-hdr-pq.mp4`, run the full asset at `4.0x` and verify audio/media time remains exact while video does not freeze for multi-second GOP gaps. The old warning `Audio catch-up: video backlog сброшен ... shed_packets=240` must not appear. A structured `Video backlog атомарно переключён на proven keyframe` warning is expected only under real overload; a typed scan-limit rollback warning is acceptable but must not loop or lose audio.
- Also manually exercise `4x -> 2x -> 0.5x/1x -> 4x`, Pause/Play, seek, media reload, EOF/replay and repeated changes. AV1/VP9 may visibly skip at safe keyframes under overload; H.264/H.265/VP8 intentionally use normal FIFO because their no-flush recovery proof is not part of the generic contract.
