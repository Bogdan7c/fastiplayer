# Video Decoder Stream Boundary

- `video-frame-contract` is the neutral source of decoder->renderer frame vocabulary: `VideoFramePixelLayout`, `FrameBitDepth`, `FrameChromaSubsampling`, `VideoFrameTransferPath`, `VideoFrameContract`, `HardwareFrameHandle`, and `DmaBufImageLayout`. Its explicit software vocabulary now covers host-planar YUV420 8/10/12, YUV422 8/10/12, and YUV444 8/10; YUV444 12-bit remains outside v1 until a real need appears. `VideoFrameContract::validate()` accepts `SoftwareHostUpload` only for explicit host-planar layouts and keeps `Nv12`/`P010` DMA-BUF production contracts unchanged. It has no dependency on `codec-core`, `video-core`, `render-core`, VAAPI, WGPU, FFmpeg, or app crates. `codec-core` explicitly maps codec-level `BitDepth`/`ChromaSubsampling` to `VideoFramePixelLayout`; the frame-contract crate must not learn codec enums or capability policy.
- `video-core::VideoDecoderThreadHandle` is the neutral decoder control boundary for playback-facing code. It exposes packet send/flush/release/receive plus stream lifecycle methods: `configure_stream(VideoStreamDecodeConfig)`, `clear_stream()`, `set_preroll_output_floor(VideoPrerollOutputFloor)`, `clear_preroll_output_floor(VideoPrerollOutputFloorClear)`, `begin_end_of_stream_drain(generation)`, and `end_of_stream_drain_state()`.
- Decoder activity wakeup is now a neutral `video-core` contract: `VideoDecoderActivityNotifier`/`VideoDecoderActivitySubscription` share a monotonic `VideoDecoderActivityEpoch` and a `crossbeam-channel` bounded(1) pulse channel. `notify_activity()` must not block decoder threads; `Full`/`Disconnected` are coalesced/ignored on the notifier side while epoch preserves latest progress and wait-side code gets typed outcomes. `VideoDecoderActivitySnapshot` exposes captured epoch plus subscription methods to check `activity_since(observed_epoch)` before entering `select!`, classify recv results, and wait with typed outcomes: `ActivityReceived`, `NoNewActivityAfterEpoch`, `Timeout`, or `Unavailable` with `UnsupportedNotifier`/`DisconnectedNotifier`/`FatalNotifier`. Default `VideoDecoderThreadHandle::decoder_activity_snapshot()` returns `UnsupportedNotifier`; `video-vaapi` now creates a notifier/subscription in `VideoDecodeThread::new_with_config`, stores the subscription in the handle, and forwards snapshots through `VaapiVideoDecoderThreadHandle` without exposing VAAPI/internal channels. `player-core` wakeup planning consumes this only through `PlaybackPipeline::video_decoder_activity_status()`, preserving `AbsentDecoder`, `Unsupported`, typed unavailable/fatal, and available snapshot instead of reading decoder storage or collapsing states into a `bool`.
- Accurate seek preroll output-floor is a video-core-neutral contract only: `VideoPrerollOutputFloor { generation, floor_pts, retain_latest_before_floor }`, clear policy `MatchingGeneration(u64)`/`Any`, and `VideoPrerollOutputFloorResult` keep `AbsentDecoder`, `Applied`, `Unchanged`, `Cleared`, `Unsupported`, typed `Backpressure`, and `Fatal` distinct. The contract must not mention VAAPI, cros-codecs, renderer, player-core, or seek_transaction internals. Suppressed preroll frames are reported through `VideoDecoderDiagnosticEvent::SeekPrerollFrameSuppressed { pts, generation, floor_pts }`. `player-core` consumes this only through `PlaybackPipeline` boundary wrappers: Accurate seek sets floor after accepted demux seek for the user target/generation, stores an applied marker only for `Applied`/`Unchanged`, clears it explicitly on commit/timeout/replacement/media reset/backend replacement, and keeps player-side preroll drop fallback for non-fatal unsupported/absent/backpressure outcomes.
- `VideoStreamDecodeConfig` carries the selected video stream contract owned by `player-core`: `track_id`, codec/profile, bit depth, chroma, coded dimensions, `display_orientation`, `frame_contract: VideoFrameContract`, optional `codec_private`, and optional packetization metadata. `surface_format` and `VideoMemoryContract` are not runtime stream-config fields; `frame_contract` is the decoder->renderer resource contract the backend must publish on `DecodedFrame`. H.264 packetization is represented as `VideoStreamPacketization::H264(H264Packetization::{AnnexB, AvccLengthPrefixed { nal_length_size }})`; H.265 packetization is represented as `VideoStreamPacketization::H265(H265Packetization::{AnnexB, HvccLengthPrefixed { nal_length_size }})` once codec metadata proves it. `VideoStreamDecodeConfig::from_requirement(track_id, requirement, frame_contract)` requires an explicit selected contract from capability selection; `VideoDecodeRequirement` and `SupportedVideoDecodeFormat` remain codec/stream-level only and must not carry backend id, concrete output transfer/layout, or renderer compatibility. Codec adapters may keep decoded pixel-layout hints in refinement results, but provider-declared `SupportedVideoOutput.frame_contract` is the source of selected output ownership/transfer.
- `DecodedFrame` stores `frame_contract: VideoFrameContract` as the runtime source of truth. `format()`, `bit_depth()`, `chroma()`, and `memory_path()` are derived compatibility helpers and must not become independent state again. `validate_self_consistency()` checks only local frame invariants and contract validity without resource-provider lookup; `validate_against_expected_contract(expected)` checks actual-vs-expected stream contract; `validate_contract()` remains only a compatibility wrapper for the current zero-copy NV12/P010 renderer path.
- `FrameResourceDescriptor` supports `DmaBuf` and provider-owned `HostPlanar`. `HostPlanarFrameDescriptor` stores private `Arc<dyn HostPlanarFrameOwner>` plus per-plane metadata (`HostPlaneDescriptor` role, owner-interpreted offset, stride, visible size, bytes/sample); it does not store pixel layout or frame dimensions. `HostPlanarOwnedBuffer` is the simple `Arc<[u8]>` owner for tests/simple owned paths, while future provider owners (for example AVFrame-backed) stay behind the neutral trait. Renderer-facing code reads only through `HostPlanarFrameDescriptor::visible_plane_row_bytes()`, which returns visible row bytes without right padding and rejects out-of-visible rows. `try_clone_for_lookup()` clones the owner/refcount plus metadata without copying frame bytes. `validate_resource_descriptor_against_contract(contract, coded_width, coded_height, descriptor)` is the low-level `video-core` API for descriptor-vs-contract validation: DMA-BUF checks neutral `DmaBufImageLayout` against descriptor export layout and coded size; HostPlanar accepts all explicit v1 software host-planar layouts (`Yuv420Planar8/10Le/12Le`, `Yuv422Planar8/10Le/12Le`, `Yuv444Planar8/10Le`; 4:4:4 12-bit remains outside v1), derives exact Y/U/V plane count, role order, visible sizes, and bytes-per-sample from `VideoFrameContract.pixel_layout` plus explicit dimensions, and bounds-checks visible row access through the owner boundary, not trailing padding.
- Configure results must keep distinct states: absent decoder, same-stream no-op, applied/cleared config, unsupported config with typed rejection, backend fatal error, and control-channel backpressure. Callers must not collapse these into `bool` when selection/retry/fatal policy depends on the reason.
- EOF/DPB drain is separate from seek `flush`. `begin_end_of_stream_drain(generation)` starts decoder tail draining for the current generation, frames still exit through normal `try_recv_frame`, and `VideoDecoderEndOfStreamDrainState` reports `Idle`, `Draining`, `Drained`, or `Fatal`. This API must not advance seek generation, clear pending packets, or read new demux packets. `player-core` should start the decoder drain only after all already-demuxed video packets for the current stream have been sent and decoder in-flight packet accounting has reached zero, then keep EOF blocked until `Drained` matches the current generation.
- `DecodePacket` includes both presentation and decode-order timestamps: `pts` remains presentation timestamp, while `dts` and `track_dts` preserve existing demux metadata for codecs such as H.264 that need decode order. Do not invent a second timestamp contract when `media-core::Packet` already provides these fields.
- Current VAAPI backend accepts the implemented VP9 and H.264 adapter matrix plus a production-shaped H.265 adapter path at configure time. H.264 remains limited to the supported 8-bit 4:2:0 ConstrainedBaseline/Main/High cases with proven packetization/codec private and zero-copy NV12 export. H.265 accepts only Main 8-bit 4:2:0 -> NV12 and Main10 10-bit 4:2:0 -> P010 configs with proven `VideoStreamPacketization::H265`; incomplete/absent `hvcC` is allowed when the stream can provide in-band VPS/SPS/PPS. H.265 must still not be advertised as production VAAPI capability until the separate validation session enables `supports_decode_format`.
- `VideoStreamDecodeConfig` also carries `display_orientation`, sourced from selected track metadata. Decoder backends must preserve this value on emitted `DecodedFrame`s but must not rotate/copy decoded surfaces for it; renderer owns the display transform. Same-stream adapter reuse must still update this metadata because it can change without changing codec.
