# Россыпь горячего пути (cpu-parity сессия 05, 2026-10-21)

Отчёт: `user/cpu-parity/results/05.md`. Решения владельца: снимок — вариант A (`Arc` без смены типов полей, публикация только при изменении, `FrameCounters` — данные окна); bind group — вариант A (кэш живёт с текстурой); находки профиля в worker-е чинить в этой же сессии.

## Метод
Профиль samply (нужны `kernel.perf_event_paranoid ≤ 1` и `kernel.perf_event_mlock_kb` ≥ 8192 — иначе `mmap failed`; samply в режиме запуска команды, плеер завершать SIGTERM-ом самого плеера, а не samply, иначе профиль не сохраняется). Разбор gecko-профиля + `.syms.json` своим скриптом (веса `threadCPUDelta`, inclusive/self/callees). Профиль нашёл то, чего не было в плане: обслуживание `about_to_wait` (снимок + MPRIS + имя файла карантина плейлиста на каждом витке), memmove аудиоистории, копию счётчиков задержек на каждом замере; SW `thread::scope` = 20 % главного потока (сессия 07).

## Владельцы и границы
- **Снимок плеера** (`player-core::worker`): канал `Arc<PlayerSnapshot>`; `LatestSnapshotPublisher` (`worker/runtime_publish.rs`) хранит `last_published` (начальное = `PlayerSnapshot::empty()`, как кэш handle) и возвращает `#[must_use] SnapshotPublication::{Published, Unchanged, NotDelivered}`; равный снимок не публикуется, при `NotDelivered` `last_published` не обновляется. `PlayerWorker::latest_snapshot() -> Arc<PlayerSnapshot>` (без параметров, `ptr_eq` пока нет новой публикации). `PlayerSession::compose_snapshot()` (было `snapshot_with_frame_counters`); builder собирает снимок литералом без начального клона `session.snapshot` (новое поле не скомпилируется, пока не решено, откуда оно). `PlayerSnapshot.frame_counters` удалено: счётчики кадров — в `app-egui::state::frame_context::AppFrameContext` (`frame_counters()`), туда же `Arc` снимка и `RenderDiagnostics`. App: `last_player_snapshot: Arc<PlayerSnapshot>`, локальные правки — `Arc::make_mut` (`state/media_jobs.rs`). Тесты: `worker/tests/snapshot_dedup.rs`, `session/snapshot_builder.rs::builder_carries_session_owned_fields_from_base_snapshot`.
- **MPRIS** (`app-egui::playlist_runtime::desktop_transport`): полная публикация (revision+1, клон вида) только если изменилось что-то кроме позиции (metadata, статус, capabilities, loop/shuffle, volume, control_revision, висящий `seeked`); иначе `DesktopIntegration::publish_position(MediaTime) -> DesktopPositionOutcome::{Updated, Unchanged}` (после terminal shutdown — `BackendAdmissionClosed`), без revision/сигнала. Входы metadata сравниваются без аллокаций: `desktop_transport/publish_gate.rs` (`MetadataInputs`, `ScalarSnapshotState`); проекция разделена на `ExternalPlaybackIdentity` + `MetadataPlan` (заимствованные срезы) и `build_metadata()` (строки только при изменении входов). Linux getter `Position` читает `LatestSnapshotSource::latest_position()`. Compound title покрыт `QueueRevisionSnapshot.metadata_revision` внутри binding. Тесты: `desktop_transport/publish_tests.rs`, `desktop-integration/src/runtime.rs` (position-only).
- **Имя файла карантина плейлиста** строится только при реальном startup completion (`persistence_runtime.rs::drain_playlist_persistence` → `startup_runtime.rs::apply_startup_completion`); тесты `persistence_runtime/tests.rs` со счётчиком `QuarantineNamePolicy`.
- **Видеорендер** (`render-wgpu-video::video::frame_bind_group_cache`): `UniformWriteGate` (последние байты на слот; первая запись нового рендерера обязательна), `BindGroupCache<T>`/`FrameBindGroupCache` (FIFO, ёмкость 4, ключ `PassBindingId` экземпляра пайплайна + uniform slot), `PassBinding` на каждый пайплайн (NV12, P010, host 8-bit, host 16-bit). Кэш принадлежит владельцу views: `ImportedDmaBufTexture.bind_groups`, `WgpuHostPlanarUploadedTextures.bind_groups` (поле первым — bind group отпускаются раньше views); рендерер держит `&cache` только на время pass-а → вытеснение импорта освобождает память как в сессии 03, цикла нет. Кадр без владельца (`from_decoded_host_yuv`, тесты) — bind group на кадр. App собирает SW-кадр через `WgpuFrameTextureViews::host_planar_plane_views()` + `WgpuRenderableFrame::from_decoded_host_planar`. Счётчики `VideoHotPathStats` (`WgpuVideoRenderer::hot_path_stats`, `render-wgpu-shell::Renderer::video_hot_path_stats` в `shell/video_hot_path.rs`) — в строке трассы `render frame stage timings`: `video_bind_groups_created/reused`, `video_uniform_writes/_skipped`. Живой прогон: HW created = числу поверхностей пула (20), SW = числу слотов (4), uniform 1 запись на прогон. Тесты: `frame_bind_group_cache/{tests.rs, gpu_tests.rs}` (GPU — host-planar путь на настоящем адаптере, без адаптера пропуск).
- **Worker**: `pipeline/passthrough_audio_history.rs::PassthroughAudioHistory` (`VecDeque`, ёмкость резервируется один раз = бюджет 600 мс + пакет; выход take побайтно как у старого `Vec`+`drain`, эталон в `pipeline/tests/passthrough_audio_history.rs`). `PlaybackDiagnostics::record_latency` обновляет в хранимом снимке только стадию замера (`diagnostics/latency_stage_update.rs`: `PipelineLatencyCounters::stage_snapshot` + `PipelineLatencyCountersSnapshot::stage_mut`) вместо пересчёта всех 13 стадий; хранимый снимок всегда актуален. Урок: первая версия переносила пересчёт на чтение — а снимок читается на каждом тике чаще, чем приходят замеры (профиль 3,0 → 8,8 мс); дешевле обновлять инкрементально, чем лениво. Тест `diagnostics/tests/latency_materialization.rs` (равенство полному пересчёту после каждого замера; откат уронил оба теста). Resampler: `resample_interleaved_into(&mut Vec)` + scratch внутри, выходной буфер — поле `AudioOutput`.
- **Span-ы**: `render_frame` и `render_ui` — `#[instrument(level = "trace", skip_all)]` (на INFO span форматировал `Debug` координатора рендерера на каждом пробуждении; INFO-строки внутри кадра больше не имеют префикса `render_frame{…}:`).

## Инварианты
1. UI видит последний опубликованный снимок не позже следующего кадра; любое изменение любого поля снимка → публикация (сравнение полным `PartialEq`). 2. MPRIS `Position` всегда свежая; сигналы/`Seeked`/detached как раньше. 3. Bind group не продлевает жизнь вытесненной текстуры. 4. Аудиоистория/диагностика/звук побайтно прежние. 5. Нет новых `unsafe`.

## Не сделано / бэклог
- SW `std::thread::scope` на каждую загрузку кадра (20 % главного потока на SW 1080p60) — сессия 07.
- `smithay-clipboard` поток (0,3 %): слушает то же Wayland-соединение, что и окно, просыпается на каждом событии композитора; устройство зависимости egui-winit — не патчено.
- `VideoDecodeThread::resource_pool_stats` (VA-API, ~4 % worker-а: lock + stats на каждом тике через `texture_pool_snapshot`) — не трогали.
- `refresh_player_snapshot` по-прежнему вызывается ≥ 2 раза за пробуждение (теперь это `Arc::clone` + `pump_embedded_subtitles`).
