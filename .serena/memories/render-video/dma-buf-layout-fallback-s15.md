# Session 15: DMA-BUF multi-object capability boundary и runtime fallback

- `video-frame-contract::DmaBufImageLayout` теперь выражает известный unsupported contract отдельным variant-ом `ComposedMultiObject`. `ComposedLayers` означает composed multi-planar image в одном DMA-BUF object-е; `SeparateLayers` остаётся поддержанным path-ом и допускает разные objects у независимых layers. Это единый exact contract, а не Cartesian-product capability fields.
- Capability schema version повышена до 6. Renderer не рекламирует `ComposedMultiObject`; capability intersection переводит его в `UnsupportedDmaBufImageLayout` с required capability `MULTI_OBJECT_DMA_BUF_IMPORT`, поэтому известная форма отклоняется до decode startup.
- `video-core::validate_dma_buf_descriptor_import_topology` — renderer-neutral ранняя runtime boundary. Typed `DmaBufDescriptorRejection` сохраняет absent objects/layers, invalid plane count, out-of-bounds object index и unsupported composed multi-object отдельно. Separate-layer descriptors с разными objects проходят.
- `render-wgpu-video::DmaBufWgpuFrameMaterializer` вызывает topology validation сразу после provider lookup и до texture-cache lock/Vulkan import. Layout rejection возвращается как `WgpuFrameMaterializationUnsupportedReason::DmaBufDescriptorRejected`; остальные Vulkan/device import failures остаются generic renderer errors.
- `app-egui::dma_buf_runtime_fallback` владеет policy runtime-only limitation. Для `hardware` software fallback запрещён. Для `auto` выбирается только заранее renderer-intersected FFmpeg software plan через `select_confirmed_software_fallback_plan`; обычный auto selector повторно не вызывается, поэтому hardware не выбирается снова.
- Controlled swap использует существующий `PlayerWorker::set_video_backend(... PipelineDemand ...)` / `PlayerSession::configure_active_video_decoder_stream`: новый decoder получает актуальный contract, выполняется reseek к current position, playback intent сохраняется, shell держит frozen previous frame до нового render generation.
- Exactly-once guard живёт в `DmaBufRuntimeFallbackController`. Он фиксируется до availability/startup/restore и не сбрасывается при изменении render generation (failed install/rollback сам может его изменить). Новый scope начинается только по явному `PlayerEvent::MediaOpenRequested`.
- Typed failure context: `SoftwarePipelineUnavailable` сохраняет исходный layout rejection + selector error; `SoftwarePipelineFailed` сохраняет layout rejection + `VideoPipelineRebuildError`. Backend startup имеет отдельный `VideoPipelineRebuildError::BackendStartup`, worker commit/rollback остаётся `Worker(PlayerRuntimeApplyError)`.
- Focused tests: known capability rejection, supported composed single-object, supported separate-layer/distinct objects, out-of-bounds object index, absent objects/layers, runtime auto success/unavailable/startup failure, hardware no-fallback и loop prevention включая render-generation change.
