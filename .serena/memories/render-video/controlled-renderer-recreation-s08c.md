# Controlled renderer recreation — Session 08C (2026-07-11)

- Render/surface settings route теперь применяется live через app-owned `RendererLifecycleCoordinator` в `crates/app-egui/src/renderer_recreation.rs`. Settings/UI видит только `SettingsRuntimeReconfigureHost::recreate_renderer(previous, next)`; concrete surface/device ownership остаётся у shell `Renderer`, а `AppState` не хранит renderer/config.
- Transaction order: preflight busy/conflict -> полностью создать candidate `Renderer` -> восстановить текущий `RenderLiveSettings` -> подготовить materializer того же active provider-а -> проверить candidate capabilities и неизменность backend/materializer класса -> освободить renderer-bound visual leases/cache/override/frozen frame -> `Device::poll(PollType::Wait)` с bounded 5 s drain -> rebind submitted-release queue -> atomically install materializer/capabilities/renderer -> resume redraw/submissions.
- Resize/maximize/minimize действия текущего UI tick-а сериализуются тем же coordinator-ом. Apply при занятой boundary возвращает retryable `RuntimeBusy(RendererLifecycle)`; hidden queue и partial mutation отсутствуют.
- `render-wgpu-video::WgpuSubmissionQueueBinding` разделяется decoder provider wrapper-ом и app materializer state. Queue меняется только после old-GPU drain. Pending submitted releases имеют exactly-once CAS guards; после доказанного device lost binding переводится в lost state, force-releases pending resources один раз, а поздние callbacks не могут сделать double release. Future late releases до rebind освобождаются сразу.
- DMA-BUF и HostPlanar materializers реализуют `WgpuFrameTextureViewMaterializer::recreate_for_renderer`, клонируя neutral provider и создавая только device-owned resources нового renderer-а. Молчаливый переход DMA-BUF <-> HostPlanar запрещён; он является typed candidate preparation failure.
- Renderer recreation failure остаётся typed через `RendererRecreationApplyError{Kind}`, `RendererRecreationRollbackError{Kind}` и `SettingsApplyFailure`. На любой creation/preparation/drain/commit error вызывается restore boundary. Только конкретный failed restore возвращает combined apply+rollback failure. Committed render snapshot обновляется лишь после owner success; failed route сохраняет старый runtime snapshot для retry того же draft.
- WGPU device lost отслеживается через `Device::set_device_lost_callback`; drain различает device lost, timeout, wrong submission index и poisoned lifecycle state.
- `RenderProfile::OpenGles` остаётся нереализованным renderer backend-ом и теперь возвращает typed `UnsupportedProfile` с сохранением active Vulkan path вместо ложного success/deferred restart.
- Focused fake lifecycle tests: success, no active video, resource busy, creation failure+restore, device lost+rollback failure, active DMA-BUF lease order, HostPlanar preservation, commit failure, resize/fullscreen conflict+retry. Settings tests закрепляют commit snapshot only after success и same-draft retry. Exactly-once release guard имеет render-wgpu-video unit test.
- Проверки 08C: app-egui 234 tests; player-core 474; render-wgpu-video 92; render-wgpu-shell 12; rustiplayer-settings 15; strict targeted Clippy; `cargo +1.96.0 check --workspace --locked`; refactor guardrails; playback smoke probe-only including installed FFmpeg runtime probe.
- End-to-end persistence order всё ещё принадлежит Session 08D: settings-core пока persist-ит перед runtime apply и фиксирует `PersistedRuntimeDiverged` на failure; 08C не удаляет этот transitional contract.
