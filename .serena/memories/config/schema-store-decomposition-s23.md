# Config schema/store decomposition — актуально 2026-08-31

- `crates/config/src/schema.rs` — тонкий `AppConfig` facade/re-export owner map. Section owners: `schema/player.rs`, `video.rs`, `render.rs`, `services.rs` (audio/network/web-media/yt-dlp), `ui.rs`; versions — `schema/version.rs`; generated settings coverage — `schema/metadata_tests.rs`.
- Default TOML documentation принадлежит `schema/default_document.rs`. Комментарии привязаны к serialized field/table; missing target ломает tests, поэтому stale documentation не игнорируется.
- `fastiplayer-config::store` остаётся coordinator API (`load_or_create*`, `load_from_path`, `load_or_recover_at`, `save_validated_atomic_at`). Atomic persistence — `store/atomic.rs`; legacy normalization/migration — `store/migrations.rs`; defaults/validation/fixtures — `store/tests.rs`.

## Восстановление битого config (UX edge cases, сессия 05, 2026-10-05)
- Приложение грузит config через `load_or_recover_at(path, now: SystemTime)` (в `app_instance::bootstrap_process`, под уже взятым lease). Строгие `load_or_create_at`/`load_from_path` не изменились: битый файл = ошибка (тесты `unsupported_schema_version_fails_validation`, `unknown_field_is_parse_error` сохранены).
- Политика (`store/recovery.rs`): нет файла → defaults атомарно; синтаксис/не UTF-8/неизвестный ключ/значение вне диапазона/старая версия (<2) → rename в `config.toml.broken-YYYY-MM-DD_HH-MM-SS.bak` (UTC, `store/backup_name.rs`, своя civil-from-days без crate `time` — `time` в config ломал вывод типов `Duration` в тестах player-core), занятое имя → суффикс `-2..-100`, затем defaults; `schema_version` новее текущей (читается из сырого TOML до строгого разбора) → файл не трогаем, defaults в памяти без записи; не читается / не файл / копия не удалась / defaults не записались → без записи. Инвариант: файл пользователя только переименовывается, никогда не удаляется и не перезаписывается.
- `LoadedConfig { config, path, origin: ConfigLoadOrigin, save_policy: ConfigSavePolicy }` (поле `created: bool` удалено). `ConfigLoadOrigin::{LoadedExisting, CreatedDefault, RecoveredFromBroken(BrokenConfigRecovery{problem, backup_file_name}), DefaultsInMemory}`; `ConfigSavePolicy::{WriteToFile, SessionOnly(ConfigSessionOnlyReason)}`. Типы — `store/outcome.rs`.
- Запрет записи исполняет `ConfigSaveTarget` (`LoadedConfig::save_target()`): `save() -> ConfigSaveOutcome::{Saved, KeptInMemoryOnly(reason)}`, validation выполняется в обоих режимах. `fastiplayer-settings::AppConfigStore::from_save_target` → `settings_core::PersistOutcome::SkippedSessionOnly` (`PersistReport::kept_for_session_only()`): транзакция успешна, без rollback.
- Запись: первая запись defaults и обычный save идут через `atomic-file-store::replace_file_atomically` (temp 0600 + fsync + rename + sync каталога). Ошибки записи — один вариант `ConfigError::ReplaceConfigFile { path, failure: ConfigWriteFailure }` (прежние Create/Write/Temp/Flush/Sync/Rename-варианты удалены). При старте `load_or_recover_at` убирает брошенные temp: шаблон `atomic-file-store` (`remove_stale_temp_files`, распознавание у владельца шаблона, `stale_temp.rs`) и прежний `.config.toml.<pid>.<n>.tmp`; только обычные файлы, только точный шаблон, только каталог config-а.
- Логи config-слоя до инициализации tracing теряются (tracing стартует после bootstrap; перенос — сессия 06). Итог загрузки логирует `app-egui::config_startup_notice::log_config_load_outcome` после init.
- Тесты: `store/tests/recovery.rs` (реальная ФС), `store/backup_name.rs` (сверка дат день-за-днём 1970–2200), `atomic-file-store/src/stale_temp.rs`, `fastiplayer-settings/src/transaction.rs` tests.
- Current schema v11 (UX edge cases, сессия 07, 2026-10-05): `LEGACY_SCHEMA_VERSION_10`; `migrations.rs::migrate_playlist_error_behavior_to_skip` на сыром TOML при версии ≤10 меняет только точное `playlist.error_behavior = "stop"` → `"skip"` (решение владельца: default-документ v10 писал `stop` явно; v11 `stop` = осознанный выбор, не трогается). Default `PlaylistConfig::error_behavior = Skip`. Golden — `crates/config/tests/fixtures/current_schema_v11.toml`; тесты — `store/tests/playlist_error_behavior_migration.rs`. При следующем bump-е: литералы `schema_version = 11` в config/settings/app tests, `scripts/tests/playback-smoke-self-test.sh`, `docs/benchmarks/tools/t480s/*-template.toml`.
- Дефолты первого запуска (2026-10-11, решение владельца): `player.start_paused = false` (открытый файл сразу играет) и `ui.show_telemetry = false` (диагностическая панель скрыта). Схема осталась v12, миграции нет: явно записанное `true` у прежних установок сохраняется как есть. Golden — `crates/config/tests/fixtures/current_schema_v12.toml`; поведенческий тест — `app-egui settings_runtime::tests::snapshot_routes::default_config_autoplays_new_media_and_hides_telemetry`. `custom_config_for_test()` в app-egui намеренно держит противоположные значения (`start_paused = true`, `show_telemetry = true`), чтобы тесты отличали committed config от default.
- Schema v10 (история). Provider-neutral quality/HDR/VOD recovery policy принадлежит strict/defaulted `[web_media]`; `[yt_dlp]` содержит только process controls. Одноразовая v9->v10 migration переносит policy keys без alias-полей и fail-closed отклоняет конфликт двух секций. Полный contract: `mem:config/schema-v10-web-media-policy-2026-08-31`.
- Прежние migrations `[youtube]` -> `[yt_dlp]` и промежуточные schema upgrades сохранены; старый policy source после v10 не принимается.
- UX-11 (2026-10-06): `[audio].volume` = последняя слышимая громкость (пишется приложением автоматически), новый additive `[audio].muted: bool` (default false, без bump схемы; golden v11 содержит `muted = false`). Контракт — `mem:app-egui/user-audio-level-persistence-ux11`.
- `[ui.sidebar].width_points: u16` default `420`, validation/Settings range `350..=600`, setting id `ui.sidebar.width_points`. Старый документ без section получает default; поле появляется после следующего успешного сохранения.

- Golden current document: `crates/config/tests/fixtures/current_schema_v11.toml`; byte-stable roundtrip сравнивает его с `AppConfig::default().to_pretty_toml()`.
- `[playlist]` остаётся strict/defaulted group с `load_siblings`, `sibling_media_filter`, playback/error behavior, save debounce, `resume_checkpoint_interval_ms` (default 5000, `1000..=60000`, step 1000) и previous restart threshold. Runtime contracts — `mem:playlist/settings-s13` и `mem:playlist/resume-position-sidecar-2026-07-19`.
- `UiAnimationsConfig::reduced_motion` остаётся defaulted additive field; подробности: `mem:settings-ui/reduced-motion-2026-07-18`.
- Verification owner set: config/settings tests, app settings runtime tests, smoke current config generation+parse, refactor guardrails, locked workspace check, fmt/diff checks.

## Browser session schema v28 (2026-10-30, browser-bridge сессия 03b)
- `CURRENT_SCHEMA_VERSION = 28` (`LEGACY_SCHEMA_VERSION_27` со всей обвязкой), миграция v27→v28 только поднимает версию (bump нужен: строгий парсер v27 счёл бы новую таблицу битым файлом → `.bak`).
