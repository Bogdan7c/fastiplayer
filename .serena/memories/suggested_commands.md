# Suggested Commands

- Build/check whole workspace: `cargo check --workspace`.
- Run app shell: `cargo run -p app-egui` (single binary target `rustiplayer`; explicit form: `cargo run -p app-egui --bin rustiplayer`).
- Run app with media path or URL: `cargo run -p app-egui -- /path/to/media.webm` or `cargo run -p app-egui -- 'https://www.youtube.com/watch?v=VIDEO_ID'`.
- Focused tests: `cargo test -p player-core`; direct HTTP media opener tests: `cargo test -p service-direct-media`; prefetch buffer/config tests: `cargo test -p media-prefetch`; capability/codec policy tests: `cargo test -p capability-core -p codec-core`; render split checks: `cargo test -p render-wgpu-video`, `cargo test -p render-wgpu-shell`, then `cargo check -p app-egui`.
- Broad tests when behavior may cross crates: `cargo test --workspace`.
- Clippy for local quality/Sonar input: `cargo clippy --workspace --all-targets`.
- Refactor dependency guardrails: `scripts/check-refactor-guardrails.py`.
- Local pre-PR path: `scripts/pre-pr-checks.sh` (runs `cargo metadata --no-deps --format-version 1`, guardrails, `cargo fmt --all --check`, `cargo check --workspace`, `cargo clippy --workspace --all-targets`).
- Format check: `cargo fmt --all --check`; apply formatting with `cargo fmt --all` when editing Rust.
- Render frame timing trace (perf analysis closed/open settings, segment parser idea in user memory project_settings_sidebar_perf.md): `RUST_LOG=info,rustiplayer::render_frame_timing=trace cargo run --release -p app-egui -- /path/to/media.webm > /tmp/timing.log 2>&1`; log lines are ANSI-colored even when redirected.
- Perf must be judged on release builds only; dev profile has opt-level 3 overrides for all external deps (`[profile.dev.package."*"]`) plus hot workspace crates (codec-core, video-vaapi, cros-*, vp9-parser, webm-demux, symphonia-demux, media-prefetch, audio) — debug now holds 4k60 VP9 at 60fps; if debug lags again, check whether a new hot member crate needs an override. BUG FIX (2026-06-18) «settings sidebar opens slowly / ~6s in DEBUG, release fine»: ROOT CAUSE was tracing, not perf/opt-levels. `AppState::render_ui` had `#[instrument(skip(self, window, frame_context))]` but did NOT skip `egui_input` and `settings_ui_model`, so the `render_ui` span recorded the ENTIRE huge `SettingsUiModel` (all ~80 descriptors+text) via Debug. egui emits a `Widget rect ... changed id between passes` WARN every frame WHILE THE SETTINGS PANEL IS OPEN (that warning is debug_assertions-only → fires in debug, NOT in release — hence release was fine), and every such WARN re-formats the giant span fields into the log (tens of KB per line × many warns/frame = seconds). Symptom appears «even without video» because it only needs the settings panel open. FIX: add `egui_input, settings_ui_model` to the `#[instrument(skip(...))]` list on `render_ui` (crates/app-egui/src/state.rs). After fix: max log line 402 chars (was tens of KB), 0 slow frames. NOTE: the underlying egui «changed id between passes» warning still fires every frame (settings widget ids unstable across egui's two passes) — now cheap, but a separate latent egui-id-stability issue in settings_ui layout worth fixing later. General lesson: never let `#[instrument]` capture large Debug structs (UI models, snapshots) as span fields — always `skip` them; a per-frame WARN turns them into a multi-second formatting sink. FOLLOW-UP (2026-06-18) on the egui «changed id between passes» WARN itself: source is NOT the settings sidebar but live overlays on the right/left (telemetry panel x=1000-1280, etc.) whose widget rects shift frame-to-frame. The telemetry panel rendered one Label per row via `ScrollArea::show_rows` (~100 widgets/frame) → flood of warnings. Fixed by collapsing the whole telemetry panel into ONE widget: build a single `egui::text::LayoutJob` (per-line color via `TelemetryPanelRow::append_to_layout_job`, monospace `TextStyle::Monospace.resolve(style)`, `job.wrap.max_width = INFINITY`) and render `ui.label(job)` inside the ScrollArea; removed per-row `render`/`telemetry_panel_row_height`. This cut warnings ~106→~32 AND is faster (1 galley vs 100 labels). Residual ~32/8s are sporadic egui debug-only relayout warnings from SidePanel geometry + other live overlays — benign, debug_assertions-only (absent in release). Tried and rejected: ScrollArea scroll_bar_visibility AlwaysVisible, panel resizable(false), per-row push_id(index), ctx max_passes=1 — none eliminate the residual (the check compares against the previous frame, so any live-updating widget whose rect changes triggers it). If zero log noise is required, filter egui's WARN in the tracing setup rather than fighting egui internals.
- Seek diagnostics local trace: `RUST_LOG=player_core=debug,symphonia_demux=debug,app_egui=debug cargo run -p app-egui -- /path/to/media.webm`.
- Seek diagnostics parser: `scripts/parse-seek-diagnostics.py --scenario "<name>" /tmp/rustiplayer-seek.log`; supports `--format csv` and `--format json`.
- Local Sonar scan only on explicit request and with token in env, not files/history: `SONAR_USER_HOME=/tmp/rustiplayer-sonar-user-home scripts/sonar-local-analysis.sh`.
- After Sonar scanner success, wait for the printed `/api/ce/task?id=...` background task before reading issues.
