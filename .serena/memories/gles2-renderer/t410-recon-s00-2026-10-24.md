# GLES2-план, сессия 00: разведка ThinkPad T410 и эталон соперников (2026-10-24)

Публичный отчёт: `user/gles2-renderer/results/00.md` (все таблицы). Здесь — то, что нужно следующим сессиям, и грабли метода.

## Железо и драйверы (живьём)
- T410: i5 M560 2C/4T, 3,6 ГиБ, Ironlake Gen5 (`8086:0046`), Mesa 26.2.4 crocus, i965 VA 2.4.5, KWin 6.8.1 Wayland + Xwayland, панель 1440×900@60.
- GLES 2.0 / GL 2.1, highp fp32, MAX_TEXTURE_SIZE 8192. Есть все расширения уровней README (texture_rg, unpack_subimage, uint index, VAO, EGL_image(+external), KHR_debug, OES_texture_3D; EGL dma_buf_import(+modifiers), fence/native fence, buffer_age, swap_with_damage, robustness, surfaceless). Нет norm16, partial_update. Альфа-конфиги: Wayland 8, X11 4 ARGB visual.
- radeonsi и llvmpipe на запрос GLES2 отдают **ES 3.2** → возможности только из ES2 + строк расширений (иначе тесты зелёные, T410 чёрный).
- VA-поверхности Ironlake линейные (`LINEAR`, pitch = ширине); R8+GR88 импорт из COMPOSED и SEPARATE — бит-в-бит; на 780M без атрибутов модификатора хрома — мусор, передавать всегда. P010 на 780M: GR88 + ABGR8888 бит-в-бит. Импорт 2 плоскостей ≈ 6 мкс.
- **H.264 VA-API на Gen5 = BSD (энтропия) + media-ядра на EU 3D-движка.** Декод без показа: Render/3D 92–98 %. Потолок ffmpeg: 720p ~93, 1080p 38,5–39,6 кадра/с; MPEG-2 1080i 111. HW 1080p60 невозможен. Наш декодер (production VideoDecodeThread) — 64/67/28/29,5 кадра/с при Render 69–77 % = последовательное ожидание → сессия 09a.
- Бюджет GPU (цель 1440×900): YUV→RGB 8 бит 7,2 мс (импорт VA 5,6), заполнение экрана 3,2, загрузка SW 1080p 1,8; загрузка в читаемую текстуру = стоп конвейера (17,4 вместо ~9) → кольцо обязательно; 16 бит ручная билинейка 23,8, LA аппаратная 6,9; `pow`-HDR +18 мс → LUT для 06. Аппаратный фильтр ILK не квантует до 8 бит (вес 1/64).
- Дисплей: sprite-плоскость YUV 4:2:2 (YUYV…), без NV12.
- Метрики: fdinfo i915 Gen5 — только `drm-*-system0` (нет drm-engine); `intel_gpu_top` — root, глобально (клиенты мусор); мощность только с батареи (V×I).
- GPU-зависания: неустранимое после VLC `--vout=xcb_xv` (нужна перезагрузка), одиночное со сбросом в kwin при mpv SW 60 fps.
- «До»: без Vulkan — kdialog «requires Vulkan»; с lavapipe wgpu берёт CPU-адаптер и играет за 216–280 % CPU.

## Эталон (лучшие чистые режимы; CPU процесс / +композитор, % ядра)
- HW: чисто только 720p30 (mpv `gl vaapi fast` ~12/15, VLC gl vaapi ~12/15); 720p60/1080p30/1080p60 теряют у всех (GPU 100 %).
- SW: 30 fps чисто у всех (720p30 ~46/52, 1080p30 ~80/86); 60 fps чисто только mpv `--vo=xv` под XWayland (1080p60 122,8/155,8); GL-режимы теряют 9–73 кадра при GPU 40 % (ритм показа). Нативный Wayland — ни одной чистой 60-fps ступеньки.
- Лесенка: 30 fps HEVC/VP9/AV1 чисто у всех; mpv Xv 10/12 (HDR без тонмапа); mpv Wayland 6/12; VLC 7/12.
- MPEG-2 1080i: VLC HW 61/65, SW 72–117.

## Решения владельца (README 12–17)
CPU двумя числами (победа по обоим); режим декода `dynamic` (HW → SW при отставании, возврат на следующем файле), default остаётся `auto`, предупреждение на GLES2 (не на wgpu); критерий T410 — в dynamic, HW 1080p60 исключён; сессия 09a — конвейер VA-API с тщательной проверкой стабильности; VLC xv исключён.

## Метод и грабли (для 09a/10/11)
- Оболочка T410 — fish → `bash -c`/скрипты. Окружение GUI: XDG_RUNTIME_DIR=/run/user/1000, WAYLAND_DISPLAY=wayland-1, DISPLAY=:0, XAUTHORITY=/run/user/1000/xauth_* (меняется), XWayland-режим = без WAYLAND_DISPLAY + QT_QPA_PLATFORM=xcb.

- Стоп-кран по росту `GPU HANG` в `journalctl -k`.
- Строгий `collect.py` v3 не подходит для перебора режимов (флаги зашиты, гейты только zero-copy, только XWayland) — адаптация в 11.
