# GLES2: аппаратный zero-copy DMA-BUF → EGLImage (сессия 07 плана gles2-renderer, 2026-10-25)

Отчёт: `user/gles2-renderer/results/07.md`. Решения владельца 32–33 README: освобождение кадра — ПОТОК-ОЖИДАТЕЛЬ внутри GLES2-рендера (приложение не меняется); HW P010 в GLES2 НЕ объявляется (GPU с 10-бит декодом всегда тянет wgpu) — только NV12 8 бит.

## `gles2-egui` (владелец EGL; EGL-типы наружу не выходят)
- `Gles2Context::attach_dma_buf_plane_to_texture(texture: glow::NativeTexture, &DmaBufPlaneTexture{fourcc, width, height, fd: BorrowedFd, offset: u32, pitch: u32, modifier: DrmModifier}) -> Result<DmaBufTextureAttached{modifier: ModifierAttribute::{Explicit, DriverChosen}, image_release: ImageRelease}, DmaBufTextureError>` — модуль `context/dma_buf_texture/` (attributes.rs — чистая сборка, attach.rs — порядок над `EglDriver` + шов `TextureImageTarget`). ОДНА плоскость = один EGLImage; EGLImage уничтожается сразу после `glEGLImageTargetTexture2DOES` (EGL_KHR_image_base: sibling-текстура держит буфер); fd НЕ закрывается (EGL_EXT_image_dma_buf_import issue 3). Модификатор LO/HI всегда, кроме `DrmModifier::INVALID` (требует `_modifiers`). Сбрасывает привязку TEXTURE_2D активного юнита и накопленные glGetError; фильтр/wrap ставит вызывающий (без них текстура на EGLImage неполная → чёрное).
- `DmaBufImportSupport::sampling_of_modifier(fourcc, modifier) -> ModifierSampling::{Sampler2D, ExternalOnly, NotListed, FormatQueryUnavailable, ImportUnavailable}`; `dma_buf_texture_stats()` (created == destroyed + destroy_failures).
- FFI — `context/safety/egl_image.rs` (`glEGLImageTargetTexture2DOES` через `eglGetProcAddress` один раз на контекст, только при `GL_OES_EGL_image`; в glow 0.17 функции нет). `context/safety.rs` 785 строк — НЕ расти.
- Тест `tests/headless.rs::fence_signals_when_waited_from_a_thread_without_current_context` — условие потока-ожидателя (EGL_KHR_fence_sync: FLUSH без текущего контекста игнорируется → fence ставится с glFlush).

## `gles2-video`
- `DmaBufNv12Frame::new(key, &DmaBufBufferIdentity, luma_extent, luma: DmaBufPlane(R8), chroma: DmaBufPlane(GR88))`; паспорт `DmaBufBufferIdentity{resource_id, objects: Vec<DmaBufObjectIdentity{device, inode, size, modifier}>, format: DmaBufFrameFormat{luma_extent, arrangement: DmaBufPlaneArrangement::{ComposedSingleObject, SeparatePlanes}, modifier}}` — БЕЗ offset/pitch (их не даёт дешёвый поиск идентичности; тот же буфер + раскладка ⇒ те же offset/pitch). Контракт синхронизации — тип-документ `DmaBufSharingContract`.
- `dma_buf_cache.rs` — чистый LRU (ёмкость `DmaBufImportCacheCapacity::matching_decoder_surface_pool`, смена формата сбрасывает всё до импорта, тот же resource_id с новым буфером заменяет). `VideoLayerRenderer::{show_cached_dma_buf_frame → CachedDmaBufFrame, import_dma_buf_frame → DmaBufImportOutcome, set_dma_buf_import_capacity, purge_dma_buf_imports, dma_buf_import_snapshot}` (`dma_buf_import.rs`, `renderer/dma_buf.rs`, `renderer/draw_plan.rs`). Текущий кадр один: загруженный (кольцо, `ring.clear_current`) ИЛИ импортированный.
- `program/nv12.rs` — паритет `nv12_to_rgba.wgsl`: Y/UV билинейно в ОДНОЙ `v_source_uv` по всей текстуре, UV `.rg`, выборки по varying без адресной арифметики. Цвет — тот же `ColorTransform` (у wgpu NV12 и host 8 бит общий `color_pipeline.rs`).
- Сессия 07 нашла дефект 06: `precision highp sampler2D` обязателен в программах 10/12 бит/HDR (GLSL ES 1.00 §4.5.3: sampler2D по умолчанию lowp, результат texture2D наследует; llvmpipe урезает → 12-бит код −1/8; CI был красным с b5bbd3e1).

## `render-gles2-shell`
- `frame_release/`: `Gles2FrameReleaseBinding::{new, publish_presented_frame_fence(Arc<GpuFence>), release_after_context_lost, resume_after_context_recreated, renderer_detaching(RendererDetachGrace) -> RendererDetachReport, stats}` + `wrap_video_backend_for_gles2_release(StartedVideoBackend, &binding) -> (StartedVideoBackend, PresentFrameResourceProviderHandle)`. Последний fence покрывает всю прежнюю работу; fence не публиковали → сразу; уже сработал → сразу (без потока); иначе FIFO-очередь ленивого потока `gles2-frame-release` (wait слайсами 50 мс). CAS ровно один раз. Ошибка ожидания → освобождение + `fence_wait_failures`. Обёртка декодера форвардит все 20 методов `VideoDecoderThreadHandle`; тест `trait_coverage` парсит исходники трейтов (новый метод без проброса → падение).
- **`renderer_detaching` обязателен перед уничтожением `Gles2Context`** (сессия 09): иначе последний fence (держит `DisplayLease`) умирал в потоке-ожидателе после уничтожения контекста, одновременно с exit() и atexit Mesa → на T410 `corrupted double-linked list` 10/10. Метод ждёт fence до grace (250 мс; не дождался → кадр отпускается без fence, счётчик `released_at_renderer_detach_unfinished`), уничтожает fence в потоке рендера. Страховка — `Drop` последнего клона забирает `last_fence`.
- `dma_buf_frame/`: `materialize_dma_buf_frame(renderer, context, provider, frame) -> DmaBufMaterialization{outcome: DmaBufMaterializeOutcome::{Shown(CacheHit|FreshImport|AlreadyCurrent), Busy, Missing, ProviderFatal, Unsupported(HostPlanarDescriptor|DescriptorRejected|FrameFormat|DriverCannotImport), ImportFailed}, resource_pool_lock_wait}`. Порядок как wgpu: контракт NV12 → идентичность без dup fd (сверка с контрактом ДО показа из кэша — показ делает кадр текущим) → кэш → дескриптор (dup fd) только на промахе → сверка → (нет идентичности → паспорт с дескриптора, второй поиск) → разбор слоёв → импорт; dup fd закрываются в конце функции. Размеры как wgpu: Y = descriptor w×h, UV = div_ceil(2). Отображение на `FrameMaterializationOutcome` — `outcome.rs`. `dma_buf_import_capacity_for(slots)`.
- `capabilities.rs`: `GLES2_HARDWARE_FRAME_CONTRACTS` (NV12 composed/separate) только при `tiers().zero_copy`; `gles2_render_capabilities_for(precision, limit, HardwareZeroCopy::{Available, Unavailable})`; P010 никогда, `p010_render_readiness = Unavailable`.

## Живые факты
- 780M: VA NV12 модификатор `0x0200000010401b04`, 1080p → 1920×1088 pitch 2048. T410: `LINEAR`, pitch = ширине, 1080p → 1920×1088.
- Стенд `video-vaapi/examples/gles2_dmabuf_bench.rs` (`--input mp4 --layout composed|separate --pace-hz --gpu-probe --verify-pixels --teardown-order natural|no-detach`): copied_bytes 0, импортов ≤ пула (21/24), поток-ожидатель вернул все кадры кроме первого. GPU-проход NV12 1440×900: T410 7,2–7,5 мс, 780M 0,11 мс. T410 720p60/1080p30 упираются в декодер (51/24 к/с, сессия 09a).
- **Ironlake без LLC**: запись CPU в импортированный udmabuf GPU не видит без `clflush` (DMA_BUF_IOCTL_SYNC у udmabuf на x86 не сбрасывает кэш); первый кадр верен (clflush при первой привязке). Тесты перезаписи используют `overwrite_contents_as_cpu_producer`. Критично для сессии 12.
- llvmpipe/softpipe не проверяют fd при eglCreateImage (принимают /dev/null и pipe) → тесты отказа драйвера там пропускаются с причиной.
