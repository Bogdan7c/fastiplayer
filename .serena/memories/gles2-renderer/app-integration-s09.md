# GLES2 в приложении: `Gles2Renderer` за `RenderShell`, автовыбор, перезапуск (сессия 09 плана gles2-renderer, 2026-10-25)

Отчёт: `user/gles2-renderer/results/09.md`. Решения владельца 35–41 — `user/gles2-renderer/README.md`. Каталог/метка/проба/контракт — `mem:gles2-renderer/render-shell-contract` (разделы P4/P5).

## `render-gles2-shell` — полный `RenderShell`
- `Gles2Renderer::new(Arc<dyn gles2_egui::WindowSource>, SurfacePresentSettings) -> Result<_, RendererCreateError>` (контекст стартует 1×1, размер — на acquire/resize), `set_color_pipeline_settings`/`set_hdr_to_sdr_settings` (стартовые цвета как у wgpu), `probe_gles2_renderer() -> RendererProbe` (offscreen-контекст + базовый уровень; нет EGL → `Unusable{CreationFailed(ApiConnection)}`, EGL<1.5 / нет ES2-конфига → `MissingRequiredFeature`; llvmpipe → Usable: GLES2 — последний кандидат). `Gles2Renderer` не `Send` (EGL-контекст в потоке окна); подготовщик `Gles2VideoImportPreparer` — `Send`, без GL-объектов.
- Тестовый/стендовый `new_offscreen(RenderSurfaceSize, ..)` + `read_offscreen_pixels()`, `frame_counters()`, `frame_release_stats()`; фича `test-support` у `gles2-egui` (`simulate_context_loss`).
- Модули: `src/shell/` (`creation`, `create_error` — таблица `CreateError`→стадия, `probe`, `presentation` — маппинг показа из results/03, `live_settings`, `gpu_idle`, `layers`, `frame`, `frame_fence`, `frame_outcome`, `frame_layers`, `video_frames`, `render_shell`), `src/video_import/` (`environment`, `prepared`, `layer_feed`, `dma_buf_outcome`, `state`, `handoff`), `frame_release/drain.rs`. Склад кадров — сам рендер (`impl VideoFrameImport for Gles2Renderer`).
- Кадр: билет — маркер (`begin_frame` внутри `FrameCompositor::render`); после КАЖДОГО кадра, где рисование началось (в т.ч. упавшего не по потере контекста), один fence → видеослой + привязка освобождения (`retire_submitted_frame_work` → `FencePublished | FinishedSynchronously (glFinish) | ContextLost | Unprotected`, счётчики `failed_frames_fenced`, `frame_fence_fallback_finishes`, `frame_fence_failures` — должен быть 0).
- Фон: `gles2_egui::FrameLayers::underlay_coverage()` / `UnderlayCoverage` — видео на всю цель освобождает сборщик от заливки (−2,2 мс GPU на T410); `UiFrameWork.background`.
- Отказанный кадр (чужой билет/ключ): `FrameCompositor::settle_content_without_frame` применяет set/free текстур UI (conformance 11).
- «Один текущий кадр» видеослоя: ключ несёт рецепт (эпоха установки декодера + ключ кадра на слое + источник), не текстуры; не-текущий ключ (заморозка, scrub, повтор при Busy, кадр прежнего декодера) показывается заново по рецепту, иначе `Failed("cannot be shown again")` — чужая картинка никогда. Кольцо занято → закрыть загрузки fence-ом и повторить один раз.
- `wait_for_gpu_idle`: fence + ожидание возврата уже отпущенных кадров (`PendingReleaseDrain`), иначе гонка с потоком-ожидателем.
- Пересоздание в семействе: новый рендер принимает привязку освобождения старого (`HandoffMark` — старый при Drop не отвязывает). Установка импорта сверяет, что декодер обёрнут ТЕКУЩЕЙ привязкой (`Gles2FrameReleaseBinding::is_same_binding`, иначе `SubmissionBindingFailed`).
- Drop: слои (`destroy`) → `detach_for_shutdown` (renderer_detaching) → контекст (последнее поле).
- `needs_follow_up_frame` = `Soon`, пока строится таблица HDR (решение 38, `mem:gles2-renderer/sw-high-bit-hdr-s06`).
- Аппаратные отказы → `RendererCannotShowHardwareFrame(HardwareFrameRefusal)` (решение 41), настоящие отказы дескриптора — `DmaBufDescriptorRejected`.
- `hot_path_stats` — нули (групп привязки нет).

## Приложение
- Каталог `[WgpuVulkan, Gles2]`, ленивые пробы; Auto: аппаратный Vulkan с NV12 → wgpu, иначе GLES2; явный профиль невыполним / метка → следующий кандидат + уведомление «до ×», настройка не меняется (35, 39); обычный выбор Auto молчит, причина — строка `Renderer:` в телеметрии и `info!("Renderer selected" renderer=… why=…)` (40). Фатальное окно — только если не годен никто («Vulkan or OpenGL ES 2.0»). GLES2 показывает всегда vsync + прозрачность, `[render.vulkan]` его не касается.
- Конфиг v24 (`mem:config/schema-store-decomposition-s23`): default `auto`, `vulkan`→`auto` при миграции, `[render.opengles]` удалён. `render.profile` → `SettingApplyMechanism::AppliesAfterRestart` (`AppRouteApplyResult::AppliesAfterRestart`, группа `RenderProfileRestart`), строка «Applies after restart» и кнопка «Restart now» (`settings_runtime/render_profile_restart.rs`, `SettingsUiAction::RestartNow`; кнопка — только когда отличается СОХРАНЁННОЕ значение и нет неприменённых правок).
- Перезапуск: `app_instance/relaunch.rs` — `AppInstanceLease::release() -> InstanceLeaseReleased` (токен), `relaunch_after_release(token, request, ShutdownQuality, ..)` запускает `current_exe()` без аргументов только после чистого закрытия; отказ (бинарь удалён/заменён, spawn) — `error!` + stderr. `main.rs` разбирает shell (`into_instance_lease`) после `finish_process_shutdown` (D-Bus имя уже отпущено).
- Программный фолбэк декода запускается и на отказ рендера (`DmaBufFallbackTrigger`).
- Сигналов (SIGTERM) приложение не обрабатывает: kill = аварийный путь. Для штатного закрытия в приёмке — KWin-скрипт `closeWindow()` по `resourceClass`.

## Живые факты (2026-10-25)
- T410 (Ironlake, без Vulkan): первый запуск Fastiplayer — Auto → GLES2 «no hardware Vulkan adapter», H.264 → `plan="vaapi-dmabuf-gles2"` + `VA-API EGL DMA-BUF`, HEVC/VP9 → FFmpeg (потоки `ffmpeg-video-decoder`, `av:hevc:*`) + `gles2-frame-release`; старт→первый кадр 403–518 мс. С временно поставленным lavapipe: Auto и явный `vulkan` → GLES2 («only a software Vulkan adapter»). Серия 20 выходов во время HW-видео (10 Wayland + 10 XWayland, проверено, что XWayland — X11-клиент) — все код 0, закрытие ≈0,15 с, без coredump/GPU HANG → общий бэклог п. 13 закрыт без правки декодера.
- 780M: Auto = wgpu, замер «до/после» в шуме (4 пары). RSS процесса зависит от того, как записан файл бинаря (только что слинкованный — мелкие страницы page cache, после `cp`/чтения — крупные folio, +10 МиБ RSS кода): в замерах доставлять оба бинаря одинаково (`cp`).
- Строка плана `Selected video pipeline plan=` пишется только для предстартового декодера; кандидаты strong open свой план не логируют — реальный декодер смотреть по потокам (`video-decode` = VA-API, `ffmpeg-video-decoder` = FFmpeg) или по `backend_contract`.
