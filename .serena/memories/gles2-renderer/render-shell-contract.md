# Контракт «приложение ↔ рендер» `render-shell-api` (сессии 01–02 плана gles2-renderer)

Отчёты: `user/gles2-renderer/results/01.md` (контракт, таблица «метод ↔ где в app-egui ↔ кто реализует»), `results/02.md` (wgpu за контрактом, app-egui на `Box<dyn RenderShell>`). GLES2 встаёт сюда же в сессии 09.

## Что это
- Crate `crates/render-shell-api`: `trait RenderShell` (object-safe) + `trait VideoFrameImport` (склад кадров рендера) + `trait VideoImportPreparer` (переносимый подготовщик импорта, сессия 02) + нейтральный словарь кадра и каталога. Зависит только от `egui` (типы мешей/текстур), `render-core`, `subtitle-raster`, `video-backend-api`, `video-core`, `video-frame-contract`, `video-present-core`. Guardrail: allowlist `RENDER_SHELL_API_ALLOWED_DEPENDENCIES` в `scripts/check-refactor-guardrails.py`; GLES2-crate-ы запрещены render-wgpu-*, контракт рендера запрещён плееру/декодерам/контрактам/media-source-open.
- Каталог рендеров (решение владельца 01) — модуль `app-egui::render_backend` (см. ниже); контракт даёт только `RendererFamily {WgpuVulkan, Gles2}`, `RendererProbe`, `RendererUnusableReason`, `RequiredRendererFeature`, `RendererCreateError{stage,message}`.

## Ключевые инварианты (держатся типами)
- Билет `AcquiredSurfaceFrame` = паспорт `RendererInstanceId` + `Box<dyn Any>` с настоящим буфером; открыть — `into_buffer::<T>(own_id)`; чужой → `Failed(ForeignSurfaceFrame)`. Drop неиспользованного = drop буфера (wgpu discard). 1 аллокация на кадр.
- `RenderableFrameKey` = паспорт + ОДИН `Arc` с КЛОНОМ `VideoFrameLease` и ресурсами рендера (24 байта). Пока жив клон ключа — кадр не возвращается декодеру. Рендер НЕ хранит ключи после `render_frame`. Кэши импорта — по идентичности буфера. Чужой ключ → `Failed(ForeignVideoFrame)`. Пересоздание рендера делает старые ключи чужими: app обязан очистить кэш/override/замороженный кадр до установки нового рендера (`release_renderer_bound_visual_state`).
- `materialize(&lease)`: контракт не объявлен (`RenderCapabilities::supports_frame_contract`) → `Unsupported(ContractNotDeclared)`; нет импорта → `NoVideoBackendBound`; затем provider/импорт: `Ready/Busy/Missing/Error(ProviderFatal|ImportFailed)`, `Unsupported(TransferPathNotHandledByActiveImport|LayoutNotHandledByActiveImport|DmaBufDescriptorRejected)`. Отчёт sample в аренду (ровно 1 раз) и Busy-фолбэк «прошлый кадр» остаются в app.
- Подключение декодера: `prepare_video_import(StartedVideoBackend, VideoImportPlan{path, DecoderSurfacePoolSlots})` → `PreparedVideoImport{backend (обёрнутый, для плеера), pending: PendingVideoImport (Send, drop = отмена)}` → `install_video_import(pending)` (чужой рендер → `PreparedByAnotherRenderer`).
- **Подготовщик (решение владельца в 02):** `RenderShell::video_import_preparer(&self) -> Box<dyn VideoImportPreparer>` (Send). Нужен, потому что кандидат strong open запускается в потоке ПЛЕЕРА (порт `DetachedVideoBackendResourcePort` уходит в worker), а рендер живёт в потоке окна. Подготовщик держит только то, что нужно обёртке/импорту (wgpu — клоны instance/adapter/device/queue; GLES2 — очередь освобождений по fence, БЕЗ GL-объектов) и ставит паспорт своего рендера. Склад рендера не меняет. Метод на `RenderShell` (`&self`), а не на `VideoFrameImport` (`&mut`), чтобы 40 read-only цепочек app не требовали `&mut`.
- Пересоздание в семействе: `export_video_import_for_recreation()` → `prepare_recreated_video_import(handoff)` (чужое семейство → `HandoffFromAnotherFamily`) → `install_video_import` перепривязывает отложенные освобождения к очереди нового рендера (только после ожидания старого GPU — порядок держит `RendererLifecycleCoordinator`). `release_after_device_lost() -> ReleasedFrameCount` — ровно один раз.
- `RenderFrameFailure.kind: {VideoRender, ForeignSurfaceFrame, ForeignVideoFrame}`. `RendererGpuDrainError` нейтральный: `DeviceLost(RendererDeviceLost)`, `Timeout`, `WaitRejected` (у wgpu — WrongSubmissionIndex), `DeviceLostStatePoisoned`. `RenderHotPathStats { resource_bindings_created/reused, uniform_writes(_skipped) }`; трасса `render_frame_timing` пишет прежние имена `video_bind_groups_*`.

## wgpu-реализация (сессия 02, `render-wgpu-shell`)
- `shell/render_shell.rs` — `impl RenderShell for Renderer` (перевод вызовов). `shell/gpu_context.rs` — instance/adapter/device/queue + device-lost (вынесено из shell.rs). `shell/present_target.rs` — цель показа `PresentTarget::{Window (surface+config+окно winit, pre_present_notify), Offscreen (#[cfg(test)])}`; билет хранит `TargetFrame`. Окно рендер держит сам.
- `video_import.rs` — `WgpuVideoFrameImport` (склад): `wrap_video_backend_for_wgpu_submission` + `DmaBufWgpuFrameMaterializer` (кэш = `DmaBufImportCacheCapacity::matching_surface_pool(plan.decoder_surface_pool)`) / `HostPlanarWgpuFrameMaterializer`, `WgpuSubmissionQueueBinding`. `PendingImportOrigin::{FreshDecoder, RecreatedRenderer}`: rebind очереди только для пересоздания. `WgpuVideoImportPreparer` — то же в потоке плеера. `video_import/renderable_frame.rs` — сборка `WgpuRenderableFrame` из ключа (NV12/P010/HostPlanar; перенесено из `app-egui::frame_prepare`); проверяется ещё в `materialize` (несовпадение → `Unsupported(LayoutNotHandledByActiveImport)`), и снова в `render_frame`.
- Стартовые цвета: фабрика каталога зовёт прежние `Renderer::set_color_pipeline_settings/set_hdr_to_sdr_settings` (НЕ `commit_live_settings`: тот отклоняет «неподдержанные» поля — было бы изменение старта). Пересоздание: умолчания + `commit_live_settings(snapshot)` как раньше.
- Рендер без окна: `Renderer::new_headless(size)` (#[cfg(test)], Vulkan как в production, Rgba8Unorm), `read_offscreen_pixel`. Стенд `src/test_support.rs` (белый/чёрный HostPlanar 4×2, журнал освобождений).

## app-egui (сессия 02)
- `AppShell.renderer: Option<Box<dyn RenderShell>>`; функции берут `&mut dyn RenderShell` (установка импорта меняет склад), слот `&mut Box<dyn RenderShell>` — только `render_frame`/`with_lifecycle_settings_adapter`/`FrameSettingsRuntimeAdapter`/`LiveRendererRecreation` (commit пересоздания заменяет рендер в слоте). `&mut Box<dyn>` в `&mut dyn` не коэрсится автоматически (компилятор пробует unsize Box) — `renderer.as_mut()` / `&mut *renderer`.
- `render_backend/` — каталог: `selection.rs` (чистая `select_renderer(profile, &[CandidateProbe], RendererStartupMarker) -> RendererSelection::{Create{family, notice}, NoUsableRenderer}`; уведомления `RequestedFamilyNotBuilt`, `PreferredCandidateSkipped`, `RetryingAfterUnfinishedStartup`; таблица тестов), `wgpu_vulkan.rs` (проба `Usable` до 09, фабрика, ЕДИНСТВЕННЫЙ маппинг `[render.vulkan]` → `SurfacePresentSettings`), `mod.rs` (`create_renderer(family, RendererCreateRequest{window, vulkan, initial_color: RendererInitialColor::{CommittedConfig, RendererDefaults}})`, `create_startup_renderer`). Профиль `opengles` на старте → wgpu + warn (решение владельца 02); Apply в настройках с opengles → прежний `UnsupportedProfile`. Метки незавершённого старта пока нет (сессия 09).
- `VideoPipelinePlan::{VaapiDmaBuf, FfmpegHostUpload}` = маршрут декода; `diagnostic_label(RendererFamily)` (wgpu — прежние `vaapi-dmabuf-wgpu`/`ffmpeg-host-upload-wgpu`; GLES2 — `*-gles2`), `import_plan()`, `decoder_thread_config()`. Запуск декодера по плану — один `video_pipeline_candidate::start_decoder_backend`.
- Прямой путь (`AppState::install_video_pipeline_plan`): `RendererVideoImportTarget { renderer_family, video_frames }` вместо 4 wgpu-ручек; порядок: старт декодера → prepare → `set_video_backend` → install (отказ install — типизированная ошибка-инвариант).
- Кандидаты: слот обобщён по ОДНОМУ `RendererImport` (production — `PendingVideoImport`); драйвер `RendererCandidateVideoPipelineResourceDriver::new(&dyn RenderShell)` берёт подготовщик и семейство; `commit_installed` отдаёт `CommittedVideoPipelineCandidate{backend_kind, renderer_import}`, `AppState::commit_installed_video_candidate(video_frames, ..)` ставит его в рендер (`StrongMediaOpenError::RendererRejectedVideoImport`). Опросы strong open (`poll_prepared_*_media_strong`, same-item, suspended resume, startup, settings rebuild, VOD recovery, local open) протягивают `&mut dyn VideoFrameImport`.
- `RenderablePresentFrame { key: RenderableFrameKey }` (`present_frame()` — аренда из ключа). Субтитры берут размер картинки из `DecodedFrame` ключа (`SubmittedFrameForSubtitles::from_submission(.., &DecodedFrame, ..)`).
- Guardrail (02): обычные зависимости app-egui без `wgpu*`/`ash`/`render-wgpu-video`/GL (`APP_EGUI_FORBIDDEN_RENDERER_DEPENDENCIES`; `wgpu`, `render-wgpu-video` — только dev-deps GPU-тестов); в исходниках `render_wgpu_shell` — только `render_backend/` и GPU-тесты, `wgpu::`/`render_wgpu_video::` — только GPU-тесты (`find_app_egui_concrete_renderer_violations`).

## Тесты и conformance
- `cargo test -p render-shell-api --features conformance --locked` (26): fake-рендер `src/tests/fake_shell.rs`, fake-декодер `src/tests/fake_decoder.rs`. Conformance (`render_shell_api::conformance`): 7 проверок — чужой билет; ReusePrevious; Unsupported≠Error; NoVideoBackendBound; освобождение 1 раз; device lost 1 раз; **(02) подготовщик в другом потоке, импорт ставится на выдавший рендер и даёт Ready**. Анти-вакуум: 7 fake-дефектов (+`PreparerStampsForeignOwner`).
- `cargo test -p render-wgpu-shell --locked` (65): conformance на НАСТОЯЩЕМ wgpu без окна (`shell/render_shell/tests.rs`), пиксельный тест «SW-кадр через контракт доходит до цели + повтор ключа берёт привязку из кэша + без видео — чёрный», focused-тесты склада (`video_import/tests.rs`: порядок проверок, Busy/Missing/Fatal, HW-кадр на SW-импорте, чужие ключ/импорт, пересоздание рисует и освобождает 1 раз, чужое семейство, stats). Без Vulkan-адаптера — явный skip в stderr.
- Не ловится conformance: «не раньше, чем GPU дочитал» — wgpu udmabuf-тест, GLES2 — fence (07).
