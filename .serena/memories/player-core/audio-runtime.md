# Player Core Audio Runtime

- S36F3B now enforces bounded packet windows with exact checked rational frame math at `DecodedPcmPacketBoundary` before tempo/history/output. Packet and global/CUE frame ranges intersect in the original decoded frame domain and produce one borrowed slice; fully outside packets decode for codec state but create/write/account no output. Unbounded behavior remains unchanged. See `mem:player-core/exact-pcm-presentation-window-s36f3b-2026-07-25`.

- S36F3A carries `PacketPresentationWindow` through private `PendingAudioPacket` storage and generation/requeue lifecycle to `DecodedPcmPacketBoundary` immediately after PCM decode and before existing global/CUE trim. F3A is transport-only and leaves samples/accounting unchanged; decoder/audio public traits remain unchanged. Exact clipping belongs to F3B. See `mem:media-services/presentation-window-transport-s36f3a-2026-07-25`.

- Audio runtime orchestration is extracted to `crates/player-core/src/session/audio_runtime.rs` under the `session` boundary.
- The module owns internal audio decoder init spec planning, lazy decoder creation from `AudioDecoderFactory`, lazy output creation from `AudioOutputFactory`, audio packet decode/write processing, autoplay audio readiness, seek audio gate classification helpers, audio high-water normalization, audio clock/buffer accessors, `disable_selected_audio_path`, and `init_audio_pipeline`.
- `audio-core` remains the neutral contract boundary. `player-core` still stores factory trait objects and uses `audio_core::AudioDecoderConfig`, `EncodedAudioPacket`, `AudioOutputSpec`, and trait-object output/clock contracts without depending on the concrete `audio` crate.
- Output creation must remain lazy until the decoder returns a decoded audio spec. Unsupported codec factory errors are mapped to `PlayerErrorKind::UnsupportedAudioCodec` and recorded as recoverable when reached through packet processing; output factory/play failures map to `AudioDeviceUnavailable` and remain recoverable in the existing lazy-init paths.
- `session/tick/mod.rs` keeps scheduling/demux admission policy, but pending audio packet processing is implemented by audio runtime through `PlayerSession::process_pending_audio_packets_with_buffer_limit`.
- Focused tests live in `crates/player-core/src/session/tests/audio_runtime.rs`; related audio gate distinction coverage also exists in `session/tests/seek_transaction.rs` and `session/tests/seek_regressions.rs`. Usual verification for this boundary is `cargo test -p player-core audio_runtime`, `cargo test -p player-core audio`, `cargo check -p player-core`, and `cargo fmt --all --check`.

## Тишина перед звуком, начавшимся позже базы часов (03e моста, 2026-10-30, коммит 457f6f58)

- Дефект: первый PCM пустого output-а звучал в `media_clock_base` (старт, цель seek, смена дорожки), даже если его PTS позже → звук опережал видео на зазор до конца/следующего seek (живой стенд: +0,44 с при звуке позже на 0,4 с; +3 с при 3 с).
- `session/audio_runtime/leading_silence.rs::align_audio_segment_start` — ЕДИНСТВЕННАЯ точка между обрезкой и записью PCM (в `audio_runtime.rs`). Чистая `plan_leading_silence(first, expected, rate, LeadingSilencePolicy::SEGMENT_START)` → `LeadingSilence::{None, Pad, TooLarge}` (допуск 20 мс, потолок 1 с); `AudioSegmentStartPlan` — явные ветви. A/V, зазор 20 мс–1 с → тишина того же формата через `write_decoded_audio_samples_at_current_rate` (до tempo, растягивается скоростью); тишина НЕ входит в `written_audio_end`/`note_audio_packet_written`. Ошибка записи тишины фатальна (как запись PCM). Audio-only → без тишины, часы переносятся к PTS первого сэмпла (`StartClockAtFirstSample`), только при зазоре ≤ 1 с (кроме активного seek: базу задаёт commit). Больше 1 с (A/V и audio-only) → `GapAboveSilenceCap`: прежнее «звук в базу» + info-лог — ждёт шага «звук ждёт своего времени».
- Признак отрезка — `pipeline/audio_segment_start.rs` (`audio_segment_awaits_first_pcm`): сбрасывается ТОЛЬКО там, где следующий PCM ляжет в точку привязки — `clear_audio_output_for_seek` (кроме `Err`: старый звук остался в ring), `clear_audio_output` (удаление output: новое media, смена дорожки, TracksChanged rebase), возврат звука после разрыва (`presentation_clock_handover.rs`). НЕ сбрасывается `begin_seek_generation` (выход из скраба без цели не чистит ring) и перепривязками часов (seek commit, rate, recreate). `written_audio_end` для признака непригоден: забывается в `reanchor_audio_clock_media_mapping`.
- Тесты: `session/tests/audio_leading_silence.rs` (18; scrub exit без цели, TracksChanged, ошибка очистки, gap resume, audio-only 3 ч), e2e `pushed-media-source/tests/audio_leading_gap_to_frame.rs` (по записанному PCM; `max_av_offset` дефект НЕ видит).

## Звук ждёт своего PTS (03e моста, 2026-10-30, коммит ac40fee6)

- Первый звук A/V-отрезка дальше базы больше потолка тишины (1 с): `session/audio_gap/scheduled_audio_start.rs`, `SegmentStartAudioSchedule::{NotApplicable, WithinSilenceCap, ScheduledLater, ImplausibleGap}` — видео стартует первым на часах без звука, звук ждёт СЖАТЫМ (output не создаётся, удержание `HoldUntilScheduledAudioStart`), вход в PTS: без output — `join_scheduled_audio_start_if_due` из `resume_audio_after_gap_if_due` (база = позиция показа; до первого PCM база подтягивается к показу — `KeptUpWithPresentation`, задержка старта устройства = пауза видео, не скачок назад); с output (seek посреди игры) — доказательство `SegmentAudioStartsLater` и обычная передача часов разрыва. Ворота старта — `PrerollAudioGate::ScheduledLater`, seek-gate — `scheduled_audio_start_releases_seek_audio_gate` (кроме `WaitingForClear`). Demux удержанным пакетом не блокируется, но запас ограничен тем же 10 с / 8 МиБ (`tick/audio_read_ahead.rs` `HeldAudioBacklogRoom`, не в seek preroll). Пробуждение к PTS удержанного звука — `tick/held_audio_wakeup.rs` (причина `PipelineWorkReady`: `diagnostics.rs` заморожен S42). Смена скорости при удержании применяется (tempo создаст первый PCM). Правдоподобие `classify_audio_start_gap`: звук < конца media и зазор ≤ 1 ч, иначе прежнее поведение + warn. Только static timeline (live — прежнее).
- Audio-only: часы к первому sample при любом правдоподобном зазоре; seek коммитит `FinalSeekCommitPosition::FirstAudioSample` (pipeline `audio_segment_first_sample` — факт только после успешной записи).
- Первый старт, где и кадр, и звук позже базы > 1 с (MPEG-TS ffmpeg, 1,4 с; шкала сырая, `presentation_start` ядро не использует): `start_at_earliest_content_if_late` переносит базу на min(кадр, звук), исход логируется в `runtime_control`. Только первый старт: seek/повтор в 0 у такого TS дают 1,4 с пустоты до кадра (открытый вопрос владельцу).
- Тесты: `session/tests/scheduled_audio_start.rs`, `tick/tests/scheduled_audio_demux.rs`, `audio_gap_clock_handover::seek_into_region_where_audio_starts_later_joins_audio_at_its_pts`, e2e `pushed-media-source/tests/audio_large_gap_to_frame.rs`.
- Не покрыто: звук, который demux ещё не прочитал (разрыв больше ~240 pending video packets), ворота старта ждут; video-only TS с первым кадром на 1,4 с ждёт 1,4 с.

## Звук живого drag-а ждёт commit (D2, 03e, 2026-10-30, коммит e099288c)

Продление живого прохода скраба вперёд (`session/seek_start/live_scrub_forward_extension.rs`) очищало output — PCM, декодированный под прежнюю цель, терялся: дыра или опережение после отпускания (живая приёмка MP4: +0,3…2,6 с). Тесты: `session/tests/scrub_audio_continuity.rs`, `pipeline/tests/audio_segment_written_reach.rs`, e2e `pushed-media-source/tests/scrub_drag_av_sync_to_frame.rs` (симулятор обвязки на паузе после очистки врал про уровень — в тесте обёртка `ClearAwareOutput`).

## Runtime audio track switch (subtitles session 07, 2026-10-16)

`SelectAudioTrack(id)` больше не заглушка: `session/audio_track_switch.rs` валидирует id (только `TrackKind::Audio` текущего media, иначе recoverable `InvalidCommand`, тот же id → no-op без события), `PlaybackPipeline::replace_selected_audio_track` (`pipeline/audio_track_switch.rs`) сбрасывает decoder/output/clock/pending packets и ставит deferred config новой дорожки, затем внутренний accurate seek в текущую позицию (Playing/Paused сохраняются; non-seekable — без seek, якорь no-audio clock; seek/scrub в полёте — присоединение). ## Audio device loss (UX edge cases session 10, 2026-10-06)

- Lazy output init (`ensure_audio_output_for_decoded_spec`) asks the factory for `SelectedOrSystemDefault`; a fallback route publishes `PlayerEvent::AudioOutputSwitchedToSystemDefault(AudioOutputSwitchReason::SelectedDeviceUnavailable { device_name })`. Audio track stays selected. No device at all → old path: `disable_selected_audio_path` + recoverable `AudioDeviceUnavailable`.
- `recreate_active_audio_output(device_request)`: settings device change passes `SelectedOnly` (error goes back to settings rollback, never substituted); recovery passes `SystemDefault`.
- Owner of the reaction: `session/audio_output_recovery.rs`, called on every tick right after `diagnose_audio_output_starvation`. Reads `PlaybackPipeline::audio_output_stream_health()` (`pipeline/audio_output_health.rs`, `None` = no output ≠ failed). Failed → recreate on default + `AudioOutputSwitchedToSystemDefault(ActiveDeviceStopped)`; position is kept (clock reanchored to `current_source_position`). Storm guard `AudioOutputRecoveryBudget`: max 3 attempts, ≥1 s apart, reset only when a fresh output is created for media/track. Exhausted → `disable_selected_audio_path` + `reanchor_no_audio_clock` (video continues on monotonic clock) + recoverable `AudioDeviceUnavailable`. No automatic switch back when the device returns (backlog); next media open tries the saved device again.
- C3 (2026-10-11): PCM queued in the old output ring is lost on recreate (consumer lives in the callback; can't be drained), but A/V sync is kept: `session/audio_output_handover.rs` writes silence of the old `submitted_output_tail` into the not-yet-started replacement output (`prefill_replacement_output_with_silence`, called from `recreate_active_audio_output` before `play`/install). Why: audio clock counts only played PCM (underrun silence does not advance it) and media time = anchor + clock, so the first real PCM written to the new output (PTS `T + tail`) otherwise played at clock `T` → audio led video by the tail (~200 ms) until a seek. Silence keeps the anchor at `T`, puts the first real PCM at clock `tail`, keeps buffer level/EOF-drain tail. Clock semantics unchanged. Write error / partial write → `AudioDeviceUnavailable`, old output untouched. Imprecision: `T` is `current_source_position` (≤ one tick stale); tail with a playback-rate change inside it is taken on the output axis. Same path for settings device switch and device-loss recovery. Tests: `session/tests/audio_output_handover.rs`.
- Tests: `session/tests/audio_output_recovery.rs` (PCM reaches the new output, position, tick wiring, paused, missing saved device, no devices, storm limits, settings strictness); fakes `ScriptedAudioOutputFactoryHandle::{set_devices, device_requests}`, `ScriptedAudioOutputHandle::fail_stream`. App texts: `mem:app-egui/notifications`.

## Audio-aware demux starvation recovery (2026-08-27)

Temporary installed-demux starvation with selected audio now proactively freezes output when usable runway cannot cover remaining retry wait plus the canonically sanitized audio low-water scheduler/callback margin, independently of queued video. Remaining wait uses a fresh post-demux decision timestamp. Any exact current pending retry, including chained TUA after a recovered packet, blocks resume until the next matching accepted source event clears the source-wait fence; then the existing audio+video preroll gate is authoritative. Buffering resume publishes `Playing`/`AudioPlaybackResumed` only after successful output play and clock anchoring; recoverable play failure remains Buffering and is retried by the ordinary preroll lifecycle. Full invariants and tests: `mem:player-core/audio-starvation-buffering-resume-2026-08-27`.


## Wakeup planner: один снимок уровня audio buffer-а (AC-3 бэклог #19, 2026-10-17)

`session/tick/wakeup.rs::worker_wakeup_plan_with_decoder_activity_status` снимает `PlannedAudioBufferLevel::observe(session)` один раз и передаёт его в `immediate_pipeline_work_available` → `pending_audio_work_available` и в `audio_buffer_refill_wakeup_delay`. Причина: CPAL callback уменьшает уровень параллельно planning-у; раньше «работа есть сейчас» читала уровень чуть выше high-water, а refill deadline — уже чуть ниже, оба отвечали «нет», и worker уходил в `CoarseProgress` 250 мс (> 200 мс буфера) → underrun ~50 мс. Сильнее всего на сыром E-AC-3 7.1 с кадрами по 256 сэмплов: уровень после refill всегда в пределах одного кадра над порогом. Инвариант: уровень за проход только падает (пополняет тот же worker после planning-а), поэтому ранний снимок ≥ любых поздних live-чтений (`demux_work_available` читает live — это безопасно). Тест: `session/tick/tests/audio_refill_wakeup.rs` (перебор всех точек пересечения порога между чтениями; падает без фикса на `CoarseProgress 250ms`). Живая проверка: 4 × 50 с, ноль silence padding.

Потолок fallback-а (решение владельца, вариант b): `session/tick/audio_fallback_wakeup.rs::coarse_progress_interval_for_audio_runway` ограничивает интервал `CoarseProgress` (ветки eof-drain и active pipeline в `wakeup.rs`; `SeekOrPreroll`, refill и прочие plan-ы не трогаются) значением `sanitize_audio_high_water_mark(audio_buffer_high_water_mark_ms) × 0.5` (`AUDIO_FALLBACK_WAKEUP_BUFFER_FRACTION`), только пока звук реально тратит буфер: выбран audio track, `pipeline.audio_output_is_playing()` и state `Playing`/`Draining`. Buffering/пауза/нет output-а → настроенные 250 мс; cap только укорачивает. Тесты: `session/tick/tests/audio_fallback_wakeup.rs`; `session/tests/eof_drain.rs::audio_only_eof_after_buffered_samples_keeps_bounded_wakeup_until_drain` теперь ждёт 100 мс.

## Refill wakeup по ритму callback-а (cpu-parity 02b, 2026-10-20)

Правила подпитки (high-water, порция) не менялись; меняется только момент пробуждения. Уровень буфера падает ступенькой в CPAL callback-е, а прежняя формула `уровень − high-water` будила worker до ступеньки (~4 пустых пробуждения на подпитку, `pipeline_work_ready` ~190/с). Теперь:
- `PlannedAudioBufferLevel` (снимок на проход) хранит ещё `AudioOutputCallbackCadence`, читаемый через `pipeline.audio_output_clock()` сразу ПОСЛЕ уровня (callback между чтениями → максимум на период позже, не раньше).
- `session/tick/audio_refill_cadence.rs::audio_refill_delay_above_high_water`: при доверенном ритме будить после k-го callback-а, `k = ⌈превышение/период⌉`, + 1/8 периода на дрожание; опоздавший callback = «сейчас». Прежняя формула, если ритм `NotObserved`, устарел (> 2 периодов), период 0 или > high-water/2.
- Инварианты: при уровне > high-water дедлайн есть всегда (AC-3 #19); пробуждение не раньше ступеньки и не позже `превышение + 1,125 периода`.
- Тесты: `session/tick/tests/audio_refill_cadence.rs` (чистая функция + перебор сетки), `session/tick/tests/audio_refill_wakeup.rs` (через session), вертикальный `worker/tests/audio_refill_wakeup.rs` (реальный wait loop, ступенчатый fake output; test-support `session/audio_drain_test_support.rs`: демуксер на EOF + очередь packet-ов).
- Живой итог: `pipeline_work_ready` 190 → 47/с (HW), 232 → 39/с (SW); отчёт `user/cpu-parity/results/02b.md`. Факт ритма — `mem:audio/core`.

## F4: пауза output-а на конце файла (2026-10-11)

`finish_eof_drain_if_ready` (`session/eof_drain.rs`) перед `Ended` вызывает `park_audio_output_after_eof` -> `pipeline.pause_audio_output_and_capture_clock()` (путь `Pause`). Только после `eof_drain_ready_to_end`, поэтому хвост не обрезается. Ошибка паузы не фатальна (warn). Флаг play-request сброшен, поэтому replay/seek после `Ended` зовут `play` как обычно. Тесты: `session/tests/eof_audio_park.rs`, `audio::output::callback_fill` (`tail_is_played_fully_then_paused_output_is_held_without_underruns`).

## Дыра посреди отрезка (D3, 03e, 2026-10-30)

Курсор отрезка — `pipeline.expected_next_audio_sample_time()` в `FirstPcmWritten` (`pipeline/audio_segment_start.rs`): PTS + декодированные кадры, только растёт, двигается в `note_audio_packet_written`, сбрасывается только `begin_audio_segment`, переживает перепривязки часов и смену скорости. Дыра > 20 мс и ≤ 500 мс — тишина через `align_audio_segment_start` → `session/audio_runtime/mid_stream_gap.rs` (`LeadingSilencePolicy::MID_STREAM`), до tempo, не входит в курсор и `written_audio_end`; audio-only тоже; live нет; перекрытие без обрезки. Больше 500 мс или тишина не влезает в вывод (`silence_output_room.rs`, предел 1,8 с = `MAX_AUDIO_STARTUP_READ_AHEAD_CAP_MS`, растянутая 1/rate) — `audio_gap_ahead` держит по курсору (`AudioGapEvidence::SilenceCannotCloseGap`); на старте отрезка — `ScheduledLater`. Запасная ветка после декодирования — без тишины, warn, не фатально (так же на паузе, в seek preroll, Buffering и у audio-only: склейка с warn). Дыра в pushed fMP4 для тестов — `with_last_sample_extended` (`pushed-media-source/tests/support/media.rs`; полка не подаёт через дыру > 100 мс). Тесты: `session/tests/audio_midstream_gap.rs`, e2e `pushed-media-source/tests/audio_midstream_gap_to_frame.rs`. `audio_runtime.rs` 790 строк — новое отдельными модулями.
