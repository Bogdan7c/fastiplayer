# Player Core

- `player-core` root modules from `src/lib.rs`: `audio_boundary`, `command`, `decoder_boundary`, `diagnostics`, `error`, `event`, `media_opening`, `pipeline`, `render_lease_bridge`, `seek_state`, `session`, `snapshot`, `state`, `worker`, `worker_scheduler`. Tick orchestration lives under the session boundary at `src/session/tick/`; `mod.rs` owns public tick config/result and the main `PlayerSession::tick` loop, while child modules own demux admission, presentation scheduling, decoder I/O, and worker wakeup planning. Root `lib.rs` re-exports the public tick types so external API paths stay unchanged.
- Public/internal player boundary exports include `PlayerCommand`, `PlayerCommandSender`, `PlayerSnapshot`, `PlaybackState`, `PlayerEvent`, `PlayerWorkerEvent`, `PlayerWorker`, `PlayerWorkerConfig`, `PresentFrameLease`, `PlayerPresentFrame`, `PlayerRenderError`, seek types, runtime settings apply contracts (`PlayerRuntimeSettingsUpdate`, `PlayerRuntimeApplyReport`, typed setting/group/outcome ids, `PlayerRuntimeApplyError`), and `video-backend-api` re-exports such as `StartedVideoBackend`/`PresentFrameResourceProviderHandle`. The factory trait lives in `video-backend-api`; concrete backend startup/materialization stays outside the playback crate.
- `PlayerWorker` owns `PlayerSession` on a worker thread. UI sends commands and reads latest snapshot/events; UI must not call `PlayerSession::tick()` directly. Settings committed player updates must use the settings-specific request/reply boundary (`PlayerCommandSender::apply_runtime_settings` or `PlayerWorker::apply_runtime_settings`) so callers receive the real `PlayerRuntimeApplyReport` rather than only command-queue acceptance; queue `Backpressure` and worker `Disconnected` are distinct typed errors.
- `PreparedMedia` is the media-opening boundary. Shell/service opens concrete demuxers and hands `Box<dyn media_core::Demuxer + Send>` plus tracks/duration/seekability to worker.
- `PlayerSession` fields are private; sibling modules outside `session` must use session-owned boundary methods instead of reading session storage. `PlaybackPipeline` owns runtime session slots but is not a data bag. Fields are private; cross-module access inside the session boundary goes through intent methods.
- Key pipeline domains: opened media/demux slots, selected tracks/active video requirement plus expected active `VideoFrameContract`, seek generation/timing, audio decoder/output/clock, packet queues, present queue, present frame/fallback frame, decoder I/O/accounting, render generation/lease accounting.
- Keep `clear_pending_packets_for_seek`, decoder resets, clock resets, render lease accounting, and texture/resource releases as explicit ownership/lifecycle decisions; do not bury them in unrelated helpers.
- Audio decode/output creation is a neutral `audio-core` boundary: `AudioDecoderConfig`, `EncodedAudioPacket`, packet timing, `AudioDecoderFactory`, `AudioOutputFactory`, `PlayerAudioOutput`, and `PlayerAudioClock` live outside `player-core`; `player-core` re-exports the contracts, stores only trait objects/config values, and uses internal missing factories for default/test constructors.
- `AudioOutputFactory` stays `Send + Sync` because it is passed into the worker, but `PlayerAudioOutput` is intentionally thread-local and does not require `Send`: production CPAL output is created inside `player-worker`, then written directly through the trait object to avoid proxy-thread/mpsc copies in the PCM refill hot path. `PlayerAudioClock` remains `Send + Sync` for CPAL callback/worker sharing.
- Video presentation resource lookup is renderer-neutral in `player-core`: `PresentFrameLease` exposes `PresentFrameResourceDescriptor`, `PresentFrameResourceLookup`, `PresentFrameResourceProviderHandle`, and release accounting only. It must not create, return, or re-export `wgpu::TextureView` or WGPU-named public API.
- Rendered texture release path is part of render lease accounting: render bridge reads stable present-frame identity through `PlayerSession::current_present_frame_identity()` and creates leases through `lease_present_video_frame()`, without accessing `PlayerSession::pipeline` directly. Only a `PresentFrameLease` marked as submitted to renderer may later release through the original `PresentFrameResourceProviderHandle`; an acquired but unsubmitted lease must not be forced into GPU-completion release and can use the normal decoder release path.
- WGPU materialization belongs outside `player-core`: `app-egui` selects a concrete app-owned `VideoPipelinePlan` from committed video config plus the last `SystemCapabilities` snapshot, composes concrete backend startup, keeps the `render-wgpu::WgpuFrameTextureViewMaterializer`, and sends only `StartedVideoBackend` / playback-facing decoder handle to `PlayerWorker`. Runtime decoder queue/channel/pool reconfigure follows the same boundary: `app-egui` rebuilds the concrete backend through `AppState`, then `player-core` records the accepted `PlayerVideoDecoderThreadConfig` through `PlayerWorker::apply_runtime_settings`; no `app-egui` code mutates `PlayerSession`, `PlaybackPipeline`, decoder queues, or decoder internals directly.
- Backend startup/resource-provider boundary lives in `video-backend-api`; concrete video backend crates, including `video-vaapi`, must not depend on `player-core` for adapter contracts.
- Closed dependency debt: `player-core` depends on `audio-core`, not `audio`; decoder creation goes through `AudioDecoderFactory` supplied by composition, output creation through `AudioOutputFactory`, and unsupported-codec typed errors remain recoverable without direct Symphonia/Opus/CPAL knowledge. The old direct `player-core -> wgpu` texture-view bridge is closed and must stay closed.
- Closed dependency violations must stay closed: no direct `player-core -> symphonia-demux/webm-demux` opening path, no direct `player-core -> video-vaapi` concrete backend internals, and no new direct `player-core -> render-wgpu` edge.
- Pipeline tests already cover many boundary methods for absent resource/no-op/error/accounting behavior; extend those focused tests when adding new boundary methods. Runtime settings focused tests live in `crates/player-core/src/worker.rs` for accepted tick apply, invalid/unsupported reports, default-volume non-mutation, decoder-thread config acceptance after app-owned controlled rebuild, request/reply response, and backpressure/disconnected distinction; `session/tests/playback.rs` keeps `ReloadConfig` compatibility-event behavior covered.
- Session diagnostics boundary lives in `src/session/diagnostics_sink.rs`: `PlayerSession` owns private `PlaybackDiagnostics`; `record_*`, diagnostics snapshot/log summary, and queue-depth attribution live behind session methods. `snapshot_builder` must use `PlayerSession::diagnostics_snapshot()` instead of reading the diagnostics field. The sink may read pipeline queue/resource snapshots but must not own or mutate pipeline state.
- Active Accurate seek preroll diagnostics are stored in `seek_state::SeekTraceState` and surfaced through `ActiveSeekDiagnosticsSnapshot::accurate_preroll` plus worker stall logs. `seek_transaction` decides when Accurate skip/preroll semantics are active; tick modules only report observed events/counters (demux event kind, skipped audio preroll, total seek video packets sent, pre-target video packets sent, target-or-after video packets sent before landing, decoded pre-target frame drops, decoder/video admission backpressure). `SeekMode::KeyframeBefore` must leave this Accurate diagnostics snapshot inactive.
- Video drop diagnostics keep raw and seek-aware totals separate: `VideoDropCountersSnapshot::total` is all typed removals, `playback_or_render` is non-seek playback/render/pause reasons, and `seek_discard` aggregates `SeekPreroll` plus `StaleGeneration`; UI/user-visible telemetry must not treat raw `total` as ordinary playback drops.
- Session media lifecycle boundary lives in `src/session/media_lifecycle.rs`: it contains `load_demuxer*`, `load_prepared_media*`, `begin_media_open`, `fail_media_open_with_error`, `install_prepared_media`, `mark_media_opened`, `reset_media_state`, demux track-list update handling, and `MediaLifecycleState { pending_autoplay }`. `PreparedMedia` remains the player-core opening boundary; do not add direct player-core dependencies on concrete demux crates. Failed prepared-open errors are recoverable when no active `Opening` request matches, so an existing playback pipeline is not reset or forced to `Failed`; failures of the currently active opening request remain fatal for that opening.
- Session capability selection boundary lives in `src/session/capability_selection.rs`: it owns capability report publication, video requirement validation/refinement, default video selection, explicit `SelectVideoTrack(TrackId)` validation, active requirement refinement after packet probes, stream decode config construction, and codec metadata helpers. `PlayerSession::capabilities` stays private session state; selected video tracks must receive a fresh matching `VideoDecodeRequirement` and, when a decoder is installed, an accepted `VideoStreamDecodeConfig` before `PlaybackPipeline` mutation, or the command is rejected with a typed `PlayerError`. H.264 config adds `VideoStreamPacketization::H264` from `avcC`; H.265 config adds `VideoStreamPacketization::H265` from parseable `hvcC` and rejects missing/invalid `hvcC` as typed `UnsupportedVideoCodec` when packetization cannot be proven from `TrackInfo`. Focused tests live in `src/session/tests/capability_selection.rs`.
- Video decoder stream lifecycle is a neutral `video-core` boundary; see `mem:video-core/decoder-stream-boundary`. `player-core` builds config from `TrackInfo`/active requirement and existing `codec_private`, including the expected `VideoFrameContract`, sends it on media open/default track selection, explicit track select, media switch clear, and backend install/restart, but does not hide seek flush/generation advance/pending packet clear inside configure. `PlaybackPipeline` stores the expected active frame contract derived from the selected requirement; `session/tick/video_decoder_io.rs` validates each current-generation decoded frame against that contract before queueing it, releases the frame handle and reports a typed runtime error on mismatch. This check must remain renderer/backend-neutral: `player-core` does not inspect host-planar bytes, import DMA-BUFs, know VAAPI/WGPU, or decide renderer compatibility.
- Session seek transaction boundary lives in `src/session/seek_transaction.rs`: it owns `PlayerSession` seek/scrub command orchestration, active seek diagnostics, trace markers, commit gates, timeout/fail/finish paths, EOF fallback video position, final seek commit position policy, and the player-side landing-frame guard. `SeekCommitState` carries the original public `SeekMode` so runtime policy stays explicit after container-level mapping: `SeekMode::Accurate` with video may ask the demuxer for a decode-safe point before target, but `actual_position` is only a decoder anchor; playback clocks, audio trimming/gate, video landing-frame guard, resume video budget, and final commit position use the user target, while decoded video frames before target and complete demuxed audio packets ending before target are seek preroll and must not enter normal playback. Active accurate seek uses fast-preroll intent methods owned by `PlayerSession`: demux/tick may temporarily use the existing audio-catchup video packet limit, decoder I/O may bypass only audio-clock decode-ahead for current-generation Accurate seek video packets until the first target-or-after landing frame, because decoder DPB/reorder output may require packets after the user target. This bypass must not bypass texture capacity, packet-channel backpressure, generation/track checks, codec bootstrap, or requirement refinement; texture-capacity bypass remains restricted to matching-generation pre-target packets when the decoder-side output floor applies. Decoded pre-target frames are dropped/released instead of presented, and dropped complete audio preroll does not consume demux packet budget only while a catch-up deadline bounds the scan. If no catch-up deadline is present, dropped audio preroll still consumes normal demux budget so manual/test zero-deadline runs remain bounded. `SeekMode::KeyframeBefore` keeps `actual_position` as the runtime anchor and may commit the actually presented current-generation frame before target. EOF fallback and no-video/audio-only commits stay separate from this guard. `SeekRuntimeState` in `src/seek_state.rs` holds session-owned seek runtime fields (`commit`, trace, simple scrub, EOF fallback marker), while decoder flush, generation advance, pending packet clear, decoder state reset, clock reset, and demux seek remain explicit lifecycle steps at the session boundary.
- Accurate seek decoder output-floor integration (RC3 rollback): `seek_transaction` owns Accurate floor lifecycle and stores only session-level marker `{ generation, floor_pts }` when decoder returns `Applied`/`Unchanged`; `PlaybackPipeline` exposes neutral `set_video_decoder_preroll_output_floor` / `clear_video_decoder_preroll_output_floor` wrappers that preserve `AbsentDecoder`, `Unsupported`, `Backpressure`, and `Fatal` result states. Accurate seek with selected video sets floor after accepted demux seek using the user target PTS and current generation, with `retain_latest_before_floor = true`; `Unsupported`/`AbsentDecoder`/`Backpressure` keep the old player-side pre-target decoded-frame drop/fallback path, while `Fatal` becomes a runtime decoder error instead of silently continuing. Floor is explicitly cleared on final commit, timeout, replacement seek, media reset, and backend replacement. `session/tick/video_decoder_io.rs` may bypass texture-capacity backpressure only for matching-generation pre-target Accurate preroll packets with decoder-side floor applied; packet channel backpressure, stale generation, track validation, codec bootstrap/refinement, and in-flight accounting remain unchanged. `VideoDecoderDiagnosticEvent::SeekPrerollFrameSuppressed` increments existing Accurate `decoded_pre_target_frames_dropped` only for active matching generation. The old RC3 landing-preview scheduler branch is removed: during active Accurate gate-wait with an empty present queue the scheduler repeats the current pre-seek present frame until a target-or-after frame arrives; near-EOF fallback presenter/commit path remains separate and still waits for decoder drain.
- `PlayerSession` unit tests are split out of `crates/player-core/src/session.rs` into `crates/player-core/src/session/tests/`: `mod.rs` holds shared imports/module wiring, `test_support.rs` holds shared fakes/builders, and domain files cover audio runtime, media lifecycle, seek regressions/transactions, decoder boundary, scrub, playback, EOF drain, capability selection, and seek trace behavior.
- `session/tick/demux_admission.rs` owns demux/audio priority policy and distinguishes video capacity from selected-audio bootstrap/catch-up/read-ahead: selected audio without output may demux until the first pending audio packet, selected audio with output above high-water blocks demux even when the pending audio queue is empty, low-water catch-up can still read through bounded video packet pressure, and video-only present queue backpressure remains unchanged.
- `session/tick/presentation_scheduler.rs` owns present/drop/repeat, scheduler timing diagnostics, present queue/decode-ahead limit helpers, and bounded adaptive catch-up; it must preserve 24/30/59.94 frame timing, late-drop grace, seek preroll fallback, and video-only present queue pressure.
- `session/tick/wakeup.rs` owns `PlayerWorkerWakeupPlan` and read-only worker wakeup planning. `PlayerWorkerWakeupPlan` includes `wait_for_decoder_activity` as an intent flag for worker-side event waits. Decoder readiness must not schedule `Duration::ZERO` merely to poll decoder progress during active Accurate preroll; it uses a bounded non-zero `DecodeReadiness` fallback (or an earlier audio/frame deadline) and sets the activity-wait flag only when the pre-snapshotted neutral decoder activity status is available. `PlayerSession::worker_wakeup_plan_with_decoder_activity_status` is the internal boundary that lets `PlayerWorkerRuntime` snapshot decoder activity before planning, then attach/use that snapshot only if the final plan still requests `wait_for_decoder_activity`. Worker timed waits keep command/shutdown priority with `select_biased!`, check `activity_since(last_observed_epoch)` before entering select to close the lost-wakeup window, update the observed epoch only on `ActivityReceived`, drain stale `NoNewActivityAfterEpoch` pulses without moving the original absolute playback deadline, and disable the current activity source after fatal/disconnected notifier so the same ready-disconnected receiver is not selected in a tight loop. Legitimate zero wakeups remain reserved for front-frame-ready, real pending audio/video/demux work, and state-machine work that can progress immediately. EOF coarse progress and worker wakeup fairness must stay intact.
- Session decoder I/O scheduler lives in `src/session/tick/video_decoder_io.rs`: it owns stateless decoder-boundary orchestration for draining decoder diagnostics/errors, completed packet acks, decoded frame intake, pending video packet send, bootstrap/keyframe gating, stale-generation drops, and packet-level requirement refinement. Callers pass typed `VideoDecoderIoLimits`/`VideoDecoderIoContext` built from tick config; seek lifecycle remains session-owned and decoder I/O must use session boundary methods for seek trace/gates and existing frame/texture release helpers. H.264 and H.265 bootstrap after seek/flush require codec-aware decode-start proof: `PacketKeyframe::Unknown` stays in dropped-until-keyframe/preroll state and must not be converted into a decoder keyframe hint unless the active codec policy has explicitly allowed that packet. H.264/H.265 packet-level requirement refinement must pass track `codec_private` through the `PlayerSession::video_codec_private_for_track` boundary into `codec_core::probe_video_packet_requirement_with_codec_private`; MP4/MKV length-prefixed packets must not be probed as raw bytes without `avcC`/`hvcC`, because length prefixes can look like AnnexB start codes and cause false profile/packetization failures. Focused regression tests include H.264 codec-private refinement tests plus `h264_unknown_keyframe_bootstrap_packet_waits_for_codec_proof`, `h265_unknown_keyframe_bootstrap_packet_waits_for_codec_proof`, and `unknown_keyframe_bootstrap_packet_is_sent_as_decoder_decode_start`.
- Session EOF drain boundary lives in `src/session/eof_drain.rs`: `PlayerSession` owns private `EofDrainRuntime` and exposes intent methods (`is_eof_draining`, `eof_drain_needs_progress`, `enter_eof_drain`, `start_eof_audio_tail_if_needed`, `finish_eof_drain_if_ready`). Entering EOF drain does not immediately flush or drain the decoder if player-side video tail is still queued: `PlayerSession` first sends already-demuxed pending video packets, waits for decoder in-flight packet ACKs, then starts decoder EOF/DPB drain through the video-core boundary without seek flush, generation advance, or new demux reads. Decoder tail frames continue through normal decoded-frame intake, and EOF completion remains blocked until the decoder reports `Drained` for the current seek generation. It transitions `Draining -> Ended`, keeps the demuxer open for seek/replay from `Draining` and `Ended`, and uses replay seek-to-zero with `PlaybackResumeIntent::Play` for direct Play from EOF.
- `TogglePlayback` treats active states (`Playing`, `Buffering`, `Seeking`, `Draining`) as pause requests; this prevents audible EOF audio tail in `Draining` from becoming replay, while `Ended` still toggles to replay seek-to-zero.
- `PlaybackPipeline::audio_eof_drain_state()` is the boundary for EOF audio tail policy. It distinguishes no selected audio, pending audio packets, absent output, output draining, drained output, and whether output play was already requested.
- During `Draining`, `session/tick/mod.rs` continues processing pending audio packets, sends already-queued video packets to the decoder, drains decoded/video-present queues, and must not read new demux packets after EOF. Active seek EOF fallback remains owned by seek commit logic.
- EOF drain depends on worker wakeup fairness: render feedback events must not slide an already-planned playback deadline forward. `PlayerWorkerRuntime::wait_for_worker_wakeup_with_timeout` preserves the absolute `PlannedWorkerWakeup` deadline while draining render feedback, otherwise continuous redraw can starve coarse EOF/audio-tail ticks.
- Audio-only playback must not rely on the coarse 250 ms worker fallback while the output buffer is above high-water. `session/tick/wakeup.rs` schedules an audio refill wakeup for the moment `audio_buffer_level_ms` reaches the high-water mark, so CPAL does not drain into underrun before demux/decode can refill the ring buffer.
- EOF `Draining` with pending audio packets is still audio refill work even though demuxing is inactive. `session/tick/wakeup.rs` must keep scheduling the refill deadline from current output buffer level for the queued audio tail, while preserving the invariant that `PlayerSession::tick` does not read new demux packets after EOF.
- Video-only EOF drain must keep using the no-audio monotonic media clock. `presentation_clock_position_at` lets `Draining` without active seek use the monotonic fallback, so queued tail video frames become presentable and the session can reach `Ended`.
- EOF completion has a defensive stale-output fallback: after player-owned queues are empty, a positive audio output buffer can be treated as drained only if the audio clock has stopped moving for `audio_stall_timeout`. This is not the confirmed root cause of the 2026 EOF/replay bug; the confirmed audio root cause was worker wakeup starvation.

- Capability selection must include selected track display orientation when building `VideoStreamDecodeConfig`. `player-core` only transports `VideoDisplayOrientation` from `TrackInfo.video.orientation` into the neutral decoder config and diagnostics; it must not apply renderer-specific rotation or inspect container matrices directly.
- Session E hardware Accurate seek validation on Intel i965 confirmed the current seek policy resumes and commits after all parsed manual seeks on H.265/VP9/H.264 stress assets, with target-or-after presentation and no never-resume case. Residual latency risk remains outside the player-side commit guard: heavy/random seeks can still stall on decoder output for roughly 0.5-2.0 s, so future seek-policy work should distinguish decoder-output latency from reclaim/backpressure failures before changing commit or fallback semantics. Session F narrowed one player-side latency source: active Accurate seek now keeps feeding the target-or-after DPB/reorder tail without audio-clock decode-ahead pacing until the first landing frame, and worker WARN diagnostics include total/pre-target/target-or-after seek video packet counters to prove whether delay is feed starvation or decoder throughput/long-GOP distance.
