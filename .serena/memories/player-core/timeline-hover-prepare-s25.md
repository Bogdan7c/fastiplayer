# Player Core Timeline Hover Prepare S25/S28

- S25 adds `PlayerSnapshot.timeline_hover_prepare: Option<TimelineHoverPrepareSnapshot>` as a read-only, player-owned guard/context DTO for app-side hover prepare/preview lookup. It carries selected video/audio track selection, video track timebase, source/backend revision guards, next SeekLanding-compatible scrub generation, and exactness policy. It does not change public `PlaybackState` and does not give app ownership over playback/session internals.
- `TimelineHoverPrepareSnapshot::target_pts(position)` and `TimelineHoverPrepareSnapshot::target_bucket(target_pts)` are the shared app/player helpers for prepared working-set keys. S17 `prepared_seek_landing_bucket` delegates to this helper so HoverPreview borrow and SeekLanding promotion use matching bucket semantics.
- `player-core` remains the only owner of prepared branch promotion/removal and SeekLanding commit/release semantics. App-side HoverPreview only borrows cloned `VideoFrameLease`s via `PlayerTimelineHoverPrepareHandoff::borrow_prepared_frame`; promotion still happens through `PreparedSeekLandingRuntime::promote_for_seek`.
- S28 adds a named hover-session cleanup boundary on `PlayerTimelineHoverPrepareHandoff`: `release_hover_owned_entries_for_session_end(reason)` delegates to the neutral working set and returns primary/recent release counters. `app-egui` uses this only after timeline hover leave grace ends or is cancelled by a non-timeline action/click. It must not be used for SeekLanding promotion/commit; promoted SeekLanding resources are already removed from hover storage and remain transaction-owned until player-core finishes/demotes/releases them.
- Current source/backend revisions are still the existing untracked S17 constants until a future real source/backend revision provider is introduced. If those guards become real counters later, update both the snapshot builder and prepared seek helper together.
