# Playback Rate Command/Snapshot + S34 No-Audio Clock Groundwork

- S32 gate decision remains: playback rate V1 uses the existing async `PlayerCommand` queue. Do not add a request/reply public command path just to surface `SetPlaybackRate` rejects.
- S33 landed command/snapshot groundwork. S34 added internal no-audio video clock/scheduler groundwork. Playback rate is still not a shipped user-facing feature until audio tempo/timestretch and minimum ship path land.
- Do not expose UI, desktop/MPRIS, external controls, TOML, Settings metadata, persistent default, or media-history restore from this groundwork. Release remains blocked until S37 `timestretch` tempo path passes the minimum ship bar.
- Public value boundary: `PlaybackRate` is a validated newtype exported by `player-core`. Inclusive range is `0.25x..=4.0x`; `PlaybackRate::new` rejects NaN/infinity as `NotFinite`, zero/negative as `NonPositive`, below-minimum, and above-maximum. `PlaybackRate::NORMAL`/`Default` is `1.0x`.
- `PlaybackRate` owns crate-internal checked/saturating conversion helpers between wall-clock deltas and media deltas. Keep positive future scheduler deadlines from collapsing into `Duration::ZERO` spin.
- Public command/read model: `PlayerCommand::SetPlaybackRate(PlaybackRate)` and `PlayerSnapshot.playback_rate`. Default worker/session snapshot stays `1.0x` for behavior parity.
- Command outcome boundary: `PlayerSession::dispatch_command` returns `PlayerResult<PlayerCommandOutcome>`. `Err` remains fatal/runtime failure; semantic rejects are `Ok(PlayerCommandOutcome::Rejected(PlayerCommandReject::...))` and must not go through worker `mark_fatal_error`.
- Current reject type: `PlayerCommandReject::PlaybackRateUnavailableForState { state }`. Worker command handling logs this non-fatally and keeps the session out of `Failed`.
- State gate is exact: `SetPlaybackRate` may mutate `PlayerSnapshot.playback_rate` only in public `PlaybackState::Playing` or `PlaybackState::Paused`. `Idle`, `Opening`, `Buffering`, `Seeking`, `Scrubbing`, `Draining`, `Ended`, `Stopped`, and `Failed` reject without mutating or pre-arming. Do not use `PlaybackState::is_playback_active()` for this gate because it includes `Buffering`.
- No-audio monotonic clock mapping is now rate-aware: `MonotonicMediaClockAnchor` stores media anchor, wall anchor, and `PlaybackRate`; position is `media_anchor + elapsed_wall_time * playback_rate` with saturating arithmetic.
- Playing rate changes re-anchor immediately at the current presentation clock position, then apply the new rate to subsequent no-audio monotonic clock movement. This must not create a seek transaction, demux seek, generation advance, decoder flush, or delayed boundary apply.
- Paused rate changes only update snapshot/current rate for next Play; they must not advance media time.
- Presentation scheduler converts wall present lead into media lead and future media deadline back into wall delay only on the no-audio path. When `PlaybackPipeline::has_audio_clock()` is true, scheduler timing stays audio-clock 1x; S34 must not fake audio tempo support.
- Audio-backed non-1x playback remains incomplete by design until S37. Do not add audio clock mapping/tempo/timestretch inside S34-era player-core code.
- Media-load policy is explicit internal `PlaybackRateMediaLoadPolicy::ResetOnMediaLoad`; every accepted new media open resets snapshot rate to `1.0x`. `PreserveAcrossPlaylist` exists only as an internal future extension point and is not wired to config/UI.
- Focused tests live in `crates/player-core/src/session/tests/playback_rate.rs`, `crates/player-core/src/pipeline/tests.rs`, `crates/player-core/src/session/tick/tests.rs`, and worker direct-path coverage in `crates/player-core/src/worker/tests.rs`. Use `cargo test -p player-core playback_rate` for the narrow S34/S33 check, then `cargo test -p player-core` for the crate check.
