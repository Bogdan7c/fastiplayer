# Playback Rate Command/Snapshot + S37 Audio Tempo Runtime + S38 UI Controls

- S32 gate decision remains: playback rate V1 uses the existing async `PlayerCommand` queue. Do not add a request/reply public command path just to surface `SetPlaybackRate` rejects.
- S33 landed command/snapshot groundwork. S34 added internal no-audio video clock/scheduler groundwork. S35 added the neutral `audio-core` tempo boundary. S36 passed the isolated `timestretch 0.4.0` minimum ship gate. S37 wires the runtime audio tempo path and rate-aware audio clock mapping without adding UI/settings/MPRIS exposure.
- S38 opened the first runtime-only `app-egui` UI surface for playback rate, but desktop/MPRIS, external controls, TOML, Settings metadata, persistent default, and media-history restore remain out of scope unless a later explicit feature session opens those surfaces.
- Public value boundary: `PlaybackRate` is a validated newtype exported by `player-core`. Inclusive range is `0.25x..=4.0x`; `PlaybackRate::new` rejects NaN/infinity as `NotFinite`, zero/negative as `NonPositive`, below-minimum, and above-maximum. `PlaybackRate::NORMAL`/`Default` is `1.0x`.
- `PlaybackRate` owns crate-internal checked/saturating conversion helpers between wall/output-clock deltas and media deltas. Keep positive future scheduler deadlines from collapsing into `Duration::ZERO` spin.
- Public command/read model: `PlayerCommand::SetPlaybackRate(PlaybackRate)` and `PlayerSnapshot.playback_rate`. Default worker/session snapshot stays `1.0x` for behavior parity.
- Command outcome boundary: `PlayerSession::dispatch_command` returns `PlayerResult<PlayerCommandOutcome>`. `Err` remains fatal/runtime failure; semantic rejects are `Ok(PlayerCommandOutcome::Rejected(PlayerCommandReject::...))` and must not go through worker `mark_fatal_error`.
- Current reject type: `PlayerCommandReject::PlaybackRateUnavailableForState { state }`. Worker command handling logs this non-fatally and keeps the session out of `Failed`.
- State gate is exact: `SetPlaybackRate` may mutate `PlayerSnapshot.playback_rate` only in public `PlaybackState::Playing` or `PlaybackState::Paused`. `Idle`, `Opening`, `Buffering`, `Seeking`, `Scrubbing`, `Draining`, `Ended`, `Stopped`, and `Failed` reject without mutating or pre-arming. Do not use `PlaybackState::is_playback_active()` for this gate because it includes `Buffering`.
- No-audio monotonic clock mapping is rate-aware: `MonotonicMediaClockAnchor` stores media anchor, wall anchor, and `PlaybackRate`; position is `media_anchor + elapsed_wall_time * playback_rate` with saturating arithmetic.
- Audio-backed playback is also rate-aware after S37: `PlayerAudioClock::now()` remains stretched output-time progress, and `PlaybackPipeline` owns an explicit audio clock mapping anchor `{ media_position, output_clock_position, playback_rate, output_tail }`. Media position is `media_anchor + (output_clock_now - output_clock_anchor) * playback_rate`. Regression invariant: after re-anchor at `2.0x`, output clock `+1s` maps to media `+2s`, not `+1s`; `1.0x` remains parity.
- Rate-change re-anchor is tail-aware (post-S38 distortion/sync fixes): `reanchor_audio_clock_media_mapping_for_rate_change` reads `audio_output_buffer_level_ms` and stores `AudioClockMappingOutputTail { end_output_clock_position, end_media_position }` — the already written-but-unplayed ring output keeps playing at the OLD rate, so the mapping linearly interpolates inside the tail (exact at both ends, end value taken from the old mapping) and applies the new rate only after the tail ends. Without this the mapping froze a permanent error `tail × (new − old)` per change (compounding across wheel steps). Plain `reanchor_audio_clock_media_mapping` (seek/media base/no buffered output) stays tail-free.
- Playing rate changes re-anchor immediately at the current presentation clock position, update `PlayerSnapshot.playback_rate`, then synchronize the active audio tempo processor through `AudioTempoProcessor::set_segment`. This must not create a seek transaction, demux seek, generation advance, decoder flush, output-buffer-boundary delay, V1 smooth ramp, or output/device flush.
- Paused rate changes update snapshot/current rate and re-anchor the audio mapping at the paused position; they must not advance media time.
- Audio tempo runtime boundary: `player-core` stores only `Arc<dyn AudioTempoProcessorFactory>` from `audio-core`; `app-egui` wires the concrete factory — с 2026-07-09 это `audio_signalsmith::SignalsmithTempoProcessorFactory` (Signalsmith Stretch; смена бэкенда — явное решение пользователя после измеренного shootout, см. `audio/core`). `player-core` must not depend on concrete tempo crates (`audio-signalsmith`, `audio-timestretch`, `signalsmith-stretch`, `timestretch`). `1.0x` startup is direct PCM passthrough; if a tempo processor already exists and rate returns to `1.0x`, `player-core` sets a normal segment instead of clearing the processor so pending processor state is not dropped. Seek/reset/media switch clears the processor; EOF flushes processor tail once before existing output drain.
- Tempo processor warmup priming: the 1.0x passthrough write path records decoded PCM into a bounded (~200 ms) `passthrough_audio_history` in `PlaybackPipeline`; a freshly created tempo processor is primed with that history and the warmup stretched output is discarded (it duplicates already-played media). This closes the phase-vocoder startup-latency click at the first `1.0x -> non-1x` splice. History is spec-keyed `(sample_rate, channels)`, one-shot, and cleared by `clear_audio_tempo_processor` (seek/output clear/media reset). Mid-stream decoded PCM format change flushes-and-drops the old processor pending tail with a warn (output is already recreated for the new spec; old-format tail cannot be written correctly).
- Quality default: `TimestretchTempoSettings::default()` is `SESSION_THREAD_DEFAULT` (`Balanced`, library FFT/hop) because tempo processing runs on the session thread with ring-buffer slack, not in a realtime callback; `LowLatency` (kept as `REALTIME_DEFAULT`) disables HPSS/adaptive phase locking/residual branch and audibly degrades PV quality — it was the main source of "distortion at non-1x" complaints. `AudioOutput::write_samples` now warns when the ring buffer overflows and samples are dropped (previously a silent `try_push` break); `sync_audio_tempo_processor_to_playback_rate` debug-logs set_segment reports (pending output, processor latency) for bounded-tail diagnostics.
- Presentation scheduler converts wall present lead into media lead and future media deadline back into wall delay only on the no-audio path. When `PlaybackPipeline::has_audio_clock()` is true, scheduler timing still uses output-clock deadlines; media position comes from the rate-aware audio mapping.
- Media-load policy is explicit internal `PlaybackRateMediaLoadPolicy::ResetOnMediaLoad`; every accepted new media open resets snapshot rate to `1.0x`, and S38 UI simply displays the reset value from `PlayerSnapshot.playback_rate`. `PreserveAcrossPlaylist` exists only as an internal future extension point and is not wired to config/UI.
