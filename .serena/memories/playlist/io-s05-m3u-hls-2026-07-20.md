# playlist-io S05: M3U/M3U8 dialect и HLS distinction (2026-07-20)

## Ownership и dependency boundary
- Новый workspace crate `playlist-io` — neutral byte-slice-only owner M3U/M3U8 parsing boundary. Он не читает filesystem/network, не делает media probe, не запускает yt-dlp/service, не знает app/player/config и не получает `PlaylistQueue`/stable-ID mutation authority.
- Normal dependencies: `playlist-core` только для существующих ID-less `PlaylistSingleImportDraft`/durable provenance values, `media-core` для `MediaDuration`, `url` для syntax/base/file-URI resolution, `unicode-normalization` для authoritative RFC 8216 NFC check.
- Production modules разделены по ownership: `limits`, `source`, `issue`, `model`, `locator`, `hls`, `m3u`; самый большой `hls.rs` остаётся <500 строк.

## Public boundary
- Единственная entry point: `parse_m3u_document(M3uParseRequest)`; request явно несёт caller bytes, `M3uDocumentSource::{Local,Network}`, `M3uDeclaredFormat::{M3u,M3u8}` и `M3uParserLimits` без hidden defaults/I/O.
- `M3uDocument` различает `Generic(GenericM3uPreview)`, `AdaptiveManifestReference` и `LocalHlsManifestUnsupported`.
- Generic preview возвращает source-ordered ID-less drafts, exact EXTINF hint, bounded `M3uIssueSummary` с exact omitted count и typed item-limit truncation. Дубликаты сохраняются как независимые drafts.
- `M3uDeclaredFormat` отделяет M3U/M3U8 provenance и BOM policy: generic M3U принимает BOM с `Utf8BomIgnored`; generic M3U8 rejected. Любой HLS candidate с BOM rejected независимо от declared family.

## Generic dialect и locator invariants
- Strict UTF-8, LF/CRLF, optional `#EXTM3U`, comments, `#EXTINF:<signed decimal>,<title>` только для следующего locator. Non-negative finite duration становится `MediaDuration`; negative остаётся `M3uDurationHint::Unknown` и никогда не становится playback span/end.
- Local relative paths разрешаются lexical parent-ом document path; native absolute paths сохраняются exact. `file:` допускает только empty/localhost authority, запрещает query/fragment и декодируется через `Url::to_file_path` без `to_string_lossy`.
- Network document relative URI разрешается через parsed base. Absolute hierarchical URI с authority валидируется `url::Url`, но durable reopen identity сохраняет exact caller string (не reserialization/normalization); derived relative URI использует canonical resolved serialization. Opaque/non-network schemes и remote-host file URI дают bounded typed issue. Actual hierarchical scheme admission остаётся app service-registry responsibility.
- `M3uDocumentSource` и downstream draft Debug/error formatting redacted; source userinfo/path/query/fragment не попадают в diagnostics.

## HLS classification invariants
- Content-first candidate scan ищет case-insensitive `#EXT-X-`, затем strict pass выполняется до generic EXTINF interpretation. Поэтому media segment URI физически не могут стать queue rows.
- Strict pass проверяет: no BOM, UTF-8, LF/CRLF only, RFC control-character exclusion, NFC, exact physical first-line `#EXTM3U`, case-sensitive tag grammar, no forbidden whitespace, quote-aware attribute lists, duplicate attribute rejection, singleton-tag rejection, URI/base syntax и required tag→URI association.
- Master/media evidence берётся из RFC tag families до row interpretation; mixed topology rejected typed. Network valid HLS возвращает только `AdaptiveManifestReference`; local valid HLS — только `LocalHlsManifestUnsupported`.
- S05 является classifier/parsing boundary, не full adaptive playback manifest parser. Unknown syntactically valid HLS tags остаются ignored по RFC, а actual segment/key/encryption/live/profile semantics принадлежат будущему HLS service scope.
