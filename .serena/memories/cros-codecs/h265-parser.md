# cros-codecs H.265 parser

- The vendored `crates/cros-codecs-patch/src/codec/h265/parser.rs` parser and `crates/cros-codecs-patch/src/decoder/stateless/h265.rs` decoder are part of the production VAAPI H.265 path even though they live outside first-party codec-core abstractions.
- iOS/Dolby Vision profile 8 MOV files can carry Dolby Vision RPU as HEVC NAL type 62. Treat HEVC unspecified NAL types 48..63 as syntactically valid headers; the stateless H.265 decoder should then ignore them through the existing unknown/other NAL path instead of rejecting the whole packet.
- H.265 slice `num_entry_point_offsets` is stream-dependent and can exceed 32 for 4K/WPP content. `SliceHeader.entry_point_offset_minus1` must stay dynamically sized; do not restore the old fixed `[u32; 32]` storage.
- H.265 RPS diagnostics must validate duplicates among resolved entries in the five RPS lists (`LtCurr`, `LtFoll`, `StCurrBefore`, `StCurrAfter`, `StFoll`) and must not compare syntactic RPS list length with `dpb.entries().len()`. During `decode_rps()`/`derive_and_mark_rps()` the DPB can still legally contain output-only/reorder pictures that were just marked `Reference::None`; they are physically removed only by the later `update_dpb_before_decoding()` path.
- H.265 seek/reset fix on 2026-06-06: `StatelessDecoder<H265, _>::flush()` now resets HEVC picture-order context for a new decode segment (`first_picture_after_eos`, `first_picture_in_bitstream`, `prev_tid_0_pic`, IRAP/RPS/slice-header scratch). In `DecodingState::Reset`, SPS/VPS/PPS are still parsed but no longer resume decoding by themselves; decode resumes only on the current HEVC IRAP NAL. This keeps hvcC parameter-set injection after seek while making CRA samples from iPhone/open-GOP MOV set `NoRaslOutputFlag` and drop following RASL pictures instead of sending VAAPI references to missing pre-seek DPB entries.
- Focused parser tests are in the patch crate: `nalu_header_accepts_unspecified_type_62_for_dolby_vision_rpu` and `slice_header_parses_more_than_32_entry_point_offsets`. RPS duplicate helper tests live in `crates/cros-codecs-patch/src/decoder/stateless/h265.rs`, but direct patch-crate unit testing is currently blocked by pre-existing backend test-support/workspace incompatibilities when the crate is isolated or addressed outside workspace membership; use workspace-level `cargo check -p video-vaapi`, `cargo test -p video-vaapi h265 --lib`, and manual H.265 playback/seek logs for practical verification until that vendored test-support is repaired.
