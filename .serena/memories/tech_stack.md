# Tech Stack

- Static DASH VOD uses first-party `dash-mpd-core` (pure S04X-backed MPD profile) and `web-media-dash` (bounded exact MPD/serialized transport orchestration). Concrete fMP4/WebM parsing remains in the existing Symphonia registrations injected through `demux-api`; no DASH/container parser dependency was added. Player integration is a provider-neutral receipted seek trait in `player-core`. See `mem:media-services/dash-vod-s34-2026-07-24`.

- Language: Rust, workspace edition `2024`, workspace MSRV `rust-version = "1.92"`, Cargo resolver `2`. Development and CI are pinned to Rust `1.96.0`, while CI validates both Rust `1.92.0` (MSRV) and `1.96.0` separately.
- Main UI/window stack: `winit 0.30`, `egui 0.34`, `egui-winit 0.34`, `egui-wgpu 0.34`.
- Render/GPU: `wgpu 29` with `vulkan` feature; production renderer crates are `render-wgpu-video` (pure WGPU NV12/P010 video renderer/materializer boundary) and `render-wgpu-shell` (WGPU device/surface/egui composition shell).
- Media/container/audio dependencies: upstream `symphonia 0.6` with `all-formats`, `all-codecs`, `all-meta`; `cpal 0.15`; `opus 0.3`; `bytes`; `ringbuf`; `crossbeam-channel`; neutral audio contracts live in local `audio-core`.
- Error/log/config stack: `anyhow`, `thiserror`, `tracing`, `tracing-subscriber`, `serde` derive, `toml 0.9`, `directories 6.0`.
- Optional FFmpeg raw binding: `video-ffmpeg` uses `ffmpeg-sys-next 8.1.0` only behind crate feature `ffmpeg` with `default-features = false` and `avcodec`; `video-ffmpeg` itself has empty defaults, but `app-egui` enables its forwarded `ffmpeg` feature by default, so normal workspace/app builds compile the software FFmpeg path and require FFmpeg dev libs/runtime. Opt out with `cargo build -p app-egui --no-default-features` when needed.
- XML stack: first-party `bounded-xml-reader` owns the only untrusted XML parsing boundary and uses `quick-xml 0.41.0` behind project-owned events and mandatory caller-defined budgets; schema/format semantics remain outside this crate. `playlist-io -> bounded-xml-reader` is the intentional XSPF schema-owner edge; XSPF does not depend on `quick-xml` directly. See `mem:xml/core` and `mem:playlist/io-s06-xspf-2026-07-20`.
- Local patches via root `[replace]`: `cros-libva:0.0.12` -> `crates/cros-libva-patch`; `cros-codecs:0.0.6` -> `crates/cros-codecs-patch`; `symphonia-format-isomp4:0.6.0` -> `crates/symphonia-format-isomp4-patch`; `symphonia-format-caf:0.6.0` -> `crates/symphonia-format-caf-patch`; `symphonia-format-mkv:0.6.0` -> `crates/symphonia-format-mkv-patch`; `symphonia-codec-aac:0.6.0` -> `crates/symphonia-codec-aac-patch`; `wayland-scanner:0.31.10` -> `crates/wayland-scanner-patch`. The Wayland patch is a narrow advisory closure that updates its parser dependency from quick-xml 0.39 to 0.41 without migrating winit/egui/window stack. The CAF and Matroska patches are current media-container compatibility owners; see `mem:symphonia-demux/audio-containers-s28c-2026-07-22`, `mem:symphonia-demux/matroska-webm-s28b-2026-07-22`, and `mem:dependency-patches/core`. These are compatibility patches, not app-owned architecture; keep Serena memories and guardrails honest about which patches are still active.
- Local crates are wired through workspace dependencies; crate package `crates/config` publishes as `rustiplayer-config` / lib `rustiplayer_config`.
- Linux config path is `~/.config/rustiplayer/config.toml`; current config schema version is `7`; unknown TOML fields are rejected and validation after serde is mandatory. Legacy schema v2/v3/v4/v5/v6 are migrated on load where supported; generic web-media settings live under `[yt_dlp]`, while legacy `[youtube]` is accepted only through migration. Schema v7 adds optional `yt_dlp.preferred_video_height` with config-owned validation and default `None`; see `mem:config/schema-v7-quality-preference-2026-07-21`.
- SonarQube is local-only for project key `rustiplayer` at `http://127.0.0.1:9000`; scanner imports Clippy JSON from `target/sonar/clippy-report.json`.
