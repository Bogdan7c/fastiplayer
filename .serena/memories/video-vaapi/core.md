# Video VAAPI Core

- `video-vaapi` owns VA display/probe/decode thread, cros-codecs adapters, VA surfaces, DMA-BUF export, neutral `FrameResourcePool`, and VA surface lifetime until renderer/player release. It must stay free of `wgpu`, `wgpu-types`, `ash`, `render-wgpu-video`, `render-wgpu-shell`, and `player-core` direct dependencies.
- Internal codec adapter shell lives in `crates/video-vaapi/src/codec_adapter.rs`. It is not public API. `VaapiVideoDecoder` owns backend-local queues/resource registration and delegates submit/flush/events/stream-info to a boxed internal `VaapiCodecAdapter`.
- Production implemented adapter is VP9 only. It wraps the existing `cros_codecs::StatelessDecoder<Vp9, VaapiBackend<InternalVaapiFrame>>` behavior. H.264 has only a fail-closed stub slot for stream-config validation: it can distinguish missing packetization and invalid profile/bit-depth/chroma/surface metadata, but still returns `BackendUnsupported` for production decode until packet conversion, DPB drain, and zero-copy path are implemented.
- VAAPI stream config validation is centralized through `VaapiCodecAdapterFactory::stream_config_rejection`; `decoder_thread::reject_unsupported_vaapi_stream_config` delegates there. VP9 Profile 0 accepts only 8-bit YUV420/NV12; VP9 Profile 2 accepts only 10-bit YUV420/P010; VP9 Profile 1/3 and future codecs are not production adapters.
- VAAPI probe still records raw VA profiles/entrypoints/RT formats for diagnostics, but advertised `supported_video_decode_formats` are filtered through the implemented adapter matrix. H.264/AV1/H.265/VP8 are not advertised by `video-vaapi` until production adapters exist.
- `capability-core::CapabilityScanner` now filters available backend formats for the final system report by DMA-BUF export plus registered renderer support. This means advertised system decode formats are the production intersection, not raw hardware capabilities.
- Reconfigure/flush cleanup must release only decoder-owned ready frames. Frames already handed to player/renderer remain guarded and must be released through the normal renderer/player release path.
