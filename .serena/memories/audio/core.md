# Audio Core / Concrete Audio

- Concrete `crates/audio` owns CPAL output, concrete `AudioClock`, Symphonia/Opus decoder integration, and adapters to neutral `audio-core` decoder/output/clock traits. CPAL output remains a simple PCM sink; playback-rate/tempo semantics do not belong in `crates/audio`.
- `audio-core::tempo` is the neutral tempo boundary: `AudioTempoProcessor`, `AudioTempoProcessorFactory`, `AudioTempoProcessorHandle = Box<dyn AudioTempoProcessor + Send>`, typed PCM format/frame count/span, `AudioTempoRatio`, `AudioTempoSegment{Id}`, `AudioTempoProcessReport`, `AudioTempoOutputProgressMapping`, and `AudioTempoProcessorError`. Reports keep decoded media input and stretched output distinct: consumed decoded media frames/duration, produced stretched output frames/duration, pending/buffered output inside the processor, processor latency, effective ratio, and segment id. `AudioTempoProcessor::set_segment(AudioTempoSegment)` is the dynamic ratio boundary; it changes the active segment without recreating the processor or producing output samples. `PlayerAudioOutput::write_samples` device tail is not processor latency and must stay owned by output/clock accounting.
- `audio-timestretch` is the concrete `timestretch 0.4.0` adapter crate and runtime factory (`TimestretchTempoProcessorFactory`). It owns `timestretch::StreamProcessor` state, converts project `AudioTempoRatio` by inversion (`2.0x` playback -> `0.5` backend stretch; `0.5x` -> `2.0`), exposes caller-preallocated `process_decoded_media_into`, implements the neutral trait/factory for runtime wiring, reports backend latency/capacity through neutral frame counts, and keeps `audio-core`/`player-core` free of concrete `timestretch`. For realtime profile use `QualityMode::LowLatency` plus FFT 1024 / hop 256; in `timestretch 0.4.0` the enum alone does not reduce FFT/hop, and the S36 test keeps latency <= 40 ms. Known limitation: Context7/README mention fixed-buffer `process_interleaved_into`/`flush_interleaved_into`, but published crates.io `0.4.0` source lacks them; use preallocated `process_into` for V1 unless a future backend/API decision changes this.
- S37 runtime integration: `app-egui` wires `audio_timestretch::TimestretchTempoProcessorFactory` into `PlayerWorkerConfig`; `player-core` stores only `Arc<dyn AudioTempoProcessorFactory>`, creates a processor between decoded PCM and `PlayerAudioOutput` for non-1x playback, and keeps clean 1.0x startup as direct PCM passthrough. If a processor already exists and rate returns to 1.0x, player-core updates the segment to `AudioTempoRatio::NORMAL` rather than clearing it, so buffered processor state is not dropped silently. Seek/reset/media switch clears the processor; EOF flushes the processor tail once before the existing output drain.
- `PlayerAudioClock` remains output-time progress: it reports stretched output/device playback time, not decoded media duration. `player-core` owns the explicit output-clock-to-media-clock mapping anchor and scales output-clock delta by the current `PlaybackRate`. Regression invariant: after re-anchor at `2.0x`, output clock `+1s` maps to media `+2s`; at `1.0x` behavior stays unchanged.
- Dynamic playing rate changes re-anchor the audio clock mapping at the current media position, then call the neutral `set_segment` on the active tempo processor immediately. They must not create a seek transaction, delay until an output-buffer boundary, smooth-ramp in V1, or flush already submitted output/device audio. Already submitted device/output tail remains bounded tail behavior, separate from processor pending output/latency.
- Direct concrete `timestretch` dependencies remain forbidden in `audio-core` and `player-core` by `scripts/check-refactor-guardrails.py`; concrete tempo wiring belongs at the app composition boundary.
- `AudioClock::samples_played` is buffer/accounting state: it counts interleaved samples pulled by CPAL callback and may include a callback buffer that is not audible yet.
- `AudioClock::now()` / `PlayerAudioClock::now()` must return stable output-time progress based on CPAL playback anchors plus `last_stable_played_samples`; seqlock write/conflict/no-anchor fallback must never return raw `samples_played` from the fresh callback end.
- Player scheduling must not compensate for audio future jumps in `player-core/tick`; the clock invariant belongs in `crates/audio`, while media-time mapping belongs in `player-core`.
- Silence/underrun callbacks may extend output duration for timestamp chaining, but media clock must clamp to real filled audio samples and not advance into silence.
- Focused clock tests live in `crates/audio/src/clock.rs` and cover unfinished anchor write, generation conflict fallback, normal interpolation, reset, legacy `record_played`, and silence tail behavior. Tempo/runtime focused tests live in `crates/audio-core/src/tempo/tests.rs`, `crates/audio-timestretch`, and `crates/player-core/src/session/tests/audio_runtime.rs` / `playback_rate.rs`.
