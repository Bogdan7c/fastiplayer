# MPEG-TS Demux Core

## S29 production contract (2026-07-22)

- `crates/mpeg-ts-demux` — first-party container owner без Symphonia/FFmpeg/HLS/network dependencies. Он реализует только S00 profile-required 188-byte MPEG-TS; 192-byte M2TS явно unsupported до отдельного evidence.
- Factory identity: container `mpeg-ts`, extension `ts`, MIME `video/mp2t`; supported neutral inputs — seekable `ByteSource`, sequential byte stream и ordered segments. Probe использует bounded signature/resync и не доверяет extension сильнее content.
- Parser modules владеют framing/resync, PSI PAT/PMT+CRC/version, fail-closed single playable program selection, per-PID continuity/PES, independent 33-bit PTS/DTS unwrap, PCR (включая отдельный PCR PID), elementary packetization, video AU assembly и VOD index. Gap/TEI/discontinuity сбрасывает только affected PID; corruption не превращается в EOF; scrambling — typed fatal.
- Supported elementary types: H.264 0x1b, H.265 0x24, AAC/ADTS 0x0f, MPEG audio 0x03/0x04 с frame-header classification MP1/MP2/MP3, AC-3/E-AC-3 (с 2026-10-16, см. ниже). LATM/subtitles/SCTE и прочий private 0x06 вне profile.
- Video AU assembler bounded через typed `video_access_unit_bytes`, сохраняет AU/config/VCL через PES boundaries и публикует только complete AU. H.264/H.265 parsing/keyframe/config semantics reuse `codec-core`; tracks advertise `media_core::VideoPacketFraming::AnnexB`.
- Lifecycle: PMT/config/in-band или ordered discontinuity публикует `TracksChanged` до зависимого packet. `OrderedSegmentDiscontinuity::StartsNewTimeline` — explicit transport→demux boundary.
- Seekable local input строит capped sparse PCR/keyframe index ограниченным initial window; seek может расширить его ровно одним bounded cancellation-aware on-demand window. Scan error/cancel transactional rollback-ит reader/parser playback state; successful partial progress сохраняет continuation. Повторный seek может продолжить; uncovered target возвращает typed unavailable.
- App local-file production composition живёт в `app-egui::local_media`: один уже открытый `LocalFileSource` передаётся app-owned registry с Symphonia + MPEG-TS factories. Signature открывает `.ts`, extensionless и conflicting-extension TS; source cancellation, fingerprint и final revalidation остаются one-handle/typed. Web/HLS/network composition не входит в S29.
- Neutral framing migration: `VideoPacketFraming::{Unspecified, AnnexB, LengthPrefixedFromCodecConfiguration}` принадлежит `media-core`; player-core переводит evidence в codec-core packetization. Symphonia маркирует avcC/hvcC rows length-prefixed; container guessing и fake hvcC запрещены.
- Hermetic generated fixture suite покрывает muxed/audio-only, H.264/H.265, AAC/MPEG audio, arbitrary chunks, CRC/version/multi-program, gaps/duplicates/TEI/scrambling/resync, PTS/DTS/PCR rollover, AU/PES splits, config lifecycle, ordered/in-band discontinuity, bounded/cancelled seek/index and local prepare/rebuild. No checked-in real media fixture.
- Проверки S29: 35 mpeg-ts tests; media-core 36; demux-api 27; player-core 571; symphonia-demux 163; focused app local tests; strict Clippy; Rust 1.96/1.92 workspace checks; fmt/diff/refactor guardrails. Dependency report keeps pre-existing unmaintained advisories for audiopus_sys/ttf-parser; S29 adds no external runtime dependency.


## Ordered-segment PES/AU flush invariant (2026-08-05)

- На каждом новом ordered TS resource предыдущий segment сначала проходит тот же strict PES/AU finalization, что clean EOF, и только затем очищается transport-local continuity/PAT/PMT/PES state. Это не даёт continuity restart-у молча уничтожить последний video RAP segment-а.
- Finalization остаётся fail-closed: incomplete declared PES возвращает typed `MpegTsDemuxError::Malformed` до публикации video packet-а; повреждение не превращается в clean EOF. Explicit discontinuity не склеивает соседние epochs: предыдущий flush завершается до reset/lifecycle следующей timeline.
- Focused owner proof требует оба RAP (0s и 1s) от двух independent ordered segments со стабильными tracks и отдельно проверяет rejection truncated PES без packet publication.
- HLS grouped VOD использует этот owner boundary для decode-safe tail restart; HLS не пытается самостоятельно собирать PES/AU.
- Проверка 2026-08-05: `cargo test -p mpeg-ts-demux` — 37/37; affected all-target Clippy `-D warnings` и Serena diagnostics — PASS.


## Resource-bounded ordered-segment initial probe (2026-08-24)

- Default initial probe остаётся 4096 TS packets для generic/local/stream input.
- Additive `MpegTsDemuxOptions::with_initial_probe_byte_budget(NonZeroUsize)` принадлежит MPEG-TS owner-у и переводит validated resource bytes в целые 188-byte packets с округлением вверх.
- HLS composition передаёт `AdaptiveTransportLimits::maximum_segment_bytes`; это позволяет дочитать topology evidence до конца уже bounded segment-а, когда один AAC PES перемежается тысячами video packets.
- Cutoff посреди declared PES нельзя путать с EOF/corruption: раньше strict finalization корректно отвергал неполный PES, но неполноту создавал сам probe. Настоящий truncated resource по-прежнему fail-closed.
- Functional owner test сначала воспроизводит failure прежнего default cutoff, затем доказывает video+audio packet playback с resource budget. Полный runtime evidence: `mem:media-services/hls-ts-resource-bounded-initial-probe-2026-08-24`.

## AC-3 / E-AC-3 (2026-10-16)

- PMT: `src/psi_descriptors.rs` владеет ES descriptor loop и классификацией. AC-3 family = ATSC `0x81`/`0x87` либо DVB private `0x06` с `AC-3_descriptor 0x6a` / `enhanced_AC-3_descriptor 0x7a` / registration `0x05` `AC-3`/`EAC3`. Один `StreamKind::Ac3Syncframes`; точный codec id (`A_AC3`/`A_EAC3`, как у `symphonia-demux` track mapper) доказывает bsid syncframe-а (E-AC-3 под 0x81 → `A_EAC3`). Дескрипторы читаются только у candidate stream_type (`is_candidate_stream_type`); дескриптор, вылезающий за ES_info loop, — `Malformed` (fail-closed). `ISO_639_language_descriptor 0x0a` → `TrackLabels.language` для всех дорожек TS (первая запись, только печатаемый ASCII). `StreamKind::{is_video, is_audio}` заменили `matches!` в demuxer-е.
- Нарезка: `src/ac3_elementary.rs` поверх `mem:ac3-syncframe/core`: до первого syncframe-а (старт/seek/сброс PID-а, `SyncframeAlignment::SearchingFirstSyncframe`) мусор и висящие dependent-ы пропускаются; после захвата повреждение → ограниченный ресинк (см. «Пакет I» ниже), не `Malformed`. Пакет = основная программа AU (substream 0 + dependent-ы); доп. программы 1–7 не попадают в пакет. channels = presentation count (5.1+Lrs/Rrs = 8). E-AC-3 AU ждёт следующий заголовок → последний пакет публикуется в `finish_pending_audio` (EOF/конец segment-а, `EndOfStream`); оборванный хвост → ragged `Malformed`.
- Аудио-путь вынесен в `src/demuxer_audio.rs` (`#[path]`-подмодуль `MpegTsDemuxer`, лимит 800 строк). PTS: `AudioAccumulator.pes_anchors` — позиция начала payload-а каждого PES; кадр получает PTS последнего PES, начавшегося не дальше его первого байта (ISO 13818-1 §2.4.3.7), иначе цепочку длительностей. Применяется ко всем аудио кодекам (ADTS/MPEG тоже: раньше PES PTS терялся, если буфер не был пуст → у E-AC-3 с lookahead таймлайн уплывал ~0.7 тика/кадр при 44.1 кГц). Drain-функции не мутируют буфер: `AudioFrameDrain { frames: Vec<BufferedAudioFrame{buffer_offset, packet}>, consumed_bytes }`, буфер и якоря сдвигает `consume` (прижатые к нулю якоря схлопываются).
- Попутный root-cause фикс `src/pes.rs`: `PesAssembler::push` больше не копит continuation без увиденного payload_unit_start (seek на PCR anchor посреди PES, старт live посреди PES, сброс PID-а). Раньше seek в ffmpeg-TS ронял поток `PES start code/header absent` (воспроизводилось и с AAC).
- Тесты: `src/tests/ac3_elementary.rs` (ручные потоки: DVB 0x6a без registration + язык, teletext 0x06 игнор, разрез по PES с якорями PTS, dependent/доп. программа, bitstream-codec под 0x81, resync, мусор, обрыв), `src/demuxer_audio.rs` (якоря), `src/pes.rs` (continuation), `src/psi_descriptors.rs`; `tests/ac3_transport_stream.rs` на ffmpeg-фикстурах `tests/fixtures/ac3/` (`generate.sh`, README: ATSC AC-3/E-AC-3 + H.264, DVB System B AC-3/E-AC-3 audio-only с языком) — codec/rate/channels/language, пакеты = целые syncframe-ы, PTS шаг кадра, seek в локальном файле.
- Пакет I (2026-10-17), ревью-фиксы:
  - Смена формата AC-3 посреди потока (вещательный 2.0↔5.1, смена частоты, даже AC-3↔E-AC-3 на одном PID-е) НЕ публикует `TracksChanged`: `demuxer_audio.rs` `audio_evidence_policy` → `AudioEvidencePolicy::FirstFrameDefinesTrack` для `Ac3Syncframes` (ADTS/MPEG audio — по-прежнему `FollowEveryFrame`). Причина: `TracksChanged` в player-core = seek-подобный сброс (видео ждёт IDR, выбор дорожки → default), а decoder семейства сам декодирует каждый кадр в его формате и player-core пересобирает output по decoded spec-у. Метаданные дорожки = формат ПЕРВОГО кадра и тихо не обновляются (player-core сравнивает копию списка дорожек с маркером seek-а).
  - Потеря синхронизации AC-3 посреди потока больше не fatal: `ac3_elementary.rs` `Ac3SyncState` (alignment + `discarded_since_last_frame` + `lost_sync_count`, warn-лог) возвращается к поиску следующего проверенного syncframe-а; предел подряд отброшенных байт без кадра `MpegTsDemuxOptions::ac3_resync_bytes` (default 256 KiB) → typed `MpegTsDemuxError::Ac3SyncLost{pid, discarded_bytes, limit_bytes}`.   - PMT: битый ES descriptor loop не роняет PMT (`psi_descriptors::recognize_elementary_stream`): самоописывающий stream_type играет без языка, private 0x06 → нераспознан; битый program loop → `StreamTypeRegistry::Standard`. Оба случая — `warn!`.
  - Blu-ray: program registration `HDMV` (`stream_type_registry`) → stream_type 0x84 = AC-3 family (DD+ = AC-3 ядро + E-AC-3 dependent); вне HDMV 0x84 только с явной AC-3/EAC3 сигнализацией. 0xA1 (secondary audio, микшируется с основным) намеренно не играется. M2TS 192 по-прежнему unsupported.
  - `tracing` добавлен в зависимости crate-а (и в `MPEG_TS_DEMUX_ALLOWED_DEPENDENCIES` guardrail-а) для диагностики восстановимых повреждений.
  - Тесты: `tests/ac3_broadcast_format_switch.rs` (ffmpeg-фикстура `ac3-broadcast-2p0-5p1-2p0-48k.ts` = склейка `audio/tests/fixtures/ac3/tones-{stereo,5.1,stereo}.ac3`; byte stream и local file: 0 `TracksChanged`, 48 пакетов 2/6/2 канала, PTS шаг 2880), `src/tests/ac3_stream_recovery.rs` (bit-flip синхрослова, мусор внутри PES → кадры до следующего PES отброшены, мусор за пределом → `Ac3SyncLost`, AC-3→E-AC-3 без lifecycle), `src/tests/ac3_elementary.rs` (битые descriptor loop-ы, HDMV 0x84), unit-тесты в `psi_descriptors.rs` и `demuxer_audio.rs`. - Ограничения: PES без PTS по-прежнему `Malformed` (spec допускает PES без PTS, если в нём не начинается кадр); fatal ошибка `next_event` возвращается раньше очереди, поэтому последний E-AC-3 AU перед оборванным хвостом теряется вместе с ошибкой. ## Seekable вход играет с начала (2026-10-16, пакет G)

- Root cause: `open` читал PAT/PMT/первые PES до `initial_topology_ready`, затем `build_bounded_initial_index` сбрасывал elementary state и `pending_events` и возвращал reader на позицию КОНЦА probe-а → всё до неё молча терялось (первый video RAP, первые аудиокадры; короткий файл, целиком в окне probe/scan, не отдавал ни одного пакета — так было и с AAC через production local registry). HLS/stream путь не затронут (index строится только для seekable).
- Фикс: `open` запоминает `playback_start_offset = reader.position()` до probe и передаёт в `build_bounded_initial_index(playback_start_offset)`; после scan reader возвращается туда. PSI/track evidence сохраняется, elementary state сброшен — пакеты probe-области переигрываются.
- Тесты: `src/tests/seekable_playback_start.rs` (seekable == forward-only по каждой дорожке; файл в окне probe и частичное окно `seek_scan_packets=4`; мутация «resume с конца probe» их роняет). Порядок пакетов РАЗНЫХ дорожек при финальном EOF-flush недетерминирован (HashMap PID-ов) — сравнивать по дорожкам. `tests/ac3_transport_stream.rs::seek_in_local_file_*` переписан: прежняя проверка «после seek пакетов меньше» держалась на этом баге (в 0.5-с фикстуре единственный decode point ≤ цели — keyframe 1.4 с, seek честно возвращает все кадры).

## Мягкий разрыв: склейка TS и потеря пакетов (2026-10-17, бэклог №18)

- Root cause: разрыв `continuity_counter` на stream PID (`cat a.ts b.ts` — у каждой записи свои счётчики; потеря пакетов в эфире) делал `reset_pid` + `publish_tracks_changed`; в player-core `TracksChanged` = seek-подобный полный пересбор (0,2–0,4 с звука, видео ждёт keyframe). Решение владельца: «мягкий» разрыв — `TracksChanged` только при настоящей смене состава (PAT/PMT, video config evidence, audio evidence по политике кодека).
- `src/continuity.rs` `ContinuityTracker::observe → ContinuityVerdict::{InOrder, Duplicate, Gap}`: дубликат = тот же счётчик И те же байты payload-а (раньше одного счётчика хватало, и на стыке склейки 1/16 шанс выбросить первый пакет следующей записи).
- `src/demuxer_continuity.rs` (`#[path]`-подмодуль `MpegTsDemuxer`): `recover_from_continuity_gap` — PSI PID → сброс сборки секции; разрыв посреди PES (пакет без PUSI) → PES отброшен целиком + `discard_incomplete_strict_audio_tail` (ADTS/MPEG: неполный кадр в буфере дал бы `Malformed`; AC-3 буфер не трогается — у него ресинк); разрыв перед PUSI → `PesAssembler::close_after_continuity_gap → InterruptedPes::{Absent, Complete, LengthNotDeclared}`: объявленная длина набрана → обработать; не набрана → warn + отбросить (не fatal); длина не объявлена (видео) → обработать только если новый PES начинает другую шкалу (`DiscontinuityWindow::raw_timestamps_restart`, PTS нового PES через `pes::peek_pes_pts`) — это стык записей и последний кадр записи полный; иначе (время идёт дальше) хвост мог быть потерян → обрезанный AU отбрасывается. Video assembler при разрыве не сбрасывается (готовый AU не теряется). Timestamp unwrapper-ы при разрыве не сбрасываются. TEI и `discontinuity_indicator` по-прежнему `reset_pid` (без изменений).
- `src/timeline_continuity.rs` `PresentationTimeline` (владелец — demuxer, поле `timeline`): одна монотонная шкала презентации поверх скачков PTS/DTS/PCR. Эпохи `EpochPlacement { id: TimelineEpochId::{StreamStart, StartsAtByte(u64)}, offset_90khz }`; полосы по PID (DTS видео / PTS аудио, ожидаемое продолжение = конец аудиокадра или DTS + шаг видео); разрыв = назад дальше `backward_tolerance` (default 100 мс) или вперёд дальше `forward_threshold` (default 10 с, как ffmpeg `dts_delta_threshold`) — `MpegTsDemuxOptions::timestamp_discontinuity: TimestampDiscontinuityThresholds` (pub). Первая полоса со скачком создаёт эпоху «встык», остальные переходят в неё (один сдвиг на запись — её A/V sync сохраняется). Эпоху от видео (`ProvisionalFromVideo`) уточняет первый аудиокадр (`EpochRevision::OffsetRefined`): аудио-часы player-core идут по сэмплам, звук второй записи должен начаться ровно в конце первой; `move_seek_anchors_to_refined_epoch` (index.rs) переносит anchor-ы этой эпохи. PCR эпох не создаёт: после скачка `ProgramClockPlacement::AwaitingEpoch` (PCR anchor не пишется). Размещение — на публикации пакета (`present_on_timeline` в `emit_video_access_unit`/`emit_audio_frames`); цепочка длительностей аудио и unwrapper остаются в raw-домене. Ordered segments/resources (HLS) → `TimelineOwnership::OwnedByTransport` (сдвиг 0, разрывы объявляет transport; `TransportPacketReader::delivers_ordered_resources`). Обычный файл без скачков — сдвиг 0, timestamps не меняются.
- Seek/index: `SeekAnchor.epoch`; seek → `timeline.restart_in_epoch(anchor.epoch)` (история полос сброшена); rewind после initial index → `restart_from_stream_start`; snapshot/continuation index-а содержат `continuity` и `timeline`. Seek-маркер `TracksChanged` локального файла (discontinuity marker reader-а после `seek_absolute`) — прежнее штатное поведение.
- Тесты: `tests/concatenated_transport_stream.rs` на ffmpeg-фикстурах `tests/fixtures/concatenated/` (`generate.sh`, README; части по 25 КБ, склейки и потери собираются в памяти): byte stream и local file — 0 `TracksChanged`, 50 аудио/16 видео, PTS встык (аудио шаг 2880, видео 9000 через стык), байты = отдельное чтение частей; seek во вторую запись (anchor на непрерывной шкале, хвост = последовательное чтение); потеря посреди PES и хвоста PES (пропадает ровно повреждённый PES, остальное байт-в-байт и на месте, видео идёт без ожидания IDR); AC-3 → AAC в PMT по-прежнему `TracksChanged`, шкала монотонна. `src/tests/timeline_rebase.rs` (видео-первая эпоха уточняется звуком, anchor переезжает), `src/tests/timeline_continuity.rs` (unit), `continuity.rs`/`pes.rs` unit. Сквозной: `media-source-open` `local_media/ts_concatenation_tests.rs` (local registry → TS → production AC-3 decoder одним decoder-ом: 0 сбросов, 50×1536 сэмплов, ни одного немого кадра, тон 440→700 Гц ровно на стыке). Тест `continuity_gap_before_pes_start_keeps_completed_units_without_track_reset` заменил прежний `continuity_gap_resets_only_affected_video_pid` (тот закреплял потерю целого кадра без потери байт).
- Живой прогон (release GUI, PipeWire null sink): `cat` двух 8-с H.264+AC-3 записей — 0 track list updates в логе, звук 15,99 с без единой дыры ≥2 мс, смена тона ровно на 8,000 с, видео идёт через стык с реальной скоростью.
- Ограничения: потеря внутри PES теряет весь PES (у ffmpeg-AC-3 ~7 кадров ≈ 0,2 с), кадры до потери не спасаются; скачок вперёд меньше 10 с не перебазируется (настоящий пропуск времени; аудио-часы player-core его не «перепрыгивают» — видео отстанет на разницу, как и раньше); PCR-скачок без скачка PES оставляет PCR без anchor-ов; anchor-ы до уточнения сдвига в другом проходе (откатанный scan) находятся по id эпохи (байтовая позиция), а не по точной истории полос.

## Длительность и дальний seek больших файлов (2026-10-19, коммит 9cdf01f6)
- Проблема была: начальный индекс (`seek_scan_packets` ≈ 6 МБ) не доходил до EOF → `duration = None` → player-core запрещал seek (`UnknownTimeline`), `--:--` у любого локального TS > ~6 МБ.
- `src/duration_probe.rs`: для seekable-входа без EOF читается хвост (`tail_probe_bytes`, 2 МиБ), max PTS (развёртка 33 бит от конца головы), семантика = сырой max PTS как при EOF. `ContainerDurationEstimate::{FromTailTimestamps, FromByteRate, Unknown}`; хвост принимается, если позже головы и битрейт файла в [2/3, 3/2] от битрейта головы, иначе оценка по размеру (решение владельца для склеек). Поле `duration_basis` у демуксера. Правило: оценка заменяет None, дальше duration только растёт.
- `src/far_seek.rs` (+ `src/seek_bisect.rs`): цель за покрытием индекса → бисекция по PTS (зонд `far_seek_probe_bytes` 512 КиБ, ≤48 зондов), для `FromByteRate`/немонотонных PTS — пропорциональная позиция; локальное окно индекса от точки (`far_seek_preroll` 4 с) и выбор anchor прежними правилами через `land_on_anchor`. Транзакционно: reader/parser восстанавливаются, `seek_index`/`index_scan_offset`/continuation не меняются.
- Инвариант покрытия: `index_coverage_end`/`index_covers_within` считают только anchor-ы до `index_scan_offset` (anchor-ы воспроизведения за покрытием больше не считаются покрытием — раньше обратный seek после дальнего садился на край индекса).
- Склейки по размеру позиционируются приблизительно (зависит от равномерности битрейта). Замер: 320 МБ / 1530 с — open 34 мс, seek ~40 мс, промах ≤0,12 с.
- Тесты: `src/tests/duration_probe.rs`, `src/tests/far_seek.rs`, `tests/large_file_duration.rs` (TS ~7,2 МБ через `LocalFileSource`).
