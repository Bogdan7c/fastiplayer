## Root causes and owning fixes

- Player worker published the media install control acknowledgement before its consumer snapshot. The app coordinator only admits Installed after this control receipt; its immediate snapshot refresh could therefore still see the old instance and compensate a successful open as MissingTerminal. `worker/runtime_commands.rs` now publishes session outputs before control acknowledgement. `LatestSnapshotPublisher` lives in `worker/runtime_publish.rs`; a shared publication mutex closes the channel drain/replacement gap against `PlayerWorker::latest_snapshot`. Snapshot construction/session/render work occurs outside this lock. The consumer does not wait for a new snapshot, but may briefly wait for the short publisher critical section; it is not strictly lock-free/nonblocking under preemption.
- `media-prefetch` previously retained a nearby forward seek only during an active fetch. Ogg tail metadata seek could arrive just after the first 64 KiB append and before the next fetch: reset to tail, reset to beginning, duplicate download, 5 requests. Shared owner now also retains a forward seek within configured initial-chunk budget when the next sequential fetch is eligible and no active fetch/pending seek/error/shutdown exists. Far seeks and cancellation retain existing semantics. Existing exact-3 HTTP/Ogg lifecycle/PCM assertion is unchanged.
- `render-wgpu-shell::Renderer::render_frame` reconciles surface size with the prepared screen descriptor before acquire. XWayland can expose the new window size before Resized arrives; otherwise a 1920-wide egui scissor can hit the old 1280-wide attachment and trigger panic/cleanup panic. Native Wayland was not the source of that observed fullscreen failure.
- VA-API thread display name is generic `VA-API`, because this thread supports multiple codec adapters. Actual adapter codec remains available through configure diagnostics; fixed initial `VA-API VP9` mislabeled H.264/HEVC.
- FFmpeg video consumer tests are gated individually, while the shared offscreen harness and feature-independent failure tests remain available in no-default builds.
- Executor timeout test now uses one held worker with channel rendezvous. The old two-worker test could observe two pending threads at a 1 ms deadline and panic before releasing its busy-loop worker, hanging Drop/join. Sender drop now also unblocks the held worker during unwind. Production shutdown implementation is unchanged.
