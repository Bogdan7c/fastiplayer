# YouTube playlist metadata enrichment (2026-07-17)

- `service-youtube` теперь владеет отдельным read-only boundary `resolve_youtube_playlist_metadata_with_config() -> YoutubePlaylistMetadata`. Он запускает `yt-dlp` только для JSON metadata (`--quiet --no-warnings --simulate --dump-single-json --no-playlist`), не открывает media bytes, не выбирает decoder/render stream и возвращает только normalized непустой title + bounded-valid duration.
- `service-youtube::process` поддерживает cooperative cancellation уже запущенного child process: owner cancellation/общий executor shutdown проверяются в bounded 25 ms wait loop, child kill+wait не оставляет zombie. Timeout, cancellation и non-zero process failure остаются раздельными; raw locator/stderr не попадают в app-visible result.
- Уже подготовленный `YoutubeStreamingMedia::playlist_metadata()` переиспользует title/duration того же `yt-dlp` snapshot-а без второго I/O. `app-egui::media_open::preparation` заполняет только отсутствующие demux title/duration; известная demux metadata остаётся primary. Поэтому exact Installed cache path тоже получает настоящее YouTube title.
- `app-egui::playlist_runtime::discovery::youtube_metadata` — новый process-lifetime owner, отдельный от neutral `playlist-discovery`. Он использует `bounded-work-executor`: максимум 2 одновременных worker-а, executor queue 16, app pending 256, failure retry delay 30 s. Terminal notifier использует существующий `AppWakePort`; UI thread не блокируется и не poll-ит network/process.
- Новый URL append сначала атомарно commit-ит ID-less draft и только затем ставит enrichment demand для выданного stable Item ID. Deferred startup add не получает выдуманный ID; когда строка станет committed/visible, тот же visible metadata boundary поставит задачу. Restore/старые YouTube URL также обогащаются при попадании в visible hint.
- Service registry (`url_service_adapter`) остаётся единственным URL parser/normalizer owner-ом и выдаёт typed `PlaylistUrlMetadataSource::YouTube`; app не проверяет host вручную и не читает raw secret URL вне registry boundary.
- Результат применяется только к совпавшим Item ID + exact `PlaylistLocator` через существующий `PlaylistMetadataPatch`. Duplicate URLs независимы; удалённая/заменённая строка не воскресает. Merge строится поверх последнего cache snapshot-а, поэтому artists/album/sequence и более точная уже известная duration не стираются. Metadata mutation не меняет order/current/active/pending/playback.
- Queue replacement/Clear/shutdown отменяют pending и active enrichment. Running `yt-dlp` видит cancellation token и завершается. Временная ошибка сохраняет safe fallback `YouTube media (host)` и допускает retry без process-per-frame loop.
- UI renderer не менялся: он уже предпочитает `CachedPlaylistMetadata::title()` перед fallback name, поэтому успешный patch автоматически показывает настоящее название.
