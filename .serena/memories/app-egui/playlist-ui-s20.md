# Session 20 — Playlist row interaction UI (2026-07-16)

## UI ownership
- `ui/playlist/actions.rs` остаётся единственным UI→post-render boundary. Row actions: exact `Select(ItemId)`, `Play(ItemId)`, `Remove(ItemId)`, `RemoveOthers(ItemId)` и один canonical `Move { item_id, MoveItemIntent }`.
- `ui/playlist/row_interactions.rs` владеет только egui click/double-click, focused keyboard и context-menu mapping. Single click выбирает без Play; double click и Enter создают explicit Play; Up/Down/Home/End выбирают и переносят focus; Delete удаляет exact focused row. Keys потребляются только при row focus, поэтому global hotkeys Session 18A не дублируются.
- Context menu вызывается на click-sensing `Response` каждый frame и содержит русские Play/Remove/Remove Others. Duplicate locator rows адресуются только stable Item ID.
- После successful removal `playlist_action_runtime` передаёт в `AppState::request_playlist_row_focus` только controller-provided D47 selected Item ID. UI не вычисляет fallback по virtualized index и не хранит Undo snapshot. Active/pending changes D61 сами focus/viewport не меняют.

## Virtualized drag
- `ui/playlist/virtualized_drag.rs` владеет ephemeral `VirtualizedDragState`: source Item ID, capture generation, pointer/viewport/scroll geometry, requested scroll offset и stable insertion target. Widget/index references не хранятся; source row может стать невидимым.
- Pinned egui 0.34.2 contract: `drag_started`/transport release flags одно-frame; built-in `DragAndDrop` payload доступен в release frame и автоматически очищается на Escape/release. Implementation дополнительно очищает playlist state и собственный matching payload при viewport leave, disappearance и lost capture; replacement payload другого UI owner сохраняется.
- Insertion slot вычисляется O(1) из pointer + scroll offset через `PlaylistViewModel::item_id_at` и преобразуется в ToFront/ToBack/Before(anchor). Drop публикует ровно один Move action; pointer motion domain не мутирует.
- Edge repaint запрашивается только в scrollable edge zone. Leave/center/content boundary/drop/cancel прекращают explicit repaint, поэтому idle spin нет.
- Renderer остаётся fixed-height `ScrollArea::show_rows`; standard egui Frame/SelectableLabel используются для interaction/accessibility/insertion marker. Прямого Painter в app-egui нет, `ui-artwork-egui` не менялся.

## Full-row desktop multi-select UI revision (2026-07-18)
- Each virtualized row lays out non-selectable child labels, then registers exactly one full-width `Sense::click_and_drag` response. Index, media glyph, title, duration, badges and trailing edge therefore share click/double-click/right-click/hover/drag semantics; system text selection is disabled.
- UI actions are intent-shaped: `UpdateSelection`, `RemoveSelected`, `RemoveUnselected` and `MoveItems`, with exact Arc-backed IDs and captured structural revision. Normal/Ctrl-or-Cmd/Shift/Ctrl-or-Cmd+Shift pointer selection, focused arrows/Home/End, Ctrl-or-Cmd+A, Escape, Enter and Delete follow desktop semantics without consuming global hotkeys outside row focus. Empty list background clears selection; Escape during drag cancels drag only.
- Context click inside selection preserves the group; outside selection first selects the row. Double click preserves an existing group but plays the exact clicked row. Context menu exposes Play, Remove selected (N), and Remove all except selected (N); full queue scans happen only when an explicit range/select-all/bulk/drag-start event needs exact IDs, not during ordinary row rendering.
- Virtualized drag captures selected IDs and structural revision once. Dragging an unselected row first collapses selection to it; selected rows move atomically as one canonical-order block. Drop slots exclude selected anchors, per-frame target lookup stays O(1), and Escape/lost capture clean ephemeral state.
- Row visuals come only from `PlaylistRowStyle`: white alpha 28 hover, 46 selected, 64 selected+hover, white alpha 128 separator, grayscale insertion/focus strokes, subtle active fill and a distinct 3-point left playback marker. Selection remains a full-row surface; confirmed active playback uses the moving marker plus a brighter title foreground and accessibility text `Сейчас играет`. The separate trailing `Play` glyph remains removed.
- Headless egui tests cover every row column/edge plus double click, secondary click, drag/drop, keyboard focus/navigation/select-all, empty-area clear and disabled text selection. Focused Playlist UI 34 PASS; full app suites 643 PASS for both feature sets.

- Authoritative undo получает pointer/keyboard interaction, tooltip и AccessKit name сразу во время fade-in. После утраты authoritative state hit-area/action/accessibility исчезают сразу, а зарезервированный slot дорисовывает только fade-out glyph. Нижнего fallback и Ctrl+Z нет.

## Визуальная непрерывность при смене трека (2026-07-19)
- `PlaylistViewSnapshot` больше не сводит UI-доступность structural intents к двусмысленному `bool`. Typed `PlaylistStructuralActionAvailability::{Available, TemporarilyBlocked, Unavailable}` отделяет краткий D08/D39 install commit-guard от устойчивой fatal-недоступности.
- `TemporarilyBlocked` по-прежнему запрещает Add/Sort/Clear intent, но toolbar рисует обычный enabled paint без egui disabled-opacity, а inline status не занимает layout. Поэтому один transition frame не затемняет toolbar и не сдвигает весь virtualized row list. Accessibility остаётся disabled, click не публикует action.
- `Unavailable` сохраняет настоящий disabled paint и отдельное inline-объяснение. `Current Item` и прочие неструктурные controls не зависят от structural gate.
- Focused headless regressions находятся в `ui/playlist/toolbar/icon_bar.rs` (равенство paint shapes + отсутствие actions) и `ui/playlist/status.rs` (нулевая разница высоты Available/TemporarilyBlocked).
- Follow-up 2026-07-19 устранил оставшийся 12-point layout jump: старый enabled/disabled путь каждой fixed-rect toolbar-кнопки проходил через `Ui::add_enabled_ui`, чей scope продвигал flow-cursor родителя, а `TemporarilyBlocked` использовал прямой `Ui::interact` без layout. Поэтому обычный кадр занимал 50 pt, guard-кадр 38 pt и весь блок от «Очередь» вниз подпрыгивал при любой установке трека.
- `icon_bar` теперь резервирует flow-высоту ровно один раз. Enabled и transient controls используют non-allocating fixed-rect interaction; настоящий disabled `Response` создаётся в прямом disabled child UI, который не коммитит свой `min_rect` родителю. Click, keyboard focus, tooltip, disabled paint и AccessKit enabled-state остаются различимыми.
- Regression `transient_guard_preserves_icon_bar_flow_height` требует, чтобы `Available`, `TemporarilyBlocked` и `Unavailable` занимали ровно высоту одной production row allocation. После follow-up: focused icon bar 8 PASS, полный `app-egui` suite 672 PASS в default и no-default наборах; strict Clippy для обоих feature-наборов, fmt, refactor guardrails и diff check PASS.


## Плавный акцент подтверждённо играющего трека (2026-07-19)
- Источник истины не менялся: `PlaylistViewModel::active_item_id()` возвращает только Item ID из подтверждённого `ActiveMediaIdentity`. Pending target, runtime error, Stop и первый `None -> Some` не запускают движение; controller/player lifecycle не получили UI-зависимостей.
- `ui/playlist/active_accent.rs` владеет неперсистентным `ActiveAccentAnimationState`: previous/target Item ID, текущим screen rect, `SlideTransition`, типом nearby/follow и последним authoritative viewport. Nearby использует 220 ms + `EaseOutCubic`; off-screen follow — 360 ms с cubic scroll и 25/50/25 edge-departure/hold/arrival. Быстрый Next retarget-ит из текущего visual rect без скачка.
- Автоследование разрешено только при видимом старом accent. Wheel/trackpad, kinetic scroll, scrollbar/content drag, playlist drag, row focus и Go Current отменяют UI motion; structural revision сбрасывает stable index/geometry и мгновенно привязывает accent к актуальному active Item ID. `UiMotion::Reduced` мгновенно применяет и accent, и необходимый clamped scroll.
- Renderer остаётся fixed-height virtualized: один `visible_rows` lookup, затем два прохода только по bounded visible range. Самый ранний shape slot держит active fill под hover/selection; content/interaction не двигаются; distinct left-edge active marker идёт поверх content/row surfaces; insertion/focus и separator сохраняют финальный приоритет. Moving layer декоративный и не создаёт AccessKit node, а visible target row сразу получает authoritative active accessibility text и brighter title foreground. Отдельный trailing vector `Play` glyph удалён; его 13-point layout-ячейка возвращена title column без сдвига pending/error-индикаторов.
- Repaint запрашивается только пока finite transition не завершён. Disabled sidebar animation copies используют отдельный default UI state и не меняют authoritative viewport/accent/output.
- Focused Playlist UI: 63 PASS в default и no-default feature-наборах; полный `app-egui`: 685 PASS в обоих наборах. 10k queue regression подтверждает bounded visible hint без full traversal; workspace test sweep, strict workspace Clippy, Rust 1.96 locked check, fmt и refactor guardrails PASS.

## Problem-only Playlist status и lifetime owner (2026-07-19)
- Единая область под toolbar теперь показывает только warning/error: startup warning, terminal sibling warning, partial/failed Manual Add, safe action feedback, persistence warning/block/fault и navigation failure. Loading, tombstone, structural lifecycle, progress, successful completion, Sort cancellation, navigation wait/exhausted/cancelled и прочие нормальные статусы полностью удалены из этой области.
- `PlaylistUiState::status` владеет `PlaylistStatusLifetimeState`: максимум пять newest-first problem slots, отдельный 10-second deadline каждой проблемы, typed dedup/replacement, suppression неизменившегося persistent snapshot после expiry и раннее удаление explicitly resolved state. Новая identity того же owner-а заменяет строку без дубля и получает собственные 10 секунд; шестая вытесняет самую старую без `+N`.
- Identity не зависит от текста: sibling warning хранит `SiblingDiscoveryScopeId`, Manual Add — opaque job event id, safe feedback — монотонное generation, save warning — `SaveRevision + occurrence_count`, navigation failure — failed Item ID либо discovery scope. Navigation accessibility-флаг origin-ended не является identity и сам по себе не перезапускает lifetime.
- Runtime interaction model заменил rich `PlaylistProgressModel` на `Option<PlaylistActiveOperation>`, нужный только toolbar busy gate. `PlaylistProgressCancelScope`, `PlaylistAction::CancelProgress` и UI cancel methods удалены. Отменённый/superseded Manual Add silent; partial/owner failure остаётся problem notification.
- Clock — `egui::InputState::time`. Owner вызывает `request_repaint_after` только до ближайшего deadline; idle immediate repaint отсутствует. После expiry общий geometry-only `SlideTransition` закрывается за 180 ms, новая проблема делает exact reverse, `UiMotion::Reduced` переключает мгновенно, hover timer не меняет.
- `RetrySave` доступен только пока authoritative persistence problem актуальна. `CancelNavigation` показывается только для `AwaitingUserAfterFailure`; обычный wait больше не имеет status action. Measurement, residual и disabled sidebar copies actionless; disabled copy читает только неистёкший owner snapshot и не восстанавливает runtime presentation заново.
- Верхний separator, wrapping, warning/error theme colors, privacy-safe text и нулевая добавочная высота пустой области сохранены. URL form validation и `Плейлист ещё подключается…` остаются вне status owner-а.
