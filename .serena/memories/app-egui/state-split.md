# app-egui state split

> **Superseded notice (2026-07-03):** любые упоминания hover preview, hover predecode, hover budget/reservation, timeline-hover prepare или hover overlay ниже являются историческими и не описывают активный контракт. Актуальные owners и запреты: `mem:core` и `mem:frame-server/core`. Остальная non-hover информация этой memory остаётся действующей.

S14 refactor-only split moved `crates/app-egui/src/state.rs` implementation details into private child modules under `crates/app-egui/src/state/` while preserving `AppState` as the owner and preserving existing external paths through re-exports where needed.

- `state.rs`: keeps `AppState` fields/constructor, frame context/timing/output structs, committed snapshot/player snapshot/redraw/desktop integration core helpers, and declares private child modules.
- `state/present_frame_cache.rs`: `PresentFrameAcquisition`, `RenderablePresentFrame`, cached/renderable present-frame identity, validation, lifecycle invalidation, texture-busy fallback, render error/frame cache methods.
- `state/main_visual_override.rs`: S16 app-owned main-video scrub visual override state for `SeekLanding`/`LiveScrub`; stores override metadata and S15-materialized renderable frame separately from playback cache; ignores stale older-generation preview/events, clears old override on newer scrub generation, handles matching `Committed`/`MatchedPlayback`, and player lifecycle invalidation.
- `state/video_backend.rs`: video pipeline init/rebuild, backend reselection, backend swap freeze/phase, system capabilities handoff.
- `state/media_jobs.rs`: `ActiveMediaSource`, local file/prepared media/direct/YouTube loading, local open job polling/result application, media reconfigure restore helpers.
- `state/telemetry_panel.rs`: telemetry panel cache/rows/tone, row building and panel rendering helpers.
- `state/ui_runtime.rs`: `render_ui`, control actions, timeline action mapping, fullscreen/hotkey/open-file UI glue, center overlay, frame counters snapshot.
- S18 adds app-owned timeline hover prepare runtime outside the visual timeline widget: `AppState` owns `timeline_hover_prepare_controller` from `crates/app-egui/src/timeline_hover_prepare.rs`, creates one `PlayerTimelineHoverPrepareHandoff` from committed config, passes a clone into `PlayerWorkerConfig`, and keeps the controller for future S24 synthetic pointer/focus wiring. No real timeline hover UI stream or visual widget behavior changes in S18. The app controller may borrow existing prepared frames through the shared handoff but does not promote/commit position and does not send ordinary `PlayerCommand::Seek`. S23 adds `crates/app-egui/src/hover_software_session.rs` as an app-owned minimal FFmpeg software hover startup boundary: it resolves `[frame_server]` pool/thread budget through `frame-server-core`, asks `video-ffmpeg::software_hover` for admission, then starts a separate reduced-budget backend through `FfmpegSoftwareVideoBackendFactory`; it is not yet wired to timeline UI or demux execution. S26 adds `crates/app-egui/src/timeline_hover_source.rs` as the app-owned active-playback hover source factory: local files reopen through `local_media::open_local_demuxer` into an independent hover demuxer, direct/YouTube are typed `Unsupported` until S27, media-open boundaries invalidate the old hover source through `TimelineHoverPrepareController::invalidate_hover_source`, and hover source open failures stay inside hover executor outcomes instead of resetting playback.
- `state/timeline_inline_status.rs`: app-owned fixed 2500 ms timeline inline failure status for scrub audio resume timeout/error; listens to existing `ScrubEvent::Failed`, clears on next timeline action, and does not add player-core snapshot/public API fields.
- `state/frame_server_diagnostics.rs`: app-owned S29B diagnostics boundary for hover/preview/grace state that does not belong in `player-core`. `AppState` owns an `AppFrameServerDiagnosticsRecorder`, records existing `TimelineHoverPrepareControllerOutcome`, visual HoverPreview update/clear/disabled-by-config events, and hover leave-grace start/re-enter/release outcomes. It reuses neutral `frame-server-core::ScrubDiagnosticsRecorder` for hover prepare/network/span counters, but UI-only state (`hover_preview_enabled`, preview ready/loading, leave-grace pending/configured duration/release outcome, network open in-flight/held target/throttle snapshot plus latest-only replacement/stale-late-ignore/throttle-delay counters) stays in an app-owned read-only `AppFrameServerDiagnosticsSnapshot` passed to `TelemetryPanelState`. Worker/UI code must consume this snapshot rather than reading `AppState` fields directly or adding app->player diagnostics APIs.
- S19/S20 timeline live scrub UI is owned by `ui/timeline.rs` + `state/ui_runtime.rs`: when committed `[frame_server].live_scrub_enabled` is true, pointer-down on the timeline emits `BeginLiveScrub` and captures shared `frame_server_core::LiveScrubSettingsSnapshot { decode_mode, max_hz }` for that gesture; drag updates emit live preview targets through that pointer-down snapshot, and release emits `EndLiveScrub` after an exact final preview target if needed. `throttled_latest` keeps UI display immediate while app-side dispatch drops intermediate decode commands up to the pointer-down `live_scrub_max_hz` and records `LiveScrubDiagnostics.throttled_latest_skip_count`; `every_drag_event` dispatches each target and keeps that count at zero. Since the post-S20 live-UX fix, `throttled_latest` dispatch is also completion-gated by `TimelineLiveScrubDispatchState.awaiting_landing_for_target`: while the previously dispatched decode target has not yet produced a presented landing frame and a bounded fallback budget (`LIVE_SCRUB_LANDING_FALLBACK_BUDGET`, 250 ms, `ui/timeline.rs`) has not elapsed, newer drag targets coalesce into the newest pending target and are NOT dispatched, so continuous fast drag no longer supersede-starves the single reused exact decoder (root cause of "almost frozen" live scrub: each `preview_scrub` supersede did flush + demux-seek-to-keyframe-before + full GOP re-decode, and the worker `drain_pending_command_batch` superseded the in-flight landing before it could present). The gate is released by `AppState::note_live_scrub_landing_for_dispatch`, wired from `PlayerEvent::SeekTargetFramePresented` in `frame_prepare::record_worker_events`, giving frame-by-frame scrubbing at the decoder's natural rate. This stays plan-conformant: exactness policy is unchanged (still exact `TargetOrAfter`, never nearest/keyframe), single reused decoder, latest-only/coalesce, no second decoder/session, no player-core semantic or resource-accounting change; `every_drag_event` keeps attempt-each (gate sets `awaiting_landing_for_target` but does not block). Mid-drag mode/max-hz committed changes are detected in `AppState::sync_committed_config_snapshot`, apply only to the next drag, increment `deferred_live_scrub_settings_change_count`, and retain only latest `DeferredLiveScrubSettingsChange { old_snapshot, new_snapshot }`; no UI hint, timeline inline status, banner/toast, timestamp, drag id, source target, ring buffer, or history is added. Live drag commands map to `PlayerCommand::{begin_live_scrub, preview_live_scrub, end_live_scrub}` / `BeginScrub`/`PreviewScrub`/`EndScrub`, not ordinary `PlayerCommand::Seek`. When `live_scrub_enabled` is false, timeline click/drag release still maps to exact `Seek` through the legacy command route.
- `state/tests.rs`: former state tests; guard tests build a combined source string from `state.rs` and the child modules so existing architecture assertions still cover moved code.

Visibility policy for this split: no new `pub(crate)`/`pub` boundary beyond preserving existing public/internal API paths; cross-child helpers use only `pub(super)` inside the private `state` parent module. Behavior, config, diagnostics, UI layout/sidebar viewport behavior, backend selection, cached-frame lifecycle, and test assertions were intended to remain unchanged.

Focused checks used for this split: `cargo test -p app-egui state`, `cargo test -p app-egui`, `cargo fmt --all --check`.
