# Рендер по изменению, а не по vsync (cpu-parity сессия 04, 2026-10-20)

Отчёт: `user/cpu-parity/results/04.md`. Решения владельца: режим «видео с прежним интерфейсом» делаем; страховочный таймер 250 мс при воспроизведении; release-ack по-прежнему будит worker (1 на кадр); телеметрия открыта → полный проход раз в 250 мс (ритм её кэша).

## Что было
При активном воспроизведении shell после каждого кадра просил `request_redraw` и просыпался на каждом vsync (`ControlFlow::Wait` + redraw), делая полный egui-проход, submit и present даже без изменений. Дефекты попутно: `has_requested_repaint()` считал отложенные `request_repaint_after` немедленными; `request_repaint_after` после прохода (preview настроек) терялся; UI не узнавал о новом кадре/событии плеера иначе как на vsync; три диагностических sample-сообщения рендера на каждый проход будили worker.

## Владельцы и границы
- **Пробуждение UI от worker-а:** `player-core::worker::presentation_wake::PlayerWorkerPresentationWake` (payload-free), `PlayerWorkerConfig::with_presentation_wake`. Worker дёргает его после `publish_session_outputs` при `PresentFramePublication::{Published, Cleared}` (возвращает `RenderLeaseBridge::publish_present_frame`, до 06a — `publish_latest_present_frame`, `#[must_use]`) и в `publish_worker_event` на каждое lifecycle-событие. Порядок: сначала слот/очередь/snapshot, потом wake. App-сторона: `AppWakeOwner::PlayerPresentation`, порт — сосед порта timeline (`AppWakePort::sibling_for_owner`), создаётся в `AppState` (`state/redraw_runtime.rs::RedrawRuntime::new`), bridge `state/startup_context.rs::player_presentation_wake_bridge`. Обработчик в `app_shell/event_loop.rs::user_event` ТОЛЬКО помечает `note_presentation_wake` и просит redraw — он НЕ «видимая мутация интерфейса» (иначе полный проход на каждый кадр; это был найденный в сессии дефект).
- **Решение о плане кадра:** чистая `frame_prepare/frame_work_plan.rs::plan_frame_work(UiPassReasons, PresentReasons) -> FrameWorkPlan::{FullPass, PresentReusingUi, Skip}`; сбор фактов — `frame_prepare/frame_decision.rs::decide_frame_work` (триггеры `AppState`, запросы egui, анимации, дедлайны, UI-модель, слот показа, `Renderer::can_reuse_retained_ui`). Причины полного прохода: ввод/оконные события, события плеера (`worker_event_count > 0`), follow-up worker-команды, видимая мутация от owner-wake (субтитры, плейлист, startup, persistence, drag&drop), egui просит сейчас/дедлайн созрел, анимация (sidebar/chrome/fade тоста), дедлайн UI-модели, изменение `UiFrameModel`, телеметрия раз в 250 мс, нет удержанного интерфейса, принудительно. Причины показа: `peek_present_frame_change` (identity слота ≠ кэш; `Busy` = изменился), seek/scrub/override, hold при смене backend-а.
- **UI-модель кадра:** `state/ui_frame_model.rs::UiFrameModel` (`PartialEq`, без `Debug`: `PlaylistInteractionModel` не печатает URL). Позиция квантуется `quantize_timeline_position` до секунды текста (`floor`) и пикселя ползунка (`floor(fraction × ширина дорожки)`; ширина — `TimelineUiState::observed_track_width_px`, пишется в `ui/timeline/render.rs`). `next_visible_position_change` даёт дедлайн следующего видимого изменения (нужен звуку без видео и 24 fps фильмам); `AppState::next_position_wake_deadline` добавляет backoff ≥ `max(frame_duration, 8 мс)`, если прошлый дедлайн прошёл, а snapshot не сдвинулся (позиция в snapshot-е обновляется тиком worker-а — иначе спин по 1 мс; найдено в сессии). Тосты: возраст квантуется «проявляется/проявился» (`NotificationsVisualKey`). Ревизии: `SettingsRuntime::ui_model_revision()`, `PlaylistViewModel::revision()`, `PlaylistInteractionModel: PartialEq`.
- **Состояние между кадрами:** `state/redraw_runtime.rs::RedrawRuntime` (одно поле `AppState::redraw`): триггеры (`note_window_input_for_redraw` — любое оконное событие кроме Redraw/Close; `note_visible_mutation_for_redraw`; `note_redraw_fallback_probe`; `force_full_ui_pass`), приёмник `Context::set_request_repaint_callback` (`EguiRepaintRequest { immediate, deadline }`, `peek`/`take`), память последнего полного прохода (`UiFrameModel` + `RetainedUiGeometry`), `last_full_pass_at`. `wants_continuous_redraw` живёт здесь (имя сохранено) и теперь означает «воспроизведение активно → страховочный таймер».
- **Планировщик:** `redraw_pacing.rs`: `RedrawPacing { immediate, playback_active }`, `RedrawControlAction { control_flow, redraw_cause: Option<RedrawCause::{Immediate, UiDeadline, BackgroundPoll, PlaybackFallback}> }`; воспроизведение больше не даёт `Wait + request_redraw` — только `WaitUntil(min(дедлайны UI, страховка 250 мс))`; `before_idle_wait(playback_active, ..)` перевзводит страховку, созревшая даёт один redraw с `PlaybackFallback` (кадр считает `redraw_fallback_found_work`, если нашёл работу).
- **Координатор `frame_prepare::render_frame`:** ввод+snapshot → desktop publish → `advance_ui_timers` (sidebar/chrome/dynamic options на каждом пробуждении) → `decide_frame_work` → `prepare_ui_frame_for_plan` (полный проход или `PreparedUiFrame::reusing_retained`) → действия панелей и runtime-опросы (на каждом пробуждении, с пустыми действиями) → `present.rs::present_frame_for_plan` (с сессии 06a: буфер swapchain `acquire_surface_frame` → стадия `SurfaceAcquire` → видео → submit → present → трасса; без буфера кадр плеера не забирается; после `Presented` — follow-up redraw ради ждущего кадра, `mem:cpu-parity/frame-selection-cadence-s06a-2026-10-21`) либо `log_skipped_frame` → pacing/дедлайны (`undo`, persist, уведомления, chrome, inline-статус, телеметрия, egui deadline, preview настроек, позиция). `FrameSequenceContract` теперь требует только монотонный порядок стадий (пропуски разрешены).
- **Shell:** `render-wgpu-shell::EguiFrameContent::{Fresh { paint_jobs, textures_delta }, ReusePrevious}` в `RenderFrameInput.egui`; `EguiCompositor` удерживает примитивы и `ScreenDescriptor` последнего `update_buffers` (`begin_frame_content` → `prepare_pending_content` → `render_retained_overlay` → `free_retired_textures_if_any`); `ReusePrevious` при несовпадении размера/отсутствии удержанного → `RenderFrameDropReason::RetainedUiUnavailable` ДО acquire (app: `force_full_ui_pass` + follow-up redraw, счётчик `retained_ui_refusals`, не surface drop). `Renderer::can_reuse_retained_ui(screen)`. По контракту egui-wgpu 0.36 `render()` читает буферы последнего `update_buffers`; uniform размера пишется только в `update_buffers`, поэтому размер обязан совпадать. GPU-тест `egui_compositor/tests.rs` (пиксели повторного кадра = свежего поверх другого «видео»; отказ без удержанного/при другом размере).
- **Worker:** в `runtime_wait.rs` из трёх `select!` убраны ветки acquire/timing/lock/reuse-samples (они `try_send` без пробуждения и вычитываются `drain_render_feedback()` в начале витка и перед `session.tick` в `run_tick_for_wakeup_plan`); будит только release-ack. Счётчик переименован: `worker_render_release_wakeups` (было `worker_render_feedback_wakeups`). Тесты `worker/tests/wakeup.rs::output_clamped_render_timing_samples_reach_diagnostics_without_waking_worker`, `..._frame_release_ack_still_wakes_worker`; `worker/tests/presentation_wake.rs`.
- **Телеметрия/трасса:** `Telemetry::record_frame_work_plan`, `FrameWorkCounters { full_passes, reused_presents, skips, fallback_found_work, retained_ui_refusals }`; строка `render frame stage timings` получила `frame_work_plan`, `ui_pass_reason`, `present_reason` и счётчики; пропуск — отдельная строка `render frame skipped` (agg_timing считает только показанные кадры). `PlayerWorker::try_present_frame_identity` / `PresentFrameIdentityProbe::{Known, Busy}` — дешёвая проверка «кадр новый?» без clone lease-а и sample-а.

## Инварианты
1. Любой ввод/оконное событие и любая owner-мутация → полный проход на следующем кадре (UI не отстаёт). 2. Новый кадр будит UI сразу после публикации (не хуже vsync-опроса). 3. `take_egui_input` вызывается на каждом пробуждении; пропускается только `run_ui`. 4. Housekeeping и runtime-опросы идут на каждом пробуждении независимо от плана. 5. В паузе/простое — `Wait` без страховки. 6. Release-ack не ждёт следующего тика.

## Заметные следствия для UX/диагностики
- FPS в панели телеметрии = частота показа (на 30 fps файле ≈ 30, не 60); `playback_repeated_frames` ≈ 0.
- Источник пробуждений UI при воспроизведении: кадры (fps) + дедлайны позиции (секунда/пиксель) + страховка 4/с. На коротких клипах (≤ 60 с) пиксель ползунка меняется чаще кадра, поэтому `PresentReusingUi` почти не срабатывает — это честно: интерфейс действительно меняется.
- Ratchet: `frame_prepare.rs` 1429 → 1469, `render_lease_bridge.rs` 1208 → 1211, `ui_interaction.rs` 825 → 828; `state.rs` 794/800, `app_shell/mod.rs` 796/800, `shell.rs` 797/800.
