# S17 topology-first Add URL collection import (2026-07-20)

## Ownership и flow
- `playlist_runtime::url_import` — новый process-lifetime owner toolbar Add URL для yt-dlp. Он хранит monotonic exact generation, один reusable worker, один заменяемый latest pending request и один generation-tagged terminal slot; renderer/UI и winit event payload не владеют raw locator/topology.
- `url_service_adapter::StartupUrlLocator::yt_dlp_topology_locator()` передаёт уже classified typed locator без второго parser-а. Direct-media-first routing не изменён: explicit direct media URL продолжает existing single append; только yt-dlp locator запускает topology job.
- Production worker вызывает существующий S15 `extract_yt_dlp_topology_with_config`, затем чистый S16 `map_yt_dlp_topology_to_playlist_drafts`, и передаёт ID-less `PlaylistImportDraft` в единственную S08 transaction с `PlaylistImportIntent::AppendToQueue`.
- Video topology становится Single preview; collection становится ordered Singles/Compounds preview; `multi_video` сохраняется first-class Compound. S08 остаётся единственным owner-ом capacity prefix, unavailable payload, structural-revision validation, Item/Group allocation и queue commit.

## Lifecycle, stale и privacy
- Rapid submit никогда не создаёт unbounded threads/processes: новый generation cooperative-cancel-ит running extraction и перезаписывает ещё не начатый latest request. Worker публикует completion только при exact current generation; submit/cancel/shutdown также очищают уже опубликованный stale slot.
- Общий `supersede_playlist_import_flow` теперь отменяет file-import job, active URL topology job и staged preview. New URL/main-open/row-play/structural replacement/shutdown поэтому не могут воскресить старый URL preview.
- `PlaylistShutdownReport` содержит отдельный `url_import` outcome. Shutdown закрывает generation, будит idle worker и join-ит его в общем `ShutdownDeadline`; timeout/panic остаются typed. Resolver panic изолируется, а poisoned worker mutex обрабатывается fail-closed без `PoisonError::into_inner`.
- Exact user locator остаётся только в typed service locator/durable payload. Query/userinfo-sensitive root передаёт count в прежний aggregated `SensitiveDurableLocatorPersistence` confirmation; Add URL никогда не добавляет `QueueReplacement` reason и никогда не Replace.
- App-visible errors generic/redacted; raw locator, service payload, stdout/stderr и config secrets не логируются.

## Queue/playback invariants
- Topology extraction/mapping и preview не меняют queue/current/player. Continue commit добавляет accepted whole-entry prefix и не выбирает current, не запускает media open/playback и не меняет active media.
- Metadata-only patch во время extraction не инвалидирует будущий append preview, потому что staging фиксирует актуальную structural revision после exact completion; существующий metadata cache сохраняется.
- Старый immediate yt-dlp append + post-commit metadata-enrichment continuation удалён. Visible-row manual yt-dlp metadata refresh остаётся отдельным discovery boundary; topology import использует metadata snapshot S16 и не запускает второй metadata process.

## UX сессия 09 (2026-10-06): прогресс, отмена, причина отказа
- Решения владельца: индикатор — строка под toolbar (`ui/playlist/toolbar/url_import_progress.rs`, статичная, без `egui::Spinner` — тот repaint-ит каждый кадр), НЕ в problem-only status (там 10-секундный lifetime). Ссылка без схемы — только подсказка.
- Owner: `latest_generation` заменён `active_request { generation, display_host }`; `progress() -> Option<PlaylistUrlImportProgress { display_host }>` (read model `PlaylistInteractionModel.url_import_progress`, отдельное поле, не вариант `PlaylistActiveOperation` — тот гейтит Sort). `cancel_active() -> PlaylistUrlImportCancelOutcome { Cancelled, NothingActive }`; пользовательская отмена — `PlaylistRuntime::cancel_playlist_url_import_by_user` ← `PlaylistAction::CancelUrlImport`. Supersede-путь (`cancel_playlist_url_import`) не изменился.
- Resolver возвращает `Result<_, PlaylistUrlImportFailure { Rejected(WebOpenFailureReason), Cancelled, Internal }>`; completion `Failed(failure)`; `drain() -> FinishedPlaylistUrlImport { completion, display_host }`. Production: `topology_extraction_failure` → `media_source_open::web_open_failure::classify_yt_dlp_topology_error` (+ `tracing::warn`); mapper/panic/poison → `Internal`. Тексты — `web_open_message::{url_import_failure_message, url_import_internal_failure_message}` → safe feedback (область проблем); отмена молчит.
- Ввод: `append_playlist_url` — единственное место `trim()`; `UrlAppendValidationError::NotUrl(NotUrlInputHint::{MissingScheme, Unrecognized})` (подсказка, только если `https://`+текст = Supported URL с доменом через точку). Тексты формы — `playlist_runtime/url_draft_message.rs`.
- Тесты: `url_import/tests/progress.rs` (сквозные на `PlaylistRuntime` с `GatedResolver`), `ui/playlist/toolbar/url_import_progress/tests.rs` (egui-клик). Итог: `user/ux-edge-cases/results/09.md`.

## UX сессия 12, решение 9 (2026-10-07): destination topology job-а
- `PlaylistUrlImportDestination { AppendToQueue, ReplaceAfterConfirmation }` (`url_import.rs`, владелец URL-импорта) фиксируется в `submit` и едет в `ActivePlaylistUrlImport`/`FinishedPlaylistUrlImport`. Add URL и бросок на панель = `AppendToQueue` (поведение неизменно). Второго job-а нет: те же classify, прогресс-строка, отмена, типизированные отказы.
- `ReplaceAfterConfirmation` (бросок ссылки на видео): `Resolved(draft)` НЕ идёт в S08 preview, а превращается в `ResolvedUrlCollection` (`playlist_runtime/resolved_url_collection.rs`; усечение под лимит через `PlaylistImportDraft::into_replacement_prefix`) и паркуется в слоте владельца `resolved_replacement`. Слот очищается в `cancel_active`/новом `submit`/shutdown, т.е. любым supersede (другое открытие/замена/Add URL/«Отменить») — устаревший результат не доставляется. Отказ/отмена идут прежней обратной связью Add URL.
- Вход: `PlaylistRuntime::start_dropped_web_url_replacement -> DroppedWebUrlReplacementStart { ResolvingTopology | SingleLink(intent) | Refused }` (direct media без topology = `SingleLink`, старый путь одной строки). Выход: `take_resolved_url_collection` ← `AppShell::drain_resolved_url_collection` → `AppState::apply_resolved_url_collection` (пустая → «По ссылке не нашлось роликов»; идёт другое открытие/импорт → «Файл ещё открывается»; иначе `InAppQueueReplacementIntent::resolved_url_collection`, подпись «N роликов с домена», D15-sensitive reason компонуется) → после допуска `replace_queue_with_resolved_url_collection` (общий `commit_dropped_replacement_drafts`) + Row Play первой строки.
- Тесты: `url_import/tests/replace_destination.rs` (13, сквозные на `PlaylistRuntime` с gated resolver).
