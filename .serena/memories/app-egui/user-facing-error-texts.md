Тексты ошибок для UI (A10, A11): Display/Debug PlayerError/SettingsError только для логов. В интерфейс текст идёт через `app-egui/src/player_error_message.rs` (`player_error_user_message`, `player_error_row_summary`, `player_error_kind_phrase` — match по PlayerErrorKind без `_`), для сбоя пересборки при смене настроек — `settings_rebuild_message.rs`, для web-причин — `web_open_message.rs`. Новый PlayerErrorKind ломает компиляцию в player_error_message — это намеренно.

Панель статуса настроек (A11, видна в окне настроек, `settings_ui/layout.rs::render_status`): `settings_runtime/status_text.rs` (summary/details по Apply/Preview/Cancel/Reset), `settings_runtime/setting_labels.rs` (`SettingLabels` — id -> «русский label» из registry; id пользователю не показывается, неизвестный id = «неизвестная настройка» + warn в лог), `settings_runtime/settings_error_message.rs` (`settings_error_text` для SettingsError, `setting_value_error_text` для SettingValueError; match без `_`). Английские message владельцев route-ов (renderer_recreation, dma_buf, media services) и Debug-формы НЕ показываются, а пишутся через tracing в status_text. `SettingsRuntime::report_runtime_error` принимает `SettingsError` (не ToString). Тесты: `settings_runtime/tests/status_text_user_facing.rs` (assert_user_facing: нет id/Debug/латиницы вне «label»). Ограничение: ApplyRouteResult::Failed{message} — строка без типа, поэтому причина сбоя route-а в UI обобщённая («не удалось применить»); детальная причина потребовала бы типизации в settings-core.
Дополнение (C2): пока пересборка после Apply идёт в фоне, статус окна — «Применяем настройки…» (`settings_runtime/stepwise_apply.rs::apply_in_progress_status`), повторное действие добавляет строку «Предыдущее применение ещё идёт: подождите его завершения.», отмена на suspend/exit — `ApplyFinalState::Cancelled` -> «Применение настроек прервано; изменения отменены» (`status_text.rs`).
