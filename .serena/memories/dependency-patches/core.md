## isomp4 edit lists `elst` (2026-10-19, финальная приёмка субтитров)
- `src/edit_list.rs` `PresentationShift`: presentation = media_pts − M + dwell (тики `mdhd`). dwell = сумма ведущих пустых правок (`media_time == -1`, movie timescale `mvhd` -> media, round-half-up u128); M = `media_time` ОДНОЙ следующей обычной правки со скоростью 1. Сдвигаются PTS и DTS (после ctts/trun) в classic и fragmented путях (`next_sample_info`), seek переводит цель presentation -> media (`seek_track_by_ts`, sidx `prepare_indexed_fragment_seek`), длительность трека = dwell + (media − M). Другие формы (несколько обычных правок, rate ≠ 1, середина, `media_time < -1`) и переполнение — warn и список игнорируется целиком (как раньше). `segment_duration` обычной правки (обрезка хвоста) не используется.
- Отрицательный PTS (AAC priming M=1024) выдаётся знаковым; нейтральная граница `packet_mapper` прижимает к 0 (прецедент Opus). `trim_start` не выставляется: media-core не несёт trim (`audio/src/decoder.rs`), priming-кадр играется как раньше.
- Инвариант порядка: межтрековый порядок в `next_sample_info` по decode time, прижатому к 0, — иначе E-AC-3 priming (−256) обгонял первый видеокадр и DASH `prime_decode_anchor` его выбрасывал (`audio_priming_preroll_does_not_overtake_the_first_video_packet`).
- Эффект: ffmpeg-MP4 с B-frame (video M=1328) и задержанным звуком (dwell) больше не идут с ~0,3 с рассинхрона; DASH/HLS fMP4 с `elst` — тоже. Риск: packager, пишущий и пустую правку, и `tfdt == S@t`, получит двойной сдвиг (по спецификации; образца нет).
- Тесты: патч `src/edit_list/{tests,reader_tests}.rs` (синтетический MP4 `test_mp4.rs`), нейтральный `symphonia-demux/tests/edit_list_av_sync.rs` + фикстура `tests/fixtures/edit-list/audio-delayed-bframes.mp4` (4 КБ, `generate.sh`), DASH `web-media-dash/src/tests/priming_av.rs`. Inventory `docs/dependency-patches.toml` (owned areas, manual matrix, removal gate: upstream должен поддержать эти формы `elst`).

## Why Each Patch Is Still Needed

- `symphonia-format-caf`: exact 0.6.0 replacement for S28C forward-only CAF. It stops initial chunk scan at `data` on non-seekable sources while preserving seekable full scan/seek-back, and exact-reads declared fixed/variable packets so structural truncation cannot become a short packet or clean EOS. Stream-friendly CAF must place `desc` and required codec configuration before `data`. Removal gate and tests live in `docs/dependency-patches.toml`; full proof: `mem:symphonia-demux/audio-containers-s28c-2026-07-22`.
- The CAF patch is MPL-2.0, excluded from workspace membership, carries its own lock, and participates in the seven-entry inventory/CI matrix.

- `cros-libva`: local replacement for the cros-libva version pulled by cros-codecs. It carries compatibility with newer system libva headers, libva version cfg/check-cfg handling, VP9 encoder ABI fields, and VA surface status/query paths used by cros-codecs/video-vaapi. Removing it can break build compatibility or decoded-surface readiness semantics.
- `cros-codecs` pooled output surfaces (2026-10-20, cpu-parity 01): `src/video_frame.rs` `VideoFrame::NativeHandle: Borrow<Surface<M>> + Into<Surface<M>>` (was `Equivalent<Surface>`, i.e. exactly `Surface`); `src/backend/vaapi/decoder.rs` `PictureState<V>`/`VaapiDecodedHandle`/`VaapiPicture` hold `V::NativeHandle` instead of a bare `Surface`, so video-vaapi's `OutputSurfaceLease` returns the surface to its pool on drop instead of `vaDestroySurfaces` per frame. Plain `Surface` impls (gbm/generic dma frames, encoders) satisfy the bound unchanged; cros-libva untouched (`Picture<_, T: Borrow<Surface>>` already supports it). Inventory owned areas now include `src/backend/vaapi/decoder.rs` and `src/video_frame.rs`; removal gate requires upstream picture-owned-surface support.
- `cros-codecs`: production VA-API codec layer for AV1/VP9/H.264/H.265; its AV1 contract consumes one OBU per `decode()` call, so the first-party AV1 adapter must resubmit the exact remaining temporal-unit suffix. Local AV1 global-motion shear math retains checked i64 intermediate products through Round2Signed/Clip3 before narrowing, preventing valid coefficients from panicking and rejecting transforms that premature truncation would admit; full contract/evidence: `mem:investigations/av1-global-motion-overflow-2026-09-09`. Since 2026-10-04 the patch also owns spec-correct AV1 global-motion parsing (`reader.rs` `decode_subexp` returns `subexp_final_bits + mk`; `setup_past_independence` resets all refs LAST..=ALTREF and params 0..=5) — upstream 0.0.6 bug that hung AMD VCN. Other local needs include H.265 Dolby Vision RPU / unspecified NAL type 48..63 acceptance, dynamic WPP entry point storage for 4K streams, H.265 seek/flush picture-order reset and `NoRaslOutputFlag` behavior for CRA/IRAP, RPS/DPB diagnostics, and `DecodedHandle::try_is_ready()` so VA query errors are not collapsed into `true` during suppressed-surface reclaim.
- `symphonia-format-isomp4`: MP4/fMP4 container patch for composition offsets (`ctts`/`trun`) so B-frames get presentation PTS, classic `stss` and fragmented effective-sample-flags sync-safe video seek, direct `sidx`+SAP indexed fragmented seek without linear `moof` scan, mandatory fragmented `tfdt` v0/v1 decode timing/gaps, honest fragmented duration authority, structural truncation distinct from clean EOF, `tkhd` display orientation tags, MP4 `colr`/`mdcv`/`clli` raw tags for neutral color/HDR metadata, and QuickTime/iOS PCM/LPCM one-frame sample coalescing to avoid tiny-packet starvation after seek, and (2026-10-10) VP8/VP9 sample-entry codec id + `vpcC` profile/level (`atoms/vpcc.rs`) so fMP4 VP9 gets keyframe probing (HLS VOD seek anchor). `sidx` indexing is codec/format-ID-neutral, bounded to direct source offsets, supports ordered startup/late indexes and muxed audio-first track order, and does not affect classic MP4. Video keyframe verification above the container remains packet-based; audio/non-video fragmented seek uses timestamp landing.
- `symphonia-format-mkv`: exact 0.6.0 Matroska/WebM patch for `CodecState -> ResetRequired` ordering before dependent packets and container-owned structural EBML truncation. It is the single parser owner; details and removal gate: `mem:symphonia-demux/matroska-webm-s28b-2026-07-22`.
- `symphonia-codec-aac`: removes the upstream AAC-LC `channels.count() > 2` complexity guard and owns coded-order → canonical-plane mapping. For indexed `channel_configuration != 0`, coded position/type selects the destination plane; `element_instance_tag` is accepted with any 4-bit value and only participates in duplicate identity validation inside its element-type namespace. For 5.1 coded `FC,FL,FR,RL,RR,LFE` becomes canonical `FL,FR,FC,LFE,RL,RR` (`[2,0,1,4,5,3]`). Config 3–7, arbitrary-tag compatibility and duplicate-tag rejection have direct patch tests; the per-frame cursor also rejects incomplete/extra elements before synthesis. This mapping is required before any downstream layout-aware downmix; removing it silently swaps dialogue/LFE/surround roles. С 2026-10-16 патч также принимает AAC-LC с `channel_configuration = 0` + Program Config Element (так свежий ffmpeg пишет 5.1): `src/aac/pce.rs` разбирает ASC/GASpecificConfig/PCE (ограниченно, типизированные ошибки), сводит раскладку к индексной 1..=7 и переписывает 4 бита в копии extra_data до `AudioSpecificConfig::read` (upstream symphonia-common не патчится); совпадающий in-band ID_PCE пропускается, конфликтующий/неизвестный — Unsupported; side и back CPE считаются одной surround-парой; только LC. Фикстуры с тоном только в FC: `tests/fixtures/pce-5p1-fc-880hz.adts`, `symphonia-demux/tests/fixtures/subtitles/aac-pce-5p1.mkv` (`tests/aac_pce_playback.rs`). Без ASC (голый ADTS с config 0) по-прежнему не поддерживается. Внимание: в `crates/*-patch/target/` cargo пишет при `--manifest-path` — эти каталоги не коммитить (не в .gitignore).
