# Fastiplayer: субтитры (issue #1)

Подготовлено 11 октября 2026 по результатам трёх read-only исследований кода (медиа-стек и дорожки, рендер и наложение поверх кадра, UI/конфиг/поиск файлов). Код в сессии подготовки не менялся. Это задания для будущих сессий, а не отчёт о выполненной работе.

**Номера строк и факты — снимок на 11 октября 2026 (HEAD `478ca752`), перед правкой всегда сверять с текущим кодом.**

Цель — закрыть [issue #1](https://github.com/Bogdan7c/fastiplayer/issues/1): нативный Rust-движок субтитров, поддержка большинства форматов (включая YouTube и стриминг), собственная отрисовка поверх кадра на GPU, опубликованная матрица совместимости.

## Что уже есть (снимок)

- **Демуксеры уже видят субтитры, но выбрасывают их на выходе.** MKV-патч мапит `S_TEXT/UTF8`, `SSA`, `ASS`, `WEBVTT`, `HDMV/PGS` и др., `CodecPrivate` (заголовок ASS) сохраняется (`symphonia-format-mkv-patch/src/codecs.rs:180-192, 373-382`). MP4-патч знает `tx3g` → `CODEC_ID_MOV_TEXT` (`symphonia-format-isomp4-patch/src/atoms/stsd.rs:758-766`). Дальше `symphonia-demux/src/track_mapper.rs:282,292` превращает их в `Unsupported(Subtitle)`, а `packet_mapper.rs:55-70` отбрасывает пакеты.
- **`media_core::TrackKind`** — только `Video`/`Audio` (`media-core/src/track.rs:52-60`); у дорожек нет языка, названия, флагов default/forced.
- **`player-core`**: `PlayerCommand::SelectSubtitleTrack` (`command.rs:392`), `PlayerEvent::SubtitleTrackSelected` (`event.rs:200`), `snapshot.selected_tracks.subtitle_track` (`snapshot.rs:170`), `InstalledSubtitleRestore` — **заглушки**: обработчик (`session/runtime_control.rs:333-338`) только пишет значение в снимок. Выбор между запусками не сохраняется.
- **HLS** разбирает `EXT-X-MEDIA TYPE=SUBTITLES` до `InstalledHlsSubtitleRendition` (`media-source-open/src/web_media_hls_subtitles.rs`), дальше не идёт. **DASH** сознательно пропускает text AdaptationSet (`dash-mpd-core/src/parser/text_adaptation.rs`).
- **yt-dlp** не читает `subtitles`/`automatic_captions`; место в модели есть — `web-media-core/src/descriptor.rs:435` `SubtitleDescriptor`, `candidate.subtitles()`.
- **Шрифты**: своего стека нет; транзитивно через egui есть `skrifa`, `harfrust`, `ttf-parser`. Нет `fontdb`, `unicode-bidi`.
- **Рендер**: `render-wgpu-shell/src/shell.rs:466` `Renderer::render_frame` — проход видео → проход egui (`LoadOp::Load`) → проход маски углов окна (`window_corner_mask.rs`, образец отдельного GPU-прохода). Трейта рендерера нет; letterbox считается только в шейдере (`render-wgpu-video/src/video/mod.rs:921` `letterbox_scale_and_offset`), CPU-функции «прямоугольник картинки» нет.
- **UI**: кнопки транспорта стоят по абсолютным rect-ам от центра play (`app-egui/src/ui/player_controls.rs:136-237`, 1061 строка — **не раздувать**); справа от repeat только 12 pt и fullscreen. Меню выбора дорожек нет вообще (даже аудио). Иконки — только через `ui-artwork-egui`.
- **Конфиг** v12, шаблон добавления полей — коммит `7127795e`; окно настроек строится из дескрипторов, `section = "subtitles"` даст новую вкладку.

## Решения владельца (11 октября 2026)

**Движок**
1. **Всё на Rust**, свои модули, нейтральные: движок не зависит от wgpu/egui; выход — список полупрозрачных картинок с координатами относительно кадра, который умеет нарисовать любой рендер (wgpu сейчас, GLES2 #6 потом).
2. **ASS — порт libass на Rust до полного паритета**, слоями (08–10). libass под ISC — перенос разрешён с сохранением копирайта. C-зависимости libass заменяются Rust-аналогами: FreeType → `skrifa`, HarfBuzz → `harfrust`, FriBidi → `unicode-bidi`, fontconfig → `fontdb`. Код FFmpeg (LGPL) и VSFilter (GPL) **не копировать**.
3. **Эталоны libass**: скрипт один раз рендерит набор ASS через системный libass, PNG-эталоны кладутся в тестовые фикстуры; Rust-тесты сравнивают с допуском. В сборке и CI нет C-кода.
4. **PGS внутри MKV — делаем** (по спецификации, не по коду FFmpeg). VobSub — бэклог. Функциональность DVD/Blu-ray-дисков не делаем.
5. **Шрифты**: вложенные в MKV → системные → встроенный **Noto Sans** (OFL, полная кириллица).
6. **YouTube**: ручные + автоматические субтитры (включая автоперевод) с пометкой «(авто)»; формат **srv3, при недоступности — WebVTT**. Плюс **выбор языка аудио** для роликов с несколькими аудиодорожками (по возможности).
7. **Стриминг**: HLS WebVTT и DASH TTML/IMSC — в конце плана (13).

**Интерфейс**
8. **Кнопка CC** справа от repeat (с соблюдением центровки и отступов ряда), в стиле YouTube. **Видна только если у текущего ролика есть хоть одна дорожка** (встроенная, файл рядом, web); иначе исчезает полностью. Клик — вкл/выкл (подчёркнута, когда включена), стрелка ▾ рядом — меню: дорожки, «Отключить», «Загрузить файл…».
9. **Вид по умолчанию** — как YouTube: белый текст на полупрозрачной тёмной плашке; в режиме редактирования переключается на обводку.
10. **Режим редактирования** вызывается из настроек в сайдбаре (раздел «Субтитры»): видео на паузе, на нём образец субтитра в рамке — тащить = положение, тянуть угол/колесо = размер; маленькая панель: цвет текста, цвет и прозрачность плашки, плашка/обводка, «Сбросить», «Готово»; Esc — отмена.
11. **Настройки вида**: простые форматы (SRT/VTT/YouTube и т.п.) подчиняются полностью; ASS — только масштаб и вертикальный сдвиг основных реплик + флажок «принудительно мой стиль».
12. **Положение**: при появлении панели управления субтитры плавно поднимаются над ней; простые субтитры могут стоять на чёрных полосах; ASS и PGS всегда привязаны к кадру.

**Поведение**
13. **Файлы рядом**: имя начинается с имени видео (`Movie.srt`, `Movie.ru.srt`, `Movie.English.ass`) в той же папке и в подпапках `Subs`/`Subtitles`/… (включая `Subs/Movie/*.srt`); язык из суффикса.
14. **Автовыбор**: список предпочитаемых языков в настройках + плеер помнит, были ли субтитры включены; forced-дорожки показываются всегда.
15. **В объёме**: сдвиг синхронизации; бросок файла субтитров на окно (подключается к текущему видео); память выбора дорожек и сдвига для каждого видео; меню аудиодорожек.
16. **Горячие клавиши**: `C` — вкл/выкл, `V` — следующая дорожка субтитров, `Z`/`X` — сдвиг ∓0.1 с, `B` — следующая аудиодорожка.
17. **Финал — отдельная сессия edge cases** (14) перед итоговой приёмкой.
18. Работа в `main`, без веток и PR (правило владельца). Коммит — в конце сессии после зелёных проверок и ручной приёмки. Push — только по отдельному поручению.

Решения, которые ещё предстоит принять, отмечены в файлах сессий как **«Стоп: согласование с владельцем»**. До решения исполнитель не реализует спорную часть.

## Архитектура (целевая)

```
источники ─────────► subtitle-core ──► subtitle-raster ──► SubtitleOverlay ──► GPU-проход
 встроенные (demux)   модель, тайминг,   шрифты, шейпинг,    (картинки +         render-wgpu-shell
 файлы рядом          поиск реплик       раскладка, эффекты,  координаты,        (GLES2 — свой
 YouTube / HLS / DASH  по времени T       растеризация        нейтральный тип)    проход потом)
        ▲
 subtitle-formats (SRT, VTT, ASS/SSA, mov_text, srv3, TTML/IMSC, MicroDVD, SAMI, кодировки)
 subtitle-pgs (PGS → картинки)
```

Инварианты, которые нельзя нарушать:
- нейтральные crate-ы субтитров **не зависят** от wgpu, egui, winit и `render-*` (закрепить в `scripts/check-refactor-guardrails.py`);
- растеризация — **только при изменении** того, что на экране (новая реплика, анимация, размер окна, стиль); на обычном кадре — только отрисовка готовой текстуры. Никаких busy-poll и per-frame аллокаций;
- время показа — `pts` кадра, который реально рисуется, плюс сдвиг синхронизации; seek, пауза, скорость, смена media (`MediaInstanceId`) и смена дорожки не оставляют «залипших» реплик;
- субтитры рисуются **между видео и интерфейсом** — меню и кнопки всегда поверх;
- все лимиты (кэш глифов, размер вложенных шрифтов, размер файла субтитров, текстуры) — в конфиге, не хардкод;
- ошибка в субтитрах **никогда** не роняет и не останавливает воспроизведение видео: дорожка помечается недоступной, пользователь видит понятную причину.

## Как пользоваться

1. Начни новую сессию агента в репозитории Fastiplayer.
2. Приложи **только один файл сессии** из таблицы и скопируй абзац из его начала в сообщение.
3. Исполнитель читает этот README (разделы «Решения владельца», «Архитектура», «Общие правила») и `results/NN.md` сессий, от которых зависит текущая.
4. Проверь результат (особенно ручную приёмку) и только потом запускай зависимые сессии.

Формат выполнения (решение владельца): основной агент отвечает за архитектуру, согласование, проверку и ручную приёмку вживую; реализацию по частям ведут последовательные субагенты (модель Sonnet), широкое исследование — read-only субагенты.

## Общие правила для всех сессий

Работай в корне checkout репозитория. Сначала `AGENTS.md`. Перед кодом:
- Serena `initial_instructions`, активация проекта, `mem:core`, `mem:task_completion`, `mem:conventions`, `mem:testing/sandbox_policy` + memories, перечисленные в файле сессии;
- Context7 для каждой затрагиваемой внешней библиотеки (skrifa, harfrust, fontdb, unicode-bidi, encoding_rs/chardetng, wgpu, egui, quick-xml и т.п.). Если источник недоступен — назови препятствие;
- для порта libass — исходники libass (ISC) как первичный источник поведения; ссылку на версию/коммит libass записать в отчёт;
- широкий поиск по репозиторию — read-only субагентом (модель Sonnet), основной агент читает только точные символы;
- перед реализацией — короткое описание архитектуры: владелец состояния, boundary-методы, инварианты, тесты (правило 9 AGENTS.md).

Код:
- новая логика — у владельца состояния, не в самом удобном большом файле; файлы ≥ 700 строк не раздувать (hard limit 800, ratchet `scripts/module-size-baseline.json` обновлять при изменении legacy-файла);
- boundary API — самодокументирующиеся (enum/newtype/intent-method, без позиционных `bool`); absent / busy / fatal / no-op не сливаются;
- **тексты для пользователя — по-английски (как весь UI, решение владельца 14 октября 2026), человеческим языком**; технические детали — в лог (`tracing`), без путей к каталогам и секретов (подписанные URL субтитров YouTube — тоже секрет);
- русская документация ключевой логики и инвариантов; без `unwrap/expect/panic` в production (`mem:panic-invariant-policy`);
- новые зависимости — только чистый Rust, лицензии совместимы с MIT (проверить `cargo deny`), зафиксировать в отчёте;
- косметический рефакторинг вместе с фичей запрещён.

Тесты: проверяют наблюдаемый результат (картинка субтитра, текст реплики в момент T, пиксели в кадре после GPU-прохода, состояние меню, событие), а не факт вызова. Обязательный функциональный тест каждой сессии с выводом на экран — **субтитр реально доходит до кадра** (readback пикселей после прохода, как тесты `window_corner_mask.rs`). Для каждого нового boundary — отсутствующий ресурс, fake/stub, ошибка, edge-case accounting, «не трогает чужое состояние». Перед завершением теста — мысленная мутация: «если сломать функцию, тест упадёт?».

Фикстуры: маленькие, сгенерированные или со свободной лицензией; бинарники фикстур — только в тестовых каталогах crate-ов, **никогда в `user/`**.

Проверки (минимум):
1. `cargo test -p <затронутые crate-ы> --locked`, затем соседние потребители изменённых контрактов;
2. `cargo fmt --all --check`, `scripts/ci-checks.sh clippy`, `scripts/ci-checks.sh tests`;
3. при изменении публичных типов/нескольких crate-ов — `cargo +1.99.0 check --workspace --locked`, `scripts/check-refactor-guardrails.py`;
4. полный `bash scripts/pre-pr-checks.sh` перед коммитом (известный FAIL `dependencies` — старые advisories, не блокер, если не появилось новых);
5. ручная приёмка по сценарию из файла сессии (GUI, реальные файлы, KDE Plasma Wayland и X11).

Выходной барьер каждой сессии — `results/NN.md` (60–120 строк): статус PASS / BLOCKED / PARTIAL; принятые решения владельца; SHA; изменённые файлы и символы; результаты проверок (PASS / FAIL / NOT RUN с причиной); сценарий ручной приёмки и итог; открытые риски; обновление черновика матрицы совместимости. В конце — self-review диффа и обновление Serena memories, если изменились boundary/API/инварианты (иначе явно написать, что не требовалось).

## Бэклог (в план сознательно не включено)

- VobSub (`.idx/.sub`), DVB-субтитры в MPEG-TS, субтитры в FLV.
- Функциональность DVD/Blu-ray-дисков (меню, навигация).
- Генерация субтитров в реальном времени (идея владельца после релиза).
- Субтитры в скриншотах/экспорте кадра — экспорта кадра в production пока нет.
- Субтитры для видеоредактора Fasticut — движок нейтральный, переиспользование отдельной задачей.

### Найдено в сессии 14 (edge cases) и сознательно не исправлено

Подробности и доказательства — в [`results/14.md`](results/14.md).

- **Цветные эмодзи** (COLR/CBDT/sbix): рисуются одноцветным контуром — это новая функция растеризатора, а не пограничный случай.
- **WebVTT `vertical`**: разбирается, но рисуется горизонтально (редкий формат).
- **ASS `Fontsize: 0`**: libass рисует буквы ~16 px, мы — нет. Нужен эталон системного libass, без него правку не делать.
- **Короткие файлы в cp1251** определяются как cp1252, а польский/греческий без языка в имени читается как cp1251 — ограничение эвристики на коротком тексте. Решение на будущее: показывать «прочитано как X» с выбором кодировки.
- **Отрицательное время в SRT/WebVTT** (`-00:00:01,000`): реплика отбрасывается целиком, а не прижимается к нулю.
- **Двойной учёт памяти кэша реплик и кэша слоёв ASS**: реальная память ограничена (замер: ровные ~54 МБ), но бюджет `render_cache_mb` вытесняет раньше, чем мог бы. Попытка вычитать общие байты отклонена: если запись общего кэша вытеснена раньше, кэш реплик держал бы её буферы «бесплатно» и память перестала бы быть ограничена. Нужен учёт по владению буфером, а не по месту создания.
- **Атлас субтитров на GPU только растёт** (до 64–256 МБ видеопамяти после одной огромной картинки PGS) — сжимать при смене media.
- **Два системных шрифта с одним именем семейства**: выбор зависит от порядка fontdb (не отсортирован).
- **Смена скорости 4× → 1×**: на окне рисования наперёд анимация ASS короткое время грубее (интервалы, посчитанные по старому шагу кадров).
- **После выключения дорожки** поток-рисовальщик дорисовывает горизонт и держит зеркало до смены media (лишняя работа, картинка не залипает).
- **Рамка режима правки во время seek** стоит по последнему известному прямоугольнику картинки.
- **Esc при сфокусированном виджете** сначала снимает фокус, второй Esc выходит из фуллскрина/правки (осознанное поведение горячих клавиш).
- **Каталог с более чем 5000 файлов**: лимит записей применяется до сортировки, нужный файл рядом может не найтись.
- **Зависшая сетевая ФС** (NFS/sshfs) при чтении файла субтитров: выход приложения ждёт фоновый поток.
- **HLS VOD**: окно подгрузки ленты считается по сумме `EXTINF` плейлиста субтитров; при сильном расхождении с видео окно смещается (времена реплик точные).
- **Дорожки, появившиеся позже через `TracksChanged`**, по-прежнему без ASS-заголовка (рисуются без стилей); реальный источник — только MPEG-TS live с растущим PMT.
- **Бросок «видео + субтитры» одним жестом**: неудачный файл субтитров виден только серой подсказкой в меню, без всплывающего сообщения.
- **Позиция и длительность TS** в интерфейсе — сырое время контейнера (на старте 1,4 с); субтитры рядом с видео поправлены (сессия 14), нормализация шкалы плеера — отдельная задача. 192-байтный M2TS не открывается вовсе.
- **Перенос CJK**: без словарной сегментации, тайский и кхмерский без пробелов не переносятся; ASS остаётся как libass.
- **Прогрев шрифтов** заполняет поиск глифов только для основного шрифта по умолчанию (ASS с `\fn` получает готовое лицо, но не готовый поиск); польза на настоящем `.ttc` замеряется вживую.
- **Плавающие GPU-тесты под тяжёлой параллельной нагрузкой** (`stream_gpu::live_history_rebuild_…`, `stream_dash_gpu::real_dash_*`, `stream_hls_vertical::…`, `startup_import` таймаут 2 с) — падают и на коде до сессии 14 (до 5 из 60 прогонов с `--test-threads=64`).
- **Сравнение CPU с mpv** не делалось — CPU-работа отложена до предрелизной полировки (решение владельца).
- **Боковые полосы у вертикального видео**: простые субтитры шириной в картинку — решение владельца 19 октября 2026: оставить как есть.
