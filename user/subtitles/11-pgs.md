## Границы

**Зависит от:** 06 (PASS).

**Memories:** встроенные дорожки из 06, `subtitle-core`.

**Разрешено:** новый crate `crates/subtitle-pgs` (нейтральный): сегменты PCS/WDS/PDS/ODS/END, RLE-декодирование, палитра YCbCr → RGBA с учётом матрицы цвета (BT.601/709 по размеру видео — как принято в плеерах), композиция объектов и окон, forced-флаг объектов; выход — тот же `SubtitleOverlay` (картинка RGBA или маска + палитра — по контракту 02, при необходимости контракт расширяется осознанно); масштабирование картинки в кадр при несовпадении размеров; пользовательский масштаб/сдвиг не применяются (решение 11 README) — уточнить на стопе.

**Запрещено:** копирование кода FFmpeg `pgssubdec.c` (LGPL); VobSub/DVB (бэклог).

## Задание

### Часть A
1. Источник — публичное описание формата (US-патент/документация BD-ROM, разборы формата); перечислить использованные источники в отчёте.
2. Время показа: PGS-«эпохи», конец показа по пустой композиции; поведение при seek (нужна последняя «эпоха» до позиции).
3. Расширяет ли PGS контракт `SubtitleOverlay` (полноцветная картинка) — решить без ломки GLES2-совместимости.

### Стоп: согласование с владельцем
Применять ли к PGS пользовательский масштаб и вертикальный сдвиг (рекомендация: только вертикальный сдвиг, если картинка внизу кадра — решить).

### Часть B. Реализация
По согласованному; битый сегмент → пропуск с подсчётом.

## Тесты
- синтетический поток PGS (сгенерированный тестом) → картинка с ожидаемыми цветами/позицией;
- **функциональный**: MKV с PGS-дорожкой → пиксели субтитра **в кадре** в момент показа и отсутствие после пустой композиции;
- forced-объекты показываются при «субтитры выключены», если дорожка помечена forced (решение 14 README);
- seek внутрь показа → картинка видна в первом кадре после seek (если «эпоха» прочитана) — ограничения описаны честно.
