## Задание

### Часть A. Архитектура
1. Кто владеет временем показа: `pts` кадра, который реально уходит в рендер, + сдвиг; что происходит на паузе, seek, при смене media (`MediaInstanceId`) — реплики старого media не показываются ни одного кадра.
2. Где живёт растеризация: не на UI-потоке, если реплика тяжёлая (оценить; для простого текста допустимо синхронно с бюджетом времени — замерить и решить).
3. Загрузка в GPU: атлас/текстура, обновляется только при `changed`; на обычном кадре — один draw.
4. Контракт для будущего GLES2: что рендер получает (тот же `SubtitleOverlay` + прямоугольник картинки + размер экрана).

### Стоп: согласование с владельцем

### Часть B. Реализация

## Тесты
- **функциональный**: локальная фикстура-видео + `Movie.srt` рядом → после открытия и воспроизведения readback кадра показывает пиксели субтитра в нижней части картинки в момент реплики и не показывает вне её;
- пауза на реплике → субтитр остаётся; seek за реплику → исчезает в первом же кадре после seek;
- смена media → реплики старого не появляются;
- letterbox 2.39:1 в окне 16:9 → субтитр внутри/на полосе по правилу 12 README;
- поиск рядом: `Movie.srt`, `Movie.ru.srt`, `Subs/Movie.en.srt`, `Subs/Movie/2_English.srt` находятся; `Other.srt` — нет; не-UTF-8 имя не искажено;
- кадр без субтитров не делает лишней загрузки текстур (счётчик загрузок = 0).

## Ручная приёмка (KDE Plasma, Wayland и X11)
Фильм с `.srt` рядом: субтитры появляются вовремя, исчезают вовремя, seek/пауза/фуллскрин/изменение размера окна корректны; загрузка CPU во время показа субтитров сравнима с воспроизведением без них.
