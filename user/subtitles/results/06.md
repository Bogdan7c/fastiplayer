# Результат сессии 06: встроенные дорожки MKV/MP4, вложенные шрифты, метки дорожек

## Статус

**PASS**: автоматические проверки и ручная приёмка в живом окне на KDE Plasma Wayland и X11 (XWayland). По поручению владельца приёмку провёл агент: uinput-клавиатура и указатель, скриншоты spectacle, изолированный конфиг. Коммит — после решения владельца, push не делался.

## Решения владельца (15 октября 2026)

1. **В приложение передаются пакеты всех субтитровых дорожек**, а не только выбранной. Реплики каждой дорожки кэшируются, поэтому смена дорожки мгновенная, а seek назад показывает реплику из кэша на любой дорожке.
2. **Неподдерживаемые дорожки** (PGS до сессии 11, VobSub, DVB и прочие) видны в меню CC серыми, с пометкой «not supported yet».
3. **Автовыбор**: при одинаковом языке файл рядом важнее встроенной дорожки.
4. **Вложения MKV больше лимита не загружаются в память**. Для этого сделана additive-правка MKV-патча. Лимиты в конфиге: 20 МБ на вложение, 100 МБ всего.
5. **Приёмку вживую проводит агент.**

Исполнитель решил сам:
- реплика без длительности показывается в течение `embedded_cue_max_open_duration_ms` (по умолчанию 5 с), а не «до следующей реплики»;
- белый цвет mov_text по умолчанию считается «цвет не задан», иначе он перебивал бы цвет пользователя;
- флаг дорожки «по умолчанию» решает при равенстве языка;
- маленькие сгенерированные фикстуры лежат в тестовом каталоге crate-а (по правилам README плана).

## Что сделано

- **media-core**: `TrackKind::Subtitle`.
  - Метки `TrackLabels` (язык, название, флаги default/forced/SDH/commentary) у **всех** дорожек.
  - Константы кодеков субтитров `subtitle_codec` и `classify`.
  - Вложения `MediaAttachments`, метод `Demuxer::take_attachments()`.
- **symphonia-demux**: субтитровые дорожки и пакеты больше не выбрасываются.
  - Метки берутся из Symphonia `Track` и из названия, которое отдаёт MKV-патч.
  - Лимиты вложений задаются в `DemuxerOptions`.
  - Субтитры никогда не служат якорем seek.
- **MKV-патч (additive)**:
  - `Name` дорожки передаётся тегом `fastiplayer.track.name`.
  - Вложения сверх лимита пропускаются без чтения. Лимит передаётся через область на потоке вокруг `Probe`, потому что общий механизм открытия Symphonia не даёт передать параметр.
  - Исправлен `FlagDefault`: если элемента нет, по спецификации это «да».
  - **isomp4-патч**: язык из `mdhd`.
  - `docs/dependency-patches.toml` обновлён.
- **player-core**: труба субтитров `subtitle_feed/`.
  - Пакеты идут мимо декодеров, ограниченная очередь, запись никогда не ждёт. Переполнение — выброс со счётчиком.
  - Сообщение о начале media с вложениями отправляется при установке.
  - `TrackSummarySnapshot.labels`.
- **subtitle-formats**: `parse_embedded_cue` — одна реплика из пакета: SRT-текст, WebVTT, строка ASS (только текст), mov_text со стилями `styl`.
- **subtitle-raster**: вложенные шрифты в три шага — подготовка в фоне (`PreparedAttachedFonts`), быстрая установка, `clear_attached_fonts()` при смене видео.
- **app-egui** (`state/subtitles/`): `embedded_track.rs`, `embedded_events.rs`, `owner_embedded.rs`, `embedded_fonts.rs`.
  - Встроенные дорожки в меню с пометкой «embedded».
  - Кэш реплик каждой дорожки.
  - Автовыбор с учётом происхождения дорожки и флага default.
  - Шрифты-вложения.
- **Конфиг v15** `[subtitles]`: `max_attached_font_mb`, `max_attached_fonts_total_mb`, `embedded_feed_capacity`, `embedded_cue_max_open_duration_ms`. Миграция v14→v15 без переписывания значений.
- `docs/subtitles/compatibility.md` — встроенные форматы и ограничения.

Наблюдения вне объёма сессии:
1. **MKV с главами после ffmpeg-ремукса не открывается** («mkv: missing edition uid»). Ошибка есть и в базовом коммите. MKV-патч требует `EditionUID`, хотя по спецификации Matroska, насколько я помню, это необязательное поле. Для приёмки файлы собраны без глав. Предложение — отдельная правка.
2. **Клик по бегунку времени uinput-указателем не перематывает**: надпись времени застревает на цели. Повторяется на сборке из базового коммита, поэтому к сессии не относится. Похоже на особенность тестового драйвера. Перемотка в приёмке делалась клавишами.
3. **Серые неподдерживаемые дорожки вживую не проверены**: ffmpeg не умеет получать VobSub из текста. Поведение покрыто тестами меню.

## Открытые риски

- В web-MKV (Progressive/OrderedSegment demuxer) вложения не передаются: `take_attachments` не пробрасывается.
- Дорожки, появившиеся позже через `TracksChanged`, получают реплики, но не шрифты.
- ASS рисуется стилем по умолчанию. Шрифт по имени стиля не выбирается до сессии 08, поэтому вложения сейчас работают только через подбор шрифта по глифу.
- WebVTT внутри MKV — без настроек позиции: Symphonia их не передаёт.
- Ёмкость трубы применяется после перезапуска приложения.
- Медиа со встроенными текстовыми дорожками запускает фоновую сборку растеризатора (~90 мс один раз), даже если субтитры не включены.
- Внутренние пределы остались константами: 2048 сообщений за кадр, буфер ожидания 4096, 256 лиц на вложения.
