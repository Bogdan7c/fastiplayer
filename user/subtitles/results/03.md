# Результат сессии 03: первые субтитры на экране

## Статус

**PASS**: автоматические проверки, real-media тест и ручная приёмка в живом окне на KDE Plasma Wayland и X11 (по поручению владельца её прогнал агент: uinput-клавиатура + скриншоты). Приёмка нашла и закрыла дефект выбора шрифта CJK (сессия 02). Push не делался.

## Решения владельца (15 октября 2026)

1. **Поиск файлов рядом — отдельной фоновой задачей после установки файла в плеер** (а не в пути подготовки открытия): одна точка для всех способов открыть файл (Open, бросок, следующий в плейлисте, пересборка после настроек, resume).
2. **Растеризация — сразу на потоке UI, только при изменении, с замером** (бюджет 8 мс → warn). Отдельный поток — если понадобится для тяжёлого ASS (08).
3. **Функциональный тест — цепочка без медиафайлов + тест на настоящем видео.** Видео с субтитрами скачано в `test-assets/subs/` (git-ignored): «Sintel» (Blender Foundation, CC-BY 3.0) + официальные субтитры; 12 сценариев на все поддерживаемые сейчас форматы, кодировки и места.

4. **Вариант иероглифов CJK — по языку дорожки, если неизвестен — по языку системы** (как fontconfig/libass). Сделано в этой сессии.
5. **Разовые ~12–14 мс на первой CJK-реплике (чтение ~20 МБ шрифта) — отложено в сессию 14**: прогрев в фоне, но продумать, как не бить по ресурсам. Записано в `14-edge-cases.md`.

Исполнитель решил сам: логика поиска — в маленьком нейтральном crate `subtitle-sidecar`; субтитры рисуются внутри картинки (полосы и подъём над панелью — сессия 05); лимиты — именованные константы в одном модуле до конфига в 04; временный автовыбор — первый показываемый кандидат.

## Что сделано

- **`render-core`** — `PictureSize`/`PictureRect`/`PictureLayout` (`picture_rect.rs`): единственная формула «картинка без полос». `letterbox_scale_and_offset` в `render-wgpu-video` делегирует ей; uv бит-в-бит прежние (тест на сетке 12⁴ размеров).
- **`render-wgpu-shell/src/subtitle_overlay/`** — проход между видео и egui: R8-атлас масок (shelf-упаковка, растёт ×2), один draw с instance-ами, premultiplied-блендинг, scissor по области видео. Загрузка в GPU только при смене содержимого (revision + идентичность масок); сдвиг картинки — только 16-байтный uniform. `RenderFrameInput.subtitle_overlay`, стадия `subtitle_overlay` в timings, `SubtitleOverlayUploadStats`. `SubtitleOverlayRenderer` публичный — переиспользуемая wgpu-реализация контракта.
- **Контракт для второго рендера (GLES2, #6):** `SubtitleOverlay` + `PictureRect` + размер экрана; (0,0) холста = левый верх картинки, округлённый до пикселя, 1 px холста = 1 px экрана.
- **`crates/subtitle-sidecar`** (новый, deps `subtitle-core`, `thiserror`; guardrails allowlist + тест «wgpu запрещён»): `find_sidecar_subtitles` по решению 13, лимиты от вызывающего, отчёт об усечениях и нечитаемых папках, отмена, пути без потерь.
- **`app-egui/src/state/subtitles/`** — `SubtitleOwner` (Idle / Loading / Ready / NoSubtitleFile / Unavailable), фоновая задача (поиск → чтение с лимитом → разбор → таймлайн; первая задача строит библиотеку шрифтов с системными), `AppWakeOwner::Subtitles`, презентатор по кадру. Запуск — `record_installed_media_observables` (`media_jobs.rs`), подключение — `frame_prepare/submit.rs`. `frame_prepare.rs` и `ui_runtime.rs` не тронуты.
- `render-wgpu-shell/src/shell.rs`: чтобы остаться под 800 строк, `choose_surface_format` с тестами перенесён в `surface_settings.rs` (без изменения поведения). `RenderFrameOutcome` — `#[expect(clippy::large_enum_variant, reason)]` вместо Box-аллокации на каждый кадр.
- **Исправление `subtitle-raster` (найдено на приёмке):** системный запасной шрифт выбирался «первым по индексу, где есть символ» без учёта веса — японский рисовался Noto Sans CJK **Black**, а 人 — шрифтом Nushu. Теперь (`fonts/system_fallback.rs`) кандидаты ранжируются как в libass/fontconfig: наклон → язык → ближайший OS/2-вес → семейство/путь; плюс непрерывность — сначала уже использованные в реплике системные лица (`ass_font_get_index`). Язык лица — из OpenType `meta.dlng`, иначе по меткам семейства (JP/SC/TC/HK/KR) (`fonts/face_language.rs`). `RenderRequest.text_language: TextLanguagePreference` (`track_then_system`: CJK-язык дорожки, иначе язык системы); язык системы читается один раз при старте (`state/subtitles/system_language.rs`, `LC_ALL`/`LC_MESSAGES`/`LANG`). Кэш поиска глифов учитывает язык.
- `docs/subtitles/compatibility.md` — раздел «On screen» и таблица файлов рядом.
- Пример замера: `cargo run -p subtitle-raster --release --locked --example measure_render_time`.

## Инварианты (как обеспечены)

- Время = pts кадра, который реально уходит в рендер (через `SubtitleSyncOffset`, пока 0). Пауза → тот же кадр → тот же overlay без растеризации и загрузки. Seek → кадр-заглушка без субтитров, первый новый кадр — реплика по своему pts.
- Реплики старого файла не показываются: overlay только если `MediaInstanceId` владельца = snapshot И `render_generation` кадра = snapshot; поздние результаты задачи старого media выбрасываются.
- Ошибка субтитров не трогает воспроизведение: дорожка `Unavailable` с типизированной причиной, warn без пути и текста.

## Открытые риски

- **pts кадра — «сырое» время контейнера.** У MPEG-TS/M2TS с ненулевым стартом sidecar разъедется на величину старта (у всех проверенных MKV/MP4/WebM старт 0). Нормализации времени старта нет во всём плеере; поправка вносится в одной точке (`SubtitleSyncOffset`/lookup). Предложение — сессия 14 или отдельное решение владельца.
- Субтитры на нижнем краю картинки могут уходить под панель управления, если картинка заполняет окно по высоте — подъём над панелью в сессии 05.
- Временный автовыбор берёт первый файл по байтовому порядку имени (в сценарии 02 — `Ukrainian` раньше `ru`); выбор по языкам — 04.
- Тест на настоящем видео проверяет поиск, кодировки, время и пиксели прохода, но не декодирование кадра (нужен отдельный MKV-харнесс). Связка «кадр → субтитр» вживую проверена ручным прогоном.
- Первая CJK-реплика разово готовится 12–14 мс (вживую; чтение ~20 МБ `.ttc`) → один пропущенный кадр за запуск + warn. Решение владельца — в сессию 14 (прогрев в фоне с учётом ресурсов).
- Язык на уровне отдельного спана (WebVTT `<lang>`) в выборе шрифта пока не учитывается — в модели `TextSpan` нет поля языка; учитывается язык дорожки/системы.
