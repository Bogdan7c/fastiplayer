# Результат сессии 14: edge cases субтитров

## Статус

**PASS**: все исправления сделаны и закоммичены, автоматические проверки зелёные (см. «Проверки»). Ручную приёмку вживую на KDE Plasma (Wayland и X11) по поручению владельца 19 октября 2026 провёл агент. Все сценарии прошли, кроме переноса окна между мониторами: на стенде один монитор (см. «Ручная приёмка»). Дефектов в исправлениях сессии приёмка не нашла. Попутно она нашла три старых дефекта, все три закрыты в этой же сессии по решению владельца (см. «Находки приёмки»). Push не делался.

## Как шла работа

1. **Аудит.** Пять параллельных read-only субагентов (Sonnet) проверяли каждый своё направление чек-листа: файлы и форматы, растеризатор и ресурсы, время и поток-рисовальщик, источники, экран и UI. Почти все пункты проверены прогоном: scratch-проекты через публичный API, замеры, тесты. Самые серьёзные находки основной агент перепроверил сам.
2. **Согласование.** Таблица находок обсуждена с владельцем простым языком, владелец выбрал объём.
3. **Исправления.** Последовательные и параллельные субагенты-исполнители правили непересекающиеся файлы. Основной агент делал ревью диффа, раскладывал правки по отдельным коммитам и проверял каждый промежуточный коммит в отдельном worktree.

## Решения владельца (18–19 октября 2026)

- Чинить весь список «сейчас» (таблица ниже), остальное — в бэклог README.
- Прогрев CJK-шрифтов делаем лёгкий: только нужные лица, только для показанной дорожки, только в простое рисовальщика.
- Старт контейнера MPEG-TS чиним в этой сессии: новое поле в границе `media-core`, поправка только для файлов рядом и брошенных.
- Перенос CJK без пробелов чиним для простых форматов, ASS остаётся как в libass.
- Субтитры вертикального видео на боковые полосы не выпускаем, оставляем как есть.
- Раздвигание ASS-реплик после перемотки: при каждой новой цели память стирается, отличие от libass документируется.

Остальные находки аудита ушли в бэклог README («Найдено в сессии 14»), у каждой указана причина. Проверено и оказалось в порядке:

Паник не нашлось ни на мусорных входах, ни на испорченных шрифтах.

Все три были и до сессии 14 (проверено на сборке `9b6b5279`). Владелец поручил закрыть их сразу, сабагентами: сначала read-only исследование корневой причины, потом исполнитель, затем ревью и проверка каждого коммита в чистом worktree.

## Открытые риски

- Бюджет перебоя ленты считается с первого сбоя. Последний запрос держится на HTTP-таймаутах, поэтому худший случай — «бюджет + время запроса».
- Прогрев шрифтов заполняет поиск глифов только для основного шрифта по умолчанию. Польза на настоящем `.ttc` не замерена: в тестах нет системных CJK-шрифтов.
- Старт TS у неперематываемого byte stream уточняется по мере чтения, а плеер берёт метаданные один раз при установке. Для локальных файлов это не так: их старт известен после начального скана.
- Пустой `.srt` рядом с видео теперь показывается как недоступная дорожка с причиной, а не как пустая.
- GPU-тесты app-egui под тяжёлой параллельной нагрузкой плавают и на коде до сессии (бэклог).
