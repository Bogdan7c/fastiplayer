## Найдено и исправлено

1. **rustdoc падал** (этап `docs` в `ci-checks.sh`). Ссылка на приватную константу `MAX_AGGREGATED_LIST_ENTRIES` в документации публичного `PlayerTickResult::absorb` (`player-core/src/session/tick/result_merge.rs`). Внесено коммитом `ec65c597` после приёмки 14; в сессии 14 этап `docs` прогонялся раньше этого коммита. Исправлено: ссылка заменена текстом.
2. **Нативный DASH не открывал обычный MPD от `ffmpeg -f dash`.** Ошибка «component selection shape is not consistent with catalog layout», видео не играло вовсе. Это давний дефект, не регрессия субтитров: без текстовой дорожки падало так же. Причину нашли read-only субагенты, исправили исполнители (Sonnet), ревью и живая проверка — основной агент. Цепочка:
   - звук у ffmpeg стартует на 0,2257 с позже видео, поэтому в MPD первый `S@t=10832`, а хвост выступает за конец Period;
   - строгое правило «static Period покрыт ровно от начала до конца» отбрасывало звуковую дорожку;
   - для оставшегося «только видео» в каталоге Topology у `build_presentation` не было ветки.

   Исправлено:
   - допуск покрытия Period — не больше одного сегмента в начале и в конце, длительность обрезается по Period; только static, живые потоки без изменений;
   - выбор «только видео / только звук» на каталоге Topology, с фильтрацией по допустимым строкам.
3. **Звук MP4/fMP4 спешил до ~0,3 с** — найдено при исправлении 2. ffmpeg записывает задержку звука пустой правкой `elst` (пауза перед дорожкой), а сдвиг B-кадров видео — правкой с `media_time`. Патч symphonia isomp4 правки не читал (`edits are not currently supported`). Затронуты локальные MP4, HLS fMP4 и DASH.
   - Решение владельца: чинить в демуксере MP4 по ISO/IEC 14496-12 §8.6.6.
   - Поддержана частая форма: ведущие пустые правки плюс одна обычная со скоростью 1. Остальные формы игнорируются, как раньше, с предупреждением в логе. Обрезка priming-кадра (`trim_start`) не подключена: media-core не несёт trim.
   - До и после на файлах Sintel (первый пакет через production `SymphoniaDemuxer`): видео 83 мс → 0, звук 0 → 225,667 / 725,667 мс — совпадает с `ffprobe start_time`.

   Тесты:
   - патч: `src/edit_list/{tests,reader_tests}.rs`;
   - нейтральная граница: `symphonia-demux/tests/edit_list_av_sync.rs`, настоящая ffmpeg-фикстура на 4 КБ;
   - DASH: `web-media-dash/src/tests/priming_av.rs` — настоящий вывод ffmpeg через production `prepare_dash_vod`;
   - `plan/timeline_coverage_tests.rs`, `representation_catalog.rs`, `component_variants_single_axis_tests.rs`.

   Все функциональные тесты падают без исправления (проверено временным отключением).

   Вживую, release-сборка:
   - исходный MPD от ffmpeg открывается: AAC-декодер и аудиовыход созданы, длительность 2:00, TTML-регион сверху на месте;
   - локальный MP4 со звуком, сдвинутым на 0,73 с, играет, четыре перемотки садятся на ключевые кадры.

   Синхрон на слух и глаз не измерялся. Его доказывают тесты и сверка первых таймстемпов с `ffprobe`.

## Черновик комментария для закрытия issue #1

Опубликован основным агентом по поручению владельца при закрытии issue.

> The native Rust subtitle engine is in `main` and is planned for **0.2.0**. The published compatibility matrix is in [`docs/subtitles/compatibility.md`](https://github.com/Bogdan7c/fastiplayer/blob/main/docs/subtitles/compatibility.md), and the user guide is in [`docs/subtitles/user-guide.md`](https://github.com/Bogdan7c/fastiplayer/blob/main/docs/subtitles/user-guide.md).
>
> **What ships**
> - Formats: SRT, WebVTT, ASS/SSA (a port of libass 0.17.5 behaviour), PGS inside MKV, MP4 `mov_text`, YouTube srv3, TTML/IMSC.
> - Sources: files next to the video, dropped files, embedded MKV/MP4 tracks with attached fonts, YouTube manual / automatic / auto-translated captions, HLS WebVTT and DASH text tracks.
> - Controls: a CC button and menu, hotkeys (`C` `V` `Z` `X` `B`), on-video appearance editing, auto-selection with forced tracks, and per-video memory of the track and delay.
> - Separation: parsing (`subtitle-formats`, `subtitle-pgs`), the model and timing (`subtitle-core`), fonts and rasterization (`subtitle-raster`), and file discovery (`subtitle-sidecar`) are independent of the GPU and UI, which a guardrail enforces. One wgpu pass draws between the video and the interface.
>
> **Acceptance criteria**
> - [x] Supported fixtures render at the correct playback time, including seek and track changes. GPU read-back tests cover every source, and a final live pass ran on Wayland and X11.
> - [x] Styled and bitmap references have reproducible visual checks. ASS is compared with 327 libass 0.17.5 reference images (the regeneration script is in `scripts/subtitle-reference/`), and PGS is checked pixel by pixel. Malformed input fails safely with typed errors and counters, and a subtitle failure never stops playback.
> - [x] The matrix and its known limits are published, without claiming every historical format. VobSub, DVB, `.sup` files and legacy text formats are listed as not supported.
>
> The work was planned and reported in public: [`user/subtitles/`](https://github.com/Bogdan7c/fastiplayer/tree/main/user/subtitles) has 15 sessions, with reports in `results/`. Known gaps are tracked there and in the matrix.
