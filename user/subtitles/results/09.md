# Результат сессии 09: ASS/SSA, слой 2 (геометрия и время) + поток-рисовальщик

## Статус

**PASS** по автоматическим проверкам и ручной приёмке, которую агент провёл вживую по поручению владельца (KDE Plasma Wayland и X11/XWayland). Сессия закоммичена двумя коммитами в `main`, push не делался.

## Решения владельца (17 октября 2026)

1. **Бюджет тяжёлых сцен.** Растеризатор субтитров уезжает из UI-потока в отдельный поток сразу, в этой сессии. План этого не предусматривал: владелец отметил, что производительность и синхронность с видео заранее не продумали.
2. **Синхронность с видео обязательна** при игре, seek, **перетаскивании по таймлайну** и **любой скорости воспроизведения**.
3. **Промах.** Если нужная картинка ещё не готова, показывается последняя показанная **без реплик, которые уже закончились**. Новая реплика может появиться кадром позже, но ничего не мигает и не «залипает», а UI не ждёт.
4. **Два коммита.** Этап 1 — поток без новых тегов. Этап 2 — теги слоя 2 и анимации.

Исполнитель решил сам и озвучил владельцу: события с `\org`, поворотом или наклоном — «надписи» (группа `Fixed`), над панелью не поднимаются. Из раздвигания реплик, как в libass, исключаются только `\pos`, `\move` и `\org`.

## Что сделано

**Источник поведения** — libass **0.17.5** (commit `4a05d8127f525943ebf45fdc6497c9e665947f0d`, ISC). ISC-шапки стоят в перенесённых файлах. Код FFmpeg, VSFilter, FreeType и HarfBuzz не копировался.

**Этап 1: поток-рисовальщик** (`app-egui/src/state/subtitles/render_worker/`, `presentation/`).
- Поток `subtitle-render` владеет `SubtitleRasterizer`, а UI выбирает готовую картинку из очереди и никогда не ждёт.
- **Срок годности картинки** — интервал `[rendered_at, valid_until)` по смене реплик (`next_change_after`). Статичная сцена растеризуется один раз.
- **Рисование наперёд** на `prerender_frames` кадров. Шаг берётся из наблюдаемых pts соседних кадров, поэтому на любой скорости и при пропуске кадров он растёт сам.
- **seek и scrub:** сначала рисуется цель, побеждает самая свежая. Опорное время планирования единое для потока и для очереди UI.
- **Ушедшие реплики** вырезаются из картинки через `SubtitleOverlay::retain_cues`: картинки знают свою реплику (`SubtitleBitmap::cue_key`).
- **Зеркала дорожек** в потоке сверяются по паре `source_id` + длина таймлайна (дописывание встроенных реплик — дельтой). Запоздавшие картинки отсекаются по `mirror_serial`.
- **Отказ потока** делает дорожку недоступной с понятной причиной, видео продолжает играть.
- **Конфиг v19:** `prerender_frames` (4), `prepared_overlays` (8). Миграция не переписывает существующие значения.

**Этап 2: теги слоя 2.**
- **subtitle-core.** Новые варианты `AssOverride::{Rotation, Shear, Origin, Fade}` (файл `ass/geometry_tags.rs`). `\frx..\org`, `\fad` и `\move` убраны из «не поддержано».
- **subtitle-raster:**
  - порт `calc_transform_matrix` (`glyph_transform/rotation.rs`);
  - 3D-трансформ контуров;
  - глиф за камерой отбрасывается;
  - `apply_baseline_shear` (`layout/baseline_shear.rs`);
  - центр поворота — `\org` или точка выравнивания, тень крутится вместе с текстом (`compose/rotation.rs`);
  - плашка BorderStyle 3 поворачивается.
- **Анимации** (`ass/animation.rs`, `event_fade.rs`):
  - `\move` (4 и 6 аргументов, перестановка t1/t2, первый тег побеждает у `\pos`);
  - `\fad` и `\fade` — у каждого глифа, как в libass: затухание задаётся в месте тега, участок берёт затухание первого глифа;
  - `mult_alpha` ко всем цветам и к плашке.
- **Граница растеризатора:** `RenderRequest.moment`, `AssEventTiming`, `AnimationChange { None, EveryFrame, At(t) }`, `SubtitleOverlay::animation_change()`. Быстрый путь кадра обслуживает статичные сцены без работы, а анимированные — пока картинка ещё верна.
- **Кэш реплик.** Анимированная реплика ключуется своим состоянием (позиция, альфа). Статичная получает ключ без времени.
- **Защита.** Глиф, у которого после 3D-трансформа сторона картинки больше `max_canvas_side`, пропускается до выделения памяти (`RasterStatistics.skipped_oversized_bitmaps`).
- **Поток сужает срок годности** по `AnimationChange`. Для «каждый кадр» интервал центрирован вокруг момента рисования: `[g − step/2, g + step/2)`. Нижняя граница зажата последней сменой реплик (`SubtitleTimeline::latest_change_within`), поэтому кадр берёт ближайшую по времени картинку, а новая реплика не появляется раньше времени.
- **Эталоны.** Генератор `scripts/subtitle-reference/` снимает один кейс в нескольких моментах: `time_ms=0,1000,2500` → `expected/<case>@t01000.png/json`.

## Открытые риски

- После долгой остановки наблюдаемый шаг кадров вырастает, и одна картинка может уйти кадру чуть старше идеального (ошибка на шаг).
- Память раздвигания ASS зависит от порядка рисования: при рисовании наперёд и перемотке назад позиции раздвигаемых реплик могут отличаться от libass.
- В режиме правки часы показа идут только к выбранной дорожке (настоящей или образцу). Первый кадр настоящей реплики может опоздать на кадр.
- Лимит гигантских картинок — по стороне (`max_canvas_side`, до 16384 px): одна картинка до ~268 МБ всё ещё допустима. Ограничение по площади — отдельное решение.
- Двигающаяся реплика даёт новую запись кэша на каждый кадр. Бюджет в байтах соблюдается, но старые записи вытесняются.
- UI помнит последние 64 изменения дорожки: картинка, отставшая сильнее, проверку не пройдёт (на практике недостижимо).
- `prerender_frames` и `prepared_overlays` действуют со следующего открытого видео.
