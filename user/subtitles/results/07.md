## Решения владельца (16 октября 2026)

1. **Память выбора** хранится в отдельном файле `track-memory.json` рядом с `playlist-resume.json`, а не в файле очереди. Лимит записей задаётся в настройках, при переполнении забываются давно открытые видео.
2. **Смена аудиодорожки** делается «тихим seek», как в mpv. Звук пропадает на долю секунды, зато синхронизация точная.
3. **Кнопка ♪▾** стоит слева от CC, в её стиле. Видна только при ≥ 2 аудиодорожках.
4. **Узкое окно**: ♪ прячется раньше CC. Кнопка видна от ~586 pt, со стрелкой ▾ — от ~614 pt. В более узком окне работает только `B`. Владелец оставил так.
5. **Что запоминается**: локальные файлы и ссылки. В файл пишется только отпечаток пути или ссылки.

Исполнитель решил сам:
- «Вкл» по `C` закрепляет для этого видео автоматически выбранную дорожку.
- Файл субтитров, брошенный вместе с видео, важнее памяти.
- Нечитаемый мусор в файле памяти уходит в карантин; молча выключать память навсегда нельзя.

## Ручная приёмка (агент по поручению владельца)

Файлы собраны ffmpeg в scratchpad:
- видео — эталон `720p_high_bframes_aac.mkv`, зацикленный до 2 минут;
- звук: FLAC 440 Гц (rus, «Dub») и Opus 880 Гц (eng, «Original»);
- субтитры: встроенные SRT ru и en с репликой каждые 4 с;
- фильм B — 12-секундная копия.

Звук шёл во временный null sink PipeWire (`PIPEWIRE_NODE`). Частота мерилась FFT записи монитора.

Повторный прогон по поручению владельца — на настоящих Bluetooth-наушниках (выход по умолчанию): выбор, перезапуск, очередь B → A — PASS (440/880 Гц на мониторе наушников). Находка 1 ниже воспроизводится и на наушниках, то есть от выхода не зависит.

| Шаг | Wayland | X11 |
|---|---|---|
| ♪ и CC в ряду; ♪ только у видео с двумя дорожками | PASS | PASS |
| `B` → «Audio: English — Original (Opus)», звук 440 → 880 Гц | PASS | PASS (по кругу 880 → 440) |
| `C` → русские (язык системы), `V` → английские, `X`×5 → +0.5 с | PASS | — |
| через 3 с в `track-memory.json` Opus / embedded eng / 500 мс, путь только отпечатком | PASS | — |
| перезапуск без аргументов (resume): 880 Гц, английские; `X`, `Z` → «+0.5 s» | PASS | — |
| открытие файла аргументом: 880 Гц, английские | — | PASS |
| очередь B → A: у B 440 Гц и русские по автовыбору, у A своя память — 880 Гц и английские | PASS | — |
| битый файл памяти → `track-memory.corrupt-*.json`, warn без путей, старт с чистой памятью, файл пересоздан | PASS | — |

**Найдено вне объёма** (есть и в базовом коммите, это не регрессия):
1. MKV, собранный ffmpeg из видео Sintel, застревает в Buffering на 00:00, если у файла есть декодируемый звук (FLAC или Opus). Так же ведёт себя в GUI фикстура `two-audio-tracks.mkv`. Видео без декодируемого звука играет; эталонное видео с теми же FLAC и Opus тоже играет. Причина не исследована. Предлагаю отдельную задачу, как было с `EditionUID`.
2. AAC, закодированный свежим ffmpeg в MKV, даёт `UnsupportedAudioCodec`, хотя эталонный AAC-in-MKV играет. AC3 и DTS декодером не поддерживаются вовсе (Symphonia).
3. Выход по умолчанию на этой машине — сетевой `roc-android`. Неподключённый, он не тикает, и A/V-файлы стоят. Для приёмки это обходилось null sink-ом.

## Открытые риски

- Для не-default дорожки при восстановлении с позиции делается два seek: переключения и позиции. Это корректно, но избыточно.
- На источнике без seek переключение продолжает звук со следующих пакетов. Возможен пропуск звука на объём упреждающего чтения; на живом потоке не проверялось.
- Одно web-видео через разные виды ссылок (manifest или страница) получает разные записи памяти.
- Привязка `AppState` проверена source-guard тестами (`wiring_guards.rs`), потому что без окна `AppState` не строится. Живьём путь проверен (см. таблицу).
- Во время анимации появления (250 мс) полупрозрачная ♪ может на миг перекрываться с Repeat. Так же ведёт себя CC.
