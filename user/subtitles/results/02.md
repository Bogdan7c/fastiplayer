# Результат сессии 02: основа растеризатора (`subtitle-raster`)

## Статус

**PASS** по автоматическим проверкам и ручной приёмке владельцем (PNG «наш / libass»). Закоммичено в `main`, push не делался.

## Решения владельца (14 октября 2026)

1. **Растеризатор и обводка — свой порт libass** (а не `zeno`/`tiny-skia`): только так получается совпадение с libass и база для ASS-сессий 08–10.
2. **Выход — маски + цвет**, как `ASS_Image`: на каждый слой (плашка, тень, обводка, буквы) — 8-битная маска покрытия и один цвет. Это вчетверо меньше памяти, чем RGBA, и цвет меняется без перерастеризации.
3. **Встроенные шрифты — Noto Sans Regular + Bold и Regular-шрифты основных алфавитов мира**, чтобы не было «кракозябр» без системных шрифтов. Владелец согласился добавить шесть крупных индийских алфавитов и лаосский. CJK и эмодзи берутся только из системы.

Исполнитель решил сам, без возражений владельца:
- libass **0.17.5** (тег, commit `4a05d8127f525943ebf45fdc6497c9e665947f0d`): та же версия стоит в системе, эталоны снимаются с переносимого кода;
- `skrifa 0.44`/`harfrust 0.12` — те, что уже есть в lock через egui (один `read-fonts`);
- шрифт, запрошенный по имени, ищется так: вложенный → системный → встроенный. Запасной шрифт для отдельного глифа ищется так: встроенные → вложенные → системные. Так результат не зависит от машины;
- перенос строк — только по пробелам, как libass по умолчанию.

## Что сделано

- **`crates/subtitle-raster`** (около 20 тыс. строк вместе с тестами, 100 файлов, все ≤ 600 строк). Зависимости: `subtitle-core`, `skrifa`, `harfrust`, `fontdb`, `unicode-bidi`, `thiserror`, `tracing`. Guardrails: `CONTRACT_CRATES` + allowlist + тест «wgpu запрещён».
  - `overlay` — `SubtitleOverlay`, `SubtitleBitmap` (маска в `Arc`, цвет, слой), `OverlayChange` Unchanged/Moved/Replaced (порт `ass_detect_change`).
  - `fonts/` — `SubtitleFontLibrary`: 22 встроенных шрифта, системные через `fontdb` с индексом покрытия (строится один раз в `load_system_fonts`), `register_attached_font` с лимитами и дедупом, учёт непригодных лиц, байты системных файлов держатся слабыми ссылками.
  - `outline/`, `raster/`, `bitmap/` — побитный порт растеризатора (тайлы 16×16), обводки (`ass_outline_stroke`), `fix_outline`, `shift_bitmap`.
  - `shaping/`, `glyph_render/`, `layout/`, `compose/` — шейпинг (`harfrust`), BiDi (`unicode-bidi`), ширина букв через автохинтер skrifa (так libass получает её от FreeType), smart-перенос, `\an`, BorderStyle 1/3/4.
  - `appearance/`, `plate/` — стили `youtube_like()` (плашка 75 % на каждую строку со скруглением, одна маска на реплику) и `outline_and_shadow()`; размер — доля высоты кадра; размещение WebVTT.
  - `renderer/`, `cache/` — `SubtitleRasterizer::render(&RenderRequest) -> &SubtitleOverlay`:
    - если реплики, холст и стиль не изменились, никакой работы не делается;
    - кэш реплик — LRU по байтам, кэш лиц ограничен числом;
    - реплики не налезают друг на друга (порт `fix_collisions`);
    - лимиты входа (`RasterLimits`);
    - ошибка одной реплики не мешает остальным;
    - подробная статистика.
- **`scripts/subtitle-reference/`** — генератор эталонов через системный libass (C-программа компилируется во временный каталог, в сборке и CI её нет). 17 кейсов в `tests/fixtures/libass/`.
- **`docs/subtitles/compatibility.md`** — раздел «Rendering».

## Паритет с libass

- Рисунки (заливка, обводка, тень, дробные позиции, самопересечения) — **0 отличающихся пикселей** на 8 кейсах. Дополнительно сверено с C-кодом libass на 50 000 случайных контуров, расхождений нет.
- Текст 1280×720: `plain` 3 px, `box3` 3 px, `outline` 26, `box4` 26, `shadow` 27, `cyrillic` 85, `two_lines` 120, `wrap` 419, `arabic_rtl` 979 отличающихся пикселей.
  - Остаток — округление контуров у FreeType и у skrifa (≤ 1/64 px на размере 256).
  - В арабском у двух глифов автохинтер даёт ширину на 1 px (на размере 256) иначе, отсюда сдвиг части слова на 1 px. На глаз не видно.
- Находка: libass берёт ширину букв после хинтинга FreeType, хотя контуры рисует без него. Без воспроизведения этого строки «уплывали» до 1 px.

`cargo run --release -p subtitle-raster --example render_samples -- <каталог>` пишет PNG реплик на латинице, кириллице, в две строки, на арабском, иврите, хинди, CJK (из системы) и с эмодзи, в обоих стилях. Плюс склейки «наш / libass» по текстовым эталонам. Владелец посмотрел и принял.

## Открытые риски

- `load_system_fonts` занимает ~90 мс на 982 лица на тёплом кэше. В сессии 03 вызывать в фоне.
- Лимиты (`RasterLimits`, `AttachedFontLimits`, `FontLookupCacheLimits`) — параметры без дефолтов; значения появятся в конфиге в сессии 04.
- Не рисуются: подчёркивание и зачёркивание, фон спана, синтетический жирный/курсив (для алфавитов без Bold-файла), вертикальный текст, регионы WebVTT, переносы CJK без пробелов.
- `OverlayChange::Moved` через публичный API пока не возникает: появится с анимациями (сессия 09) или с памятью позиций между кадрами.
- Пресеты стиля подобраны по описанию YouTube; сверить вживую в сессиях 03–05.
