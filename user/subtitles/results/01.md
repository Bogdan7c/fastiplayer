## Решения владельца (14 октября 2026)

1. **Кодировка — автоопределение.** Порядок такой: BOM (UTF-8/UTF-16) → UTF-16 без BOM → корректный UTF-8 → детектор `chardetng` с подсказкой «кириллица». Результат несёт название кодировки, чтобы позже показать «read as windows-1251».
2. **Авторские стили поверх стиля пользователя.** `<font color>`, `<b><i><u><s>` из SRT, а также классы и простой `STYLE` из WebVTT сохраняются в модели. Позже можно добавить флажок «игнорировать цвета файла».
3. **Тексты интерфейса — на английском**, как весь UI. Строка общих правил в `README.md` плана поправлена.

Исполнитель решил сам, без возражений владельца: языковые теги через `oxilangtag`. Декодер плейлистов (`playlist-io`) не переиспользуется: там только UTF-8 и cp1251, и он внутренний.

## Что сделано

- **`crates/subtitle-core`** — нейтральная модель, зависимости: `oxilangtag`, `thiserror`.
  - Время и сдвиг: `SubtitleTime` (мкс), `SubtitleSyncOffset` (плюс — субтитры позже).
  - Дорожка: `SubtitleTrackDescriptor` (происхождение, формат, язык BCP-47, название, default/forced/auto).
  - Реплика: `SubtitleEvent` (`[start, end)`, слой, `#[non_exhaustive]`-содержимое; варианты для ASS и PGS добавят сессии 08 и 11).
  - Размеченный текст: `StyledText`/`TextSpan`/`SpanStyle`.
  - Размещение: `CuePlacement` (все настройки VTT + якорь `\anN`), `SubtitleRegion`.
  - **`SubtitleTimeline`** — дерево максимумов окончаний.
    - `collect_active_at` работает за O((k+1)·log n) без аллокаций и возвращает реплики в порядке (слой, начало, вставка).
    - `next_change_after` нужен для перерисовки только при изменениях.
    - Реплики можно дописывать во время работы, дубликаты после seek игнорируются.
- **`crates/subtitle-formats`** — зависимости: `subtitle-core`, `encoding_rs`, `chardetng`, `thiserror`.
  - Точка входа: `load_text_subtitle(bytes, формат, подсказка кодировки, &лимиты)`.
  - Определение формата: `sniff_text_subtitle_format`.
  - Модули: `encoding`, `limits`, `report`, `error`, `srt/`, `webvtt/`.
  - Лимиты (размер, число реплик, длина списка проблем) передаёт вызывающий код, `Default` нет.
  - Фатальные ошибки: `InputTooLarge` (проверка до декодирования), `TooManyEvents`, `NotWebVtt`. Битые реплики пропускаются и считаются в `SubtitleParseReport` с номером строки.
- **Guardrails.** Оба crate-а включены в `CONTRACT_CRATES` и получили строгие allowlist-ы зависимостей. Тест `test_subtitle_core_rejects_gpu_dependency` проверяет, что wgpu в `subtitle-core` ловится.
- **Workspace.** Изменены `Cargo.toml` (members, workspace deps `chardetng 1.0.0`, `oxilangtag 0.1.6`) и `Cargo.lock`; inventory в `scripts/ci-checks.sh` дополнен.
- **Документация.** Создан черновик `docs/subtitles/compatibility.md`, добавлена Serena memory `subtitles/core` и ссылка на неё в `core`.

## Ручная приёмка: пример «файл → реплики в момент T»

SRT в Windows-1251 без BOM, 4 реплики. Третья реплика битая: таймкод `00:00:0X,000`.

```
1  00:00:01,000 --> 00:00:04,000  <i>Где мы?</i>
2  00:00:03,000 --> 00:00:05,500  {\an8}[ДВЕРЬ СКРИПИТ]
3  00:00:0X,000 --> 00:00:07,000  битая реплика
4  00:00:06,000 --> 00:00:08,000  Дома.
```

Результат:

```
encoding: windows-1251, skipped: 1
T=0.5s -> []
T=2.0s -> ["Где мы?"]
T=3.5s -> ["Где мы?", "[ДВЕРЬ СКРИПИТ]" (top)]
T=4.0s -> ["[ДВЕРЬ СКРИПИТ]" (top)]     ← на ровно 4.000 первая реплика уже ушла
T=6.5s -> ["Дома."]
T=9.0s -> []
```

## Открытые риски и ограничения

- SRT `,5` читается как 0,5 с, а ffmpeg и VLC читают это как 5 мс. Файлы такие редкие, отличие записано в матрицу.
- UTF-16 без BOM, где совсем нет латиницы, не распознаётся. На SRT такого не бывает: в таймкодах всегда есть ASCII.
- WebVTT разбирается строго по W3C: блоки разделяет только пустая строка, `STYLE` и `REGION` принимаются только до первой реплики. Подмножество CSS и пробелы перечислены в матрице.
- `SubtitleTimeline::insert` стоит O(n). Для потока демукса (единицы реплик в секунду) этого хватает; массовая загрузка идёт через `from_events`/`extend`.
- Связь `SubtitleTime` с pts плеера, конфиг лимитов и уведомление «read as …» — сессия 03.
