## Решения владельца (18 октября 2026)

1. **Автоперевод** — подменю «Auto-translate» в меню CC. Сверху предпочитаемые языки, ниже остальные по алфавиту, с прокруткой. В основном списке — ручные дорожки и распознанная речь «(auto)».
2. **Ошибка загрузки** (429, нет сети). Видео играет дальше, появляется уведомление, дорожка остаётся в меню, повторный клик пробует снова. Сами в фоне не повторяем.
3. **Дубляж**: по умолчанию оригинал, как на YouTube. Другие языки — в меню ♪ и клавишей `B`. Выбор запоминается для этого видео.
4. **srv3 (XML)** разбирается в `subtitle-formats` через существующий `bounded-xml-reader`.
5. **Баг открытия «HLS-видео + https-аудио»** (найден на приёмке, был и до сессии) — владелец поручил исправить в этой же сессии отдельным субагентом Opus.

Исполнитель решил сам:
- выбор web-субтитров запоминается для этого видео;
- ручные дорожки при автовыборе важнее распознанных;
- автоперевод никогда не выбирается автоматически, потому что почти всегда получает 429;
- `V` перебирает только основной список.

## Исследование: что отдаёт yt-dlp 2026.08.19

- `subtitles` — ручные дорожки; `automatic_captions` — распознанная речь и автоперевод. Признак перевода — параметр `tlang` в ссылке; признак распознанной речи — `kind=asr` без `tlang`.
- У роликов с автодубляжом распознанная речь есть отдельно для каждого языка звука: `ru-orig`, `en-orig` и т.д.
- В `automatic_captions` лежат ещё и HLS-плейлисты (`protocol=m3u8_native`) для каждого ручного языка. Их надо отфильтровать.
- У live вместо субтитров лежит `live_chat`, его тоже отфильтровываем.
- Ссылки подписанные, живут около 7 часов (`expire`).
- **Автоперевод почти всегда отвечает 429.** Так происходит даже у самого yt-dlp, и имитация браузера не помогает. Это ограничение YouTube.
- Дубляж: у аудио-форматов есть `language`; у оригинала `language_preference` 10, у дубляжей −1.
- Размер JSON: у ролика с автодубляжом 10,8 МБ. Это укладывается в лимиты (138 тыс. узлов JSON, порог — 1 млн).

## Что сделано

- **srv3** (`subtitle-formats/src/srv3/`, 8 модулей):
  - перья (цвет, жирный/курсив/подчёркивание);
  - окна и позиции;
  - прокрутка окна автосубтитров на `rc` строк;
  - время появления каждого слова;
  - схлопывание дублей YTSubConverter;
  - типизированные ошибки без эха содержимого.
- **Слова по мере появления** (`subtitle-core::timeline::reveal`, `subtitle-raster::renderer::reveal`):
  - ещё не появившееся слово не рисуется и не занимает места;
  - перерисовка происходит ровно в моменты появления слов, не на каждом кадре;
  - заодно заработало караоке WebVTT `<00:00:01.500>`.
- **yt-dlp → дорожки** (`service-ytdlp/src/candidate/subtitles*`, `web-media-core::descriptor::subtitle`):
  - `SubtitleKind {Manual, AutoGenerated, AutoTranslated}`;
  - лимит 256 дорожек: в первую очередь ручные, затем распознанные, затем переводы;
  - у типов со ссылками свой `Debug` без URL.
- **Скачивание** (`media-source-open::web_subtitle_fetch`):
  - `WebSubtitleFetchHandle::fetch`, блокирующий, с отменой;
  - srv3 → VTT при отсутствии формата;
  - 429 и сетевые ошибки возвращаются как типизированные ошибки, без перехода на другой формат;
  - просроченная ссылка — один повторный запрос к yt-dlp.
- **Приложение** (`app-egui/src/state/subtitles/{web_download,web_track,web_load_job,owner_web}.rs`, `subtitle_control/translation_menu.rs`):
  - владелец субтитров зависит от трейта `WebSubtitleDownloader`, а не от HTTP;
  - фоновая загрузка;
  - уведомления об ошибках;
  - повтор по клику;
  - подменю автоперевода;
  - различение одинаковых названий языков (`state/language_label_disambiguation.rs`).
- **Память** (`playlist-state` track_memory):
  - `RememberedSubtitleChoice::Web`;
  - отдельное поле `web_audio_language`;
  - схема `track-memory.json` поднята до 2: старая версия плеера не сочтёт новый файл битым, а просто не будет его трогать.
- **Языки дубляжа**:
  - каталог `media-source-open/src/web_media_open/audio_languages.rs`;
  - третий источник в меню ♪ (`state/audio_tracks/web_audio_languages.rs`);
  - переоткрытие на той же позиции через путь same-item switch;
  - восстановление запомненного языка — одно переключение после открытия;
  - попутно исправлено: переоткрытие с неоригинальным языком падало (`catalog.rs::adopt_active_separate_pair`).
- **Таблица языков** (`subtitle-core::language_table`):
  - полный ISO 639-1 и алиасы (`iw→he`, `in→id`…);
  - язык из имени файла рядом с видео определяется по-прежнему только по 42 частым языкам, чтобы не было ложных срабатываний.
- **Баг 616** (Opus):
  - Корень: планировщик проверял половинки пары «видео + аудио» по отдельности. Смешанную пару HLS + https он признавал играбельной, а открыть её нечем. Ошибка считалась фатальной, поэтому следующий кандидат не пробовался.
  - Исправление: `TransportFamily::shares_component_composition_route`, отказ планировщика `ComponentRouteMismatch`, замена пары на видео с совместимым транспортом (`web_media_open/compound_route_substitute.rs`). Аудио и язык при этом сохраняются, высота кадра — та же.

Новые зависимости: `bounded-xml-reader` (свой crate) для `subtitle-formats`; `serde_json` как dev-dependency для `media-source-open`. Внешних crate-ов не добавлено.

## Открытые риски и бэклог

Пункты про формат 616, сброс языка дубляжа при смене качества, «gates ready» и фон слов srv3 по решению владельца перенесены в общий бэклог: [`general_backlog.md`](../../general_problems/general_backlog.md), пункты 7–10.

- Фон под отдельными словами (`bc`/`bo` перьев srv3) разбирается, но не рисуется.
- Окно srv3 с якорем слева использует стандартную ширину блока текста.
- Ошибка разбора web-дорожки показывается серой строкой без уведомления.
- Формат 616 (HLS, самый высокий битрейт 1080p) не используется. Чтобы его играть, нужен новый путь открытия «HLS-видео + отдельное аудио».
- Ручной выбор в пикере качества всё ещё может собрать смешанную пару HLS + https (`compose_inventory_av` не проверяет транспорт).
- Если пара yt-dlp неиграбельна по другой причине (например, AV1 HDR при SdrOnly), открывается видео без звука (найдено на `LXb3EKWsInQ`).
- Смена качества в пикере на другую строку видео сбрасывает выбранный язык дубляжа на оригинал.
- Строка «gates ready» в логе старта появляется не всегда, даже на обычных роликах (3 из 4 запусков без неё); воспроизведение при этом идёт. Похоже на давнюю гонку учёта готовности — отдельная задача.
- Один раз при открытом меню ♪ видео выглядело чёрным; повторить не удалось.
