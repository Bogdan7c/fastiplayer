# Сессия 01: честное «видео не поддерживается»

> Выполни сессию 01 плана `user/mpeg2/`. Сначала прочитай `user/mpeg2/README.md`, `results/00.md`, этот файл, общий бэклог п. 6 и п. 16.

## Проблема

Если видеодорожка есть, но плеер её не умеет, пользователь видит чёрный экран без объяснения. Причины:
- демуксер TS выбрасывает незнакомый `stream_type` ещё при разборе таблицы программ, и дорожка не создаётся;
- для MKV/MP4 общий отказ «unsupported video format» существует, но из-за второй отменённой попытки открытия пользователь видит внутреннюю строку (бэклог п. 6).

## Что сделать

1. **Дорожка «есть, но не играется»** — общее понятие на уровне описания дорожек. Демуксер TS создаёт дорожку для известных, но неподдерживаемых видео-`stream_type`, а не выбрасывает её. Сейчас это MPEG-1/2; после сессии 03 MPEG-2 уходит из этого списка.
2. **Решение плеера**:
   - есть звук — играет звук;
   - пользователь один раз видит понятное сообщение: «Видео MPEG-2 пока не поддерживается, играет только звук»;
   - нет звука — честная ошибка открытия.
3. **Корень бэклога п. 6** — почему вторая попытка открытия перекрывает понятную причину. Чинить там, а не в тексте сообщения.

Архитектура — владельцу до кода: кто владеет признаком «не играется», как он доходит до UI.

## Тесты

- Сквозной: TS с MPEG-2 видео + MP2 → звук доходит до вывода, состояние «играет», событие для пользователя ровно одно и с правильной причиной.
- MKV с неизвестным видео-кодеком → та же причина, без внутренней строки (бэклог п. 6).
- Файл без звука и с неподдерживаемым видео → понятная ошибка, не зависание.
- Мутация: дорожку снова молча выбросить — тест падает.
