# Сессия 02: MPEG-2 и MPEG-1 в словаре кодеков

> Выполни сессию 02 плана `user/mpeg2/`. Сначала прочитай `user/mpeg2/README.md`, `results/00.md`, этот файл.

## Что сделать

1. `codec-core`:
   - `VideoCodec::Mpeg2` (и `Mpeg1`, если решено в 00);
   - профили Simple/Main (4:2:2 — по решению 00);
   - идентификаторы контейнеров: TS `stream_type` 0x01/0x02, MKV `V_MPEG1`/`V_MPEG2`, MP4 objectType 0x60–0x65/0x6A;
   - политика проверки требований (`requirement_preflight`).
2. Все места, где перечисляются кодеки (около 30 файлов: web-кандидаты, yt-dlp, HLS/DASH, VA-API probe, FFmpeg, настройки, UI требований). Новый вариант не должен ломать ни один из них.
   - Где кодек ещё не играется, это видно явно: «не поддерживается этим бэкендом».
   - Скрытого «как H.264» быть не должно.
3. Возможности бэкендов. MPEG-2 заявляется только там, где декодер реально есть. До сессий 04 и 07 — нигде, и дорожка честно уходит в отказ сессии 01.

## Тесты

- Каждый идентификатор контейнера → правильный кодек и профиль.
- Проверка требований: MPEG-2 Main без бэкенда → понятный отказ, а не паника и не «как H.264».
- Конфиг: старый файл настроек без MPEG-2 читается как раньше.

Это изменение границы — отдельный коммит без попутного рефакторинга.

Memories: memories `codec-core`, `player-core/capability-*` (через `list_memories`).
