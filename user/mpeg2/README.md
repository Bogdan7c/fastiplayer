# Fastiplayer: видео MPEG-2 (и MPEG-1)

План подготовлен 30 октября 2026 по итогам финальной приёмки сессии 03e плана `user/browser-bridge/`. Многосессионный: этот README — решения владельца, общие правила, порядок и бэклог; по файлу на сессию; отчёты — в `results/NN.md`.

## Зачем

MPEG-2 видео — это DVB-эфир и его записи (`.ts`), DVD (`.vob`), старые камеры и архивы (`.mpg`). Такого контента много именно на старом железе, а старое железо — главная идея проекта. Ironlake (T410) декодирует MPEG-2 аппаратно и дёшево: VLC через VA-API играет 1080i за 61 % CPU.

Сейчас у Fastiplayer видео MPEG-2 нет вообще. Хуже того, файл открывается **молча без картинки**:
- звук MP2 играет, экран чёрный;
- ни ошибки, ни сообщения пользователю.

Найдено дважды:
- сессия 11 плана `user/gles2-renderer/`, 27.10.2026, T410, серия 576i/1080i. Решение 55 того плана: «в общий бэклог», общий бэклог п. 16;
- финальная приёмка 03e, 30.10.2026.

Слова владельца: «Уже не первый раз сталкиваюсь с этим блядским mpeg2».

## Что известно о коде (разведка 30.10.2026, снимок на `32cae116`)

Почему картинки нет — **цепочка обрывается в шести местах**, а не в одном:

| Звено | Сейчас | Где |
|---|---|---|
| Разбор TS | `stream_type` 0x02 (MPEG-2 видео) и 0x01 (MPEG-1) отбрасываются **молча**: дорожка даже не создаётся | `mpeg-ts-demux/src/psi_descriptors.rs` (`is_candidate_stream_type`, `recognize_elementary_stream`), `psi.rs` |
| Сборка кадров в TS | сборщик кадра (access unit) понимает только NAL (H.264/H.265); у MPEG-2 свои start-code-ы (`0x000001B3` sequence header, `0x00000100` picture) | `mpeg-ts-demux` `video_assembler.rs`, `elementary.rs`; `media-core` `VideoPacketFraming` |
| Словарь кодеков | в `codec-core::VideoCodec` есть VP8, VP9, AV1, H.264, H.265 — MPEG-2 нет; нет профилей Simple/Main | `codec-core` `model.rs`, `profile.rs`, `container_codec_id.rs`, `requirement_preflight.rs` |
| Программный декод | встроенный FFmpeg собран с `--disable-everything` и декодерами `h264,hevc,vp8,vp9,libdav1d`; `mpeg2video`/`mpeg1video` не включены | `ffmpeg-vendor/src/build_options.rs`, `video-ffmpeg/src/codec_adapter.rs` |
| Аппаратный декод | в `cros-codecs` нет stateless-декодера MPEG-2 и интерлейса («We don't intend to support interlaced»); в `cros-libva` буферы MPEG-2 есть | `cros-codecs-patch`, `cros-libva-patch/.../buffer/mpeg2.rs` |
| Чересстрочность | в контракте кадра нет флага «чересстрочный / какое поле первое»; деинтерлейсера нет нигде: ни в wgpu, ни в GLES2, ни в VA-API (VideoProc), ни в FFmpeg (avfilter выключен) | `video-frame-contract`, `render-wgpu-video`, `gles2-video` |

Другие контейнеры:
- **MKV** уже знает `V_MPEG1/V_MPEG2` в патче Symphonia, но `symphonia-demux` не пропускает их дальше (`track_mapper.rs`);
- **MP4/MOV** (`mp4v` с objectType 0x60–0x65/0x6A) — редкость, разбора objectType для видео нет;
- **MPEG-PS** (`.mpg/.mpeg/.vob`) и сырого `.m2v` — демуксеров нет вообще.

Добавление нового `VideoCodec` затрагивает около 30 файлов: web-кандидаты, yt-dlp, HLS/DASH, VA-API probe, FFmpeg, настройки, UI требований.

Остальное:
- **MP2-звук в TS уже играет.**
- **Файлы для проверки:**
  - `test-assets/benchmark-t410/576i25/` — 720×576, SAR 64:45, tff, MP2;
  - `test-assets/benchmark-t410/1080i30/` — 1920×1080, tff, MP2.

  Оба Main, 4:2:0, чересстрочные. Лежат вне git. Синтетические фикстуры делаются в сессии 00.

## Общие правила сессий

Работай в корне checkout-а. Сначала `AGENTS.md`.

Перед работой:
- Serena: `initial_instructions`, активация, `mem:core`, плюс memories из конца файла сессии;
- **Context7** — для FFmpeg (`avcodec`, флаги `AVFrame` про поля), VA-API, wgpu и всего, что правится;
- источник истины по битстриму — ISO/IEC 13818-2 (MPEG-2 видео), 13818-1 (TS и PS), 11172-2 (MPEG-1), а не память модели;
- широкий поиск по репозиторию — read-only субагент (Sonnet). Основной агент читает только точные символы.

Код:
- новые границы — по архитектурным правилам `AGENTS.md`: кто владеет, intent-методы, focused-тесты на отсутствие, ошибку, учёт и «не трогает чужое»;
- файлы ≤ 800 строк (храповик `scripts/module-size-baseline.json`), новые фичи — в новых модулях;
- крупный сторонний код в ядро — только с обоснованием (auto-memory владельца «no unaudited big crates»). Встроенный FFmpeg уже принят проектом.

Тесты:
- **тест проверяет результат, а не вызов**: доказательство — **кадр дошёл до рендера** с правильным содержимым (выжженный номер кадра, поля в нужном порядке), а не «декодер вызван»;
- фикстуры маленькие и синтетические, команда генерации записана в `generate.sh` рядом. Тесты не требуют ffmpeg во время запуска. Реальные DVB/DVD-файлы — только локально.

Машины:
- T410 (Ironlake, i965: MPEG-2 Simple/Main аппаратно) и T480s — по ssh, команды одобрены;
- **замеры и GUI — только когда владелец отдал машину**. Длительность называется заранее и не превышается;
- живой запуск плеера — только с изолированными XDG-каталогами. Конфиг и очередь владельца не трогать (урок 03e).

Отчёты `results/NN.md`:
- состав: статус, SHA, решения владельца, что сделано, доказательства, ограничения, memories;
- в `user/` только Markdown, без личных путей и логов.

Git:
- работа в `main`, коммит после зелёных проверок, сразу push;
- соседняя сессия → коммитятся только свои пути.
