# B1. Кодировка `.m3u`/`.cue`: UTF-8, затем Windows-1251

Статус: PASS

## Корень
`playlist-io` принимал только UTF-8 (`m3u.rs` -> `InvalidUtf8`, `cue/encoding.rs` -> `UnsupportedOrInvalidEncoding`), а плейлисты с кириллицей, созданные на Windows, лежат в Windows-1251. Пользователь получал отказ без объяснений.

## Решение (владелец)
Сначала UTF-8 (с BOM или без) без уведомлений; если это не валидный UTF-8 — декодирование как Windows-1251 и уведомление «Плейлист прочитан в кодировке Windows-1251».
- Новый общий модуль `playlist-io/src/text_encoding.rs`: `decode_utf8_or_windows_1251`, политика `LegacyFallback`, публичный тип `PlaylistTextEncoding`. Дока модуля объясняет решение (раньше было «без legacy code-page guessing»).
- `.m3u8` — fallback запрещён (по RFC 8216 всегда UTF-8), невалидный UTF-8 остаётся прежней ошибкой.
- CUE: BOM-логика не менялась (UTF-8/UTF-16 по BOM); без BOM — UTF-8, иначе Windows-1251 (`CueTextEncoding::Windows1251`). NUL в тексте по-прежнему отказ (UTF-16 без BOM).
- XSPF не тронут: это XML, кодировку объявляет сам документ.
- Пути: после декодирования это обычные Unicode-пути Linux; для переносимых с Windows файлов с кириллицей имена в UTF-8 совпадают.
- Библиотека `encoding_rs 0.8.42` (workspace dependency; лицензии `(Apache-2.0 OR MIT) AND BSD-3-Clause`, MIT/Apache — в allowlist; `dependency-patches` не затронут, это не fork). Транзитивно добавлены `core_detect`, `multiversion_no_op`.
- Доставка в app: `GenericM3uPreview::text_encoding()`, счётчик `LocalPlaylistExpansionSummary::windows_1251_documents()`, `CueDocument::encoding()` -> `import_io/notice.rs` (`PlaylistImportNotice`) -> `drain_playlist_import_notices` -> `AppState::show_playlist_import_notices` -> info-toast 8 с. Одно уведомление на импорт.

## Тесты
- `playlist-io/tests/legacy_encoding.rs`: cp1251 m3u (названия и пути кириллицей сравниваются как строки/Path + признак), cp1251 cue (TITLE/PERFORMER), UTF-8 с BOM и без -> без fallback, `.m3u8` с невалидным UTF-8 -> `InvalidUtf8`, UTF-16 без BOM -> ошибка, счётчик в expansion.
- `text_encoding::tests` (заимствование без копии для UTF-8, ошибка при Forbidden); `budgets.rs` уточнён под `.m3u8`.
- app: `import_path/tests.rs` — cp1251 m3u и cue импортируются в preview с нужным числом записей и дают ровно одно уведомление с текстом; UTF-8 — без уведомления.
- Не покрыто тестом: сам вызов `show_playlist_import_notices` в `frame_prepare` (нет headless `AppState`); метод тонкий и использует проверенный `notify_info`.

## Ручная приёмка
1. Создать m3u в cp1251 (`iconv -f utf-8 -t cp1251`) с кириллическими `#EXTINF` и путями, импортировать (меню или перетаскиванием): записи с читаемой кириллицей, toast «Плейлист прочитан в кодировке Windows-1251».
2. То же для `.cue`.
3. UTF-8 m3u — без toast. `.m3u8` в cp1251 — «Файл не прошёл проверку формата плейлиста».

## Риски
Любой невалидный UTF-8 без NUL читается как cp1251 (в т.ч. другие кодировки, например KOI8-R, дадут «кракозябры» без предупреждения). Решение владельца.
