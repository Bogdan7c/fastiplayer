# A7-A8: отказ player-а на staging и «VOD» для live-потоков

Статус: **A7 PARTIAL** (предпосылка задачи не подтвердилась, сделана только защитная правка), **A8 PASS**.

## A7. Отказ player-а на staging

**Что выяснилось.** План автоперехода действительно выбрасывается на staging
(`stage_prepared_playlist_source` забирает `pending_staging`, при `Err` admission с планом дропается).
Но единственный отказ на этом шаге — `PlayerRejected`: команда установки не дошла до player-а
(очередь переполнена или поток завершился; причина всегда «player не отвечает»). Это не ошибка файла.
Отказа «файл битый» на staging не бывает: такие отказы приходят позже (`PlayerFailed`), когда план уже принят
controller-ом и идёт обычным маршрутом.

**Решение.** Возвращать план при `PlayerRejected` неправильно: пропуск перебрал бы очередь на том же
недоступном player-е и пометил бы хорошие файлы битыми. Поэтому поведение «очередь встаёт с причиной» оставлено.
`target_itself_failed` (`state/strong_media_open/pending.rs`) раньше считал `PlayerRejected` виной файла;
теперь вина файла — только отказ подготовки (кроме отмены) и `PlayerFailed`. Сейчас это не меняет поведение
(ветка недостижима, пока admission не сохраняется), но закрывает ловушку на будущее. Отмена по-прежнему без возврата плана.

**Тесты** (`pending/unadmitted_plan_tests.rs`): `PlayerRejected` с планом -> обычная ошибка, плана нет;
`PlayerFailed` с планом -> `TargetFailedBeforeAdmission` с причиной «формат видео». Прежние тесты на отмену остались.

**Вопрос владельцу.** Если нужно, чтобы очередь переживала кратковременную занятость player-а, варианты:
(а) оставить как есть (стоп с причиной «player не отвечает»); (б) один автоматический повтор staging при
переполнении очереди (Backpressure), без пропуска; (в) пропуск только при Disconnected не имеет смысла.
Рекомендация: (а), пока такого не видели вживую.

## A8. «VOD» для live

**Корень.** `playback_status` в `web_media_stream_model.rs` хардкодил `is_live: false`. Знание о live уже есть
на правильной границе: `PlayerSnapshot.timeline.mode == TimelineMode::Live` (его публикует player для live HLS/DASH/yt-dlp,
тем же признаком пользуется `pending/resume.rs`). Парсить манифесты в sidebar не нужно.

**Изменения.** `is_live: bool` заменён на `UrlSidebarStreamKind { Live, Vod, Unknown }`; `stream_kind(snapshot)` в
`web_media_stream_model.rs`; `stream_kind_label` в `ui/url_sidebar.rs`: «Прямой эфир» / «VOD» / «Определяется».
Честность: пока media не установлено (`media_instance_id == None`), timeline дефолтная, поэтому режим «Неизвестен»
(показывается «Определяется»), а не «VOD». Кнопка «к прямому эфиру» не делалась.

**Тесты.** Модель: live-timeline -> `Live`, static -> `Vod`, пустой snapshot -> `Unknown`
(`web_media_stream_model/tests.rs`). UI: в доступном дереве строка «Прямой эфир»/«VOD»/«Определяется», чужих подписей нет
(`ui/url_sidebar.rs::mode_row_names_live_vod_and_unknown_streams_honestly`).
