# A13-1: завершённый EVENT-плейлист открывается как VOD

Статус: PASS.

## Решение владельца
Плейлист `#EXT-X-PLAYLIST-TYPE:EVENT` + `#EXT-X-ENDLIST` (итог `ffmpeg -hls_playlist_type event`) открывать как обычное видео.

## Корень
`hls-playlist-core::validate_vod_profile` отвергал любой EVENT (`HlsProfileError::EventPlaylist`), а live-профиль не принимает ENDLIST на старте. Завершённый EVENT не открывался нигде. По RFC 8216 EVENT только дополняется, а после ENDLIST не меняется, то есть это конечный VOD.

## Что изменено
- `crates/hls-playlist-core/src/profile.rs`: из `validate_vod_profile` убрана проверка EVENT (с комментарием про RFC); `error.rs`: удалён неиспользуемый вариант `EventPlaylist`.
- Дальше по цепочке править не пришлось: VOD или live в `web-media-hls` (`catalog/discovery.rs`, `native_ingress.rs`) выбирается по `end_list`, а не по типу плейлиста. Длительность, перемотка, отсутствие refresh и «Режим: VOD» в сайдбаре идут от общего VOD-пути (сайдбар берёт режим из `timeline.mode`), поэтому завершённый EVENT ведёт себя как VOD везде. Master с вариантом EVENT+ENDLIST тоже классифицируется как VOD.
- EVENT без ENDLIST: не менялся. Классифицируется как live (`validate_live_profile` его принимает, VOD-профиль отказывает с `NonVod`). Подтверждено тестами.

## Тесты
- `hls-playlist-core/tests/parser.rs`: завершённый EVENT проходит VOD-профиль и не проходит live (`EndedLivePlaylist`); EVENT без ENDLIST: VOD отказ `NonVod`, live принят.
- `web-media-hls/tests/event_vod.rs` (новый): дословные манифесты ffmpeg (ts и fMP4) открываются через `prepare_hls_vod`, длительность равна 6 с (сумма EXTINF), доходят видео и аудио пакеты; EVENT без ENDLIST отклоняется VOD-путём; master с EVENT+ENDLIST-вариантом классифицируется как `Vod`.
- `web-media-hls/src/native_ingress.rs` (тест): admission завершённого EVENT = `TopMedia(Vod)`, EVENT без ENDLIST и обычный live не изменились.
- `media-source-open/.../web_open_failure/tests.rs`: тест «профиль отказал» использовал EVENT, переведён на SAMPLE-AES (по-прежнему вне профиля).
- Проверки: `cargo test` для hls-playlist-core, web-media-hls, media-source-open; `cargo fmt --all --check`; clippy `-D warnings` по трём crate-ам; `s42_module_size_guardrail.py` проходит. `check-refactor-guardrails.py` падает на `playlist-io -> encoding_rs` (из коммита B1, не связано с A13-1).

## Живая проверка
ffmpeg (H.264+AAC из test-assets, `-hls_playlist_type event`, ts) раздан по http, открыт в release-сборке с изолированным XDG-профилем: длительность 00:08, перемотка на ~6 с, воспроизведение с кадрами, сегменты запрашиваются один раз, повторных запросов манифеста нет. Приложение остановлено.

## Приёмка вручную
Раздать каталог с ffmpeg-EVENT HLS, открыть через «Добавить URL»: играет, таймлайн конечный, перематывается, в сайдбаре «Режим: VOD».

## Риски
Строку «Режим: VOD» глазами не проверял (по коду она следует из `timeline.mode`). Незавершённые EVENT-потоки не затронуты.
