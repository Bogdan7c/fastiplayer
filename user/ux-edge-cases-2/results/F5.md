# F5: плавающий тест post_allocation_validation_error_releases_codec_context_and_extradata

Статус: PASS

## Корень
Тест сравнивал process-wide `AtomicUsize` (`LIVE_CODEC_CONTEXT_ALLOCATIONS`) до и после `CodecContext::open`.
Тесты бинаря идут параллельно, и decoder-thread тесты тоже открывают/закрывают контексты: `before` мог
захватить чужой живой контекст, к `after` его уже освободили (`left: 0, right: 1`). Это гонка в тесте, не в production.

## Решение
Счётчик стал thread-local (`Cell<usize>`), только под `cfg(all(test, feature = "ffmpeg"))`.
Почему корректно: `CodecContext` is `!Send + !Sync` (проверяется `assert_not_impl_any!` в tests.rs), значит
создаётся и освобождается на одном потоке; инкремент и декремент всегда попадают в один счётчик, а контексты
других тестов (других потоков) невидимы. Выбрано вместо per-context id (громоздко) и test-mutex (сериализует
несвязанные тесты и не защищает от будущих тестов без мьютекса). Production-код не менялся.

Другие `*_for_test` глобальные счётчики в crate-е: нет (остальные `*_for_test` — методы-хелперы без глобального состояния).
