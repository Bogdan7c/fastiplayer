# A13-3: HLS без видео (audio-only, интернет-радио)

Статус: PARTIAL (VOD и live audio-only, ts и fMP4, master из audio-only вариантов работают; packed audio `.aac`/ID3 сознательно не тронут, см. «Нужно решение владельца»).

## Решение владельца
Поддержать HLS без видео (радио): VOD и live.

## Архитектура
- Форму дорожек знает открытый main demux (после probe первого сегмента), а не manifest: у top media playlist нет CODECS.
- Intent: новый `HlsMainTrackLayoutIntent::VideoWithOptionalAudioOrAudioOnly` только для top media playlist (видео с опциональным звуком ИЛИ ровно один звук). `VideoWithOptionalAudio` (master-variant) и `MuxedAv`/`VideoOnly`/`AudioOnly` не ослаблены.
- Live: random access больше не фиксируется до probe. Новый enum `HlsLiveRandomAccessSource` (`VideoDecodeStart` / `EveryAudioPacket`) заменил positional bool; `live::open` после открытия main проверяет форму и сообщает coordinator-у вывод методом `prove_main_random_access`. Якорь для радио - первый аудио-пакет (каждый AAC-фрейм независим). Для видео инварианты те же: keyframe + SPS/PPS, звук внутри видео-потока якорем не становится.
- VOD seek: `HlsSeekIndex` получил `declare_video_absent()` (вызывает `prime_initial_seek_anchor`); без видео `DecodePointBefore`/`Preview` берут аудио-пакет, а не video RAP. Это был второй, скрытый дефект: seek радио падал «не содержит доказанный VideoRandomAccessPoint».
- Clock: штатный audio clock, player-core не менялся.

## Что изменено
`web-media-hls`: `selection.rs`, `open.rs` (`validate_track_shape`), `live/{snapshot,timeline,open,mod}.rs`, `seek.rs`, `epoch_demux.rs`, `native_ingress.rs` (top intent + `audio_only_candidate` для master: один mp4a в CODECS, без RESOLUTION/AUDIO group, ранг после любого видео, лучший bandwidth), `catalog/build.rs` (arm для нового intent).

## Тесты
`web-media-hls/tests/audio_only_hls.rs`: ts VOD (длительность 30 с, аудио-пакет, seek садится на 10 с и первый пакет после seek не раньше), fMP4 VOD, ts live (DVR строится и сдвигается после refresh; мутация «политика всегда VideoDecodeStart» роняет тест), master радио через каталог (открыт именно high по EXTINF), регрессия muxed. Unit: форма дорожек (все 6 случаев), evidence (звук не якорь при видео), seek-index, admission master. В `video_only_hls.rs` удалён устаревший тест «audio-only отвергается». Проверки: `cargo test` web-media-hls, hls-playlist-core, media-source-open, `app-egui hls`; fmt; clippy `-D warnings`; `check-refactor-guardrails.py`; module-size guardrail; `cargo check --workspace --all-targets`.

## Живая проверка (release, изолированный XDG, `Add URL` через диалог, ffmpeg `-vn`, http rangesrv)
ts VOD (50 с): открылся, строка с иконкой «нота», таймер идёт, перемотка 00:06 -> 00:30 -> 00:35, поток PipeWire `alsa_playback.fastiplayer` активен (`pw-top` R, не corked). ts live (скользящее окно 5x2 с): таймер 00:13 -> 00:32 -> 00:56, плашка LIVE, DVR продвигается, обновления плейлиста идут. fMP4 VOD: открылся, 00:49, играет. Скриншоты `a133_*` (в scratchpad, не в репозитории). Всё остановлено.

## Нужно решение владельца
**Packed audio** (`.aac`/`.mp3` сегменты с ID3 PRIV timestamp, частый формат радио): сейчас typed отказ `UnsupportedMainContainer` (контейнеры HLS закрыты на ts и fMP4). Объём: новый `HlsRequiredContainer` + factory для ADTS/MP3-сегмента (symphonia умеет ADTS, но не знает ID3 PRIV), разбор `com.apple.streaming.transportStreamTimestamp` как базового PTS сегмента, packet-wise duration, live/VOD seek-индекс. Средне-крупная задача (отдельная сессия).

## Риски
- UI: подпись live осталась прежней «LIVE» (общая для видео и звука), не «Прямой эфир»; не менял, чтобы не трогать общий UI.
- DVR у audio-only live строится по реально прочитанным сегментам (как у видео): сразу после открытия окно короткое и растёт по мере чтения.
- На старте live-радио телеметрия показала `Audio underruns: 62` (не росло потом; у VOD 0). Не исследовал, возможно прайминг буфера при старте.
- Новый live-ветка валидирует форму только для top intent-а; muxed/master live не получили новой проверки (как и раньше).

## Приёмка вручную
Раздать `ffmpeg -vn -f hls` (ts, VOD и live со скользящим окном, плюс `-hls_segment_type fmp4`), открыть через «Добавить URL», дважды кликнуть по строке: звук идёт, таймер идёт, перемотка VOD работает, live продвигается.
