# B9: кнопка «Повторить» на ошибке открытия

Статус: **PASS** (тесты и живая приёмка).

## Решение владельца
Кнопка «Повторить» на ошибке открытия, только когда повтор осмыслен.

## Где ошибка видна и что стало
- Центр (ошибка с ×): теперь рядом с × может быть обычная egui-кнопка «Повторить» (в дереве accesskit это Button с подписью).
- Производители ошибок центра и цель повтора:
  - локальный файл (Open, drag and drop, CLI): открыть этот файл тем же путём, что кнопка Open;
  - ссылка из командной строки: открыть эту ссылку путём «ссылка, брошенная на видео»; восстановленный элемент очереди: Play строки;
  - остановка очереди без сети (B8): то же, что Play на остановленном элементе (`play_queue_blocked_item`);
  - сбой воспроизведения (`Failed`) по сети: переоткрыть элемент с позиции обрыва (путь Play строки с `RestoreExact`, как Undo Clear);
  - ручной выбор элемента очереди, который не открылся: раньше был только бейдж и строка статуса в сайдбаре, теперь дополнительно ошибка в центре (иначе повтор не мог бы «упасть снова с кнопкой»). Это единственное изменение видимого поведения вне кнопки, стоит подтвердить.
- Toast-ы кнопки не получают.

## Модель
Цель повтора — тип `MediaRetryTarget` (файл / ссылка / элемент очереди / снять блок очереди / переоткрыть упавшее), задаёт тот, кто породил ошибку (`RetryPlan`). Центр уведомлений её только хранит, UI знает лишь «рисовать ли кнопку». Осмысленность по причине — `media_open/retry_advice.rs`, `match` без `_`.
- Повтор есть: нет сети, таймаут, обрыв, 5xx, 429, таймаут yt-dlp; локальный файл не найден / нет доступа / ошибка чтения / таймаут чтения / файл изменился (флешку могли вернуть); таймаут подготовки и «плеер не отвечает».
- Повтора нет: формат не поддерживается, файл повреждён/пустой/папка, 404/410, приватное, нужен вход, yt-dlp не установлен или выключен, неклассифицированное, внутренние ошибки. Сбой воспроизведения: повтор только для `NetworkError`.

## Нажатие
`NotificationAction::Retry` -> `request_retry` -> исполнитель кадра (`state/media_retry/executor.rs`, порт `MediaRetryPort`). Занято (открытие из Open идёт): «Файл ещё открывается», **ошибка остаётся** с кнопкой. Иначе ошибка снимается и вызывается существующий путь; параллельного пути открытия нет, повторный отказ даёт новую ошибку с кнопкой.

## Живая приёмка (release, изолированный профиль, rangesrv)
Запуск с http-ссылкой при выключенном сервере: в центре «Не удалось открыть ссылку (127.0.0.1): нет соединения с сервером — проверьте интернет» + «Повторить» (b9_11). Сервер поднят, клик: видео играет (b9_12/13, в логе сервера запросы). Сервер выключен, клик: запрос подтверждения замены очереди, после него снова ошибка с кнопкой (b9_14/15).

## Риски и решения на подтверждение
1. Повтор ссылки из CLI идёт путём «ссылка на видео»: при непустой очереди спросит подтверждение замены (исходный CLI-старт не спрашивал).
2. Текст ошибки ручного отказа строки очереди без имени/домена (`Не удалось открыть ссылку: …`).
3. Не покрыто: отказ установки в player при CLI-старте и восстановление очереди после рестарта (нет кнопки); план `QueueItem` для восстановленного элемента проверен только компиляцией и общими тестами.
4. Известный лишний вопрос: Play без медиа показывает состояние Playing (старая особенность).
