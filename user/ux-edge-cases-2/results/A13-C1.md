# A13 + C1: native HLS с локального http и ролики YouTube (VP9/HLS)

Статус: PARTIAL (A13 объяснён, C1 исправлен; два пункта ждут решения владельца).

## Корень

**A13 — в основном ошибка тестовых данных.** Файлы `media/t*.mp4` живой приёмки были без звука, а native HLS-профиль принимает media playlist только как «видео+звук в одном потоке» (`MuxedAv`). Точная ошибка: `HLS main track shape mismatch: expected MuxedAv, video=1, audio=0`. Тот же манифест с видео+AAC открывается. Это сознательное ограничение профиля, не баг парсера. Master-вариант без аудио-кодека в `CODECS` или без `RESOLUTION` тоже не admitted.

**C1 (и реальный баг, найденный попутно).** YouTube-форматы 602–604/616 — video-only VP9 в fMP4 по HLS (подтверждено `yt-dlp -F` и скачиванием манифеста itag 602: стандартный `PLAYLIST-TYPE:VOD` + `EXT-X-MAP`). Локальный isomp4-patch принимал sample entry `vp09`, но не назначал треку codec id (`unknown_video`). Поэтому keyframe-проба VP9 не запускалась, все пакеты были `Unknown`, HLS VOD не находил seek anchor: «HLS VOD завершился до доказанного initial seek anchor». H.264-ролики работали, VP9 — нет.

## Что исправлено

- `symphonia-format-isomp4-patch`: новый `atoms/vpcc.rs` (profile/level из `vpcC`), в `atoms/stsd.rs` запасной codec id по типу sample entry `vp08`/`vp09`; инвентарь `docs/dependency-patches.toml`.
- `media-source-open/src/web_open_failure.rs`: `HlsProfileError` -> «у видео нет формата, который плеер умеет воспроизводить», `HlsParseError` -> «сервер ответил некорректно» (вместо общего «не удалось получить видео»). Сырые англ. тексты остаются только в логе.

## Нужно решение владельца (профиль не расширялся)

1. **Завершённый EVENT-плейлист** (`PLAYLIST-TYPE:EVENT` + `ENDLIST`; ffmpeg `-hls_playlist_type event`) не открывается нигде: VOD-профиль отвергает EVENT, live-профиль не принимает ENDLIST на старте. Расширение: трактовать как VOD (малая правка в `hls-playlist-core::validate_vod_profile`, риск низкий, плюс тест).
2. **Video-only media playlist по прямой ссылке** (без звука). Сейчас отказ. Расширение: разрешить `VideoOnly` для media playlist без master — средняя сложность (выбор layout по содержимому, плеер без аудио-трека). Для YouTube не нужно: там видео и звук собираются отдельно.
