# A11. Панель статуса применения настроек

Статус: PASS.

## Где видно
Панель — это `render_status` в окне настроек (`settings_ui/layout.rs`): жирная сводка плюс строки
деталей под полями. Не телеметрия и не флаг разработчика, её видит обычный пользователь после
«Применить», при live-предпросмотре, отмене, сбросе и ошибках полей. Поэтому переведена целиком.

## Корень
Статус собирался из внутренних структур как есть: `Route `settings.x`: failed: <английский message>`,
`{:?}` для отката и активности, id настроек списком, `baseline/current` поколения, `TOML`/`runtime`
в сводках. Английские сообщения `renderer_recreation.rs` и `dma_buf_runtime_fallback.rs` приходят
туда же через `ApplyRouteResult::Failed { message }`.

## Решение
- `settings_runtime/setting_labels.rs` (новый): `SettingLabels` берёт название настройки из metadata
  registry (то же, что подписи полей). Неизвестный id не показывается.
- `settings_runtime/status_text.rs`: все тексты переписаны по-русски, `match` по результатам без `_`.
  Показывается «что применилось / применено частично / не удалось / плеер занят / значение
  изменилось в другом месте / не удалось вернуть прежнее значение (перезапустите приложение)».
  При пересборке pipeline/renderer добавлено «воспроизведение могло ненадолго прерваться».
  Технические message, имена route-ов, поколения, активность — в `tracing`.
- `settings_runtime/settings_error_message.rs` (новый): таблицы `SettingsError` и `SettingValueError`
  -> русская фраза (подсказки под полями теперь тоже русские, например «Значение должно быть от 0 до 1»).
- `settings_runtime.rs`: `report_runtime_error` принимает `SettingsError`; тексты прогресса и
  ошибок полей без `TOML`/`runtime owners`/id. Вызывающие передают ошибку без изменений.

## Тесты
`settings_runtime/tests/status_text_user_facing.rs` (11): успех, пересборка, частичный, сбой + сбой
отката, занят + конфликт, `SettingsError`, предпросмотр (применён/ждёт/ошибки), отмена, сброс,
неизвестный id, сквозной сбой через живой `SettingsRuntime`, ошибка значения поля. Общий
`assert_user_facing`: нет route/id/Debug/`{`/английских слов вне «названий» и нет английского
message владельца. Проверки: `cargo test -p app-egui --locked` (1493 ok), fmt, clippy -D warnings.

## Приёмка владельцем
1. Открыть настройки, изменить громкость/сетевую настройку, «Применить»: строки вида
   ««Название»: применено», без `Route`/id.
2. Сломать применение (например, при перемотке сменить сеть): «плеер занят…», без `RuntimeBusy`.
3. Ввести недопустимое значение в числовое поле: подсказка по-русски.

## Риски и остаток
- Причина сбоя route-а обобщённая: `Failed { message }` в settings-core это строка без типа.
  Детальные причины по-русски потребуют типизации в settings-core (отдельное решение).
- Нет отдельного исхода «нужен перезапуск» в типах; перезапуск советуется только при сбое отката.
