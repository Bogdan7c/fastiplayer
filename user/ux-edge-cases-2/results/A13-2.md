# A13-2: HLS без звука (video-only media playlist)

Статус: PARTIAL (видео без звука поддержано полностью; audio-only HLS сознательно не тронут, см. ниже).

## Решение владельца
Видео без звука бывает часто, поэтому video-only HLS media playlist должен открываться и играть.

## Корень
Форму дорожек для top-level media playlist задавал `native_media_selection` как `MuxedAv` («ровно видео + звук»). У media playlist нет CODECS, форма неизвестна до probe сегмента, а сам runtime (`validate_track_shape`, VOD/live, player без audio clock) video-only уже умел: `VideoOnly` существовал для YouTube-подобных split-потоков. Ошибка: `HLS main track shape mismatch: expected MuxedAv, video=1, audio=0`. Тем же ограничением страдал master-variant без audio-кодека в CODECS.

Попутно найден второй, реальный дефект player-core: при перемотке (клик по таймлайну = live-scrub) HLS публикует `TracksChanged` как маркер самого seek-а. `handle_demux_track_list_update` отменял scrub как «внешнюю команду», цель перемотки терялась при уже переставленном demuxer-е. С аудио позицию догонял audio clock по PTS пакетов, а у видео без звука таймер навсегда застревал на старой позиции (живой прогон: после клика на 00:27 позиция оставалась 00:04).

## Что изменено
- `web-media-hls/src/selection.rs`: новый intent `HlsMainTrackLayoutIntent::VideoWithOptionalAudio` (video=1, audio не больше 1, форму доказывает содержимое).
- `native_ingress.rs`: top media playlist использует его; master-variant без audio-кодека и без AUDIO group admitted native (variant с AUDIO group без audio-кодека по-прежнему идёт в extractor).
- `open.rs` (`validate_track_shape`), `catalog/build.rs` (provider default: coupled-строка варианта, иначе video-only).
- `player-core/src/session/media_lifecycle.rs`: первый `TracksChanged` при активном seek-е и неизменных дорожках не отменяет live-scrub; смена дорожек отменяет, как раньше (защита S19).

## Таблица до/после (путь x форма)
| Путь, форма | До | После |
|---|---|---|
| media playlist ts, VOD, видео+звук | открывается | открывается (регрессия проверена) |
| media playlist fMP4, VOD, видео+звук | открывается | открывается |
| media playlist ts VOD, video-only | shape mismatch | открывается, длительность, seek |
| media playlist fMP4 VOD, video-only | shape mismatch | открывается |
| media playlist ts live, video-only | shape mismatch | открывается, играет |
| master, variant без audio-кодека и без AUDIO group | extractor fallback | native, video-only |
| master, AUDIO group, CODECS без звука | extractor fallback | без изменений |
| master, split video+audio (YouTube-подобный) | открывается | без изменений |
| media playlist, только звук (радио) | shape mismatch | без изменений (не поддержано) |

Другие пути (DASH, progressive http) в этой задаче не менялись; их формы определяются своими owner-ами и этим кодом не затронуты.

## Audio-only (радио): описание, не реализовано
VOD можно было бы принять тем же intent-ом, но live упирается в `HlsLiveTimelineEvidence::requires_video_random_access`: признак «есть видео» фиксируется до probe, а аудио-only live без video-якоря не получает decode anchor. Нужно передавать результат probe в live-coordinator. Это отдельная работа; решение владельца нужно, если радио нужно сейчас.

## Тесты
- `web-media-hls/tests/video_only_hls.rs`: ts VOD (длительность 30 с, видео-пакеты с keyframe, перемотка садится на keyframe второго сегмента), fMP4 VOD, live, master без audio-кодека через каталог до видео-пакетов, регрессия muxed ts/fMP4 (обе дорожки), audio-only top по-прежнему shape mismatch. Мутация (вернуть `MuxedAv`) роняет ts/fMP4 тесты.
- `native_ingress.rs`: admission master без audio-кодека и с AUDIO group.
- `player-core/.../scrub_track_list_marker.rs`: маркер seek-а не отменяет scrub; второй TracksChanged отменяет (мутация роняет первый тест); существующий тест смены топологии проходит.
- Проверки: `cargo test` player-core, web-media-hls, media-source-open; fmt; clippy `-D warnings`; `check-refactor-guardrails.py`; module-size guardrail.

## Живая проверка (release, изолированный XDG-профиль, http раздаёт ffmpeg-ts без звука)
VOD video-only: открылся (00:40), играл, перемотка на 00:27 дала 00:34/00:35 с идущим таймером, ошибки «нет звука» нет. Live video-only: играл, таймер 00:17 -> 00:22, окно DVR. Локальный mp4 без звука и muxed HLS ранее перематывались корректно. Приложение остановлено.

## Приёмка вручную
Раздать ffmpeg-HLS с `-an` (ts, VOD и live) по http, открыть через «Добавить URL»: играет, таймер идёт, клик по таймлайну перематывает и воспроизведение продолжается.

## Риски
Master-variant без audio-кодека, где звук всё же зашит в сегменты, теперь открывается как muxed (раньше уходил в extractor). Master/каталог с video-only проверены тестом, не вживую. Правка player-core затрагивает только первый TracksChanged при совпадающих дорожках.
