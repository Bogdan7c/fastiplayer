## A12. `ftp://example.com/a.mp4` принимается как direct media

**Предпосылка задачи не подтвердилась.** Все входы (поле «Добавить URL», вставка, drag&drop текста, пересылка второму экземпляру, CLI, импорт m3u/xspf, переоткрытие строки) идут через один `classify_startup_url`; расхождения путей нет.
FTP(S) для direct media реально поддерживается: провайдер `web-media-ftp` зарегистрирован (`media-source-open/direct_progressive_open`), в реестре `PRODUCTION_YT_DLP_INPUT_PROVIDERS` ftp/ftps отмечены Implemented (S37), `service-direct-media` явно принимает http(s) и ftp(s).
Текст «Ссылки `ftp` пока не поддерживаются» срабатывает только если провайдер не зарегистрирован; сейчас такая ситуация возможна лишь в тестах. Исключены по профилю rtmp/rtmpe («исключены из поддерживаемых в этой версии»), остальные схемы отказывают сразу.
Отказ «Пропущено из-за ошибки» для `ftp://example.com/...` приходит из-за того, что на example.com нет FTP-сервера: это сетевая ошибка воспроизведения (`SourceError::FtpTransport` -> «нет связи»), а не неподдерживаемая схема. Проверить достижимость сервера при добавлении нельзя без сетевого запроса в UI-потоке, поэтому поведение оставлено.
Изменение: тест `add_url_accepts_supported_ftp_and_refuses_excluded_scheme_up_front` (`playlist_runtime/actions.rs`) фиксирует границу: ftp добавляется, rtmp отказывает сразу с русской причиной, очередь не меняется.
Импорт .m3u: ничего не менялось, он классифицирует теми же правилами; ftp-строка принимается как любая поддерживаемая.

## A14. «Перемотка» и заголовок секции

**Корень.** Строка «Перемотка» брала `MediaInfo::seekable` (свойство контейнера), а seek player отклоняет по `PlayerSnapshot::timeline` (`seekable`, `mode`, `seekable_range`; см. `begin_exact_timeline_seek`: `NotSeekable`, для live вне окна `Expired`). Поэтому у live сайдбар обещал «Доступна», а player отказывал.
**Изменения** (`web_media_stream_model.rs`, `ui/url_sidebar.rs`): `seekable: bool` заменён на `UrlSidebarSeekAvailability { Unknown, Unavailable, Available, WithinLiveWindow }`, выводится функцией `seek_availability(snapshot)` из `timeline`:
- media не установлено -> «Определяется»; `timeline.seekable == false` -> «Недоступна»;
- Static + seekable -> «Доступна»; Live + seekable -> «В пределах окна эфира» (по семантике player-core вне окна seek вернёт «эта часть эфира уже недоступна»).
Заголовок «Прямой web-поток» относится к `WebMediaIngressKind::DirectResource`, т.е. «direct» = прямая ссылка на файл, а не live; переименован в «Прямая ссылка на медиафайл».

## Тесты
Модель: live без окна -> Unavailable, live с окном -> WithinLiveWindow, static seekable/нет -> Available/Unavailable, пустой snapshot -> Unknown. UI (AccessKit): каждая подпись строки «Перемотка» присутствует, остальные нет; заголовок direct-ссылки не содержит «web-поток».
