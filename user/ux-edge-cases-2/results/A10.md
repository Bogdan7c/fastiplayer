# A10. Ошибки на смеси языков

Статус: PARTIAL (самые видимые пути закрыты; хвост перечислен ниже).

## Корень
`Display` у `PlayerError` печатает `"{Kind:?}: {message}"` — формат для логов, но его
брали прямо в toast, центр уведомлений и бейдж строки плейлиста. Пользователь видел
«SeekUnavailable: Live stream ...». Аналогично строки `NetworkError: ...`, «media services»,
«controlled reopen» и `{error:?}` попадали в UI напрямую.

## Решение
Display/Debug и логи не менялись. В UI текст идёт через явный слой (маппинг в app, контракт
player-core не тронут, достаточно типизированного `PlayerErrorKind`):
- `player_error_message.rs` (новый): таблица «вид ошибки -> русская фраза», match без `_`
  (новый Kind ломает компиляцию). Используется в toast (RecoverableError), центре (Failed)
  и бейдже строки плейлиста (`navigation.rs`, было «Ошибка воспроизведения (DemuxError)»).
- `settings_rebuild_message.rs` (новый): сбой пересборки media при смене настроек; причина
  web берётся из `web_open_message`; детали пишутся в `tracing::warn!`.
- `url_service_adapter.rs`: `safe_error()` без `NetworkError:` и жаргона («Некорректная ссылка»,
  «Ссылки `ftp` пока не поддерживаются» и т. д.).
- `startup_media.rs`: два сообщения запуска job-а больше не несут `NetworkError:`/`{error}`.
- `ui/url_sidebar.rs`: «Источник будет открыт заново; очередь при этом не меняется.»
- `audio_runtime.rs` (player-core): доходит только как `AudioDeviceUnavailable`, у которого уже
  человеческий текст; сырой текст не показывается — не менялся.

## Тесты
Новые: все 20 Kind не содержат имени Kind, английского `message` и путей; `Display` остаётся
`"SeekUnavailable: ..."` для логов; бейдж; все 5 причин unsupported URL; sidebar (AccessKit);
тексты rebuild. Обновлены ожидания toast/центра/оверлея/CLI-ошибок.
Проверки: `cargo test -p app-egui -p player-core --locked`, fmt, clippy -D warnings — зелёные.

## Приёмка владельцем
1. Live-поток: нажать перемотку -> toast «Перемотка для этого видео недоступна».
2. Вставить `ftp://...`/мусор в «Добавить URL» -> русская причина без «NetworkError».
3. Изменить сетевую настройку при играющем битом web-источнике -> статус без `rebuild failed`.
