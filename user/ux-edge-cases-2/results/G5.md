# G5. Чёрный первый кадр на паузе после старта

Статус: PASS

## Корень
Не гонка и не http-специфика. Новое media устанавливается сразу в `Paused`, а декодер получает пакеты только в «активных» состояниях (`Playing/Buffering/Seeking/Draining`). Если после установки остаётся пауза (`player.start_paused`, CLI-ссылка, resume у конца по B2 → `Continue` без seek-а), ни один кадр не декодируется, и окно чёрное до Play или перемотки. При resume из середины кадр есть только потому, что позиция восстанавливается обычным seek-ом. Воспроизводилось и с локальным файлом. Механизма «показать кадр на паузе без seek-а» не существовало; «иногда» — потому что кадр появлялся, если seek/preroll случайно успевал до паузы.

## Решение
Владелец — player-core, новый модуль `session/paused_poster_frame.rs`. `pause()` после перехода в `Paused` вызывает `request_paused_poster_frame_if_missing()`: если выбран видеотрек, на экране нет кадра, нет активного seek/scrub и таймлайн static + seekable, запускается обычный seek на текущую позицию с resume intent Pause. Он декодирует и публикует кадр и возвращает `Paused`. Второго пути декодирования не добавлено. Отказ seek-а пишется в лог (warn), пауза остаётся успешной. Live и несикабельные источники постер не получают (seek дал бы пользовательскую ошибку). Autoplay (`Play`) не затронут: лишнего seek-а на быстром пути нет.

## Тесты (`session/tests/paused_poster_frame.rs`)
- Пауза без кадра -> seek -> декодированный кадр доходит до presentation, кадр на экране, состояние `Paused`, позиция 0.
- Постер берётся с текущей позиции паузы (7 с), а не с начала.
- Пауза с кадром на экране — seek не запускается и нет `SeekRequested`.
- Несикабельный источник и audio-only — без seek-а и без ошибки.
- Pause отменяет идущую перемотку: постер на удержанной позиции, не на отменённой цели.
Шесть существующих тестов (worker/scrub/demux_retry), где Pause проверялся на fixture без кадра, получили кадр на экране (как при реальном воспроизведении).

## Живая проверка (release, изолированный профиль, скриншоты g5_*)
До фикса: CLI http-mp4 и локальный файл — чёрный кадр на 00:00 Paused. После: (а) CLI http — кадр есть, Paused; (б) рестарт с resume у конца -> 00:00, кадр есть; (в) рестарт без аргументов с 00:21 — кадр есть; (г) локальный файл — кадр есть; Play из постера играет, FPS 60.

## Ручная приёмка
1. `start_paused = true`, открыть любой видеофайл или ссылку: на 00:00 сразу виден кадр, состояние Paused.
2. Перемотать к концу, закрыть, открыть снова: с начала, кадр виден.
3. Нажать Play — воспроизведение идёт без задержки.

## Риски
Во время постера (~50-100 мс) состояние кратко `Scrubbing/Seeking`, как при restore-seek. Live на паузе и несикабельный источник по-прежнему без кадра до Play.
