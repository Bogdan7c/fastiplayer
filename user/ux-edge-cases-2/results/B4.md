# B4: экспорт плейлиста пропускает неподходящие записи

## Статус

**PASS** по автоматическим проверкам. Ручная приёмка владельцем (GUI) не выполнялась.

## Решение владельца (README, B4)

Неподходящие записи пропускаются, остальное экспортируется, пользователь видит «Экспортировано M, пропущено N» с короткой причиной.

## Корень

В `preflight_playlist_export` цикл по записям возвращал `?` на первой же непредставимой записи, и падал весь экспорт. Ошибки записи файла сводились к одному тексту «Не удалось атомарно сохранить файл».

## Какие записи «неподходящие»

- Локальный путь не UTF-8, чужой ОС, относительный, не превращается в `file:` URI.
- Ссылка, которую владелец URL-сервиса не признал переносимой (нет стабильного адреса); сервисные payload-ы пока всегда отклоняются.
- XSPF: непредставимый адрес корня группы. Части при этом экспортируются плоско (как в M3U8) с предупреждением, а не теряются.
- CUE: остаётся «всё или ничего». Пропуск трека ломает последовательность FILE/INDEX, а пункт и так отключён в UI, пока область не подходит.

## Что сделано

- `playlist-io/export/skip.rs` (новый): `PlaylistExportSkipReason`, `PlaylistExportSkipCounts`. `PreparedPlaylistExport` получил `skipped()` и `skip_counts()`. Цикл preflight собирает пропуски вместо `?`.
- `app-egui/playlist_runtime/export_io/report.rs` (новый): `PlaylistExportReport` (сколько записано/пропущено), `PlaylistExportWriteFailure` (нет прав, только чтение, диск полон, папки нет, прочее) по `io::ErrorKind` без пути.
- `export_io/messages.rs` (новый): все русские тексты. Путей к каталогам в тексте нет.
- Если пропущено всё, файл не создаётся: «Нечего экспортировать: ни одна из N записей не подходит…».
- Запись файла не менялась: temp + rename из `atomic-file-store`, при сбое прежний файл цел, полуфайла нет.

## Тесты

- `playlist-io/tests/export_core.rs`: 3 записи, одна плохая, M3U8 и XSPF, в документе ровно 2 записи и нет плохой; корень группы отклонён, части в документе; все плохие, 0 треков и 2 пропуска; два прежних теста `expect_err` переписаны под пропуск.
- `export_io/tests/skip_report.rs`: реальный файл с 2 из 3 записей и текст «Экспортировано 2, пропущено 1: …»; все плохие, файл не создан; несколько причин в тексте; read-only каталог, «нет прав на запись», пути нет в тексте, полуфайла нет (при запуске от root тест пропускает проверку); ENOSPC (`StorageFull`) через writer-стаб доходит до текста; маппинг `ErrorKind`.
- Проверки: `cargo test -p playlist-io -p app-egui --locked`, `cargo fmt --all --check`, `clippy -D warnings`, module-size guardrail.

## Ручная приёмка для владельца

1. Плейлист из 3 записей, одна с относительным локальным путём или нестабильной ссылкой: Экспорт M3U8, затем в файле 2 записи, в тосте «Экспортировано 2, пропущено 1: …».
2. Только неподходящие записи: файл не появился, сообщение «Нечего экспортировать…».
3. Сохранить в папку без прав записи: «нет прав на запись в выбранную папку».

## Риски

- Тост показывает прежний «безопасный feedback» (одна строка); длинный список причин не помещается, поэтому текст сделан коротким.
- Обычный экспорт без пропусков по-прежнему молчит (как раньше).
- Текст про составные группы больше не называет M3U8 (теперь возможен и в XSPF).
