# A9c: Undo пропадал после автоперехода в живом приложении

Статус: PASS.

## Симптом
После A9b юнит-тесты были зелёными, но вживую (4 mp4 по 7 с, shuffle выключен) кнопка Undo исчезала почти сразу после автоперехода, хотя 8 секунд не прошли. Пропадал только Undo; строки и текущий трек были верными.

## Корень
Тесты A9b проводили автопереход через прямой `PlaylistRuntime::on_playlist_installed`. Приложение же после успешного открытия медиа регистрирует lineage через `register_successful_strong_install` (`state::strong_media_open`). В этом пути оставалась прежняя безусловная проверка «lineage сменилась — сбросить Undo», не знавшая про решение A9b (`undo_survives_current_change`). Первый путь A9b починил, второй (боевой) нет. То же правило было продублировано ещё в одном месте resume-ветки.

## Что сделано
- `removal_undo.rs`: единый метод `release_removal_undo_for_new_lineage` — единственный владелец правила «новая lineage освобождает Undo» (с учётом shuffle и удалённой играющей строки). Сброс пишет debug-лог с причиной (target `rustiplayer::removal_undo`).
- `on_playlist_installed_with_playback_intent` и оба места в `suspend_resume.rs` (резюме и `register_successful_strong_install`) используют этот метод вместо собственных сравнений lineage.

## Тесты
`removal_undo/tests/current_change.rs` получил режим `InstalledPath::StrongInstall` (автопереход Ended -> запрос -> авторизация -> `register_successful_strong_install` с реальным binding). Новые тесты: Undo после такого автоперехода возвращает строку и не перезапускает играющий трек; строка выше играющей; регрессии боевого пути — shuffle и удалённая играющая строка по-прежнему сбрасывают Undo.
Мутационная проверка: возврат старого кода в `suspend_resume.rs` роняет оба «выживающих» теста; на текущем коде до фикса они падали.
