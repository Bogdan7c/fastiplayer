# C3: звук опережает видео после пересоздания аудиовыхода

## Статус

**PASS.** Исправлено без изменения семантики audio clock. Проверено юнит-тестами и вживую.

## Корень

- Audio clock считает только **проигранный настоящий PCM**: тишина при underrun его не двигает. Media-время = якорь + позиция clock-а.
- К моменту пересоздания output-а в кольце старого выхода лежит непроигранный хвост (`submitted_output_tail`, около 200 мс). Decoder уже ушёл дальше него: следующий PCM для нового output-а имеет PTS `T + хвост`.
- Старый код привязывал clock нового output-а к `T`, а кольцо оставалось пустым. Первый записанный PCM (`T + хвост`) играл при clock-е `T` — звук опережал видео на хвост до перемотки.
- Измерение на fake output-е (хвост 200 мс, `T = 42 с`): clock 42 с, PTS звука 42,2 с, расхождение ровно 200 мс. Вживую хвост был 223,6 мс.
- Хвост забрать нельзя: consumer кольца живёт внутри callback-а потока, который при потере устройства мог умереть.

## Варианты

- **а) Перенести PCM старого выхода.** Нет доступа к кольцу, нужен новый контракт output-а. Отклонён.
- **б) Откатить clock на хвост.** Меняет семантику clock-а, видео ждёт, а звук всё равно уходит вперёд. Отклонён.
- **в) Внутренний seek на текущую позицию.** Перезапуск demux и decoder-ов, видимая заминка видео, гонки с состояниями seek/pause. Слишком тяжёлый.
- **г) Выбран: тишина вместо потерянного хвоста.** В новый output до запуска пишется тишина длиной хвоста. Anchor остаётся `T`, первый настоящий PCM встаёт в clock-позицию `хвост`, то есть ровно в `T + хвост`.
  - Видео не прыгает и не ждёт, clock не менялся.
  - Пользователь слышит короткую паузу (~200 мс) вместо постоянного рассинхрона.
  - Уровень буфера и граница EOF-drain сохраняют прежнюю длину хвоста.

Решения владельца не требовалось: поведение «звук не опережает видео» уже было ожидаемым, меняется только способ передачи.

## Изменения

- Новый `player-core/src/session/audio_output_handover.rs`:
  - `PlayerSession::audio_output_unplayed_tail`;
  - `prefill_replacement_output_with_silence` (ошибка записи или неполная запись дают `AudioDeviceUnavailable`, старый output остаётся нетронутым).
- `session/audio_runtime.rs`: `recreate_active_audio_output` вызывает prefill до `play` и установки. Один путь обслуживает восстановление после потери устройства и смену устройства в настройках.
- Тесты: `session/tests/audio_output_handover.rs`. В `audio_output_recovery.rs` общие хелперы стали `pub(super)`.

## Тесты

Каждый тест проверяет наблюдаемый результат: медиа-время presentation clock в момент, когда новый output доходит до первого настоящего PCM, против PTS этого PCM. Допуск 1 мс (кадр 48 кГц ≈ 21 мкс).

- Потеря устройства с хвостом 200 мс: расхождение ≤ 1 мс. С отключённым prefill тест падает: «clock 42s, PTS звука 42.2s».
- Смена устройства в настройках: тот же синхрон.
- Пересоздание на паузе: тишина записана, output не запущен.
- EOF-drain (`Draining`): хвост той же длины, output запущен.
- Нет хвоста (после перемотки): в новый output ничего не пишется.
- Длина тишины по sample rate и каналам, нулевой хвост, ошибка записи, неполная запись.
- Перемотка в процессе: отдельного теста нет, перемотка очищает кольцо, хвост становится 0 (покрыт тестом «нет хвоста»).

## Живая проверка

Изолированный XDG-профиль, release-сборка, ролик H.264 + AAC 40 с, устройство в config `pulse`. Запись звука системы не делалась, синхрон оценён по логу и тестам.

- Во время воспроизведения отключили только клиента плеера (`pw-cli destroy <client>`), общий pipewire не перезапускался.
- Лог: ошибка потока → `default` → «Хвост старого вывода звука заменён тишиной… silence_frames=10735 unplayed_tail_ms=223.6» → «восстановлен на устройстве по умолчанию». Настоящий output принял всю тишину, ошибок и предупреждений после этого нет.
- Скриншот после переключения: Playing, `Frame pacing: OK`, плашка «Звуковое устройство отключено — звук переключён на устройство по умолчанию».
- Скриншоты и логи остались в scratchpad (не в репозитории). Телеметрии A/V drift в плеере нет.
- Системные аудионастройки не менялись, процессы убиты.

## Ручная приёмка для владельца

1. Запусти видео со звуком, включи Telemetry. Переключи устройство в настройках (или отключи BT-гарнитуру на выбранном напрямую устройстве).
2. Ожидание: короткая пауза звука ~200 мс, затем звук и картинка совпадают без перемотки.

## Риски

- Anchor `T` берётся из `current_source_position` (отстаёт не больше чем на один tick). Хвост при смене playback rate внутри него считается по оси output-а, возможна ошибка в доли хвоста.
- Физическое выдёргивание USB/BT вживую не проверялось (нет железа), как и в сессии 10.
