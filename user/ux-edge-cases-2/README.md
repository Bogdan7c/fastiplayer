# Fastiplayer: UX edge cases, часть 2 (бэклог)

Подготовлено 10 октября 2026. Источник — раздел «Бэклог» плана [`ux-edge-cases`](../ux-edge-cases/README.md) и «Открытые риски» его отчётов `results/01–18.md`. Каждый пункт перед стартом сверён с кодом на HEAD `e184313e` (read-only субагент). Номера строк — снимок на эту дату.

Уже закрыто попутно и из плана исключено: классификация HTTP 404/410/429 (`web-media-http` теперь различает `NotFound/Gone/RateLimited`), `reduced_motion` по умолчанию `false`.

## Решения владельца (10 октября 2026)

Владелец принял рекомендации исполнителя целиком:

- **B1. Кодировка `.m3u`/`.cue`** — сначала UTF-8; при ошибке — Windows-1251 с уведомлением «прочитано как Windows-1251».
- **B2. Resume у конца** — если осталось < 5 % длительности или < 10 с, трек начинается с начала.
- **B3. Хоткеи** — громкость колесом над видео, ↑/↓ — громкость, Ctrl+O — открыть файл, подсказка времени при наведении на таймлайн, клавиши скорости работают глобально (а не только при наведении на play).
- **B4. Экспорт плейлиста** — неподходящие записи пропускаются, остальное экспортируется, пользователь видит «пропущено N».
- **B5. Системный reduced motion** — не делаем.
- **B6. Hardware-only без VA-API** — предупреждение строкой в настройках.
- **B7. Clear плейлиста** — без диалога подтверждения; Undo Clear возвращает и воспроизведение.
- **B8. Очередь без сети** — останавливаться на первом элементе с причиной «нет сети», а не перебирать всю очередь.
- **B9. Кнопка «Повторить»** на ошибке открытия — делаем.
- **B10. Автовозврат на вернувшееся аудиоустройство** — пока не делаем.

Решения по ходу работы (10 октября 2026):

- **A9. Undo после автоперехода** — Undo возвращает только удалённую строку, указатель «что играет» не трогается; только без shuffle. Если удалена была играющая строка — Undo после автоперехода по-прежнему сбрасывается.
- **A7. Отказ player-а на staging** (это отказ доставки команды, а не битый файл) — очередь останавливается с причиной «player не отвечает», без пропуска и без автоповтора.
- **A13-1. Завершённый EVENT-плейлист** (`PLAYLIST-TYPE:EVENT` + `ENDLIST`) — открывать как VOD.
- **A13-2. HLS без звука (video-only media playlist)** — поддержать. Владелец: «видео без звука бывают и часто, это очень давний проёб». Делается после A13-1.
- **A13-3. HLS без видео (audio-only, интернет-радио)** — поддержать, включая live. Делается после A13-2.
- **A13-4. Packed audio HLS** (сегменты `.aac`/`.mp3` с ID3 PRIV timestamp — частый формат интернет-радио) — поддержать.
- **C2. Подвисание окна при применении настроек** — вариант 1: многокадровая транзакция настроек. Apply сразу возвращает управление («Применяем…»), пересборка — неблокирующим stepwise strong-open; запись config и «применено» только после реального успеха, при ошибке — откат и человеческий текст; повторный Apply — «занято». Подготовка источника (`prepare_*`) уходит с UI-потока.

## Как идёт работа

- Основной агент — оркестратор; каждую задачу делает субагент (Sonnet 5.5, medium) с общими правилами из [`ux-edge-cases/README.md`](../ux-edge-cases/README.md#общие-правила-для-всех-сессий).
- Работа идёт прямо в `main` (решение владельца), задачи — строго по очереди в одном checkout; один коммит на задачу, результат проверяет основной агент.
- Ручная приёмка владельцем — пакетом после группы; найденные проблемы чинятся следующим коммитом.
- Отчёты — `results/<id>.md` (коротко: статус, корень, изменения, проверки, приёмка, риски).
