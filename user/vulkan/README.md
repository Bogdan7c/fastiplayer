# Fastiplayer: разведка «догнать GLES2 на wgpu (Vulkan)»

Подготовлено 28 октября 2026, после сессии 13b плана [`user/gles2-renderer/`](../gles2-renderer/README.md). Код плеера при подготовке не менялся.

## Зачем

В сессии 13b на ThinkPad T480s (Intel UHD 620, Vulkan ANV) наш собственный рендер GLES2 оказался заметно дешевле wgpu на тех же сценах и с тем же декодером. При этом Auto на такой машине выбирает wgpu. Владельца это натолкнуло на мысль о полностью своём рендере Vulkan.

Прежде чем менять рендер целиком, надо понять, **откуда разрыв**:
- сделан ли он «своим рендером» как таковым;
- или несколькими конкретными приёмами, которые есть только в GLES2 и которые можно перенести внутрь wgpu.

## Решения владельца

1. **Цель плана (28.10.2026):** разведать, реально ли сократить разрыв между wgpu и GLES2 **без отказа от wgpu**. Итог — материал для решения: что закрывается внутри wgpu, какой ценой и что останется. Когда заниматься реализацией (и заниматься ли своим Vulkan) — отдельное решение владельца после разведки.

## Отправная точка (цифры, которые надо объяснить)

Все замеры — программный AV1 без CPU-копии, кадры те же, без потерь.

**T480s, протокол v4, XWayland, когорта «оба наших рендера против VLC»** (`user/gles2-renderer/results/13b.md`):

| Сцена | CPU процесса: wgpu / GLES2 | GPU процесса (fdinfo, движок render): wgpu / GLES2 |
|---|---|---|
| AV1 720p30 | 15,8 / **14,7** | 15,3 / **5,7** |
| AV1 1080p30 | 34,3 / **32,9** | 17,1 / **5,7** |
| AV1 1080p60 | 61,7 / **57,2** | 34,2 / **11,3** |

**T480s, ABBA, нативный Wayland** (главный поток, доля ядра): wgpu / GLES2 — 720p30 3,8 / 2,8; 1080p30 3,9 / 2,8; 1080p60 5,8 / 3,6; 4K60 7,4 / 5,6.

**Radeon 780M** (`results/13.md`, AV1, окно 20 с): главный поток wgpu / GLES2 — 1080p60 4,0 / 2,0, 4K60 5,2 / 2,3; занятость `gfx` 2,3 / 1,4 % и 5,4 / 1,6 %.

Разрыв, таким образом, есть на двух разных GPU и двух драйверах: GPU в 2,5–3 раза, главный поток в 1,4–2,3 раза. CPU процесса отличается меньше (−1…−4,5 п.п.): основную часть съедает декодер, он одинаковый.

**Не измерено:** аппаратный декод (VA-API → DMA-BUF) на wgpu против GLES2. На T480s он есть для H.264/HEVC/VP9, и именно им пользуется большинство. Сессия 00 меряет и его.

## Гипотезы: из чего может состоять разрыв

| # | Статья расхода | Что делает GLES2 | Что делает wgpu | Где в коде |
|---|---|---|---|---|
| H1 | Лишний проход GPU на программном кадре | Читает плоскости прямо из памяти декодера: memfd → udmabuf → EGLImage (сессия 12) | Импортирует память декодера буфером (`VK_EXT_external_memory_host`) и **копирует GPU** буфер → текстура каждый кадр (cpu-parity 08b; «настоящий ноль» не делался, 13a) | `render-wgpu-video/src/video/host_planar_upload/wgpu_backend.rs` (`copy_buffer_to_texture`), `host_planar_upload/host_memory_import.rs`; GLES2 — `render-gles2-shell/src/host_block_import.rs` |
| H2 | Стоимость пикселя видеошейдера | Трюк C1 «дешёвый пиксель» (12a): координаты выборок в вершинах, nearest для co-sited 4:2:0, без ветвления letterbox — scissor + clear. На T410 вдвое дешевле | Шейдеры без этих трюков (проверить) | `render-wgpu-video/shaders/*.wgsl`; GLES2 — `gles2-video`, memory `gles2-renderer/extreme-optimization-s12a` |
| H3 | Перерисовка всего кадра | Частичный показ: `EGL_EXT_buffer_age` + `swap_buffers_with_damage` (12a) | Полная перерисовка каждый кадр. Есть ли в wgpu damage / `VK_KHR_incremental_present` — проверить | `render-wgpu-shell` (кадр, swapchain) |
| H4 | Частота проходов интерфейса egui | Удержание UI-кадра (`ReusePrevious`, 04/12a) | В трассе T480s 13b у wgpu мелькали полные проходы `ui_pass_reason="ui_model_changed"`. Бывают ли они в установившемся режиме чаще, чем у GLES2, — проверить | трасса `render frame stage timings` (`ui_full_passes`, `ui_reused_presents`, `ui_pass_reason`) |
| H5 | CPU главного потока на кадр | Тонкие вызовы GL | Запись команд, отслеживание ресурсов wgpu, bind groups; на amdgpu ядро проверяет `userptr`-импорты на каждом submit (cpu-parity 08b) | профиль `perf`/`samply` главного потока |
| H6 | Путь показа | EGL, swap interval | Swapchain Vulkan (FIFO, `max_frame_latency = 2`) | `render-wgpu-shell`; композитор в 13b одинаковый (~2 % у обоих) — вероятно, не причина |

H1–H4 — кандидаты на перенос внутрь wgpu. H5–H6 могут оказаться «ценой самого wgpu», то есть доводом за свой Vulkan.

## Общие правила сессий

Работай в корне checkout-а. Сначала `AGENTS.md`. Перед работой:
- Serena: `initial_instructions`, активация, `mem:core`, `mem:render-video/core`, `mem:render-video/host-planar-staging-belt-upload`, `mem:gles2-renderer/core`, `mem:gles2-renderer/extreme-optimization-s12a`, `mem:gles2-renderer/sw-zero-copy-s12`, `mem:gles2-renderer/t480s-recon-s13b`;
- Context7 — для `wgpu`, `wgpu-hal`, `ash` (что wgpu реально умеет: импорт внешней памяти и картинок, damage/incremental present, timestamp queries). Для расширений Vulkan источник истины — спецификация Khronos;
- широкий поиск по репозиторию — read-only субагентом (модель Sonnet), основной агент читает только точные символы.

**Код плеера не меняется.** Временные сборки для опытов (как вариант «копия» в 13/13a) собираются в отдельном worktree или с временной правкой, которая в git не идёт. В отчёт — SHA бинарника и точное описание временной правки.

Замеры:
- метод — как в 13a/13b: `docs/benchmarks/tools/dev/run_pass.py` и короткие ABBA, прогрев 12 с, окно 20 с; строгий протокол v4 — только если владелец попросит;
- сравниваются только одни и те же сцены, окна одной длины, release с release, в один день, с чередованием;
- **T480s — только по команде владельца** (он отдаёт машину). Длительность называется заранее и не превышается (`mem:measurement-duration-feedback`). На основной машине GUI-замеры — когда владелец разрешил;
- стоп-краны T480s: экран не заблокирован, питание от сети, `GPU HANG` в `journalctl -k`;
- курсор при замерах не трогать.

Отчёты `results/NN.md`: статус, решения владельца, SHA, метод, таблицы, причина каждого вывода, известные ограничения, обновлённые memories. В `user/` только Markdown, без личных путей, имён хостов и логов; сырые данные — в scratchpad.

## Что уже известно о машинах

- **T480s:** i5-8350U 4C/8T, UHD 620 (Kaby Lake-R), Mesa 26.2.4, ANV с `VK_EXT_external_memory_host`, EGL 1.5 / ES 3.2; VA-API iHD: H.264, HEVC Main/Main10, VP9 0/2, AV1 нет; общий кэш CPU и GPU; масштаб KDE 1,25. `intel_gpu_top` стоит, но без правила sudoers NOPASSWD harness его не запускает — правило добавляет владелец, если нужен глобальный Render/3D. Подробности — `mem:gles2-renderer/t480s-recon-s13b`.
- **Основная машина:** Radeon 780M (RADV / radeonsi).
- **T410** — без Vulkan, в этом плане не участвует.

## Контекст решений, который нельзя потерять

- Шов «приложение ↔ рендер» — trait `RenderShell` и каталог рендеров (план gles2-renderer, решение 3). Новый рендер — новый крейт и строка каталога, приложение не меняется. Значит, вопрос «свой Vulkan» — про объём и сопровождение, а не про архитектуру приложения.
- Планы на Windows: wgpu (DX12/Vulkan) и свой рендер DirectX 10 (решение 3 плана gles2-renderer, `mem` владельца «future platforms render seam»).
- Рендер должен переиспользоваться в редакторе Fasticut (решение 2 плана gles2-renderer).
- Принцип зависимостей: из чужого — только тонкие «провода» к драйверу, которые уже есть в дереве (решение 1 плана gles2-renderer). `ash` уже приходит через `wgpu-hal`.
