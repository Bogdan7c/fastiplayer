# Сессия 00: замер и разложение разрыва wgpu против GLES2

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 00 плана `user/vulkan/`: разведка, откуда разрыв между рендерами wgpu и GLES2 (T480s: GPU в ~3 раза, главный поток в ~1,5 раза; 780M — тот же знак). Только замеры и чтение кода, код плеера не меняется. Итог — таблица «статья расхода → доля разрыва» по гипотезам H1–H6 README плана. Сначала прочитай `user/vulkan/README.md` и `user/gles2-renderer/results/13b.md`.

## Что сделать

1. **Инвентаризация работы на кадр** — read-only субагентом, по коду. Для каждого рендера и каждого пути (SW 8/10 бит, HW NV12/P010):
   - какие проходы GPU (копии, видеослой, интерфейс, субтитры, композиция, показ);
   - какие вызовы на главном потоке;
   - что и когда перерисовывается при неизменном интерфейсе.

   Итог — две колонки «wgpu / GLES2» по шагам кадра, с ссылками на символы.
2. **Инструменты профиля GPU по проходам** — выбрать и проверить в начале сессии:
   - Intel: `INTEL_MEASURE` (Mesa, работает и для iris, и для ANV) — проверить по документации Mesa, что он даёт время на проход/рендер-пасс в обоих API;
   - AMD 780M: RGP через RADV (`MESA_VK_TRACE`) для wgpu, для GLES2 — GL timer queries или статистика `gles2-video`;
   - запасной вариант — timestamp queries wgpu (Context7: возможность `TIMESTAMP_QUERY`) во временной сборке.
3. **Замеры** — основная машина (780M) и T480s **по команде владельца**. Длительность назвать заранее.

   Сцены:
   - SW: AV1 1080p30, 1080p60, 4K60 (файлы `make_matrix.py --preset t410` и `benchmark-matrix`);
   - **HW:** H.264 и HEVC 1080p60, VP9 4K60 (на T480s есть VA-API);
   - каждая сцена: wgpu против GLES2, ABBA, окно 20 с, нативный Wayland.

   Метрики:
   - CPU процесса и главного потока;
   - GPU процесса (fdinfo) и время GPU по проходам (п. 2);
   - доля кадров с полным проходом интерфейса (`ui_full_passes` / `ui_reused_presents` / `ui_pass_reason` из трассы);
   - память.
4. **Профиль CPU главного потока** (`perf` или `samply`) на 1080p60 SW и HW для обоих рендеров: где wgpu тратит больше (запись команд, отслеживание ресурсов, bind groups, импорт, submit, ядро).
5. **Разложение.** Для каждой гипотезы H1–H6 — оценка доли в разрыве GPU и в разрыве главного потока, с указанием, чем доказано (время прохода, профиль, счётчик) и насколько надёжно.

## Критерий выхода

- Отчёт `results/00.md`:
  - инвентаризация из п. 1;
  - таблицы замеров по машинам и сценам, SW и HW;
  - таблица «гипотеза → доля разрыва GPU / главного потока → доказательство».
- Отдельной строкой: есть ли разрыв на **аппаратном** декоде. Если его нет, вопрос сужается до программного пути.
- Список того, что сессия 01 проверяет опытами, по убыванию ожидаемого выигрыша.
