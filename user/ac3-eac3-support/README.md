# Fastiplayer: поддержка AC-3 / E-AC-3 (Dolby Digital / Dolby Digital Plus)

Подготовлено и выполнено 16–17 октября 2026 серией рабочих пакетов под управлением координатора. Код написан агентами, решения по архитектуре и поведению принимал владелец. Итоговый отчёт приёмки — [`results/01.md`](results/01.md).

## Зачем

До этой работы плеер умел *вынимать* AC-3/E-AC-3 из MKV и MP4 (демуксер отдавал дорожку `A_AC3`/`A_EAC3`), но декодера не было: такие файлы открывались без звука с ошибкой «кодек не поддерживается». Это один из самых распространённых форматов звука в фильмах, сериалах, ТВ-записях (MPEG-TS) и в части web-потоков (HLS/DASH с `ec-3`).

## Решения владельца

1. **Декодер — собственный crate `ac3-decoder`** (пересмотрено владельцем 17 октября 2026). Сначала был выбран готовый сторонний crate-декодер с локальным патчем (f32-выход вместо 16-битного). Владелец ему не доверился: ~55 тысяч строк кода, который никто не проверял, а при нашей проверке нашлась неверная таблица для 44,1 кГц. Свой декодер дороже по времени, но каждую строку можно сверить со спецификацией, и он не тянет чужие зависимости в ядро плеера. Сторонний crate и его патч полностью удалены из репозитория. Новый декодер написан с нуля «чистой комнатой»: только по спецификациям ATSC A/52:2012 и ETSI TS 102 366 v1.4.1, исходники чужих декодеров не читались; без внешних зависимостей и без `unsafe`. ffmpeg используется только как внешняя программа — кодер тестовых потоков и эталон для сравнения.
2. **Выход декодера** — f32 без обрезки пиков и настоящая раскладка каналов каждого кадра (позиции громкоговорителей, включая каналы E-AC-3 7.1). Адаптер в crate `audio` раскладывает их по нейтральным позициям плеера; для «surround direct» (Lsd/Rsd), у которых нет своей позиции, берётся боковая пара, а если она занята — задняя. Если раскладку перевести нельзя, плеер сообщает об этом один раз и дальше играет тишину (без ошибки на каждый пакет).
3. **Громкость как у обычных декодеров**: динамическое сжатие (`dynrng`) применяется полностью — режим «line out», как у ffmpeg по умолчанию; нормализация диалога (`dialnorm`) и даунмикс внутри декодера не делаются — каналы сводит микшер плеера.
4. **Полная поддержка, а не «только MKV»**: MKV, MP4/MOV, MPEG-TS (включая HLS с TS-сегментами), сырые файлы `.ac3/.eac3/.ec3` (новый crate `ac3-elementary-demux`), web/adaptive кандидаты (HLS/DASH/yt-dlp с кодеками `ac-3`, `ec-3`).
5. **Смена формата посреди потока** (ТВ-эфир: реклама в стерео, фильм в 5.1) — звуковой выход пересобирается в player-core без потери синхронизации с видео и без дыры (старый поток доигрывает свой хвост). Раньше любая смена раскладки/частоты была фатальной ошибкой.
6. **Web-потоки: Dolby только запасной вариант по умолчанию.** Если у web-видео есть AAC и E-AC-3, по умолчанию выбирается AAC (как было раньше); Dolby выбирается сам, только если другого звука нет. Зато в меню звука «♪» (и клавишей `B`) версии подписаны, например «English (AAC 2.0)» / «English (E-AC-3 5.1)», и пользователь может переключиться.
7. **Smooth Streaming + Dolby — не делаем.** Профиль Smooth в проекте только H.264+AAC, а init-сегмент там синтезируется из манифеста без битового потока — для Dolby пришлось бы читать первый фрагмент заранее. Решено не тратить на это силы.
8. **Битый пакет AC-3 → тишина длиной кадра + предупреждение в лог**, а не ошибка на экране на каждый пакет (так же ведут себя декодеры Symphonia/Opus). Синхронизация с видео при этом не уезжает. Контрольные суммы кадра (CRC) проверяются всегда: кадр с несовпавшей суммой не играется.

## Общие правила серии

- Тест проверяет результат, а не вызов: доказательством служит звук, дошедший до выхода (тон на нужном канале, RMS против эталона ffmpeg), а не факт вызова декодера.
- Фикстуры маленькие, синтетические, сгенерированы ffmpeg; команда записана в `generate.sh` и README рядом с фикстурой. Тесты не требуют ffmpeg во время запуска.
- «Чистая комната» для декодера: каждая таблица в коде ссылается на номер таблицы спецификации и проверяется тестом (контрольные суммы по тексту спецификации или структурное свойство); каждый алгоритм — на раздел спецификации.
- Сверка с эталоном: на синтетических потоках — построчно с PCM ffmpeg (критерий ≥ 90 дБ вне известной сетки округления ffmpeg); там, где спецификация разрешает случайность (dither), — доказательство, что остаток именно dither. Реальные потоки Dolby (samples.ffmpeg.org) — только для прогонов разработчика, в репозиторий не коммитятся.
- Агенты работают в `main` без веток и ничего не коммитят; коммит делает координатор после приёмки.

## Порядок работ

Первая волна (16 октября, со сторонним декодером):

| Пакет | Что |
|---|---|
| A | Адаптер `audio` на стороннем декодере (позже заменён, см. D5) |
| B | MPEG-TS: AC-3/E-AC-3 в PMT (ATSC `0x81/0x87`, DVB-дескрипторы), нарезка на кадры, crate `ac3-syncframe` (заголовки и access unit-ы) |
| C | player-core: пересборка звукового выхода при смене формата посреди потока |
| D | crate `ac3-elementary-demux`: сырые `.ac3/.eac3/.ec3` |
| E | web/adaptive кандидаты (HLS/DASH/yt-dlp), политика «Dolby только запасной» |
| F | меню «♪»: выбор web-версии звука |
| G | сквозные проверки MKV/MP4/fMP4 (DASH, HLS), сырой AC-3 по HTTP/FTP и в yt-dlp |
| H1 | первый живой прогон (на стороннем декодере) |
| I | ревью-исправления: bsid 9/10, AC-3 ядро + E-AC-3 зависимый в одном access unit-е, потеря синхронизации в TS не фатальна, перенос истории скорости при пересборке выхода |

Вторая волна (17 октября, собственный декодер):

| Пакет | Что |
|---|---|
| D1 | `ac3-decoder`: битовый поток AC-3 → частотные коэффициенты (экспоненты, распределение бит, мантиссы, coupling) |
| D2 | синтез PCM AC-3: rematrix, DRC, IMDCT с переключением блоков, overlap-add; сверка с ffmpeg |
| D3 | E-AC-3 (Annex E) до коэффициентов: AHT, SPX, enhanced coupling, зависимые substream-ы, chanmap |
| D4 | PCM E-AC-3: сведение программы 7.1, transient pre-noise processing, единый декодер AC-3/E-AC-3 |
| D5 | адаптер `audio` переведён на собственный декодер; сторонний crate и патч удалены |
| D6 | полный release gate, живой прогон GUI с записью звука из PipeWire, эти документы |

## Бэклог и открытые решения

Каждый пункт — отдельное решение владельца или отдельная работа.

| # | Что | Суть |
|---|---|---|
| 1 | **bsid 9/10 («половинная/четвертная» частота AC-3)** — решено владельцем: играть | Обе спецификации велят такие кадры *глушить*, но владелец решил их играть на 24/22,05/16 (или 12/11,025/8) кГц: если такой файл встретится, звук скорее будет, чем нет, а потерять нечего. Реальных потоков не нашлось ни одного, ffmpeg их тоже не декодирует — проверено только самосогласованностью; при появлении реального образца — сверить. |
| 2 | Enhanced coupling (ECPL) E-AC-3 не проверен | Реализовано по ETSI v1.4.1 (ATSC в этом месте отличается), но ни одного реального потока с ECPL нет, а ffmpeg его не кодирует. |
| 3 | Пониженные частоты E-AC-3 (24/22,05/16 кГц) | Проверены только эквивалентностью: реальные кадры, переписанные на пониженную частоту, дают тот же PCM. ffmpeg такие потоки не поддерживает, внешнего эталона нет. |
| 4 | Защита от «дребезга» формата | Если формат меняется каждые несколько пакетов (битый эфир), каждый раз создаётся новый аудиопоток. Нужен ли порог («менять раскладку только если новая держится N кадров»)? |
| 5 | Запоминать выбранную web-версию звука для видео | Сейчас выбор AAC/E-AC-3 в меню «♪» живёт до закрытия. Чтобы вспоминать его при следующем открытии, нужен повторный выбор компонента на старте — работа через несколько слоёв. |
| 6 | Версия звука, которая есть только при другом качестве видео | Если E-AC-3 доступен только вместе с другим разрешением, меню «♪» его не показывает (качество видео ради звука молча не меняем). Показывать с пометкой «сменит качество»? |
| 7 | Подпись Atmos / JOC | E-AC-3 с объектами (`CHANNELS="16/JOC"`) подписывается как обычный 5.1; для подписи «Atmos» нужно новое поле в описании версии. Сами объекты (JOC) не декодируются — играет базовый 5.1. |
| 8 | E-AC-3 7.1 в MP4 до первого кадра | До первого декодированного кадра число каналов берётся из контейнера; для 7.1 через dependent substream контейнер может сообщать 6. После первого кадра формат исправляется пересборкой выхода. |
| 9 | HLS с «упакованными» сегментами `.ac3/.ec3` (без TS) | Не проверялось и не подключено: HLS-реестр демуксеров знает только Symphonia и TS. |
| 10 | Smooth Streaming + Dolby | Отклонено владельцем (см. решение 7). |
| 11 | Старый баг, не связанный с AC-3 | Native HLS master, где все variant-ы только со звуком, падает в `NativeHlsSourceState::new` («component selection shape is not consistent with catalog layout»); воспроизводится и с AAC. |
| 12 | Dual mono (режим 1+1) | Два независимых моно-канала (например, два языка) сейчас играются как левый/правый, метаданные режима не передаются в плеер. Выбор «только первый / только второй / оба» — отдельная фича. |
| 13 | yt-dlp: сырые форматы `ac3`/`eac3` | Теперь планируются и играются как прогрессивный сырой AC-3 (раньше отвергались как неизвестные). Живьём на реальном сайте не проверялось. |
| 14 | M2TS (Blu-ray, 192-байтные пакеты) | Не поддерживается: MPEG-TS-демуксер понимает только 188-байтные пакеты. Сам декодер Blu-ray-звук (AC-3 ядро + E-AC-3 зависимый, 7.1) уже понимает. |
| 15 | Lsd/Rsd без свободной пары | Правило: Lsd/Rsd → боковые, если они заняты — задние; если заняты обе пары, раскладка неконвертируема и плеер сообщает об этом один раз и играет тишину. На реальных потоках такой раскладки не встречалось. |
| 16 | Лицензия реальных образцов | Реальные потоки Dolby с samples.ffmpeg.org использованы только локально для сверки и в репозиторий не добавлены: лицензия большинства образцов не указана. |
| 17 | Сообщить об ошибке 44,1 кГц в upstream стороннего декодера | Неактуально: сторонний декодер удалён (решение 1). |
| 18 | Склеенный MPEG-TS (находка живого прогона) | Сброс счётчика непрерывности на стыке файлов демуксер считает сменой дорожек: плеер пересобирает весь pipeline, теряет ~0,2–0,4 с звука, видео ждёт ключевой кадр. Так же сработает и потеря пакета в записи эфира. Общее поведение TS, не AC-3; нужен ли «мягкий» разрыв без пересборки? |
| 19 | Опустошение буфера на сыром E-AC-3 7.1 без видео (находка живого прогона) | В 2 из 3 прогонов по 50 с — одна пауза ~52 мс после того, как рабочий поток плеера проспал 250 мс (резервный интервал пробуждения). На FLAC с тем же звуком и на E-AC-3 5.1 не воспроизводится. Нужен разбор планировщика player-core. |
| 20 | HLS: строгое «выравнивание» версий звука (находка живого прогона) | Версии звука и видео обязаны иметь одинаковое число сегментов и точно одинаковую сумму `EXTINF`, иначе открытие падает целиком с неточной ошибкой «manifest metadata conflicts with probed media». Упаковщики часто пишут разные длительности для AAC и E-AC-3. Ослабить правило (допуск) и/или отбрасывать только несовместимую версию? |
| 21 | Переключение версии звука в последнем сегменте HLS (находка живого прогона) | За ~2 с до конца переоткрытие отказывает или ждёт кадр видео до конца ролика. Общее поведение переоткрытия у конца. |
| 22 | Метаданные соседних сырых `.ac3/.eac3` в плейлисте | Поиск метаданных соседей пробует только Symphonia: длительность не показывается, в логе `ERROR probe reached EOF`. |
