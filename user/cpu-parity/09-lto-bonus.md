# Сессия 09: LTO-бонус

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 09 плана `user/cpu-parity/`: добавь релизный профиль с thin LTO и `codegen-units = 1`, докажи выигрыш отдельным замером и зафиксируй цену по времени сборки. Требует сессий 06 и 08 (чтобы эффект не смешивался с архитектурными правками). Сначала прочитай `user/cpu-parity/README.md` и `results/06.md`, `results/08.md`.

## Решение владельца (19 октября 2026)

Паритет достигается архитектурой; LTO/`codegen-units = 1` — «приятный бонус», делается **после** архитектурных сессий, отдельным коммитом и с отдельным замером.

## Что делать

1. В корневом `Cargo.toml` (сейчас секции `[profile.release]` нет — cargo defaults: opt-level 3, без LTO, 16 codegen-units):
   ```toml
   [profile.release]
   lto = "thin"
   codegen-units = 1
   ```
   `panic` оставить `unwind` (политика `mem:panic-invariant-policy` и диагностика паник). `strip`/`debug` — не менять без решения владельца (символы нужны профилям).
2. Проверить по Context7 (Cargo reference) взаимодействие с `[profile.dev.package.*]` overrides, с `cargo-llvm-cov` и с MSRV-гейтом; CI (`scripts/ci-checks.sh`, GitHub Actions) должен собираться в разумное время — замерить время `cargo build --release -p app-egui --locked` до/после на чистом кэше и с инкрементальной правкой одного файла в `app-egui`.
3. Замер CPU/RSS до/после по сценам HW 1080p60, HW 4K30, SW 1080p60, SW AV1 4K60 (`run_pass.py`, 3 повтора каждая, одинаковая машина и условия). Размер бинарника до/после.
4. Если thin даёт < 3 % или время сборки растёт > 2× — обсудить с владельцем fat/откат; не решать самостоятельно.

## Критерий выхода

- Отчёт `results/09.md` с таблицей CPU/RSS/размер/время сборки до/после; обновить `mem:tech_stack` и `mem:suggested_commands` (время сборки, профиль).
