# Fastiplayer: свой рендер OpenGL ES 2.0 для старого железа (issue #6)

Подготовлено 23 октября 2026 в сессии планирования. Код плеера в этой сессии не менялся. Ниже задания для следующих сессий.

**Цель владельца:** дать новую жизнь старым компьютерам по принципу «софт должен уважать железо». Fastiplayer должен запускаться и играть видео плавно на машинах, где нет Vulkan (эталон — ThinkPad T410 без дискретной видеокарты). На таком железе он должен обходить лидеров рынка по производительности и крутить видео, на которых mpv и VLC уже теряют кадры.

Ссылки на строки кода — снимок на 23 октября 2026 (HEAD `cba51ace`). Перед правкой сверять с текущим кодом.

## Решения владельца (23 октября 2026, сессия планирования)

1. **Рендер полностью свой.** Рисование интерфейса egui, видео, шейдеры цвета, HDR→SDR, субтитры, скругление углов окна пишем сами. Готовый `egui_glow` не используем. Из чужого берём только два тонких «провода» к драйверу: `glow` (таблица функций OpenGL) и `khronos-egl` (контекст EGL на окне). Оба уже есть в `Cargo.lock` как зависимости `wgpu-hal` (`glow 0.17`, `khronos-egl 6.0`), то есть в проект не приходит новый непроверенный код.
2. **Переиспользуемость.** Рендер должен подключаться к любому egui-приложению (в первую очередь к редактору Fasticut) без хардкода под плеер. Переиспользуемые crate-ы живут в нашем workspace, а guardrail-скрипт запрещает им зависеть от любого crate-а плеера. Вынос в отдельный репозиторий или на crates.io — потом, когда API устоится.
3. **Шов «приложение ↔ рендер» — общий интерфейс (trait), а не переключатель на две ветки.** Требование владельца: дальше нас ждут Windows через wgpu (DX12/Vulkan) и свой рендер на DirectX 10, и рефакторинг шва повторять нельзя. Поэтому:
   - приложение знает только контракт `RenderShell` и не видит ни wgpu, ни GL;
   - **рендер сам владеет импортом кадров декодера** (DMA-BUF сегодня, DXGI shared handle завтра) и освобождением кадра после GPU. Приложение передаёт нейтральную аренду кадра и получает непрозрачный ключ;
   - выбор рендера делает **каталог рендеров платформы**: упорядоченный список кандидатов с проверкой «годен / не годен и почему». Чтобы добавить DX10, надо дописать строку каталога и crate, а не править приложение.
4. **Автовыбор (`Auto`).** wgpu, если есть аппаратный Vulkan с нужными нам расширениями. GLES2, если Vulkan нет, если есть только программный Vulkan (lavapipe/llvmpipe, `DeviceType::Cpu`) или если wgpu не смог стартовать. Если рендер упал на старте (метка «запуск рендера не завершён» осталась с прошлого раза), следующий запуск в `Auto` пропускает его и показывает уведомление.
5. **Ручной выбор** — в настройках. Смена рендера применяется после перезапуска приложения, живую смену семейства рендера не делаем. Пересоздание внутри одного семейства (режим показа и т.п.) работает как сейчас.
6. **Инварианты копий.** Аппаратный декод — строго zero-copy (VA-API → DMA-BUF → EGLImage). Программный декод — не больше одной копии (драйвер копирует кадр в текстуру). Архитектура источника плоскостей сразу допускает и 0 копий; попытка добиться 0 копий — отдельная сессия-эксперимент (`12`), решение по замеру.
7. **Строгий паритет с wgpu** по внешнему виду и по шейдерам цвета: цветокоррекция, HDR→SDR BT.2446-C, ориентация, letterbox, исключения под сайдбаром, оба слоя субтитров, скругление углов, прозрачность окна. Единственный допустимый компромисс — 10-бит **аппаратного** декода, если драйвер не даёт импортировать P010. Программный 10/12-бит обязан работать полностью. Заглушка конфига `render.opengles.simple_ui` противоречит паритету и удаляется.
8. **Критерий успеха на T410.** Соперники — mpv (в лучшем режиме, который работает на GL 2.1 / GLES 2.0: `gpu-next` там не стартует) и VLC 3 (в лучшем рабочем режиме). Критерий из трёх частей:
   - (1) на обычных видео (H.264 720p/1080p, аппаратно и программно, **обязательно включая 60 fps**) у нас 0 потерянных кадров и CPU не выше, чем у обоих соперников;
   - (2) «стресс-лесенка»: поднимаем разрешение, fps и кодек (программные HEVC/VP9/AV1, 10-бит), пока плеер не начнёт терять кадры. Наш потолок должен быть выше, чем у обоих;
   - (3) память не хуже.

   Сначала всё проверяем на основной машине (Radeon 780M, режим GLES2), потом на T410 по ssh.
9. **Аппаратный MPEG-2** (Ironlake его умеет, наш VA-API декодер — нет) — в бэклог, решаем по замеру программного MPEG-2 на T410 в сессии 11.
10. Работа в `main`, без веток и PR. Коммит — в конце сессии после зелёных проверок. Push — по отдельному поручению.
11. Запрет «альтернативного рендерера» из плана `user/cpu-parity/` (решение 5, issue #10) относился к поиску CPU-паритета внутри wgpu. Этот план — отдельное осознанное решение владельца по issue #6 и тот запрет не нарушает.

### Инварианты (нарушать нельзя)

- **HW-путь — zero-copy**: ни readback, ни CPU-конверсии, ни повторной загрузки аппаратного кадра. Если импорт DMA-BUF невозможен, GLES2 честно не объявляет контракт `HardwareZeroCopy` → `auto` уходит в программный декод, а не в тихую копию.
- **SW-путь — не больше 1 копии** (один `glTexSubImage2D` на плоскость кадра). Никакой промежуточной CPU-переупаковки. Без `GL_EXT_unpack_subimage` — загрузка «текстура шириной в stride + обрезка в шейдере», а не построчный repack.
- **Кадр декодера освобождается только после того, как GPU закончил его читать** (EGL fence), ровно один раз. Освобождение не зависит от того, нарисует ли UI следующий кадр (рендер по изменению из cpu-parity 04 может спать).
- **`RenderCapabilities` GLES2 выводятся из реально найденных возможностей драйвера.** Нет highp — нет 10-бит/HDR-контрактов. Нет импорта DMA-BUF — нет zero-copy. Честное «не поддерживается», а не чёрный экран.
- **Ограниченные пулы**: кольцо загрузки и кэш EGLImage ограничены и согласованы с пулом поверхностей декодера (как `DmaBufImportCacheCapacity::matching_surface_pool`). Без небоундед-роста.
- **Поведение wgpu-пути не меняется**. Сессии 01–02 — чистый рефакторинг шва с замером «до/после» и quality-gate.
- Переиспользуемые crate-ы (`gles2-egui`, `gles2-video`) не зависят ни от одного crate-а плеера. Это проверяет `scripts/check-refactor-guardrails.py`.
- egui-контракт: premultiplied alpha, смешивание в гамма-пространстве, текстуры не sRGB, `ONE, ONE_MINUS_SRC_ALPHA`, `CLAMP_TO_EDGE` (так делает egui-wgpu и так требует egui).

### Уровни возможностей GLES2 (определяются на старте, а не по имени GPU)

| Уровень | Требует | Даёт |
|---|---|---|
| Базовый (обязательный) | GLES 2.0, EGL 1.4, NPOT-текстуры с clamp без mip (ядро GLES2), `GL_LUMINANCE` | интерфейс, SW 8-бит 4:2:0/4:2:2/4:4:4, субтитры, углы |
| Точность | `GL_FRAGMENT_PRECISION_HIGH` | SW 10/12-бит, HDR→SDR BT.2446-C |
| Zero-copy | `EGL_EXT_image_dma_buf_import` + `GL_OES_EGL_image` + импорт `DRM_FORMAT_R8`/`GR88` | VA-API NV12 без копий |
| Zero-copy 10-бит | то же + импорт плоскостей P010 как `GR88`/`ABGR8888` (сборка 16 бит в шейдере) | VA-API P010 (на Ironlake не нужен: нет 10-бит декода) |
| Удобства | `GL_EXT_unpack_subimage`, `GL_OES_element_index_uint`, `GL_OES_vertex_array_object`, `EGL_KHR_fence_sync`, `EGL_EXT_buffer_age` | меньше вызовов; без них — описанные фолбэки (u16-батчи egui, `glFinish` перед освобождением с явным счётчиком) |

### Как не повторять рефакторинг под Windows/DX10

- Контракт `render-shell-api` не содержит ни одного типа wgpu/GL/Linux. Импорт кадров идёт через `video-present-core::VideoFrameLease` и нейтральные `video-core`-дескрипторы. Новые виды аппаратных кадров (DXGI) добавляются как новые варианты нейтрального словаря `video-frame-contract`, а рендер объявляет их в `RenderCapabilities`.
- Окно передаётся через `raw-window-handle` (работает и для HWND).
- Каталог рендеров — данные платформы (`#[cfg(target_os)]`-список кандидатов), а не `if` в приложении.
- Тесты контракта (`render-shell-api` conformance-набор с fake-рендером + одинаковые пиксельные тесты для каждого реального рендера) пишутся один раз и прогоняются для каждого семейства.

Тесты (тест проверяет результат, а не вызов):
- каждый путь рендера — пиксельный тест с readback из offscreen-цели (EGL surfaceless/pbuffer на Mesa: на машине разработчика и в CI через llvmpipe). Проверяются известные цвета, позиции, смешивание. Пропуск теста без EGL — с явной причиной в выводе, не молча;
- **кросс-рендерный паритет**: один и тот же вход (egui-кадр, YUV-кадр, оверлей субтитров) рисуется wgpu и GLES2, пиксели сравниваются с допуском и с объяснением любого расхождения;
- для каждого нового boundary/API — focused-тесты: отсутствующий ресурс, активный fake, ошибка, edge-accounting, «метод не трогает чужое состояние»;
- функциональные тесты: видео из фикстуры доходит до стадии показа через GLES2 (а не «декодер открылся»);
- оптимизации — тестом, который падает без фикса (счётчик загрузок/импортов/draw-call-ов, а не «функция вызвалась»).

Замер — обязательная часть каждой сессии с кодом рендера (с 04 и дальше):
- на основной машине в режиме GLES2: `docs/benchmarks/tools/dev/run_pass.py` до и после, `agg_timing.py` по стадиям кадра; сравнивать только в один день с чередованием;
- с сессии 11 — те же сцены на T410;
- запрещено сравнивать разные сцены, окна разной длины, debug с release.

Quality-gate (ничего не сломать):
- wgpu-путь: уникальные кадры, `drops_*`, RSS/PSS, CPU — без изменений относительно базы дня (сессии 01, 02, 09 проверяют это явно);
- GLES2-путь: ≥ 99 % уникальных кадров от «fps × окно» (как протокол v2), A/V-синхрон, seek/scrub/pause/resume/смена файла/resize/фуллскрин вручную на двух файлах (HW и SW);
- `scripts/ci-checks.sh all` зелёный, существующие тесты не ослабляются, Vulkan validation layer и `KHR_debug` (где есть) без новых сообщений.

Код:
- новая логика — у владельца состояния. Файлы ≥ 700 строк не раздувать (hard limit 800, ratchet `scripts/module-size-baseline.json`). Особенно не расти `app-egui/src/frame_prepare.rs` (1467, legacy) и `app_shell/mod.rs` (798);
- boundary API самодокументирующиеся (enum/newtype/intent-method), absent / busy / fatal / no-op / unsupported не сливаются в `bool`;
- `unsafe` (EGL/GL FFI, fd) — в отдельных модулях безопасности с `// SAFETY:` и hermetic-тестами владения fd, по образцу `render-wgpu-video/src/dma_buf_import/safety.rs`;
- без `unwrap/expect/panic` в production (`mem:panic-invariant-policy`). Ошибка компиляции шейдера, отказ драйвера, потеря контекста — типизированные ошибки;
- русская документация ключевой логики и инвариантов;
- в `user/` только Markdown, без личных путей, имён хостов и логов. Сырые логи, профили, дампы `eglinfo` — в scratchpad (в отчёт — выжимка).

## Удалённая работа с T410

- Доступ: ssh-алиас `t410` в `~/.ssh/config` владельца (имя хоста и пользователь в план не пишутся). Сессия 00 проверяет `ssh t410 true`, Mesa, ядро, композитор и права на `/dev/dri/renderD128`, `/dev/udmabuf`.
- Система T410 (со слов владельца, 23.10.2026): свежая установка, графическая сессия **Wayland**.
- **Решение владельца (23.10.2026): тестируем в обоих режимах — нативный Wayland (EGL `wl_egl_window`) и XWayland (EGL X11).** Это касается ручной приёмки, пиксельных/функциональных тестов окна и квалификации против mpv/VLC на обеих машинах. Под XWayland протокол v3 уже запускает плееры. Соперники в каждом режиме тоже идут в одном и том же режиме, режимы не смешиваются.
- Сборка: на основной машине (`x86_64`, тот же дистрибутив — бинарник совместим; иначе собирать на T410), доставка `rsync` бинарника + `target/release/lib/` (свой FFmpeg, RUNPATH `$ORIGIN/lib`).
- Запуск GUI по ssh — в живой графической сессии T410 (`DISPLAY`/`WAYLAND_DISPLAY`/`XDG_RUNTIME_DIR` пользователя), замеряющие скрипты работают **на самом T410**, артефакты забираются обратно. Удалённой оркестрации в `docs/benchmarks/tools` сейчас нет — её добавляет сессия 11 (тонкая обёртка, не переписывание протокола).

## Инструменты диагностики

- `docs/benchmarks/tools/dev/{thread_cpu.py,run_pass.py,agg_timing.py}` — быстрые срезы (CPU по потокам, GPU по fdinfo, стадии кадра).
- `docs/benchmarks/tools/local/` — строгий протокол v3 (cgroup, чередование, quiet/diagnostic, quality-gate). Привязан к KWin/XWayland/amdgpu: имена движков `gfx`, память `drm-memory-gtt/vram`. Для i915 нужны `render`/`video`/`copy` и `drm-total-system` — адаптирует сессия 11.
- Профилировщик `samply` (`perf_event_paranoid ≤ 1`). Для GL: `MESA_DEBUG`, `KHR_debug`-лог (где есть), `INTEL_DEBUG=perf` на crocus, `apitrace` для разбора кадра.

## Бэклог (не в этом плане)

- **Аппаратный MPEG-2 через VA-API** (решение владельца: по замеру программного MPEG-2 на T410 в сессии 11). Это работа декодера (`video-vaapi`, в cros-codecs MPEG-2 нет), а не рендера.
- **Windows: wgpu (DX12/Vulkan) и свой рендер DirectX 10.** Шов из сессий 01–02 спроектирован под них; сами рендеры — отдельные планы.
- **Частичный показ** (`EGL_KHR_swap_buffers_with_damage`/`EGL_KHR_partial_update`) для кадров, где меняется только интерфейс. Решать по замеру сессии 11.
- **Меньшие пулы по умолчанию для слабого железа** (`video.zero_copy_surface_pool_slots = 24` ≈ 75 МБ NV12 1080p в общей памяти). Решать по замеру памяти сессии 11, решение владельца.
- **Linux-путь `TILING_LINEAR` в wgpu-импорте DMA-BUF** (`mem:render-video/core`, известный дефект) — не трогаем в этом плане.
