> Выполни сессию 04 плана `user/gles2-renderer/`: напиши в `gles2-egui` свой художник egui на GLES 2.0 (текстуры, меши, отсечение, удержание UI-кадра для повтора без egui-прохода) и маску скруглённых углов. Докажи пиксельный паритет с wgpu на одних и тех же egui-кадрах. Сначала прочитай `user/gles2-renderer/README.md` и `results/03.md`.

## Зачем

Интерфейс — то, что пользователь видит всегда. Паритет «внешки» (решение владельца 7) начинается здесь. На старом GPU egui-проход тоже стоит денег, поэтому повтор UI без нового прохода (cpu-parity 04) обязателен и здесь.

## Контракт egui (источник — документация egui и поведение egui-wgpu 0.36)

- `TexturesDelta`: `set` (полная или частичная загрузка, по порядку для одного id), `free` — только после показа кадра. Так делает `EguiCompositor::free_retired_textures` (`render-wgpu-shell/src/egui_compositor.rs`).
- Смешивание `ONE, ONE_MINUS_SRC_ALPHA` (premultiplied), в гамма-пространстве. Текстуры `RGBA8`, не sRGB, `CLAMP_TO_EDGE`, фильтры из `TextureOptions`. Цвет вершины = 4 байта, шейдер делит на 255.
- Позиции в точках × `pixels_per_point` → NDC в вершинном шейдере (`u_screen_size`).
- `ClippedPrimitive` → scissor (ось Y в GL снизу, перевод и обрезка по экрану).
- Индексы `u32`: при `GL_OES_element_index_uint` — как есть; без него — разбиение меша на батчи с `u16` (тест на меш > 65535 вершин).
- `Primitive::Callback` — в проекте не используется (разведка: ни одного `PaintCallback`). Поддержку не делать, на входе — типизированный отказ с логом.

## Что сделать

1. **`gles2-egui::painter`**:
   - программа GLSL ES 1.00 (`#version 100`, `precision highp` при наличии, иначе `mediump`);
   - VBO/IBO стриминг с orphaning (`glBufferData(NULL)` перед записью), без аллокаций на кадр в установившемся режиме;
   - VAO через `OES_vertex_array_object`, если есть, иначе явная настройка атрибутов (без эмуляции на каждый draw);
   - кэш текстур egui по `TextureId`.
2. **Удержание UI-кадра.** Аналог `EguiFrameContent::ReusePrevious`: последний набор примитивов и `ScreenDescriptor` хранятся в буферах GPU. Повтор допустим только при том же размере/scale, иначе `RetainedUiUnavailable` (семантика из cpu-parity 04 / контракта 01).
3. **Маска скруглённых углов** (паритет `window_corner_mask.wgsl`): аналитический SDF скруглённого прямоугольника, AA 1 px, радиус = точки × `pixels_per_point`, не больше половины меньшей стороны.
   - Смешивание для premultiplied и postmultiplied surface — как в wgpu.
   - Оптимизация для старого GPU: рисовать **только 4 угловых квадрата** размером радиус+AA, а не полноэкранный проход. Пиксельно результат тот же (тест).
   - `gl_FragCoord` — ось Y снизу (переворот, тест).
4. **Сборка кадра в `gles2-egui`**: видео-слой (заглушка цвета до 05) → место под оверлеи → egui → маска углов → swap. Порядок как у wgpu (`shell.rs:472-650`).

## Пиксельный паритет с wgpu (главный тест сессии)

- Набор эталонных egui-кадров: текст разных размеров, полупрозрачные панели поверх цветного фона, скругления, иконки `ui-artwork-egui`, отсечённые области, частичное обновление текстуры, кадр после `free`.
- Каждый кадр рисуется offscreen wgpu-шеллом (существующий тестовый путь `egui_compositor/tests.rs`) и GLES2-художником. Сравнение попиксельно с допуском (±1–2 на канал из-за растеризации/дизеринга). Любое расхождение больше допуска — объяснить или исправить.
- Тест на `ReusePrevious`: новый видео-фон + повтор UI → UI-пиксели идентичны полному проходу (как `reused_frame_draws_identical_ui_pixels_over_new_video`).
- Маска углов: прозрачные углы, неизменный центр, промежуточная альфа AA для обеих кодировок, квадрат при радиусе 0 / NaN.

## Замер

- Основная машина, режим GLES2-примера с реальным UI плеера (через тестовый стенд или пример, который рисует `app-egui`-подобный кадр), `perf`/`samply`: стоимость полного egui-прохода и повтора. Цель — повтор UI ≈ стоимость одного draw-call-а на кадр.
- T410: тот же пример по ssh, кадр с открытой панелью. Сколько стоит полный проход и сколько повтор.

## Критерий выхода

- Паритетный набор зелёный, расхождения задокументированы.
- Повтор UI и маска углов работают, счётчики draw-call-ов/загрузок показывают отсутствие работы при повторе.
- Пример на T410 рисует egui плавно (в отчёте — время кадра).
