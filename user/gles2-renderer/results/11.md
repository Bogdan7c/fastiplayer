## Решения владельца (26.10.2026, в README — 51–53)

51. **Полная серия, 5–7 ч.** Фактически цепочка шла 22:50–03:13, плюс перезапуск лесенки — 4,4 ч.
52. **Соперник без режима без потерь** сравнивается в режиме с наименьшими потерями, с пометкой. Применять не понадобилось: на обычных сценах в этой серии ни mpv, ни VLC не теряли кадры.
53. **11a — точечно для слабых машин** (≤ 4 логических CPU): AV1 до 1080p — 2 кадра в работе, HEVC — все логические CPU (`results/11a.md`).

## Найдено

1. **Потери 15 % на SW 60 fps (наследство 09b) — уже вылечены сессией 10.**
   - Бинарь 09b в тех же условиях: 53,5 кадра/с, Render/3D 99,9 %. Текущий: 60,0, Render/3D 90,5 %.
   - Окно decode-ahead ни при чём: старый бинарь и с окном 2000 мс давал 53,5.
   - Причина — непрозрачность окна из сессии 10 (`e5f0467a`): KWin перестал перерисовывать всё под окном.
2. **AV1 и HEVC на слабом CPU** — подсессия 11a, исправлено (`4696070d`). AV1 1080p60: 16 → 60 кадров/с, HEVC 1080p60: 56 → 60.
3. **Лог не показывал путь файла.**
   - HEVC/VP9/AV1 стартуют через VA-API, а кандидат файла молча ставит программный план. Строку «Selected video pipeline» писал только старт.
   - Две первые лесенки поэтому были невалидны.
   - Исправлено в плеере (`7dce9848`) и в протоколе (`46a1e7d4`).
4. **Главная находка — ARGB-поверхность окна на Ironlake.**
   - Окно создаётся с альфой ради скруглённых углов. У основной плоскости дисплея Ironlake нет ARGB (разведка 00), поэтому KWin копирует наш кадр каждый кадр, хотя в фуллскрине окно объявлено непрозрачным.
   - На 780M плоскость ARGB умеет, поэтому сессия 10 этого не увидела.
   - Доказательство — A/B на временной сборке с непрозрачным EGL-конфигом, по одному прогону:

     | | Render/3D | CPU KWin | кадров/с |
     |---|---|---|---|
     | SW 1080p60, сейчас | 90,5 % | 9,2 % | 60 |
     | SW 1080p60, непрозрачная поверхность | **60,6 %** | **6,0 %** | 60 |
     | SW 1080p60, mpv | 30,2 % | 6,3 % | — |
     | HW 720p60, сейчас | 99,9 % | 4,8 % | **40,1** |
     | HW 720p60, непрозрачная поверхность | 95,5 % | 3,9 % | **53,7** |

   - Второй A/B (27.10, ~04:00): та же ARGB-конфигурация, но поверхность создана с `EGL_PRESENT_OPAQUE_EXT` (Khronos `EGL_EXT_present_opaque`). Контекст и конфиг прежние, пересоздаётся только поверхность.
     - **Wayland** — тот же эффект: SW 1080p60 Render/3D 90,3 → 61,7 %, KWin 8,9 → 5,8 %; HW 720p60 40,1 → 54,2 кадра/с.
     - **XWayland** — Mesa отвергает атрибут (`CreateWindowSurface failed: BadAttribute`), плеер не стартует. Под X11 непрозрачность решает только visual окна (24 бита без альфы).
   - Это объясняет лишний CPU KWin (+2,5–3 п.п. на 60 fps в обоих режимах) и большую часть провала HW.
   - Остаток: наш проход показа примерно вдвое дороже mpv `profile=fast` (60 % против 30 % GPU) — тема 12a.
5. **MPEG-2 у Fastiplayer нет вообще.**
   - В `codec-core::VideoCodec` нет MPEG-2 видео, файл играет только звук.
   - Замер «программный MPEG-2 против соперников» (решение 9) невозможен. Данные соперников — в 00.
6. **Соперники на T410 больше не теряют кадры** на обычных сценах (в 00 теряли 16–405).
   - Вероятная причина — закрытый перед серией «Системный монитор»: его графики занимали тот же GPU.
   - Отдельно не проверялось.
   - Следствие: на обычных сценах выигрыш «по плавности» исчез, всё решает CPU.

## Что не выполнено и почему

- **HW-критерий и XWayland 720p60** упираются в находку 4. Фикс меняет поведение окна → решение владельца (подсессия 11b, вопрос ниже).
- **Против Xv по CPU процесса** мы проиграем при любом рендере, пока сами копируем кадр. Xv переносит перевод цвета в сервер Xwayland. Убрать копию — сессия 12 («0 копий»). Сумма с композитором у нас уже лучше на 13 п.п.
- **Память против mpv**: пул VA-поверхностей 24 на слабом железе — давний пункт бэклога, решение владельца.
- **Потолок против VLC — ничья.** Наши 1080p60-ступеньки чистые, у VLC тоже. Доказать «выше» можно только ступенькой тяжелее, например HEVC/AV1 выше 1080p60 — решение владельца.

## Известные ограничения метода

- t = 10 делает интервалы широкими: мы ниже соперника в каждом повторе 1080p60, но вердикт INC.
- CPU лесенки — по диагностическим попыткам (трасса включена), без пар.
- A/B непрозрачной поверхности — по одному прогону на временной сборке, не серия протокола.
- GPU-память на HW-пути считается дважды (VA-API и EGL клиенты) у всех плееров.
- A/V-синхрон Fastiplayer не измеряется (нет метрики).
