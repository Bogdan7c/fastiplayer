## Находка: нативный Wayland, HW 30 fps (открыта, бэклог п. 23)

Под нативным Wayland HW 720p30 стоит 16,2 % против 11–12 % у соперников, принудительный HW 1080p30 — 16,6 % и 110 из 600 кадров на развёртку позже (не потеряны), GPU 98 %. Под XWayland та же сборка на уровне соперников и без опозданий. `dynamic` уводит 1080p30 на SW через 6,6 с.

Два A/B после серии (тот же протокол, три сборки плеера, нативный Wayland):

| Сборка | 720p30 HW | 1080p30 HW | опоздания 1080p30 HW |
|---|---|---|---|
| контроль 12a (`08b331f5`) | 15,1 % | 14,7 % | 133 и 29 потерь |
| финал 12a.1 | 16,2 % | 16,1 % | 106 |
| опубликованная | 16,4 % | 16,6 % | 83 |
| финал 12a.2 / финал 13b (`dynamic`) | 16,2 / 16,3 % | — | — |

Вывод: регрессии опубликованного кода нет (она лучшая по каденсу). Но та же сборка контроля 12a 27.10 мерила 11,5 % на 720p30, а 12a.2 28.10 — HW 1080p30 без опозданий. Пакеты T410 между днями не менялись, соперники мерили как раньше. Причина «по дням» не найдена; кандидаты и план разведки — в п. 23 бэклога. В README и отчёте это сказано прямо.
