# Сессия 12: эксперимент «0 копий» для программного декода

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 12 плана `user/gles2-renderer/`: проверь, можно ли на GLES2 показывать программно декодированный кадр без единой копии — блоки памяти декодера (cpu-parity 08b) превращаются в DMA-BUF через `/dev/udmabuf` и импортируются в EGLImage. Принимается только по замеру на T410. Сначала прочитай `user/gles2-renderer/README.md`, `results/11.md` и `user/cpu-parity/results/08b.md`.

## Зачем

Решение владельца 6: сначала надёжная 1 копия, потом отдельная попытка 0 копий. Это аналог 08b из cpu-parity: там Vulkan импортировал наши блоки через `VK_EXT_external_memory_host` и убрал CPU-memcpy, а он стоил 43–59 % главного потока.

## Идея

- FFmpeg уже декодирует в наши блоки (`video-ffmpeg/src/ffi/direct_frame_buffers.rs`, `host_frame_memory.rs`): начало на 2 МиБ, stride — нечётное кратное 256.
- Блоки выделяются из `memfd` (sealed `F_SEAL_SHRINK`), а не из анонимной памяти. Через `UDMABUF_CREATE` блок становится dma-buf. Плоскости импортируются в EGL как `DRM_FORMAT_R8` (8-бит) / `GR88` (16-бит, сборка из 06) с `DRM_FORMAT_MOD_LINEAR`.
- Нужен `PlaneSource::DmaBuf` из 05 — тип заложен с самого начала.

## Вопросы, на которые отвечает эксперимент

1. Пускает ли система: права на `/dev/udmabuf` (часто root/kvm), модуль ядра загружен. Факт 00: на T410 (CachyOS) `/dev/udmabuf` есть, у пользователя ACL rw; импорт R8/GR88 с `LINEAR` crocus принимает (стенд VA-поверхностей). Без прав — путь честно недоступен, работает 1 копия. Никаких `sudo`/udev-правил от плеера без решения владельца.
2. Принимает ли crocus/radeonsi такой импорт (линейный, системная память, кратность pitch), и не делает ли драйвер скрытую копию сам (профиль).
3. Цена: время импорта (`UDMABUF_CREATE` + `eglCreateImage`) на кадр против копии. Урок 08b: импорт amdgpu userptr проверялся ядром на каждом submit для каждого живого импорта, поэтому кэш импорта там был вреден. Здесь — замерить: кэш по блоку пула (блоков немного, их переиспользует пул) против импорта на кадр.
4. Синхронизация: декодер не пишет в блок, пока GPU читает (возврат блока в пул только после fence — то же правило, что для 1 копии).
5. dav1d (AV1) не поддерживает DR1 → для AV1 остаётся 1 копия. Записать.

## Наследство сессии 05 (`results/05.md`)

- Цена копии, которую эксперимент убирает: на T410 загрузка 1080p 4:2:0 — 2,4 мс CPU главного потока на кадр (~14 % ядра при 60 к/с), 4K — 13,6 мс. На 780M — 0,07 мс CPU потока: radeonsi копирует в своём потоке.
- `PlaneSource::DmaBuf` уже в словаре; кадр держится до fence (решение 30), поэтому импорт не меняет правило освобождения.


## Наследство сессии 07 (`results/07.md`)

- **У Ironlake нет LLC.** GPU читает чужой dma-buf мимо кэша процессора. Запись CPU в память udmabuf после импорта GPU не видит, пока производитель не сделает `clflush` по записанному диапазону.
  - Первый кадр верен: i915 сбрасывает кэш при первой привязке страниц. Значит, дефект прячется.
  - `DMA_BUF_IOCTL_SYNC` у `udmabuf` на x86 кэш не сбрасывает (доказано экспериментом на T410).
  - Цена `clflush` по кадру входит в замер «0 копий против 1 копии».
  - Тест обязан перезаписывать буфер между кадрами на T410. Образец протокола — `overwrite_contents_as_cpu_producer` в тестах `gles2-video`.
- Импорт плоскостей готов: `Gles2Context::attach_dma_buf_plane_to_texture` (одна плоскость = один `EGLImage`, модификатор, fd не забирается). Кэш по паспорту — `gles2-video::dma_buf_cache`. Освобождение по fence — `render-gles2-shell::frame_release`.

## Порядок

1. Стенд в scratchpad на T410 и 780M: memfd → udmabuf → EGLImage → readback.
2. Если стенд жив — реализация за флагом возможностей (fail-closed на 1 копию), счётчики `frames_without_cpu_copy` / `frames_through_upload`.
3. Замер «до/после» на T410: SW H.264 1080p60, SW HEVC 1080p30, ступенька лесенки, где потолок упирался в главный поток.

## Критерий выхода (решение — владельцу по замеру)

- Либо путь включён: выигрыш по CPU/потолку лесенки на T410 больше шума, стабильность и память не хуже, есть фолбэк.
- Либо закрыт откатом с объяснением (как LTO в cpu-parity 09). Отчёт и memory `...-REJECTED`, чтобы не повторять.
