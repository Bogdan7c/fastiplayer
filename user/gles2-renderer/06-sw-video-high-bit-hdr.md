# Сессия 06: программные 10/12 бит и HDR→SDR

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 06 плана `user/gles2-renderer/`: добавь в `gles2-video` программный путь YUV 10/12 бит (420/422 10/12, 444 10 — матрица v1 wgpu) без целочисленных текстур GLES3, через пары байтов и сборку значения в шейдере, плюс HDR→SDR BT.2446-C с полным паритетом. Сверка — CPU-эталон `bt2446c_reference` и readback wgpu. Сначала прочитай `user/gles2-renderer/README.md` и `results/05.md`.

## Зачем

Решение владельца 7: компромисс допустим только для **аппаратного** 10-бит. Программные HEVC Main10, VP9 Profile 2, AV1 10-бит и HDR-контент должны показываться так же, как в wgpu. На T410 это ступенька стресс-лесенки (HEVC Main10 1080p30).

## Проблема

wgpu-шейдер `host_yuv420_16bit_to_sdr.wgsl` читает `R16Uint` через `textureLoad`, а размеры — через `textureDimensions`. В GLES 2.0 нет ни целочисленных текстур, ни `texelFetch`, ни 16-битных нормализованных форматов (`EXT_texture_norm16` на старом железе нет).

## Решение (без лишней копии)

- 16-битный отсчёт LE загружается **как есть** в `GL_LUMINANCE_ALPHA` (2 байта на тексель: L = младший, A = старший байт). Это та же одна копия, без переупаковки на CPU.
- Шейдер собирает код: `code = floor(L*255 + 0.5) + 256 * floor(A*255 + 0.5)`. Нужен `highp` (README, уровень «Точность»). Без highp контракты высокой битности не объявляются.
- Фильтрация: билинейная фильтрация по байтам ломает значение, поэтому `GL_NEAREST` и выборка по центру текселя. Это паритет: wgpu 16-бит путь тоже nearest (`textureLoad`).
- Цветность — как в wgpu (`floor(luma_texel / subsampling)`). Размеры плоскостей — uniform.
- Нормализация по битности (`bitdepth` → max code), limited/full в кодах: luma `16<<s..235<<s`, chroma центр `128<<s`, диапазон `16..240` (`host_yuv420_renderer.rs:831-870`).
- SDR: только BT.709 с явным диапазоном, остальное — та же ошибка, что у wgpu (`host_yuv420_renderer.rs:740`).
- HDR→SDR BT.2446-C — порт констант и шагов 1–8 из `p010_bt2446c_to_sdr.wgsl` / `host_yuv420_16bit_to_sdr.wgsl`: BT.2020 → PQ EOTF / HLG inverse OETF с system gamma 1.2 → crosstalk 0.04 → XYZ → тон-маппинг k1..k4 с перегибом 58.5 нит → BT.709 → обратный crosstalk → BT.1886 γ 2.4.
- Проверить precision `pow/exp/log` на highp GLES2 (PQ-экспоненты 1/78.84) на обеих машинах.
- Настройки `HdrToSdrSettings` и отказ «HDR при выключенном HDR→SDR» — как у wgpu.

## Тесты

- Константы шейдера = константы `render-wgpu-video/src/bt2446c_reference.rs`: тест разбирает текст GLSL, как уже сделано для WGSL (`shader_bt2446c_constants_match_cpu_reference_constants`).
- Readback векторов CPU-эталона: нейтральные и цветные PQ/HLG-векторы, SDR 10/12-бит limited/full; допуск задокументировать и объяснить (точность highp против f64 эталона).
- Сборка кода из байтов: значения 0, 1, 255, 256, 1023, 4095 доходят до шейдера точно (readback на специальном кадре).
- Кросс-рендерный паритет с wgpu на одних и тех же кадрах 10/12-бит SDR и HDR. Закрывает и найденный разведкой пробел: у wgpu нет GPU-readback теста 16-битного пути, добавить его тоже (отдельный маленький коммит).
- Без highp: контракты высокой битности не объявлены, `auto` честно не предлагает этот путь.

## Замер

SW HEVC Main10 1080p30 и 4K30 на основной машине: стоимость кадра GLES2 против wgpu (`agg_timing.py`). На T410 — в сессии 11, ступенька лесенки.

## Критерий выхода

- Все контракты v1 матрицы wgpu для программного пути объявлены GLES2 при highp и проходят паритет.
- Ограничения точности задокументированы числами.
