# Сессия 13a: все программные кодеки без копии на wgpu — матрица, тесты, сравнения

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 13a плана `user/gles2-renderer/`: проверь и доведи до конца путь программного декода без CPU-копии на wgpu для всех программных кодеков и раскладок, которые играет Fastiplayer, на основной машине (780M). Составь матрицу «кодек × битность × subsampling → путь (без копии / копия и почему)», закрой дыры тестами, сравни с копией и с mpv. Сначала прочитай `user/gles2-renderer/README.md` (решения 82–86), `results/13.md`, `user/cpu-parity/results/08b.md`.

## Зачем (решение владельца 85)

- Цель владельца: на Linux все программные пути без копии.
- На wgpu без CPU-копии работает cpu-parity 08b (импорт блоков декодера через `VK_EXT_external_memory_host`). Принимался он на 4 сценах из 5. Полной картины «какой кодек и какая раскладка реально идут без копии» нет.
- После сессии 13 к ним добавился AV1.

## Что известно

- `get_buffer2` с нашими блоками ставится декодерам с `AV_CODEC_CAP_DR1`: H.264, HEVC, VP9, VP8, а после 13 и AV1 (`mem:video-ffmpeg/software-design`).
- wgpu: `render-wgpu-video::host_planar_upload::direct_upload` — нейтральный план (плоскость = слот, stride % 256, offset % sample) и `host_memory_import` (`HostMemoryImporter`).
  - Fail-closed на staging-копию: нет расширения, выравнивание > 4 КиБ, нет coherent-типа.
  - Импорт на каждую копию без кэша, кэш вреден (`mem:render-video/host-planar-staging-belt-upload`).
- Блоки для wgpu — только анонимная память (amdgpu `userptr`), не memfd (`host_frame_memory_for`).
- Остаётся одна GPU-копия «буфер → текстура». Настоящий ноль на wgpu (udmabuf → DMA-BUF → линейная картинка Vulkan) — не в этой сессии. Это кандидат в бэклог, если матрица покажет, что GPU-копия где-то мешает. Сначала нужен известный дефект `TILING_LINEAR` wgpu-импорта (`mem:render-video/core`).

## Что сделать

1. **Матрица на 780M.** Для каждого программного кодека и раскладки, которые играет плеер, — какой путь реально выбран и почему.
   - Кодеки: H.264, HEVC, VP9, VP8, AV1.
   - Раскладки: 8/10/12 бит; 4:2:0 / 4:2:2 / 4:4:4, где кодек их даёт.
   - Источник правды — счётчики рендера и лог причины, а не предположение. Фикстуры — `test-assets/`, `benchmark-fixtures/` (`mem:local-test-media-inventory`); недостающие делаются `make_fixtures.py` / ffmpeg в scratchpad, в git не идут.
2. **Дыры:** каждая клетка «копия» получает причину.
   - Если причина наша (план прямой загрузки не знает раскладку, выравнивание блока, формат текстуры) — чиним в сессии, если правка локальная.
   - Если это архитектурная граница или большая работа — стоп, вопрос владельцу.
3. **Тесты:** на каждый кодек — функциональный тест «кадр из фикстуры доходит до показа wgpu без CPU-копии» (счётчики импорта и прямой загрузки + пиксельный readback против пути копии). Мутация «импорт выключен» должна ронять тест.
4. **Сравнения на 780M, ABBA:**
   - без копии против принудительной копии (staging) — CPU главного потока и процесса, GPU, память;
   - против mpv в лучшем режиме (`--vo=gpu-next` / `gpu`, DR) на тех же файлах.
   - Сцены: H.264 1080p60, HEVC 1080p60 и 4K60 (8 и 10 бит), VP9 4K60, AV1 4K60. Длительность называется заранее.

## Критерий выхода

- Матрица опубликована в отчёте `results/13a.md`: все клетки, которые играет плеер, либо без копии, либо с честной причиной копии.
- На всех сценах сравнения CPU не хуже копии; где без копии — заметно ниже.
- Тесты на каждый кодек есть, `scripts/ci-checks.sh all` зелёный.
