# Сессия 05: SW-видео 8 бит, одна копия

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 05 плана `user/gles2-renderer/`: создай переиспользуемый crate `gles2-video` (без зависимостей от crate-ов плеера) и программный путь 8-бит YUV 4:2:0/4:2:2/4:4:4 с ровно одной копией, полным паритетом цвета с wgpu (матрицы, диапазон, цветокоррекция, ориентация, letterbox, исключения) и источником плоскостей, готовым к «0 копий». Сначала прочитай `user/gles2-renderer/README.md` и `results/04.md`.

## Зачем

Программный декод — единственный путь для всего, кроме H.264/MPEG-2 на T410: HEVC, VP9, AV1. Это и есть «стресс-лесенка» критерия успеха. Каждая лишняя копия кадра на двухъядерном Westmere — минус ступенька.

## Архитектура `gles2-video`

- **Свой словарь**, не `video-core`. Плоскость = роль (Y/U/V/UV), размер в отсчётах, байт на отсчёт, источник:
  - `PlaneSource::HostRows { bytes, stride, visible_row_bytes, rows }` — одна копия драйвером;
  - `PlaneSource::DmaBuf { fd, offset, pitch, modifier, drm_format }` — импорт (сессии 07 и 12).

  Решение владельца 6: источник с самого начала допускает 0 копий, поэтому DMA-BUF-вариант заложен в тип сразу, хотя реализуется позже.
- **Кольцо загрузки**: ограниченный набор наборов текстур (по умолчанию 3, параметр вызывающего, не хардкод). Мы не пишем в текстуру, которую GPU ещё читает (неявная синхронизация драйвера = стоп конвейера). Слот свободен после fence кадра, который его рисовал (`GpuFence` из 03). Если все слоты заняты — `Busy` (как wgpu-пул: не растём, не освобождаем кадр декодера).
- **Шейдер YUV** (`#version 100`):
  - плоскости `GL_LUMINANCE` (ядро) или `GL_RED_EXT` (`EXT_texture_rg`);
  - матрица BT.601/BT.709 (BT.2020/unknown → BT.709, как wgpu), limited/full;
  - `apply_sdr_adjustments` в том же порядке операций: насыщенность → контраст вокруг 0.5 → `exp2(exposure)` → яркость → gain/offset → clamp;
  - ориентация (affine-матрица `orientation_transform_row0/1`), letterbox через `uv_scale/uv_offset` из `render_core::PictureLayout`; вне [0,1] — чёрный.

  Цветовая часть — единый модуль, который потом переиспользуют 06 и 07.
- **Выбор отсчёта цветности — как у wgpu-хоста**: `floor(luma_texel / subsampling)`, центр текселя цветности, фактически nearest co-sited. Размеры плоскостей — uniform-ами (в GLES2 нет `textureDimensions`).
- **Исключения (сайдбар)**: тот же список scissor-прямоугольников (`visible_video_draw_rects`), один draw на прямоугольник. Чёрная заливка полной цели.

## Одна копия без `GL_EXT_unpack_subimage`

- С расширением: `GL_UNPACK_ROW_LENGTH = stride / bytes_per_sample`, один `glTexSubImage2D` на плоскость.
- Без расширения: текстура шириной **в stride** (а не в видимую ширину), загрузка одним вызовом всего блока строк (`visible_plane_block` из `HostPlanarFrameDescriptor` уже отдаёт один непрерывный срез). Хвост строки обрезается в шейдере через `uv_scale`.
- Цена — чуть больше байт на передачу, а не вторая копия. Построчные вызовы и repack запрещены инвариантом README.
- `GL_UNPACK_ALIGNMENT = 1` либо по фактическому выравниванию stride (у блоков 08b — кратно 256).

## Адаптер плеера (начало `render-gles2-shell`)

- `HostPlanarFrameDescriptor` → `PlaneSource::HostRows`, проверка descriptor-vs-contract через `video-core`.
- Удержание кадра декодера: AVFrame живёт, пока GPU не закончил копию (fence). Это то же правило, что `frame_stays_alive_until_its_gpu_copy_is_done` в wgpu.
- `RenderCapabilities` GLES2: точные контракты `SoftwareHostUpload` для 8-бит 420/422/444. Высокая битность — в 06.

## Тесты

- Readback известных цветов для 420/422/444, limited/full, BT.601/709 (эталон — CPU-формула из `render-wgpu-video/src/color_pipeline.rs`, не «глазом»).
- Кросс-рендерный паритет: тот же кадр через wgpu `host_yuv420_8bit_to_rgba` и GLES2, допуск ±1–2.
- Цветокоррекция: каждая ручка по отдельности и все вместе против CPU-формулы.
- Ориентация 0/90/180/270 и letterbox (полосы чёрные, картинка в `PictureRect` пиксель-в-пиксель).
- Исключения: под сайдбаром не рисуется ничего.
- Ширина с хвостом (нечётная видимая ширина, stride > ширины) без `unpack_subimage` → без мусорной полосы справа.
- Кольцо: N+1 кадр при занятых слотах → `Busy`, без аллокации и без освобождения кадра декодера; после fence слот переиспользуется.
- Счётчик: ровно 1 загрузка на плоскость кадра, 0 на повтор того же кадра.

## Замер

На основной машине пример/стенд с реальным декодером FFmpeg (SW H.264 1080p60, SW VP9 4K60) — стоимость загрузки на главном потоке. Сравнение со стоимостью `video_prepare` wgpu-пути из `results/08b.md` (cpu-parity), только как ориентир: там копию делает GPU.

## Критерий выхода

- Все тесты зелёные, паритет с wgpu подтверждён.
- `gles2-video` без зависимостей от плеера (guardrail).
- Документировано, где на T410 живёт копия (драйвер crocus: CPU или blit), — по `perf` в 11 или раньше, если стенд запускается на T410.
