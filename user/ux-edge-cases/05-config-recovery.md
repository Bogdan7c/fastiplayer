## Предыстория (факты аудита, сверить с кодом)

1. `parse_config_text` (`config/src/store.rs:90-117`) возвращает ошибку на: синтаксис TOML, одно значение вне диапазона, один неизвестный ключ (`deny_unknown_fields` в `schema.rs:35`, `schema/ui.rs:21`, `schema/video.rs:11`), `schema_version` ≠ 10 (`validation.rs:275-284`; миграции только v2→v9 в `store/migrations.rs`).
2. `main.rs:55` пробрасывает ошибку через `?` → stderr + exit 1, окна нет. Tracing инициализируется после bootstrap (`main.rs:57-61`) → в логах ничего.
3. Конфиг от более новой версии (downgrade) падает так же.
4. Первая запись default config неатомарна: `create_new` + `write_all` без fsync (`store/atomic.rs:62-76`), права по umask (у temp-пути — 0600). Крах посреди первой записи → обрезанный TOML → п.2 при каждом запуске.
5. После краха остаются `.config.toml.<pid>.<n>.tmp`, никто их не чистит.
6. Instance lease берётся **до** загрузки config (`app_instance`) — порядок не менять в этой сессии.
7. Тесты `unsupported_schema_version_fails_validation`, `unknown_field_is_parse_error` (`store/tests/field_validation.rs:517,529`) фиксируют отказ загрузки — сохранить (это поведение parse), а восстановление — новый слой над ним.

### Часть B. Реализация
- Типизированный исход загрузки: нормально / создан новый / восстановлен из битого (с причиной и именем backup) / работа без сохранения (с причиной). Без `bool`.
- Восстановление выполняет config-хранилище; app только показывает уведомление.
- Атомарная первая запись (temp + fsync + rename, права как у обычного save); чистка своих устаревших `.tmp` при старте (только по точному шаблону имени, только в каталоге config).
- Предупреждение в окне через сессию 04: «Файл настроек был повреждён, сохранена копия config.toml.broken-….bak, используются настройки по умолчанию».

## Тесты (временный XDG_CONFIG_HOME)
- синтаксический мусор / неизвестный ключ / значение вне диапазона → backup создан с исходными байтами, новый config = defaults, исход «восстановлен», приложение получает уведомление;
- новая версия схемы → файл не изменён, исход «без сохранения», save в эту сессию отказан типизированно;
- нечитаемый файл → без backup, исход «без сохранения»;
- первая запись прерывается (fault injection) → нет обрезанного config.toml;
- чужие `.tmp` с другим шаблоном не удаляются;
- нормальный config загружается как раньше (регрессия).

## Ручная приёмка
Испортить `config.toml` (лишняя скобка) → плеер стартует, видно предупреждение, рядом `.bak`. Поставить `schema_version = 99` → старт, предупреждение, файл не тронут.
