**Запрещено:** менять семантику громкости в player-core (clamp 0..1, валидация), добавлять громкость колесом/стрелками (бэклог), сохранять playback rate.

## Предыстория (факты аудита, сверить с кодом)

1. Слайдер и mute шлют `PlayerCommand::SetVolume`/`ToggleMute`; обратно в config/state ничего не пишется. При следующем запуске громкость = `audio.volume` из config, mute сброшен.
2. Внутри процесса громкость переживает смену media и suspend/resume (`media_jobs.rs:~217`, `desktop_effective_volume`).
3. Mute ставит `snapshot.volume = 0.0` (`runtime_control.rs:~265-268`) — при сохранении различать «громкость» и «mute», иначе после рестарта громкость будет 0.
4. Сохранение config при каждом движении слайдера — плохая идея (переписывает весь TOML, `store/atomic.rs`); у playlist-state уже есть debounce-сохранение (`state_save_debounce_ms`).

## Задание

### Часть A. Исследование
Варианты хранения: (A) поле `audio.volume` в config через settings-транзакцию (тогда «громкость по умолчанию» в настройках = последняя громкость); (B) отдельный state-файл рядом с playlist state (config остаётся «громкостью по умолчанию», state — «последняя»); (C) в существующем playlist/app state. Цена, атомарность, debounce.

### Стоп: согласование с владельцем
- где хранить (рекомендация — B или C: config не переписывается на каждое движение слайдера);
- сохранять ли mute (рекомендация — да, громкость отдельно от mute);
- что важнее при старте: сохранённая последняя громкость или `audio.volume` из настроек (рекомендация — последняя, если есть).

### Часть B. Реализация
- Владелец «последней громкости» с intent-API (`record_user_volume`, `restored_volume_for_startup`), debounce, сохранение при shutdown через существующий порядок завершения.
- Повреждённый/отсутствующий файл → fallback на config без ошибки для пользователя (лог).

## Тесты
- изменить громкость → перезапуск (новый AppState с тем же каталогом) → громкость та же; mute → перезапуск → mute + прежняя громкость при unmute;
- 100 изменений слайдера → не более 1–2 записей (debounce, fake time);
- битый state-файл → громкость из config, без паники;
- громкость доходит до аудио-потребителя (fake output получает масштабированные сэмплы), а не только до snapshot.
