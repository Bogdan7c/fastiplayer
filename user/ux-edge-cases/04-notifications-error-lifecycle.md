## Предыстория (факты аудита, сверить с кодом)

2. Не удалось открыть новый файл, пока играет старый → старый играет (хорошо), а красная ошибка висит поверх видео бесконечно.
3. `player_snapshot.last_error` приоритетнее `startup_error` (`ui_runtime.rs:200-203`) → пока висит старая ошибка player-а, «Подготовка…» не видно.

Recoverable ошибки player (`runtime_control.rs:~384`) ставят `last_error`; `clear_error` вызывается только из media lifecycle/install (`media_lifecycle.rs:238,316,328`, `staged_media_install/commit.rs:143`). Итог: безобидное ← на не-seekable стриме («Seek невозможен: timeline не seekable», `seek_admission.rs:46`) или «Replay невозможен…» висит до следующего открытия.

6. Уже есть локальный прецедент: `state/timeline_inline_status.rs` — фиксированные 2500 мс inline-статус. Использовать как образец/учесть, не дублировать.

## Задание

### Часть A. Исследование
1. Инвентаризация всех каналов показа: центральный overlay, playlist status bar (`ui/playlist/status/presentation.rs`), url sidebar, timeline inline status, telemetry. Кто владеет, когда очищается.
2. Классифицировать сообщения по смыслу: **фатальная для текущего media** (воспроизведение остановилось) / **временная** (seek отклонён, Open занят, пропущен файл) / **информационная** (настройки сброшены, переключено аудиоустройство) / **прогресс** (подготовка).
3. Context7 egui: `Area`/`Order::Foreground`, анимация появления, учёт `reduced_motion`.

### Стоп: согласование с владельцем
- вид: toast в углу / полоса сверху / оставить центр для фатальных + toast для остального (рекомендация — последний);
- время показа временных (например 4–6 с), ручное закрытие (×), закрывать ли по клику на видео;
- как ведёт себя очередь уведомлений (последнее заменяет / стопка до N);
- красная фатальная ошибка: закрываемая вручную, исчезает при следующем успешном действии.

### Часть B. Реализация
- Владелец уведомлений с intent-API (например `notify_transient(...)`, `notify_info(...)`, `show_media_failure(...)`, `dismiss(...)`), время берётся из frame timing, а не из системных часов внутри UI-кода; длительности — константы с объяснением или config (не хардкод без обоснования).
- Recoverable ошибки player (seek/replay rejected) идут как временные, не как вечные.
- Open во время загрузки → временное «Файл ещё открывается».
- Подготовка («Подготовка…») не скрывается старой ошибкой.
- `reduced_motion` уважается.

## Тесты
- временное уведомление исчезает через заданное время (fake time), фатальное — нет, но закрывается вручную и при успешном открытии;
- seek на не-seekable media → временное уведомление, через N с overlay пуст;
- неудачное открытие при играющем media → старое играет, ошибка закрываемая;
- «Подготовка…» видна, даже если была старая ошибка;
- повторный Open → уведомление «ещё открывается», второй диалог не открыт;
- модуль не меняет состояние player/playlist (только отображение).

## Ручная приёмка
Открыть битый файл поверх играющего видео → закрыть ошибку ×. На live/не-seekable потоке нажать ← → сообщение исчезает само. Дважды Open подряд.
