## Предыстория (факты аудита, сверить с кодом)

1. `PlaylistErrorBehavior::Stop` — default (`schema/playlist.rs:284`). Один битый/перемещённый файл посреди очереди останавливает воспроизведение; виден только бейдж ошибки у строки (`upsert_runtime_error`).
2. То же при восстановлении после рестарта (`controller/startup_restore.rs:135-139`): файл перемещён → плеер стартует «ни с чем».
3. **Default config записывается целиком**, включая `error_behavior = "stop"` (`default_document.rs:45`) → у всех существующих пользователей значение уже записано явно. Простая смена default **не затронет** их; миграция не может отличить «выбрал сам» от «осталось по умолчанию».
4. Причина остановки только в логе: `stop_for_active` (`automatic_lifecycle.rs:676-695`, комментарий «причина остаётся в логе»), `AllCandidatesFailed`/`EndOfQueue`/`ErrorPolicy` → `tracing::debug!` (`:482-487`). `cause` в `AutomaticLifecycleOutcome::Stop` есть только под `#[cfg(test)]`.
5. Skip-цепочка ограничена и не зацикливается (хорошо, покрыто тестами `transport_execution_audit_regressions.rs:240`).

## Задание

### Часть A. Исследование
1. Где начинается и заканчивается skip-цепочка, где известны: сколько пропущено, какие элементы (item id → безопасное имя файла по решению 1а), почему остановились.
2. Как schema-миграции делаются сейчас (`store/migrations.rs`), цена bump-а до v11.

### Стоп: вопросы владельцу (рекомендации в скобках)
1. **Существующие конфиги со `stop`**: (A) миграция v10→v11 меняет `stop` на `skip` у всех — пользователь, который сам выбрал stop, потеряет выбор (сейчас пользователей мало — рекомендация A); (B) только новый default для новых установок; (C) A + разовое уведомление «поведение изменено, можно вернуть в настройках».
2. Текст уведомления: «Пропущено N файлов: a.mkv, b.mp4…» (сколько имён показывать — рекомендация до 3 + «и ещё K»).
3. Если пропущены **все** элементы: «Ни один файл очереди не удалось открыть» — фатальное (закрываемое) уведомление.

### Часть B. Реализация
- Исход automatic lifecycle несёт типизированную причину остановки и сводку пропусков в production (не только в тестах); app превращает её в уведомление.
- Сводка накапливается на уровне владельца цепочки, а не в UI.
- Миграция/default — по решению.

## Тесты
- очередь A(ok) → B(битый) → C(ok): после A играет C, уведомление называет B;
- все элементы битые → остановка, одно уведомление «ни один не открылся», нет цикла;
- `error_behavior = stop` (явно выбран) → поведение как раньше + видимая причина;
- restore после рестарта с перемещённым текущим файлом → играет следующий (при skip), уведомление;
- миграция (если выбрана): v10 `stop` → v11 `skip`, остальные поля без изменений; повторная загрузка идемпотентна;
- ручной Next на битый элемент не пропускает автоматически (регрессия D55).
