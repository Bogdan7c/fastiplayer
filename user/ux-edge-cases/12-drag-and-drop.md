## Тесты
- серия drop-событий одного жеста → одно намерение с N путями в исходном порядке;
- 1 файл при пустой очереди → воспроизведение доходит до рендера (реальная фикстура);
- 1 файл при непустой очереди → показано подтверждение замены, очередь не изменена до ответа;
- папка → очередь из media-файлов папки по правилам discovery;
- `.m3u` → preview импорта;
- non-UTF-8 и пробелы в имени → путь не искажён;
- drop во время открытия другого файла → поведение по решению (уведомление «ещё открывается»).

## Результат исследования (6 октября 2026)

- **winit 0.30.13**: `DroppedFile`/`HoveredFile` эмитит только X11-бэкенд (`platform_impl/linux/x11/event_processor.rs`); в Wayland-бэкенде data device не реализован вообще. X11 к тому же молча отбрасывает не-`file://` URI (`x11/dnd.rs::parse_data` → `UnexpectedProtocol`) и не сообщает точку броска.
- **winit 0.31** (beta.3, сентябрь 2026; PR #4571 «New drag and drop API»): `WindowEvent::DragEntered/DragMoved/DragDropped/DragLeft` + `DataTransferReceived`, типизированные данные (`text/uri-list`, текст), позиция, реализация для X11, Wayland, Win32, macOS. egui-winit 0.36.2 требует winit `^0.30.13`, поэтому перейти сейчас нельзя.
- **KWin 6.7** (`src/wayland/seat.cpp::setDragTarget`) рассылает drag-события во все `wl_data_device` клиента, так что data device winit-а уживается с data device буфера обмена smithay-clipboard.
- Во время Wayland-DnD окно не получает `wl_pointer`-движений, и последняя позиция мыши в egui устаревшая. Поэтому точку броска обязан сообщать источник событий.
- Готовые пути в приложении:
  - Open одного файла: `AppState::apply_local_file_open_result` (ветка `Selected`) → `classify_in_app_local_file_selection` → `admit_in_app_queue_replacement`. Busy-проверка есть только в `AppState::open_file`.
  - Добавление в конец: `PlaylistRuntime::start_manual_file_add(Vec<PathBuf>)`, папки не раскрывает.
  - Импорт по известному пути: `PlaylistImportIoOwner::start_path` (`pub(super)`), публично доступен только `StartupReplace`.
  - Рекурсивного обхода папок в проекте нет: `playlist-io::local_expansion` раскрывает только плейлист-документы.
  - Уведомление `notify_open_still_in_progress()` («Файл ещё открывается») уже есть.

## Решения владельца (6 октября 2026)

1. **Wayland — патч winit 0.30** (`crates/winit-patch`, по схеме существующих `[replace]`-патчей). Патч устроен так, чтобы при выходе стабильного winit 0.31 (и egui на нём) его можно было выбросить, переписав только один файл-переходник в приложении. Вся логика маршрутизации, тесты и UI при этом не меняются. По возможности переходник же обслуживает Windows без дублирования логики.
2. **Drag & drop ссылок входит в объём** (раньше был в бэклоге).
3. **Место броска решает**: на панель плейлиста → добавить в конец; на видео → новая очередь (с подтверждением замены непустой очереди). Правило одно для файлов, папок, ссылок и (по умолчанию) плейлистов.
4. **Папка — рекурсивно, с подпапками.** Лимиты (число файлов, глубина) хранятся в `config.toml` и редактируются в окне настроек.
5. **Плейлист-файл** — поведение задаётся настройкой: «по месту» (по умолчанию) / «всегда новый плейлист» / «всегда добавить». Во всех случаях с предпросмотром импорта.
6. Без отдельного вопроса (рекомендация агента, владелец не возражал):
   - смесь плейлистов с медиа/папками → медиа и папки обрабатываются, плейлисты пропускаются с уведомлением;
   - бросок во время открытия другого файла → «Файл ещё открывается», бросок игнорируется.
7. Выполнение: в одной сессии, последовательными субагентами (Sonnet). Основной агент отвечает за архитектуру и финальную проверку.

## Архитектура

```
winit 0.30 (patch)          app-egui                                              существующие пути
X11/Wayland ──ExternalDrag──▶ external_open::winit_source  (ЕДИНСТВЕННЫЙ winit-aware файл)
Win32/macOS ──DroppedFile──▶        │  DropGestureEvent {Entered{pos}|Moved{pos}|Dropped{pos, payload}|Left}
                                    ▼
                             external_open::gesture   — состояние жеста, подсветка, сбор в одно намерение
                                    ▼  ExternalOpenRequest { target: Playlist|Video, items: [LocalPath(PathBuf)|WebUrl] }
                             external_open::classify  — чистая классификация (без I/O кроме metadata)
                                    ▼  ExternalOpenPlan
                             external_open::dispatch  ──▶ Open / start_manual_file_add / замена очереди на N файлов /
                                                          импорт по пути / Add URL / открыть URL / уведомления
```

- **Патч winit** только добавляет новое, ничего не ломая. Публичный `WindowEvent` не меняется (egui-winit матчит его исчерпывающе). Новый канал — additive API модуля `winit::platform::external_drag` по образцу 0.31: вход/движение/бросок/уход с физической позицией и полезной нагрузкой «сырые URI из `text/uri-list` + опциональный простой текст». В Wayland — data device через sctk 0.19 с неблокирующим чтением pipe через calloop. X11 — расширение существующего XDND (позиция, не-file URI, текст). Legacy-события `HoveredFile/DroppedFile` для `file://` сохраняются (на Wayland тоже эмитятся), так что egui ведёт себя одинаково.
- **Декодирование `file://` URI → `PathBuf`** (percent-decoding в байты → `OsString`, без потерь для не-UTF-8) живёт в приложении, а не в патче: в 0.31 URI приходят так же строками.
- **Точка броска** → `DropTarget` через hit-test по rect панели плейлиста. Rect публикуется UI каждый кадр; пересчёт физических пикселей в points через scale factor. Нет точки (legacy-источник) → `Video`.
- **Новые boundary у владельцев состояния**:
  - замена очереди на N локальных путей через существующий `replacement_confirmation` (новый вариант target, без «trusted»-обхода);
  - `PlaylistRuntime::start_playlist_import_path(path, intent)`;
  - рекурсивный обход папки с бюджетами из config (владелец — крейт обнаружения файлов, не app-egui);
  - новые поля config + миграция + UI настроек.
- Файлы ≥ 700 строк не раздуваем: `state/ui_runtime.rs` (824, legacy) получает только вызовы новых модулей.

### Дополнение (7 октября 2026)

8. **Папка на видео при непустой очереди: сначала обход, потом подтверждение** — с числом файлов в вопросе («23 файла из папки «Музыка»»). Это осознанное исключение владельца из инварианта S14A «никакой работы с диском до подтверждения»: до Confirm выполняется только чтение списка файлов папки, без demux/подготовки/discovery.
9. **Ссылка-коллекция (плейлист YouTube и т.п.), брошенная на видео, раскрывается** тем же получением структуры, что и Add URL (индикатор + отмена), затем — подтверждение «заменить очередь на N роликов» (непустая очередь) и воспроизведение первого. Как и для папки, подтверждение идёт после получения списка.
10. **Бросок на панель сохраняет порядок броска/обхода папки**, как и замена очереди (раньше Manual Add пересортировывал пачку по полному пути). Кнопка «Добавить файлы» не меняется.
11. Найдено ручной приёмкой и чинится в этой сессии **отдельными коммитами** (оба бага существовали до сессии 12):
    - ползунок настроек сам меняет значение при отрисовке (egui `Slider` с `SliderClamping::Always` каждый кадр прилипает к сетке шага от минимума: 2000→2001, 30000→31000, 250→251), и Apply записывает это в config;
    - строки YouTube-плейлиста (Add URL и бросок) не запускаются: при запуске yt-dlp получает URL всего плейлиста (`item.locator()` = root provenance) вместо ссылки на ролик из `durable_payload.reopen_locator`, полный разбор плейлиста упирается в таймаут 30 с.
