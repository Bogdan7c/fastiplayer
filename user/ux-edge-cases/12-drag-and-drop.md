## Задание

### Часть A. Исследование
1. Поддержка drop в winit 0.30.13 на Wayland и X11 (первичный источник — исходники/CHANGELOG winit). Если на Wayland не поддерживается — стоп и сообщить владельцу с вариантами.
2. Карта: какие существующие действия подходят для «1 media-файл», «несколько файлов», «папка», «файл плейлиста», «смесь».

### Стоп: согласование с владельцем
Поведение (рекомендация):
- 1 media-файл → как кнопка Open (с подтверждением замены, если очередь не пуста);
- несколько файлов / папка → новая очередь из них (с подтверждением) — или «добавить в конец», если drop на панель плейлиста;
- файл плейлиста (.m3u/.xspf/.cue) → импорт с preview;
- смесь media + плейлист → только media или отказ с уведомлением;
- подсветка «Отпустите, чтобы открыть» при наведении.

### Часть B. Реализация
- Сбор файлов одного drop-жеста в одно намерение (drop нескольких файлов приходит серией событий — собрать за кадр).
- Намерение «внешний запрос открытия» с типизированными вариантами, исполняется через существующие пути.
- Пути без потерь (`PathBuf`/`OsString`), ошибки — тексты сессии 02.

## Тесты
- серия drop-событий одного жеста → одно намерение с N путями в исходном порядке;
- 1 файл при пустой очереди → воспроизведение доходит до рендера (реальная фикстура);
- 1 файл при непустой очереди → показано подтверждение замены, очередь не изменена до ответа;
- папка → очередь из media-файлов папки по правилам discovery;
- `.m3u` → preview импорта;
- non-UTF-8 и пробелы в имени → путь не искажён;
- drop во время открытия другого файла → поведение по решению (уведомление «ещё открывается»).
