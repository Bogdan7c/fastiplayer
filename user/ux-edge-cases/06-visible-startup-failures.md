## Предыстория (факты аудита, сверить с кодом)

1. wgpu поднимается **только Vulkan**: `render-wgpu-shell/src/shell.rs:183` `Backends::VULKAN`, `force_fallback_adapter: false`. Нет адаптера → `app_shell/mod.rs:260-267` `tracing::error!` + `event_loop.exit()` → окно мигает и исчезает, **код выхода 0** (`main.rs:84-91`). Текст «Проверьте драйверы Vulkan» — только в логе.
2. Так же молча выходят: ошибка создания AppState (`app_shell/mod.rs:298-304`), неверные настройки цвета рендера (`274-281`), ошибка создания окна (`event_loop.rs:138-142`).
3. Ошибки bootstrap до окна (CLI: неизвестная опция, лишний позиционный аргумент — `app_instance/mod.rs:212-232`; lease) → только stderr + exit 1. Запуск из файлового менеджера — пользователь ничего не видит.
4. Тексты lease-ошибок — Debug-имена: «UnsafeArtifact { reason: ConfigDirectoryOwnerMismatch }» (`app_instance/mod.rs:140-153`). Типичная причина — каталог config создан от root после одного запуска через `sudo`.
5. Сообщение «другой экземпляр уже запущен» — тоже только stderr (полноценный forwarding — сессия 13, здесь достаточно видимости, если решит владелец).

## Задание

### Часть A. Исследование
1. Полный список путей фатального выхода (grep `event_loop.exit`, `?` в `main`, `std::process::exit`), для каждого: есть ли окно, есть ли GPU, код выхода.
2. Варианты показа ошибки без рабочего wgpu (Context7 / первичные источники):
   - (A) системный диалог через внешнюю утилиту (`kdialog` / `zenity`), если есть в PATH; иначе stderr;
   - (B) desktop-уведомление (freedesktop Notifications по D-Bus) — работает и без окна;
   - (C) простое окно ошибки без GPU (winit + CPU-отрисовка, например `softbuffer`) — новая зависимость;
   - (D) комбинация: B всегда + A для «нет GPU».
   Для каждого: зависимости, лицензия, KDE/GNOME/без DE, тестируемость.
3. Как отличить «запущен из терминала» (stderr достаточно?) — рекомендация: показывать всегда, stderr дублировать.

### Стоп: согласование с владельцем
Выбор варианта показа (рекомендация — D или B, без тяжёлых зависимостей), список ошибок, которые показываются, тексты.

### Часть B. Реализация
- Один тип «фатальная ошибка запуска» с человеческим текстом и технической деталью для лога; одна функция показа; все пути из п.1 идут через неё.
- Ненулевой код выхода при фатальной ошибке.
- Человеческие тексты lease-ошибок: например «Каталог настроек ~/.config/fastiplayer принадлежит другому пользователю (возможно, плеер запускали через sudo). Исправьте владельца каталога». Путь к каталогу config показывать можно (это не media-путь) — подтвердить у владельца.
- Tracing инициализируется как можно раньше, чтобы фатальные ошибки bootstrap попадали в лог.

## Тесты
- каждая фатальная ошибка (fake: нет адаптера, ошибка окна, lease mismatch, bad CLI) → вызов показа с ожидаемым текстом и ненулевым кодом выхода (через fake-показ);
- нормальный запуск не вызывает показ;
- тексты не содержат `{:?}`-имён типов.

## Ручная приёмка
`VK_ICD_FILENAMES=/nonexistent fastiplayer` (или аналог отключения Vulkan) → видно сообщение. Запуск с неизвестной опцией из файлового менеджера/`.desktop` → видно сообщение.
