**Решение владельца (уже принято, 1а):** в тексте ошибки для пользователя показывается **имя файла без пути к папке**. Parent-каталоги не показываются нигде. В логах (`tracing`) — как сейчас, без имени файла, если владелец не решит иначе.

**Разрешено:** `safe_local_open_label` (`app-egui/src/playlist_runtime/replacement_confirmation.rs:716`) и его 7 вызовов; `PrepareLocalOpenError` (`app-egui/src/media_open/local.rs:50-70`) — классификация причины; форматирование сообщений `local_file_prepare_error_message` (`app-egui/src/local_file_open.rs:~333`), `startup_media/orchestration/drain.rs:24-35`; новый маленький модуль-владелец «причина → текст» (не раздувать существующие файлы); тесты.

**Запрещено:** причина отказа на этапе установки в player (`PlayerRejected`, «worker недоступен») — это сессия 03; жизненный цикл красного overlay — сессия 04; менять типы `source-core`/`media-source-open` сверх добавления классификации, если её нельзя сделать в app; выводить parent path.

## Предыстория (факты аудита, сверить с кодом)

1. `safe_local_open_label(_path)` игнорирует путь и возвращает константу «локальный media-файл». Итог: «Ошибка открытия media-файла локальный media-файл: …» — кривая грамматика, файла не видно.
2. `SafeMediaLabel::from_local_path` уже существует (`media-source-open/src/safe_media_label.rs:27`), но при отсутствии `file_name()` (путь `/`, `..`) **возвращает весь путь** — это утечка parent path; исправить fallback (например, константа).
3. `PrepareLocalOpenError` Display теряет причину: битый файл, нулевой размер, неверное расширение, картинка, неподдерживаемый контейнер, каталог → одинаковое «не удалось открыть media container» (внутренняя причина — в `#[source]`, `{error:#}` thiserror-цепочку не раскрывает). Нет файла / нет прав → сырой английский текст ОС, ещё и продублированный (`Source(#[source])` + `{0}`).
4. Каталог: `File::open` на Linux успешен для каталога, ошибка возникает только при первом чтении → проверить, как классифицировать («это папка, а не файл»).
5. Путь через CLI (`drain.rs:24-27`) даёт голую строку без префикса и имени; отмена startup-подготовки показывается как ошибка («Startup local preparation отменена»).
6. Тест `malformed_local_ts_returns_safe_typed_error_without_path_disclosure` (`media_open/local.rs:~362`) проверяет отсутствие имени — его нужно переписать под решение 1а: имя файла **есть**, parent-каталог **нет**.

## Тесты (реальные файлы во временном каталоге, через настоящий prepare-путь)
- несуществующий файл, файл без прав (chmod 000; пропуск под root), каталог, пустой файл, случайный мусор, PNG, обрезанный MP4/TS → каждая причина даёт свой текст, содержит имя файла и **не** содержит имя родительского каталога;
- путь без `file_name` → нет утечки пути;
- non-UTF-8 имя → текст строится (lossy), без паники;
- отмена → нет пользовательской ошибки;
- CLI-путь и кнопка Open дают одинаковый текст.
