# Fastiplayer: исправление UX edge cases

Подготовлено 4 октября 2026 по результатам глобального UX-аудита (5 read-only исследований: открытие файлов, транспорт/управление, плейлист, настройки/устройства, сеть/веб). Код в сессии подготовки не менялся. Это задания для будущих сессий, а не отчёт о выполненной работе.

Ключевые находки аудита перепроверены по коду (ссылки в файлах сессий). **Номера строк — снимок на 4 октября 2026 (HEAD `172c5363`), перед правкой всегда сверять с текущим кодом.**

## Решения владельца (4 октября 2026)

1. **Имя файла в ошибках — показываем имя без пути к папке** (вариант 1а). Parent-каталоги по-прежнему не показываются и не пишутся в логи. Сессия 02.
2. **Битый `config.toml` — резервная копия `.bak`, запуск с настройками по умолчанию, предупреждение в окне** (вариант 2а). Сессия 05.
3. **Битый файл в очереди — по умолчанию «Пропустить» с уведомлением** (вместо «Остановиться»). Сессия 07.
4. Работа идёт в `main`, отдельные ветки и PR не создаются (правило владельца). Коммит — в конце сессии после зелёных проверок и ручной приёмки владельцем. Push — только по отдельному поручению.

Решения, которые ещё предстоит принять, отмечены в файлах сессий как **«Стоп: согласование с владельцем»**. До решения исполнитель не реализует спорную часть.

## Как пользоваться

1. Начни новую сессию агента в репозитории Fastiplayer.
2. Приложи **только один файл сессии** из таблицы и скопируй абзац из его начала в сообщение.
3. Исполнитель читает этот README (раздел «Общие правила») и `results/NN.md` сессий, от которых зависит текущая. Больше ничего прикладывать не нужно.
4. Проверь результат (особенно ручную приёмку) и только потом запускай зависимые сессии. Независимые сессии можно делать в любом порядке.

## Общие правила для всех сессий

Работай в корне checkout репозитория. Сначала `AGENTS.md`. Перед кодом:
- Serena `initial_instructions`, активация проекта, `mem:core`, `mem:task_completion`, `mem:conventions`, `mem:testing/sandbox_policy` + memories, перечисленные в файле сессии;
- Context7 для каждой затрагиваемой внешней библиотеки (egui, winit, wgpu, cpal, toml, serde и т.п.). Если источник недоступен — назови препятствие;
- широкий поиск по репозиторию — read-only субагентом (модель Sonnet), основной агент читает только точные символы;
- перед реализацией — короткое описание архитектуры: владелец состояния, boundary-методы, инварианты, тесты (правило 9 AGENTS.md).

Код:
- новая логика — у владельца состояния, не в самом удобном большом файле; файлы ≥ 700 строк не раздувать (hard limit 800, ratchet `scripts/module-size-baseline.json` обновлять при изменении legacy-файла);
- boundary API — самодокументирующиеся (enum/newtype/intent-method, без позиционных `bool`); absent / busy / fatal / no-op не сливаются;
- **тексты для пользователя — по-русски, человеческим языком, без `{:?}`, имён Rust-типов и внутреннего жаргона**; технические детали — в лог (`tracing`), без путей к каталогам и секретов;
- русская документация ключевой логики и инвариантов; без `unwrap/expect/panic` в production (`mem:panic-invariant-policy`);
- косметический рефакторинг вместе с фичей запрещён.

Тесты: проверяют наблюдаемый результат (текст, состояние, кадр, событие), а не факт вызова. Для каждого нового boundary — отсутствующий ресурс, fake/stub, ошибка, edge-case accounting, «не трогает чужое состояние». Перед завершением теста — мысленная мутация: «если сломать функцию, тест упадёт?».

Проверки (минимум):
1. `cargo test -p <затронутые crate-ы> --locked`, затем соседние потребители изменённых контрактов;
2. `cargo fmt --all --check`, `scripts/ci-checks.sh clippy`, `scripts/ci-checks.sh tests`;
3. при изменении публичных типов/нескольких crate-ов — `cargo +1.99.0 check --workspace --locked`, `scripts/check-refactor-guardrails.py`;
4. полный `bash scripts/pre-pr-checks.sh` перед коммитом (известный FAIL `dependencies` — advisories `ringbuf`/`rustls`, не блокер, если не появилось новых);
5. ручная приёмка владельцем по сценарию из файла сессии (GUI, медиа, железо — вне sandbox).

Выходной барьер каждой сессии — `results/NN.md` (60–120 строк): статус PASS / BLOCKED / PARTIAL; принятые решения владельца; SHA; изменённые файлы и символы; результаты проверок (PASS / FAIL / NOT RUN с причиной); сценарий ручной приёмки и итог; открытые риски. В конце — self-review диффа и обновление Serena memories, если изменились boundary/API/инварианты (иначе явно написать, что не требовалось).

## Бэклог (найдено аудитом, в план сознательно не включено)

Мелкие или спорные пункты; брать отдельными задачами по решению владельца:
- Импорт `.m3u`/`.cue` в cp1251/Latin-1 целиком падает (`playlist-io/src/m3u.rs:77`, `cue/encoding.rs:24`). Нужен выбор: lossy-декодирование, эвристика кодировки или выбор вручную.
- Resume-позиция у самого конца (выход за 2 с до конца) восстанавливается как есть → трек сразу заканчивается (`app-egui/src/playlist_runtime/resume_persistence.rs`). Нужен порог «почти досмотрено → с начала».
- Undo удаления пропадает от фоновых metadata-патчей и автоперехода (`removal_undo.rs:113`); Clear без подтверждения и Undo Clear не возвращает воспроизведение.
- Сайдбар всегда пишет «VOD» для web-потоков (`web_media_stream_model.rs:241`, `is_live: false`); нет кнопки «к прямому эфиру».
- Нет громкости колесом мыши и ↑/↓, нет Ctrl+O, нет подсказки времени при наведении на таймлайн; клавиши скорости работают только при наведении на кнопку play.
- Ошибки на смеси языков: `PlayerError` Display `"{Kind:?}: …"` (`player-core/src/error.rs:92`), «URL scheme не поддерживается media services», «provider для `ftp` ещё не реализован», jargon «controlled reopen» в сайдбаре.
- yt-dlp: нет cookies/логина, нет проверки версии; классификация HTTP 404/410/429 как `NetworkUnavailable` (`web-media-http/src/lib.rs:~479`).
- Экспорт плейлиста: одна неподходящая запись прерывает весь экспорт; общий текст ошибки для read-only/диск полон.
- `reduced_motion` по умолчанию `true` и не читает системную настройку.
- Пробелы/переводы строк вокруг вставленного URL не обрезаются; несколько URL в одной строке не распознаются.
- Окно можно сжать до ~1 px по высоте (`with_min_inner_size(400, 1.0)`).
- Hardware-only backend без VA-API: проверить, предупреждает ли settings UI.
