# Результат сессии 05: битый config.toml — резервная копия, defaults, предупреждение

## Статус

**PASS (автоматические проверки + ручной прогон агентом).** Клик по × и «Применить» руками не нажимались — нет средств ввода в окружении, закрыто автотестами. Коммит — после подтверждения владельца, push не делается.

## Решения владельца (5 октября 2026)

1. **Конфиг от более новой версии** — файл не трогаем, настройки по умолчанию только в памяти, изменения в этот запуск не сохраняются, предупреждение.
2. **Предупреждение о восстановлении** висит в углу, пока его не закроют ×: сброс настроек нельзя пропустить, даже если в момент запуска пользователь не смотрел в окно.
3. **Имя копии** — дата и время в UTC: `config.toml.broken-2026-10-05_14-30-12.bak`. Хранятся все копии.
4. **Режим «без записи»** (новая версия, файл не читается) — изменение настройки применяется до выхода, на диск не пишется, пользователь видит временное уведомление.
5. Два выхода за пределы `config` одобрены: новый исход `PersistOutcome::SkippedSessionOnly` в `settings-core` и перевод обеих записей config-а на общий `atomic-file-store`.

Решено по умолчанию, без отдельного вопроса: конфиг сбрасывается целиком (частичный сброс — бэклог); слишком старая версия схемы (0/1) считается повреждённой.

## Исследование (часть A)

- **Различимость ошибок.** Мусор в TOML и неизвестный ключ давали одну ошибку `ParseConfigFile`. Значение вне диапазона и любая неподходящая версия схемы давали `ValidateConfigFile(InvalidValue)`. «Новая версия» отдельным типом не различалась. Миграции (v2→v9→v10) не падают никогда.
- **Корень проблемы.** Любая ошибка загрузки проходила через `?` в bootstrap, и процесс выходил до создания окна. Первая запись defaults создавала файл сразу под настоящим именем, без fsync: сбой посреди записи оставлял обрезанный TOML навсегда.
- **У config-а была своя копия атомарной записи.** Её temp-файл получал права по umask, а уборки брошенных `.tmp` не было нигде. В проекте уже был `atomic-file-store` (temp 0600, fsync, rename, тесты с имитацией сбоев), им пользовался только плейлист.
- **Quarantine плейлиста.** Он переименовывает без перезаписи. Идею взяли, формат имени по решению владельца сделан читаемым.

## Что сделано (часть B)

- **Решение «что делать с файлом» принимает config-хранилище** (`config/src/store/recovery.rs`, `load_or_recover_at`). Приложение вызывает его под уже взятым lease. Порядок «lease → config» не менялся.
  - Версия схемы читается из сырого TOML **до** строгой проверки, иначе файл новой версии с незнакомыми ключами выглядел бы «повреждённым».
  - Главный инвариант: файл пользователя **только переименовывается**, никогда не удаляется и не перезаписывается. Если копию сделать нельзя, файл остаётся на месте, а запуск идёт без записи.
- **Типизированный итог** вместо `created: bool`:
  - `ConfigLoadOrigin::{LoadedExisting, CreatedDefault, RecoveredFromBroken{problem, backup_file_name}, DefaultsInMemory}`;
  - `ConfigSavePolicy::{WriteToFile, SessionOnly(причина)}`.
- **Запрет записи нельзя обойти.** `ConfigSaveTarget::save` возвращает `Saved` или `KeptInMemoryOnly(причина)`, проверка значений выполняется в обоих режимах. `AppConfigStore::from_save_target` переводит это в `PersistOutcome::SkippedSessionOnly`: транзакция настроек успешна и не откатывается.
- **Атомарная запись.**
  - Первая запись defaults и обычный save идут через `atomic-file-store`.
  - Семь вариантов ошибок записи заменены одним `ConfigError::ReplaceConfigFile`, причина описана по-русски.
  - При старте убираются брошенные temp-файлы: шаблон `atomic-file-store` (`remove_stale_temp_files`; распознаёт шаблон его владелец) и прежний шаблон config-а. Удаляются только обычные файлы, только с точным именем, только в каталоге config-а.
- **Дата в имени копии** считается своим кодом (`backup_name.rs`), без crate `time`. Подключение `time` к `config` ломало вывод типов `Duration` в тестах `player-core`. Алгоритм сверяется с наивным счётом дней на каждом дне 1970–2200 годов.
- **Приложение только показывает итог.**
  - `config_startup_notice.rs` переводит итог загрузки в русский текст без путей к каталогам.
  - `AppShell` один раз передаёт предупреждение первому `AppState`.
  - В `NotificationCenter` добавлен вид `ToastKind::Warning`: висит до ×, не будит окно, а при переполнении стопки вытесняется последним.
  - При сохранении в режиме без записи hook `report_settings_kept_for_session_only` показывает toast, статус окна настроек говорит то же самое.

## Ручная приёмка (сценарий для владельца)

1. Закрыть плеер. В `~/.config/fastiplayer/config.toml` добавить в конец строку `[[[`.
   - Ожидание: плеер стартует, в правом нижнем углу красная плашка «Файл настроек был повреждён (ошибка в тексте файла). Сохранена копия config.toml.broken-….bak…». Плашка не исчезает сама, × её закрывает. Рядом лежит `.bak` с исходным текстом, а `config.toml` — свежий по умолчанию.

   - Ожидание: старт, плашка «…создан более новой версией Fastiplayer и оставлен без изменений…».

## Открытые риски

- Логи config-слоя до инициализации tracing теряются, итог загрузки логируется уже из `main`. Ранний tracing — сессия 06.
- Строгий `load_or_create_at` больше не защищён от параллельного создания файла через `create_new`. Им пользуются только тесты и smoke-утилита, приложение работает под lease.
- Если `AppState` пересоздан после suspend, незакрытое предупреждение повторно не показывается. Так задумано: оно передаётся один раз.
- Удалены публичные варианты `ConfigError` для записи. Внешних потребителей нет.
