# Результат сессии 18: кнопка Open не подвешивает окно на время установки файла

## Статус

**PASS.** Ручную приёмку по поручению владельца (10 октября 2026) прогнал агент: реальный GUI через `/dev/uinput`, изолированный профиль. Два коммита в `main`, push не делался.

## Решения владельца (10 октября 2026)

1. **Вариант A:** Open использует тот же общий неблокирующий путь, что старт и плейлист. Его опрашивает маленький владелец «установка из Open».
2. **Повторный Open во время установки:** сразу «Файл ещё открывается» (уведомление сессии 04). Диалог выбора не открывается.
3. **Индикатор:** строка «Открываем «clip.mkv»…». Она уже была, просто раньше окно висело и её не рисовало.
4. **Next/Stop/строка плейлиста во время открытия** молча отменяют открытие, после чего команда выполняется. Это то же правило, что для плейлиста и старта. Разрешена правка `guarded_transport.rs` (файла не было в списке разрешённых).

## Исследование (часть A)

- **Подвисание реально.** `install_prepared_media_strong` → `drive_media_open_to_terminal` → `wait_for_media_open_progress` → блокирующий `recv()` без срока, прямо на UI-потоке. Это воспроизведено тестом с настоящим `PlayerWorker`: блокирующий шаг держит поток весь предпросмотр.
- **Слот один, и coordinator тоже пускает один запрос:** при занятом `current` любой старт получает `Busy`. Поэтому вариант B (отдельный слот) невозможен без смены протокола.
- **Владельцы слота** различают «свой» request каждый по-своему: старт (`pending_install`), плейлист (`active_request_id`), VOD (`strong_open_started`), переключение качества (request_id). Open устроен так же.
- **Новая ситуация:** раньше нажать Next/Stop во время Open было нельзя, окно висело. Guard относил чужой request к «старту» и вызывал `supersede_startup_media_apply`, который Open не отменяет. Исправлено отдельной веткой.
- **Остальные блокирующие вызовы (не трогались):**
  - пересборка после смены настроек (`settings_runtime_adapter.rs`) — **может висеть до таймаута предпросмотра**, кандидат на отдельную сессию;
  - `suspend_resume.rs`, `suspended_media_resume.rs`, `same_item_candidate_switch.rs` (lifecycle) и cancel-loop `cancel_rejected_media_open` ждут только ответа на отмену, это коротко.

## Открытые риски

- Пересборка после смены настроек по-прежнему может подвесить окно до 15 с.
- Open, нажатый, пока слот занят установкой плейлиста или старта, по-прежнему получает «занято» только после выбора файла (прежнее поведение).
