## Причина (root cause)

- В `local_file_open.rs` ошибка сразу превращалась в строку `format!("{error:#}")`. thiserror при этом печатает только верхний уровень, поэтому битый файл, PNG, пустой файл и папка давали одно и то же «не удалось открыть media container».
- `safe_local_open_label` возвращал константу «локальный media-файл».
- В coordinator-е поле `PreparationFailed.kind` существовало только в тестах (`#[cfg(test)]`), так что причина до строки плейлиста не доходила.
- Каталог на Linux «открывается»: ошибка всплывала только при чтении внутри demux probe, где `io::ErrorKind` уже потерян.

## Итоговая таблица текстов

Шаблон: «Не удалось открыть «clip.mkv»: …». Пока файл готовится: «Открываем «clip.mkv»…». Бейдж строки содержит ту же причину с заглавной буквы.

| Причина | Текст |
|---|---|
| нет файла (`NotFound`) | файл не найден |
| нет прав (`PermissionDenied`) | нет доступа к файлу |
| каталог | это папка, а не файл |
| 0 байт | файл пустой |
| `NoMatch`, `FactoryRejected::Rejected` (PNG, мусор) | формат файла не распознан или не поддерживается |
| `Truncated`, `Malformed`, `FactoryRejected::Backend` | файл повреждён или обрезан |
| `InputFailure`, прочие io | не удалось прочитать файл |
| `DeadlineExceeded`, `TimedOut` | файл читается слишком долго |
| нет дорожек | в файле нет ни видео, ни звука |
| файл изменился | файл изменился во время открытия, попробуйте ещё раз |
| сбой registry, `AmbiguousMatch`, `UnexpectedContainer` | внутренняя ошибка плеера |
| отмена | ничего не показываем |

Путь без имени (`/`, `..`) показывается как «(без имени)».

## Ручная приёмка (сценарий для владельца)

1. `fastiplayer /нет/такого/файла.mkv` → «Не удалось открыть «файла.mkv»: файл не найден».
2. Открыть (CLI или Open) папку → «…: это папка, а не файл».
3. Картинку, переименованную в `.mp4` → «…: формат файла не распознан или не поддерживается».
4. Пустой файл (`touch empty.mp4`) → «…: файл пустой».
5. Файл без прав (`chmod 000`) → «…: нет доступа к файлу».
6. Добавить в очередь файл, удалить его с диска, кликнуть по строке → бейдж «Файл не найден» на строке.
7. Открыть через Open файл при непустой очереди → диалог называет имя файла.

### Итог приёмки (4 октября 2026, агент по поручению владельца)

Как прогоняли: debug-бинарь, `XDG_CONFIG_HOME` во временном каталоге (конфиг, lock экземпляра и очередь владельца не тронуты), скриншоты `spectacle`.

|---|---|---|---|

| 2 | CLI, папка | «Не удалось открыть «folder-clip.mkv»: это папка, а не файл» | PASS |

| 6 | очередь `.m3u` [A, B], B удалён, `Next` через MPRIS (тот же путь ручной навигации, что и клик) | A продолжает играть; в лог дошло `PreparationFailed { kind: LocalOpen(FileNotFound) }` | PASS по логу и тестам, **бейдж визуально не снят** |

- **Почему бейдж не снят.** Панель плейлиста при старте закрыта. Инструментов ввода (ydotool/xdotool) в системе нет, а AT-SPI не видит окно: AccessKit не регистрируется, пока на рабочем столе выключена доступность. Включать её глобально не стали. Сам бейдж — существующий механизм `runtime_errors`, текст проверяет тест `transport_execution::tests::first_pre_barrier_failure_…`.
- **В первом прогоне сценария 2** в окне висел `SeekUnavailable: Seek невозможен: media pipeline ещё не открыт`. Это ввод (стрелка или media-клавиша) в окно, оказавшееся в фокусе на рабочем столе, к правке отношения не имеет: повторный прогон показал правильный текст. Текст ошибки на смеси языков уже есть в бэклоге README.

### Найдено и исправлено во время приёмки

1. **Имя файла попадало в лог.** `StartupMediaController::handle_preparation_failure` логировал текст для пользователя, в котором теперь есть имя.
   - Решение: обработчик разделён на `handle_preparation_failure` (лог + публикация, для URL-путей без изменений) и `publish_preparation_failure` (только UI и строка очереди).
   - Локальный старт идёт через `drain.rs::handle_local_preparation_failure` и пишет в лог только `reason`.
   - Заодно строка restored-элемента получает короткую причину («Файл не найден») вместо полного текста: этот риск закрыт.
2. **Повторы в техническом логе.** `diagnostic_chain()` дублировал ошибку ОС, потому что `Display` некоторых уровней уже включает `{source}`. Теперь звено, текст которого уже есть в цепочке, пропускается. Тест `diagnostic_chain_does_not_repeat_causes_already_in_display`.

## Открытые риски / вне объёма

- Бейдж строки при ручной навигации визуально не проверен (см. приёмку) — стоит глянуть при случае.

- Стартовый pending «Подготовка local media...» без имени файла.
- «worker недоступен» — сессия 03.
- Английский текст при пересборке после смены настроек (`settings_runtime_adapter`) — бэклог.
- Тест «в файле нет ни видео, ни звука» есть только на уровне классификации: синтетической фикстуры без дорожек нет.
- Прямой тест «CLI-drain и кнопка Open дают одинаковый текст» не написан: оба зовут одну функцию от одного типизированного результата, а сами потребители требуют `AppState` и renderer.
