## Статус

**PASS.** Ручной прогон 6 октября 2026 провёл агент по поручению владельца: настоящий GUI на рабочем столе, изолированный `XDG_CONFIG_HOME`, все 5 сценариев PASS. Коммит и push в `main` — по поручению владельца.

## Решения владельца (6 октября 2026)

1. **Где прогресс:** строка под тулбаром плейлиста «Получаем данные по ссылке (домен)… [Отменить]».
   - Область проблем она не занимает. Та закрывает каждую строку через 10 секунд, а yt-dlp может работать до 30.
   - Правило «в области под тулбаром только проблемы» сохраняется: строка рисуется на месте формы ввода URL.
2. **Причина отказа:** доработать `service-ytdlp`, чтобы путь получения списка видео (topology) различал причины так же, как открытие видео в сессии 08. Это выход за список разрешённых файлов, владелец его одобрил.
3. **Ссылка без `https://`:** только подсказка, сами схему не дописываем.

## Исследование (часть A)

- **Жизненный цикл:**
  1. toolbar публикует `SubmitUrl`;
  2. `submit_playlist_url_draft` вызывает `append_playlist_url`, тот вызывает `classify_startup_url`;
  3. для ссылок yt-dlp запускается `start_playlist_url_import`;
  4. latest-only worker `url_import` получает список видео;
  5. `drain_playlist_url_import_job` строит S08 preview, после «Продолжить» строки добавляются в очередь.
- **Где «идёт операция»:** только `latest_generation` внутри владельца импорта, наружу не видно. `PlaylistActiveOperation` нигде не рисуется: от него только кнопка «Сортировать» становится серой.
- **Отмена:** у владельца был `cancel_active()` (generation 0, процесс yt-dlp останавливается через `is_cancelled`). Его вызывали только при замене запроса новым (supersede), пользовательской отмены не было.
- **Где терялась причина:**
  - `url_import.rs` делал `.map_err(|_| ())`;
  - путь получения списка видео в `service-ytdlp` не читал stderr (`ExtractorRejection { stderr_bytes }` без причины);
  - отсутствие yt-dlp сливалось в `ProcessFailure`;
  - классификатор сессии 08 этот тип ошибки не знал.
- **Пробелы (п.5):** подтвердились, `trim` не было нигде.

## Архитектура (часть B)

- **`service-ytdlp`.**
  - `YtDlpTopologyError::ExecutableNotFound` (запуск вернул `NotFound`, как в single-item пути);
  - `ExtractorRejection { stderr_bytes, reason }`;
  - topology-reader stderr переиспользует `StderrRejectionClassifier` из сессии 08 и возвращает `StderrObservation`. Текст stderr по-прежнему не хранится.
- **`media-source-open`.**
  - `classify_yt_dlp_topology_error(&YtDlpTopologyError) -> Option<WebOpenFailureReason>`: отмена даёт `None`;
  - то же звено добавлено в цепочку `classify_web_open_failure`;
  - новая причина `CollectionTooLarge`: в подборке больше 2000 записей, лимит сервиса. Без неё пользователь видел бы ложное «обновите yt-dlp».
- **`app-egui/playlist_runtime/url_import`** (владелец импорта).
  - `PlaylistUrlImportFailure { Rejected(reason), Cancelled, Internal }` вместо `()`. Отказ показывается, отмена молчит, panic и poisoned state — внутренний сбой, а не «сайт отказал».
  - `active_request { generation, display_host }` заменил `latest_generation`.
  - read-only `progress()` и intent-метод `cancel_playlist_url_import_by_user() -> PlaylistUrlImportCancelOutcome { Cancelled, NothingActive }`.
  - Лог: `warn` с причиной и безопасным Display ошибки сервиса.
- **Тексты** (`web_open_message.rs`):
  - «Не удалось добавить ссылку (домен): <фраза из таблицы 08>»;
  - внутренний сбой: «Не удалось добавить ссылку (домен) — попробуйте ещё раз»;
  - `CollectionTooLarge`: «в подборке слишком много видео, чтобы добавить её целиком».
- **UI.**
  - `PlaylistInteractionModel.url_import_progress`;
  - `ui/playlist/toolbar/url_import_progress.rs` — статичная строка, без `egui::Spinner`: по Context7 спиннер просит перерисовку каждый кадр, и окно крутилось бы до 30 с;
  - `PlaylistAction::CancelUrlImport`.
  - Индикатор — отдельное поле, а не новый вариант `PlaylistActiveOperation`. Тот один на все операции, и через него серая Sort: импорт ссылки не должен блокировать сортировку и вытеснять другие операции.
- **Ввод.**
  - `trim()` в одном месте — начало `append_playlist_url`, единой границы ввода URL в очередь;
  - `NotUrl(NotUrlInputHint::{MissingScheme, Unrecognized})`. Подсказка появляется, только если `https://` + текст даёт поддерживаемую ссылку с доменом через точку;
  - тексты формы вынесены из `ui_interaction.rs` (legacy 848 → 831) в `url_draft_message.rs`.

**Не менялось:** latest-only модель и generation fence, таймауты yt-dlp, отмена открытия элемента плейлиста, разбор нескольких URL в строке.

## Тесты (что ловят)

- **Настоящий `PlaylistRuntime` + управляемый fake вместо процесса yt-dlp** (`url_import/tests/progress.rs`):
  - индикатор с доменом виден до результата, потом исчезает, строки вставлены;
  - «Отменить»: worker увидел отмену, индикатор исчез, поздний результат не доставлен, очередь и плеер не тронуты, ошибки нет, повтор → `NothingActive`;
  - отмена без активного импорта не трогает черновик URL;
  - шесть причин → шесть разных текстов с доменом, без пути и токена;
  - panic resolver-а → внутренний текст;
  - второй URL заменяет первый, индикатор один;
  - «  https://…?id=7 \n» → тот же locator;
  - «youtube.com/watch?v=…» и «  www.youtube.com/…» → подсказка, «привет» и «hello» → общий текст;
  - лог: причина и код `private-media` записаны, отмена как отказ не логируется.
- **Настоящий egui-кадр:** текст индикатора с доменом и без; клик по «Отменить» (координаты из дерева доступности) → `CancelUrlImport`.
- **Настоящий процесс:**
  - скрипт печатает `ERROR: … Private video … token=very-secret` → `PrivateMedia`, токена нет в Debug;
  - несуществующая программа → `ExecutableNotFound`;
  - настоящий adapter через `PathOverrideLauncher`: пустой PATH → `ExtractorNotInstalled`, подставной yt-dlp → `SitePrivateMedia`.

## Ручная приёмка (сценарий для владельца)

Запуск: `cargo run -p app-egui --release`, открыть панель плейлиста, кнопка «Добавить URL».

1. **Плейлист YouTube:** ссылка `https://www.youtube.com/playlist?list=…` → «Добавить». Сразу видна строка «Получаем данные по ссылке (youtube.com)… [Отменить]», затем окно импорта, «Продолжить» → строки в очереди, строка прогресса исчезла.
2. **Отмена:** та же ссылка → «Добавить» → сразу «Отменить». Строка исчезает, очередь не меняется, сообщения об ошибке нет.
3. **Приватное видео:** `https://www.youtube.com/watch?v=yZIXLfi8CZQ` → «Не удалось добавить ссылку (youtube.com): видео приватное». Если YouTube потребует вход, будет «…: сайт требует войти в аккаунт…» — это тоже корректно.
4. **Без https:** `youtube.com/watch?v=dQw4w9WgXcQ` → подсказка под полем «Похоже, в начале ссылки не хватает https:// …».
5. **Пробелы:** вставить ссылку с пробелом и переводом строки в конце → добавляется как обычно.

## Открытые риски / вне объёма

- Метки yt-dlp могут измениться в новой версии → общая фраза «сайт не отдал видео…».
- Флак `zenity_disables_markup…` (сессия 06, ETXTBSY) — отдельная задача.
- Poisoned state владельца импорта сообщает о сбое на каждом `drain` (старое поведение, не менялось).
- Строка прогресса не обновляет процент: yt-dlp не сообщает прогресс получения списка.
