# Результат сессии 12: drag & drop файлов, папок, плейлистов и ссылок

## Статус

**PASS.** Ручную приёмку по поручению владельца провёл агент 7 октября 2026: реальный GUI на KDE Plasma 6.7 (Wayland и X11/XWayland), виртуальная мышь через `/dev/uinput`, отдельный Qt-источник перетаскивания (тот же Wayland data-device механизм, что у Dolphin; сам Dolphin проверен на примере патча winit), изолированный профиль с копией config владельца. Коммит в `main`, push не делали. Два найденных при приёмке старых бага чинятся следующими отдельными коммитами (см. «Открытые риски»).

## Решения владельца

Полный список — в [`../12-drag-and-drop.md`](../12-drag-and-drop.md), разделы «Решения владельца» 1–11. Кратко:
1. Wayland — локальный патч winit 0.30, который выбрасывается при стабильном winit 0.31 (переписывается один файл-переходник); Windows обслуживается тем же переходником.
2. Ссылки входят в объём (раньше бэклог).
3. Место броска решает: панель → в конец, видео → новая очередь (с подтверждением непустой очереди).
4. Папки — рекурсивно; лимиты в `config.toml` и окне настроек.
5. Плейлист-файл — настройка «по месту» (по умолчанию) / «всегда новый» / «всегда добавить», всегда с предпросмотром.
6. Смесь с плейлистом/ссылками → они пропускаются с уведомлением; бросок во время открытия → «Файл ещё открывается».
7. Выполнение последовательными субагентами, основной агент — архитектура и финальная проверка.
8. Папка на видео: сначала обход, потом подтверждение с числом файлов (осознанное исключение из S14A, до Confirm — только чтение списка файлов).
9. Ссылка-коллекция на видео раскрывается (как Add URL), затем «заменить очередь на N роликов».
10. Бросок на панель сохраняет порядок броска/обхода (кнопка «Добавить файлы» сортирует как раньше).
11. Старые баги, найденные приёмкой, чинятся в этой же сессии отдельными коммитами.

## Что сделано (владельцы и границы)

- **`crates/winit-patch`** — точная копия winit 0.30.13 (sha256 сверен) + additive API `winit::platform::external_drag` и `ApplicationHandler::external_drag_event`. Wayland: data device per seat, только copy, неблокирующее чтение. X11: точка броска, не-file URI, текст. Публичные `Event`/`WindowEvent` не менялись, egui-winit не тронут. Inventory `docs/dependency-patches.toml`, CI-матрица, `scripts/check-dependency-patches.py` (8 патчей).
- **`app-egui::external_open`** — конвейер «событие → жест → цель (hit-test панели) → URI → классификация → шаги → диспетчер» через trait `ExternalOpenHost`; единственный winit-aware файл `winit_source.rs`. Подсветка `ui/external_drop_overlay.rs`.
- Новые границы у владельцев: `QueueReplacementTarget::LocalFiles` + `PlaylistRuntime::replace_queue_with_local_files`; `start_playlist_import_path`; фоновый обход `DroppedCollectionWalkOwner`; `PlaylistUrlImportDestination::ReplaceAfterConfirmation`; `ManualAddOrder::PreserveGiven`.
- **`playlist-discovery::folder_walk`** — бюджетированный рекурсивный обход; **config v12** — три поля + миграция + валидация (`validation/playlist_drop.rs`).
- Попутно найдено и исправлено (с тестами, падающими без исправления): коммит импорта плейлиста не публиковал снимок очереди в persistence (`commit_staged_playlist_import`) — импорт мог потеряться при выходе.

Изменено ~70 отслеживаемых файлов (+990/−148) плюс новые модули и `crates/winit-patch`.

## Открытые риски

- **Старые баги, найденные приёмкой (чинятся отдельными коммитами в этой сессии):** ползунок настроек сам меняет значение при отрисовке (2000→2001, 30000→31000, 250→251) и Apply пишет это в config; строки YouTube-плейлиста запускаются по URL всего плейлиста и падают по таймауту 30 с.
- Предпросмотр URL-импорта однажды исчез без действий пользователя; по коду автопереход импорт не отменяет, целенаправленно не воспроизвелся (два автоперехода подряд — предпросмотр на месте).
- Windows/macOS: только файлы, без точки броска (бросок всегда «на видео») — до winit 0.31.
- Файлы у лимита размера: `validation.rs` 799, `startup_media.rs` 792, `state.rs` 796.
