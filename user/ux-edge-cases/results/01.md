# Результат сессии 01: клавиатура — фокус и Esc

## Статус

**PASS.** Ручная приёмка владельцем пройдена 4 октября 2026, закоммичено в `main`.

## Решения владельца (4 октября 2026)

1. **Esc — вариант A.** Esc закрывает то, что сверху: popup/меню → подтверждение замены очереди → preview импорта → выход из фуллскрина → ничего. Приложение по Esc больше не закрывается.
2. **Фокус — вариант 1.**
   - Кнопки play/prev/next/сброс скорости после клика мышью не держат клавиатуру.
   - При фокусе на кнопке или строке плейлиста работают F/M/J/L/P/N, а пробел, стрелки и Esc остаются виджету.
   - Текстовые поля глушат всё, кроме media keys.
   - Цена: `+ / - / 0` работают при наведении на play или при Tab-фокусе, но уже не после «кликнул и убрал мышь».
3. **Настройки по Esc не закрываются**, чтобы не терять несохранённые правки.

## Причина бага (root cause)

- В egui 0.36 `egui_wants_keyboard_input()` = `memory.focused().is_some()`, то есть фокус у **любого** виджета. Флаг `consumed` из egui-winit для клавиш вычисляется так же.
- Кнопки делали `request_focus()` при клике, поэтому после клика все хоткеи, кроме media keys, подавлялись.
- Esc классифицировался как `Close` и закрывал приложение на winit-событии, ещё до того, как egui успевал закрыть popup.

## Ручная приёмка (владелец)

1. Кликнуть по play → F: включился фуллскрин.
2. Esc: вышли из фуллскрина, плеер жив.
3. → (стрелка вправо): перемотка.
4. Кликнуть в поле URL, напечатать «f» и пробел: печатается текст, хоткеи не срабатывают.

Дополнительно:
5. Клик по play, затем пробел: одна пауза (не пауза+play).
6. Tab до кнопки play, затем пробел: одно переключение.
7. Открыть файл при непустой очереди → в диалоге «заменить очередь?» нажать Esc: диалог закрылся, очередь не тронута.
8. Esc в оконном режиме без диалогов: ничего не происходит.
9. Открыть меню импорта/экспорта → Esc: меню закрылось, плеер жив.

Итог ручной приёмки: **PASS** (владелец, 4 октября 2026).

## Открытые риски и ограничения

- Если фокус у виджета (например, строка плейлиста или кнопка, выбранная Tab), первый Esc только снимает фокус или выделение (это делает egui). Диалог или фуллскрин закроет второй Esc.
- Редактор URL закрывается по Esc, только когда его поле в фокусе (существующий обработчик). Открытый, но несфокусированный редактор Esc не трогает.
- Мёртвая ветка `KeyCode::Space` в `AppState::handle_hotkeys` не тронута (вне объёма сессии).
