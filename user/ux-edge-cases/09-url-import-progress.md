## Предыстория (факты аудита, сверить с кодом)

1. Добавление URL страницы (YouTube-подобной) запускает topology extraction, возвращает `ResolvingTopology`, редактор сразу закрывается (`ui_interaction.rs:~605` `finish_success()`).
2. `PlaylistActiveOperation` знает только `MetadataSort`, `ManualAdd`, `SiblingDiscovery` (`ui_interaction.rs:379`) → для URL-импорта нет индикатора. До 30 с (`resolve_timeout_ms` по умолчанию 30000, `config/src/schema/services.rs:~397`) плейлист выглядит неизменным.
3. Ошибка выбрасывается: `url_import.rs:73,75` `.map_err(|_| ())` — даже без лога; затем общий текст «Не удалось получить структуру media URL» (`url_import.rs:~333`).
4. Отменить можно только отправкой другого URL (latest-only supersede — работает, тесты есть).
5. Пробелы вокруг URL не обрезаются (`parse_yt_dlp_media_locator` хранит строку как есть) — подозрение, проверить.
6. `NotUrl` (нет «://», включая голое `youtube.com/…`) → «Введите корректный http(s) URL» — можно подсказать «добавьте https://».

## Тесты
- добавление page URL → видна активная операция до результата; по результату — строки вставлены, индикатор исчез;
- «Отменить» → worker отменён (fake), строки не вставлены, индикатор исчез, без ошибки;
- fake topology возвращает каждую причину → свой текст, ошибка залогирована;
- « https://x/y \n» → тот же locator, что и «https://x/y»;
- «youtube.com/watch?v=…» → подсказка про https://;
- latest-only: второй URL заменяет первый, индикатор один (регрессия).
