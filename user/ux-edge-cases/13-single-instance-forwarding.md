## Решения владельца (8 октября 2026)

1. **Канал — нейтральный контракт + D-Bus.** Логика, проверки и тесты живут в общем коде без привязки к ОС. На Linux транспорт — стандартный `org.freedesktop.Application` (`Open`/`Activate`) на session bus с явной проверкой uid отправителя. Windows/macOS позже добавляют только свой транспорт: на macOS систему открытия файлов доставляет сама ОС, на Windows нужны named pipes. Свой Unix-сокет отклонён: больше своего кода безопасности и нет интеграции с KDE.
2. **ID приложения — `io.github.Bogdan7c.Fastiplayer`** (имя на D-Bus, в будущем имя `.desktop`-файла и Flatpak).
3. **Окно на Wayland поднимается по-настоящему:** additive-дополнение локального патча winit 0.30 (как в сессии 12). Первый экземпляр предъявляет билет активации второго (`XDG_ACTIVATION_TOKEN` → `platform_data["activation-token"]`). Без билета — мигание в панели задач. На X11 — штатный `focus_window`.
4. **Несколько файлов в CLI — в этой сессии**, и при первом запуске, и при пересылке, по правилам drag & drop (сессия 12). Выполняет отдельный субагент (Opus 5.5, effort medium).
5. Поведение при пересылке — как «бросок на видео» (сессия 12): непустая очередь → подтверждение замены, окно поднимается.

## Задание

### Часть A. Исследование
Варианты, простыми словами + безопасность:
- (A) Unix-сокет в `$XDG_RUNTIME_DIR` (0700 каталог, проверка `SO_PEERCRED` uid), простой бинарный/JSON протокол с лимитом размера;
- (B) D-Bus session bus: свой интерфейс или `org.freedesktop.Application` (`Open(uris)`, `Activate`) + `DBusActivatable` в `.desktop`;
- (C) MPRIS `OpenUri` (если MPRIS уже есть) — только одна ссылка за раз.
Для каждого: зависимости, гонка «первый ещё стартует», поведение при зависшем первом экземпляре (таймаут → понятная ошибка, см. сессию 06), поднятие окна на Wayland/KDE (activation token из `XDG_ACTIVATION_TOKEN`).
Также: нужно ли разрешить несколько файлов в CLI (`fastiplayer a.mkv b.mkv` → очередь) — это меняет CLI-грамматику, отдельный вопрос владельцу.

### Стоп: согласование с владельцем
Выбор варианта (рекомендация — B, `org.freedesktop.Application`, если D-Bus уже в зависимостях; иначе A), поведение: «заменить очередь с подтверждением» как у drag & drop; поднимать окно — да.

### Часть B. Реализация
- Отправитель: при `AlreadyRunning` с media-аргументом → отправить запрос, дождаться подтверждения (таймаут), выйти с 0; без аргумента → только поднять окно.
- Получатель: запрос валидируется (размер, uid, только пути/URL), превращается в намерение сессии 12 и исполняется на UI-потоке после wake.
- Ошибки IPC типизированы и логируются; запрос от чужого uid — отклонён.

## Тесты
- два экземпляра в тесте (fake/реальный сокет во временном runtime dir): второй с файлом → первый получил намерение с тем же `PathBuf`, второй вышел с 0;
- без аргумента → первый получил «активировать», путей нет;
- первый не отвечает → второй выходит с понятной ошибкой по таймауту;
- слишком большой / мусорный запрос → отклонён, первый жив;
- (A) чужой uid → отклонён (если тестируемо, иначе юнит-проверка политики).
