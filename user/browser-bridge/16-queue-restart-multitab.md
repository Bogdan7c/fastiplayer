# Сессия 16: очередь после перезапуска, свежий поток, много вкладок (веха M3)

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 16 плана `user/browser-bridge/`: строки очереди из браузера переживают перезапуск плеера (хранится только ссылка страницы и адаптерный ID варианта); при открытии такой строки плеер просит у экстеншена свежий поток, а если браузер закрыт — пробует yt-dlp. Восстановление посреди просмотра при просроченном потоке, предзагрузка следующей серии, много вкладок и окон браузера. Затем веха M3. Сначала прочитай `user/browser-bridge/README.md`, `results/04.md`, `results/14.md`, `results/15.md`.

## Зачем

Решения 16 и 29: очередь — «ахуевшая веселуха» (слова владельца). Потоки браузера живут минуты, очередь — дни.

## Что сделать

1. **Долгоживущая строка:** `DurableReopenLocator` нового вида «страница браузера» (ссылка страницы + ID адаптера и варианта, без секретов). Публичная форма для экспорта плейлиста — ссылка страницы. Политика подтверждения для ссылок с query — как сейчас (`mem:media-services/secret-safe-locators-s10b`).
2. **Свежий материал:** при открытии строки (и при предзагрузке следующей) плеер шлёт `FreshMaterial`-запрос через мост. Ответа нет за N с или нет экстеншена → гибрид: yt-dlp по ссылке страницы. Никаких «вечных» ожиданий: Stop и Next отменяют запрос (правила UX18 / D3).
3. **Восстановление посреди просмотра:** поток истёк (403 после `Installed`) → `WebMediaRecoveryStrategy`: свежий материал от экстеншена на той же секунде. Нет экстеншена → yt-dlp. Ничего не вышло → понятная ошибка.
4. **Много вкладок и окон:** запрос свежего материала адресуется вкладке, если она жива, иначе любой вкладке профиля, где установлен экстеншен, иначе фоновая вкладка (по решению из 14). Два профиля браузера и два браузера одновременно → чей экстеншен ответил, тот и отдаёт. Поведение записать.
5. **Инкогнито-строки** после закрытия плеера не сохраняются (04) — проверить вместе с перезапуском.

## Тесты

- Стенд: очередь из 3 серий → выход из плеера → запуск → строка 2 открывается свежим потоком от экстеншена, **кадр в рендере**; браузер закрыт → yt-dlp-заглушка; ничего не работает → понятный бейдж строки и пропуск по `playlist.error_behavior`.
- Истечение ссылки на стенде посреди просмотра → продолжение на той же секунде ± 1 с.
- Stop во время ожидания свежего материала → тишина, без отложенного старта.
- **Поколения:** ответ свежего материала приходит после Next → отброшен (`Superseded`), не попал в следующую строку; два ответа на один запрос (две вкладки ответили) → используется один.
- Сон и пробуждение машины во время ожидания свежего материала и посреди просмотра (токены протухли) → восстановление, а не зависание.
