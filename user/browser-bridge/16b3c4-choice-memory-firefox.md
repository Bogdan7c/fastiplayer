# Сессия 16b3c4: память выбора в Firefox на полном прогоне

Отделена решением 392 (16b3c3). Идёт до [16b4](16b4-feed-live-acceptance.md). Задача 4 из [16b3c3](16b3c3-hls-start-seek-hang.md): там починили только зависание HLS.

> Выполни сессию 16b3c4 плана `user/browser-bridge/`: выведи заметки фона экстеншена в журнал стенда, найди, почему `series-memory-restart` в Firefox красная в полном прогоне, и принеси владельцу решение. Сначала прочитай `user/browser-bridge/README.md`, этот файл, `results/16b3c2.md` (раздел о `series-memory-restart`) и `results/16b3c3.md`.

## Что известно

- В обоих полных прогонах 16b3c2 строка `series-memory-restart` в Firefox красная: «the memory holds 0 series». Страница сменила озвучку, но экстеншен её не записал. Отдельно и рядом с нагрузкой строка проходит (68–78 с). В 16b3c3 одиночный прогон тоже прошёл (77,6 с).
- Экстеншен запоминает смену на странице только при условиях `extensions/browser/src/background/choice-memory/session-choice-memory.ts` (решения 284, 15a):
  - в последние 2 с не было его собственной команды выбора;
  - фильм серии уже на экране (`filmOnScreen`);
  - на экране не реклама;
  - выбор страницы не «автоматический».
- Каждое такое условие пишет заметку (`note(...)`): например «page switched audio before the episode's film was on screen: not remembered». Заметки идут в `console.debug("[fastiplayer] …")` фона (`background/handoff/browser-wiring.ts`).
- **Консоль фона в Firefox до журнала доходит, но журнал затирается (проверено в 16b3c3).**
  - Firefox стенда дублирует консоль в `<work>/firefox.stderr.log` (`devtools.console.stdout.content`/`chrome`). Заметка фона `variant-mirror.ts` («variant adapter … describes the page») там есть.
  - Строка `series-memory-restart` перезапускает браузер. Стенд открывает журнал заново через `File::create` (`browsers/support.rs::spawn_browser`) по тому же пути (`browsers.rs::stderr_log_path`) и затирает первый запуск — тот, где память записывает выбор.
  - Заметок памяти нет и после перезапуска (ожидалась «choice memory found remembered choices»). Это не объяснено.
  - У Chromium стенд консоль служебного воркера не слушает вовсе.

## Что сделать

1. **Канал заметок фона в журнал стенда.**
   - Firefox: журнал перезапуска не затирает первый (дописывание или журнал на каждый запуск). Тест стенда: после перезапуска заметки первого запуска на месте.
   - Понять, почему заметок памяти нет и после перезапуска.
   - Chromium: подписка стенда на консоль воркера через CDP.
   - Тестовый канал в экстеншене — только если иначе нельзя; это решение владельца.
2. **Поймать.** Полный прогон частями (22 мин, называется владельцу заранее) или та же точка расписания. Увидеть, какое условие не выполнилось.
3. **Решение владельца.** Если строка выбирает раньше, чем экстеншен признаёт выбор человеком, это вопрос продукта на сериальных сайтах, а не только стенда.

## Тесты

- Канал заметок проверен тестом стенда: заметка фона доходит до журнала части.
- Стенд: `series-memory` в обоих браузерах; полный прогон — без `series-memory-restart` среди провалов (критерий выхода 16b3c3, решение 390).

- Memories: `mem:browser-bridge/core` (раздел 16b3c4).
