# Сессия 03c: источник — `<video src>` и «буфер доигран»

Общий замысел — [03-browser-byte-source.md](03-browser-byte-source.md).

> Выполни сессию 03c плана `user/browser-bridge/`: проигрывание `<video src=mp4>` по запросам байтов и событие «буфер доигран». Сначала прочитай `user/browser-bridge/README.md`, `results/03b.md`, этот файл.

## Что сделать

1. **`<video src>`** (MDN, archive.org, клипы Twitch): файл качает background экстеншена с `Range` по запросу плеера (решение 83, протокол 01: `fetch_range`, рамка вида 2, `range_fetch_finished`).
   - Плеер видит такой файл как обычный источник с перемоткой: чтение позиции X — запрос `fetch_range` и ожидание рамок.
   - Рамки вида 2 сервер не проверяет (02): источник сам сверяет `request_id`, смещение и длину с выданными запросами, чужое — `stream_rejected`.
   - Запросы не больше 16 МиБ, кэш ограничен.
2. **«Буфер доигран»** (решение 42): после `tab_gone` источник доигрывает полученное и сообщает «доиграно». Машине `ProcessLifecycle` нужно ждать этого события, а не выходить сразу.

## Тесты

- Файл MP4 через запросы байтов → кадр до показа; перемотка — новый запрос с нужного смещения.
- Чужой `request_id`, смещение мимо запроса, лишние байты → отказ.
- `tab_gone` посреди фильма → полученное доигрывается, потом событие «доиграно».
