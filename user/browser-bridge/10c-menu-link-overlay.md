# Сессия 10c: правый клик, ссылка, кнопка поверх видео, настройки входов

Добавлена 5 ноября 2026 при разделении сессии 10 (решение 213).

> Выполни сессию 10c плана `user/browser-bridge/`: правый клик по видео, правый клик по ссылке через фоновую вкладку (решение 45), кнопка поверх видео (выключена по умолчанию, решение 53), плашка на странице с итогом (решение 211), настройка набора входов. Сначала прочитай `user/browser-bridge/README.md`, `10-mode1-entry-points.md`, `results/10b.md`.

## Зачем

Решения 7, 45, 53, 211. Остальные входы режима 1 на готовой команде 10b.

## Что сделать

1. **Меню на `<video>`.** Браузер сообщает фрейм, но не элемент. Скрипт страницы запоминает элемент последнего правого клика, фон передаёт именно его через выбранное видео 10b. Меню создаётся по `runtime.onInstalled`.
2. **Сайт забрал правый клик** (свои меню, как у YouTube): пункт на странице вокруг видео отдаёт главное видео вкладки.
3. **Ссылка (решение 45):** фоновая вкладка → ждём видео (сайт запускает сам, адаптеры появятся в 14) → передача.
   - Срок ожидания — настройка в константах модуля. Истёк — понятное сообщение, фоновая вкладка закрывается.
   - Вкладка закрывается вместе с сеансом: крючок `onSessionEnded` в `tab-handoffs.ts`. Отказы до сеанса этот крючок не зовут, их закрывает сам вход.
   - Закрывается только вкладка, которую открыл вход. Обычная вкладка с сеансом не закрывается никогда.
4. **Кнопка поверх видео:** Shadow DOM, свой слой, появляется при наведении, не ломает вёрстку. Выключена по умолчанию (решение 53).
5. **Плашка на странице (решение 211):** «Opened in Fastiplayer» или причина отказа, изолирована от сайта. Плюс «!» на значке. На страницах браузера плашки нет, остаётся значок и текст в попапе.
6. **Настройки:** какие входы включены. Выключенный вход исчезает сразу, без перезапуска браузера.
7. **Права:** новых не требуется. `manifest/PERMISSIONS.md` обновить под пункт на ссылке.

## Тесты

- `node:test`: выбор элемента правого клика, закрытие только своей вкладки, срок ожидания, настройка входов.
- Стенд, настоящая мышь (решение 212), Chromium и Firefox:
  - правый клик по видео × `mse-fmp4`, `mse-webm`, `video-src`, `iframe-cross-origin`, `shadow-dom` → кадр в рендере;
  - на странице два видео → в плеере то, по которому кликнули;
  - страница, забирающая правый клик → пункт вокруг видео;
  - новая страница со ссылкой → фоновая вкладка → кадр в рендере, закрытие плеера закрывает вкладку;
  - ссылка без видео → сообщение, вкладка закрыта;
  - кнопка поверх видео выключена по умолчанию, включена → кадр в рендере, вёрстка страницы не сдвинулась;
  - выключенный в настройках вход не показывается.

## Поправки по итогам 10b (6.11.2026, решения 214–215)

- **Команда готова:** `hand_off_tab` принимает `video` (`VideoRef`), устаревшая ссылка даёт `video_gone`. Меню на `<video>` передаёт элемент этой же ссылкой. Выбранное человеком видео всегда роль `film`.
- **Живой сеанс на вкладке:** другое видео заменяет текущее в том же окне (решение 215), `replaceSession` в `tab-handoffs.ts`. Если человек выбрал то же видео, ответ `started` без новых сеансов.
- **Отказ при закрытом попапе** пока показать некому: плашка закрывает этот пробел (решение 211).
- **Стенд:** новый вход — вариант перечисления `Entry` в `scenarios/entries.rs` и его нажатие в `entries/robot.rs`. Мышь `Mouse::{move_to, click_at}`, клавиши `Keyboard::press`, снимок попапа `popup_snapshot`, браузер вперёд `CompositorWindows::bring_browser_forward`. Экран `DesktopSetup::pointer_stand()` 1920×1200.
- **Панели браузера двигаются:** координаты брать только после `find_settled_extension_icon`.
- Фокус в попапе Firefox на один Tab дальше, чем в Chromium: первый Tab отдаётся документу.

## Поправки по живой проверке 10b (6.11.2026, решение 216)

- **Окно плеера уже открыто — попап не закрывается.** Сегодня удача закрывает попап всегда, а зритель остаётся на странице и не видит, что видео сменилось. Попап остаётся и говорит примерно так: «Now playing in the Fastiplayer window. Switch to it to watch.» Точный текст в `outcome-text.ts`.
- **Как понять, что окно уже было.** Фон должен сказать попапу, новое это окно или замена: сейчас исход один, `started`. Плеер это знает (`grant=ReplacedPrevious`). Проверить оба случая: другое видео той же вкладки и видео другой вкладки при открытом окне.
- **Новое окно ведёт себя как раньше:** забрало фокус, попап закрылся сам.
- **Остальные входы** (меню, ссылка, кнопка поверх видео) попапа не имеют: при открытом окне то же самое говорит плашка.
- **Тесты.** `node:test`: текст и шаг попапа «замена, не закрываемся». Стенд: `choice_row` ждёт, что попап остался и показывает этот текст. Активное окно после замены робот читает через `active_window_class`, чтобы случай был закреплён, а не предположен.
