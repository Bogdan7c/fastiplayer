# Сессия 15a2: субтитры YouTube в меню CC

Часть сессии 15 ([общий замысел](15-reference-site-adapters.md)), решения 20, 54, 271, 276, 283, 287, 292, 293. Зависит от 15a, идёт до 15b.

> Выполни сессию 15a2 плана `user/browser-bridge/`: адаптер YouTube показывает в нашем меню CC список субтитров ролика и автоперевод на все языки (решения 292, 293). Выбор зрителя просит YouTube включить язык, YouTube скачивает сам, мост ловит документ, как в 13b. Живая проверка на невидимом экране, в конце — проверка владельцем вместе с 15a (решение 291). Сначала прочитай `user/browser-bridge/README.md`, этот файл, `results/15a.md`, `results/13b2.md`, `results/14a.md`.

## Почему это отдельная часть

План 15 требовал субтитры YouTube, 15a их пропустила. Владелец увидел: у окна на YouTube нет кнопки CC. Причина — решение 20: мост показывает только субтитры, которые страница уже скачала. YouTube качает их только при включённом CC на своей странице. У плеера без единой дорожки кнопки CC нет.

## Разведка (10 ноября 2026, невидимый Chromium, настоящие ролики)

- **Список.** Ответ плеера `getPlayerResponse().captions.playerCaptionsTracklistRenderer`:
  - `captionTracks` — `languageCode`, `kind` (`asr` у автосубтитров), `vssId` (`.en`, `a.en`), `name`, `isTranslatable`. У проверенных роликов 18–26 дорожек;
  - `translationLanguages` — 156 языков автоперевода.
  - Список из ответа есть и во время рекламы. `getOption("captions","tracklist")` в рекламе пуст.
- **Выбор.** `setOption("captions","track", {languageCode, vss_id, kind})` включает язык. Это работает и при выключенных на старте субтитрах (`isSubtitlesOn` становится `true`). YouTube сразу скачивает `json3` со своим защитным токеном `pot`. Перевод — та же команда с `translationLanguage: {languageCode}`, YouTube качает с `tlang`. Пустой объект выключает субтитры. В рекламе команда не действует.
- **Повторный выбор.** en → de → en: YouTube качает документ заново при каждой смене. Склад 13b при одинаковом содержимом даёт тот же номер дорожки и отправляет её плееру заменой. Значит, правило «последняя скачанная — включена» (271) работает и для повторного выбора, связка «пункт ↔ дорожка» не нужна, протокол не меняется.
- **Текущий выбор.** `getOption("captions","track")` → `vss_id` и `translationLanguage.languageCode`. Без субтитров — пустой объект.
- **Ограничение стенда.** В безоконном Chromium YouTube отвечает на timedtext пустым телом (200, длина 0), даже на свои загрузки. Настоящий текст доказывают стенд с экстеншеном (в 13b2 он получил json3 с репликами) и проверка владельцем.

## Архитектура

**Протокол не меняется.** `variant_menu_changed` с видом `subtitles` и `select_variant` есть с 1.0. Плеер сейчас пропускает меню субтитров со счётчиком.

**Экстеншен:**
- Контракт вариантов получает третий вид `subtitles` и поле описания `subtitles`. У адаптеров без субтитров оно пустое. Проверка кадра (`shared/variant-watch-validation.ts`), зеркало меню и отказ «subtitles are page tracks» обновляются.
- Память выбора не записывает и не ставит субтитры как варианты. Субтитры памяти идут прежним путём 14b2 (`subtitle_choice` → `subtitle_preference` по языку и подписи).
- Рука YouTube:
  - описание плеера отдаёт дорожки, языки перевода и текущий выбор;
  - новое действие `select_captions` вызывает `setOption`;
  - пункт меню: сначала родные дорожки ролика, потом переводы; всё вместе не больше 256.
- **Подписи — одна функция на две стороны:** английские названия языков, «(auto-generated)», «(auto-translated)». Её используют пункты меню и именование скачанного документа timedtext 13b, чтобы память находила язык по подписи. Сейчас документ с `tlang` подписан как обычная дорожка — исправить. Две родные дорожки одного языка различаются названием YouTube в скобках.
- **Перевод** идёт с той дорожки, которая сейчас выбрана на странице, если её можно переводить. Иначе — с первой ручной переводимой, иначе — с первой переводимой.

**Плеер:**
- Полка вариантов хранит меню субтитров.
- Меню CC показывает строки страницы: отметка — выбор страницы при включённых у нас субтитрах. Скачанные страницей документы (`page_download`) при меню страницы в списке не дублируются. Кнопка CC видна, если есть строки.
- **Выбор строки:**
  - уходит странице как `select_variant`, без возврата секунды и без смены поколения;
  - в рекламе отклоняется;
  - ставит «жду документ этой строки»: следующая пришедшая страницей включённая дорожка становится выбором зрителя, субтитры включаются, выбор уходит в память (`subtitle_choice`).
- V ходит по родным строкам. C, как раньше, включает и выключает показ.
- `state/subtitles.rs` уже 727 строк: новое — в новые модули.

**Отложено:** память ставит запомненный язык на свежей вкладке, если его не скачал сам YouTube. Сначала вживую смотрим, не делает ли это «липкая» настройка CC YouTube, как с языком озвучки. Подменю «Auto-translate» для переводов вместо одного длинного списка — к полировке интерфейса.

## Что сделать

1. Экстеншен: контракт, рука и адаптер YouTube, общая функция подписей, именование timedtext, зеркало, память. Тесты через настоящие клиент и исполнитель руки.
2. Плеер: полка, меню CC, выбор строки, «жду документ», V. Тесты: строка в меню → `select_variant` → пришедший документ рисуется (пиксели слоя субтитров).
3. Живьём, невидимый стол, Firefox и Chromium: ролик с выключенными субтитрами → меню CC с языками → выбор → реплики на кадрах → перевод → второй язык. Проба страницы считает загрузки timedtext.
4. Проверка владельцем вместе с 15a.

## Критерий выхода

`results/15a2.md`; строка субтитров YouTube в таблице совместимости 15b. Memories: `mem:browser-bridge/core`, при изменении плеера — `mem:app-egui/*` по субтитрам.
