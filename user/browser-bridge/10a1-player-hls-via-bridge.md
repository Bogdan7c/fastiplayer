# Сессия 10a1: HLS — плеер и протокол

Добавлена 7 ноября 2026 в начале сессии 10a (решения 228–230). Общий замысел — [10a](10a-native-hls-in-src.md).

> Выполни сессию 10a1 плана `user/browser-bridge/`. Научи плеер играть нативный HLS через мост: готовый HLS-движок плеера читает плейлист и просит каждый ресурс у экстеншена по номерку, протокол 1.1 на обеих сторонах. VOD и live до кадра в рендере на тестах без браузера. Сначала прочитай `user/browser-bridge/README.md` (решения 37, 100–104, 228–230, инварианты 1, 2, 5, 6), этот файл, `results/03c.md`, `mem:browser-bridge/core`, `mem:media-services/native-hls-vod-n07-2026-09-01`, `mem:media-services/native-hls-live-n08-2026-09-01`, `mem:pushed-media-source/core`.

## Главный механизм (подтверждён владельцем, решение 228)

```
 страница: <video src=…m3u8>
      │ file_source → фон (10a2)
      ▼
 фон: hls_source_added{generation, root: №0} ──► плеер: HLS-поколение
                                                    │ движок web-media-hls
                                                    │ через «розетку» транспорта
 фон качает по номерку  ◄── fetch_resource{id, №N, диапазон?} ──┘
  с куками страницы,
  плейлист переписан ──► рамки вида 2 + resource_fetch_finished{id, итог}
  (адреса → номерки)
```

Плеер видит только номерки. В тексте плейлиста номерок записан адресом-заглушкой одного вида, например `https://resource.fastiplayer-bridge.invalid/<N>`. Домен `.invalid` зарезервирован и никуда не ведёт. Что угодно, кроме этого вида, транспорт плеера отвергает у себя и в протокол не отправляет.

## Разведка начала 10a (что уже есть)

- Вся сеть HLS-движка проходит через `AdaptiveHttpContext` (`web-media-adaptive/src/fetch.rs`): мастер- и media-плейлисты, сегменты, `EXT-X-MAP`, ключи AES, byte-range, обновление live. Внутри лежит конкретный `HttpSourceSession` (reqwest), трейта нет. Настоящие вызовы сети — две функции в `fetch/execution.rs` (`fetch_with_redirects` — буфер, `open_stream_with_redirects` — поток).
- Вход native HLS — `media-source-open/src/native_startup/hls.rs`: `ProductionNativeHlsAdmissionPort::prepare()`, `prepare_native_hls_attempt`, `native_adaptive_http_context`. Здесь подставляется транспорт моста. app-egui только вызывает.
- `pushed-media-source::range_file` — образец «блокирующее чтение ↔ асинхронный ответ экстеншена» (замок + Condvar, очередь запросов, брошенный запрос → `StaleDropped`).
- Протокол строгий: `deny_unknown_fields`, `KNOWN_TYPES`, `strict_shape.rs`. Новое сообщение — это minor 1.0 → 1.1, слать только при общей версии ≥ 1.1. Фикстуры общие с TS (`fixtures/manifest.json`, `generate_fixtures.py`).
- Браузерная сессия app-egui: `GenerationSource::{Segments, File}` (`browser_session/intake_notice.rs`), переводчик `translator/file_generation.rs`, приёмник `session_media/generation_feed.rs`, очередь запросов `outbound.rs`, сторож `stream_gate.rs`.

## Что сделать

Архитектуру сначала коротко описать (правило 9 `AGENTS.md`): кто владеет состоянием, какие методы — граница, какие инварианты и какие тесты их закрепят.

1. **«Розетка» транспорта — отдельный коммит без изменения поведения** (правило 8). В `web-media-adaptive` появляется трейт транспорта ресурса (буфер и поток), `AdaptiveHttpContext` держит его вместо конкретного `HttpSourceSession`. Обычный HTTP — первая реализация. DASH, HDS и Smooth делят тот же контекст: их тесты должны остаться зелёными без правок. Поверх транспорта остаются повторы, кэш завершённых ресурсов VOD, редиректы и политика секретов. Для моста секреты не нужны: куки приклеит браузер.
2. **Протокол 1.1** (Rust и TS сразу, иначе общие фикстуры уронят CI экстеншена):
   - страница → плеер `hls_source_added{generation, root}`: это поколение — HLS, корневой плейлист — номерок `root`;
   - плеер → страница `fetch_resource{request_id, resource, byte_range?, max_bytes}`;
   - страница → плеер `resource_fetch_finished{request_id, outcome}`: `completed{size}` или `failed{network_error | http_error{status} | refused | too_large}`;
   - байты идут рамками вида 2 по `request_id`. Формат рамки не меняется: что значит запрос, плеер знает по номеру запроса;
   - сторож поколений: третий вид содержимого «HLS». MSE- и файловые сообщения в таком поколении — ошибка;
   - лимиты в `limits.rs`: номерок, `max_bytes`, сколько запросов ресурсов одновременно;
   - версии: при общей версии 1.0 HLS-поколение не начинается, экстеншен оставляет честное «not supported yet» (инвариант 5).
3. **Транспорт моста в плеере.** Блокирующий вызов движка → запрос в очередь сеанса → ожидание рамок и итога. Отмена (перемотка, смена поколения, конец сеанса), таймаут, лимит размера. Несколько запросов одновременно: движок качает параллельно. Нейтральная часть «очередь запросов ресурсов» — рядом с `range_file` в `pushed-media-source`. Реализация трейта — там, где собирается native HLS (`media-source-open`). Окончательное место выбрать по зависимостям crate-ов и guardrail.
4. **HLS-поколение браузерного режима.** Ветка `GenerationSource::Hls`, переводчик рядом с `file_generation.rs`, очередь запросов в `outbound.rs`, открытие через native HLS `media-source-open` с транспортом моста. Перемотку ведёт плеер, как у файла (03c). Live — обновление плейлиста тем же транспортом. Отказы — в `rejection`-модели по классам, как у файла: нет ресурса, отказ фона, не HLS, непригодно.
5. **Ошибки честные.** 403 и 404 на сегменте, отказ фона (`refused`), обрыв, слишком большой ресурс — зритель видит причину, сеанс не висит на спиннере.

## Тесты (до кадра в рендере, без браузера)

- Сквозной в `app-egui/tests/browser_session_process/`: поддельный экстеншен по протоколу 1.1 раздаёт HLS из фикстур репозитория по номеркам → **кадры в рендере**. TS и fMP4, мастер с двумя вариантами, AES-128.
- VOD: перемотка вперёд и назад докачивает нужный сегмент и снова даёт кадры.
- Live: скользящее окно плейлиста. Кадры идут дальше начального окна, плейлист обновляется.
- Безопасность: плеер шлёт только номерки. Адрес не того вида в плейлисте → отказ без запроса в протокол. Отказ фона и 403 → честная ошибка.
- Версии: общая версия 1.0 → `hls_source_added` не принимается, старый путь работает.
- Focused-тесты каждой новой границы (правило 7 `AGENTS.md`): ресурса нет, поддельный транспорт, ошибка, учёт запросов, метод не трогает чужое.
- Розетка: прежние наборы HLS, DASH, HDS и Smooth зелёные без правок.
