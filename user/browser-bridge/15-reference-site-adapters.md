# Сессия 15: адаптеры эталонных сайтов

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 15 плана `user/browser-bridge/`: адаптеры для эталонных сайтов из `results/00.md` — YouTube (качества, дорожки звука, субтитры, Next, возврат), Twitch (качества live) и украинские сайты с фильмами и сериалами (серии, озвучки, качества). Если объём велик — раздели на 15a (YouTube, Twitch) и 15b (украинские сайты), каждая с отдельным отчётом. Сначала прочитай `user/browser-bridge/README.md`, `results/00.md`, `results/00c.md`, `results/14.md`.

## Зачем

Решения 1, 17, 19 на настоящих сайтах. Сайты — главная причина, ради которой фичу будут ставить.

## Что сделать

1. **YouTube:** качества и дорожки звука из API плеера страницы; субтитры (включая автоперевод, если плеер страницы его даёт); Next и автопереход; возврат на секунду; Shorts и live; реклама отдельным элементом не уходит, вшитая — честно в матрицу.
2. **Twitch:** качество live, переход live ↔ запись; вшитая реклама — честное ограничение.
3. **Украинские сайты** (по списку 00, 4–6 шт.): серии, сезоны, озвучки, качества; плеер во iframe; автопереход серии. Для каждого — фикстуры и тесты, как в 14.
4. Для каждого сайта — строка в матрице совместимости (`docs/browser-bridge/compatibility.md`): что работает (режимы 1 и 2, Next, озвучки, качества, субтитры, возврат), что нет и почему.

## Тесты

- Модульные по фикстурам каждого сайта: `matches`, `describe`, `select`, `next`.
- Живые на сайтах — в этой сессии и в приёмке 22, в профиле владельца, если нужен логин. В отчёт — только результат, без ссылок и имён аккаунтов.

## Критерий выхода

- `results/15.md` (или `15a.md` / `15b.md`): матрица сайтов, известные ограничения, проверка «серия → следующая серия → другая озвучка → память озвучки» на каждом сериальном сайте.
- Memories: `mem:browser-bridge/core` (список адаптеров и где их фикстуры).
