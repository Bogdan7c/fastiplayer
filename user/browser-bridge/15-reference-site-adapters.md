# Сессия 15: адаптеры эталонных сайтов

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 15 плана `user/browser-bridge/`: адаптеры для эталонных сайтов из `results/00.md` — YouTube (страница, плейлист, live → yt-dlp, позиция и следующий ролик), Twitch и украинские сайты с фильмами и сериалами (серии, озвучки, качества). Если объём велик — раздели на 15a (YouTube, Twitch) и 15b (украинские сайты), каждая с отдельным отчётом. Сначала прочитай `user/browser-bridge/README.md`, `results/00.md`, `results/14.md`.

## Зачем

Решения 1, 16, 17, 19 на настоящих сайтах. Сайты — главная причина, ради которой фичу будут ставить.

## Что сделать

1. **YouTube:**
   - страница → `Handoff` со ссылкой страницы, куками и текущей секундой;
   - плейлист и «Смотреть далее» → очередь через топологию yt-dlp (база) или через адаптер (если yt-dlp даёт меньше, чем видно на странице);
   - live, Shorts;
   - возврат на страницу с той же секунды (`?t=` или API плеера страницы).
2. **Twitch:** live и записи. Свежий плейлист с токеном — через адаптер (поток живёт минуты). Реклама в потоке — честное ограничение или отсев по меткам плейлиста.
3. **Украинские сайты** (по списку 00, 4–6 шт.): серии, сезоны, озвучки, качества; плеер во iframe; одноразовые ссылки. Для каждого — фикстуры и тесты, как в 14.
4. Для каждого сайта — строка в матрице совместимости (`docs/browser-bridge/compatibility.md`): что работает (режимы 1 и 2, серии, озвучки, качества, субтитры, возврат), что нет и почему.

## Тесты

- Модульные по фикстурам каждого сайта: `matches`, `describe`, `resolve`.
- Живые на сайтах — в этой сессии и в приёмке 22, в профиле владельца, если нужен логин. В отчёт — только результат, без ссылок с токенами.

## Критерий выхода

- `results/15.md` (или `15a.md` / `15b.md`): матрица сайтов, известные ограничения, проверка «серия → следующая серия → другая озвучка» на каждом сериальном сайте.
- Memories: `mem:browser-bridge/core` (список адаптеров и где их фикстуры).
