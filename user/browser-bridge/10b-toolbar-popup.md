# Сессия 10b: кнопка на панели и попап, настоящая мышь на стенде

Добавлена 5 ноября 2026 при разделении сессии 10 (решение 213).

> Выполни сессию 10b плана `user/browser-bridge/`: клик по кнопке экстеншена сразу отдаёт главное видео, попап показывает итог и список найденного с выбором другого видео. На стенде появляется настоящая мышь внутри невидимого рабочего стола (решение 212). Сначала прочитай `user/browser-bridge/README.md`, `10-mode1-entry-points.md` с его поправками, `results/09c.md`, `results/09d.md`.

## Зачем

Решения 7–9, 198, 199, 209, 212. Первый вход режима 1 и инструмент, которым стенд проверяет все входы.

## Что сделать

### Экстеншен

1. **Опрос без передачи.** Сейчас опрос фреймов запускается только внутри `handOffTab`. Нужна отдельная команда «опросить вкладку» (только от страниц экстеншена), она обновляет модель вкладки (решение 198).
2. **Передача выбранного видео.** `handOffTab` берёт только главное видео. Команда `hand_off_tab` получает необязательную ссылку на видео (`VideoRef`), фон сверяет её со свежим опросом. Устаревшая ссылка — отдельный честный исход, а не молчаливая подмена другим видео.
3. **Попап при открытии** (решение 209):
   - определяет активную вкладку и сразу отдаёт главное видео;
   - окно плеера забирает фокус, и попап закрывается сам: это и есть подтверждение;
   - не вышло — попап остаётся и показывает причину текстом;
   - список найденного: заголовок вкладки или хост фрейма, размер, длительность, метки «ad?» / «DRM» / «not supported yet», выбор другого видео;
   - статус связи и ссылка на настройки, как сейчас.
4. **Закрытие попапа не отменяет передачу.** Её держит фон. Проверить тестом.
5. **Исходы текстом** (в отдельном чистом модуле, как `status-text.ts`): `no_video` с подсказкой «нажмите play на странице», `protected`, `not_supported_yet{form}`, `local_address_refused`, `player_unavailable`, `failed`, вкладка браузера без доступа. Новый исход передачи и вид строк — из поправок файла 10.
6. **Вопрос про локальный адрес** (решение 199): `local_address_needs_consent{host}` → вопрос в попапе → та же команда с `consented_local_host`.
7. **Страницы браузера** (`chrome://`, `about:`, магазины): без передачи, понятный текст.

### Стенд: настоящая мышь

Прототип решения 212 показал: в `kwin_wayland --virtual` на переменной `KWIN_WAYLAND_NO_PERMISSION_CHECKS=1` протокол `org_kde_kwin_fake_input` даёт настоящий клик. Родное контекстное меню открылось в Chromium 156 и Firefox 158, экран владельца не занят.

8. **Модуль мыши в `browser-bridge-bench`:** перемещение, клик, клавиша через `fake_input`. Протокол уже есть в `wayland-protocols-plasma` (проверить, не тянет ли он лишнего; иначе маленький свой клиент). Только в окружении `DisplayTarget::Virtual`, переменная ставится только этому KWin.
9. **Снимок экрана и поиск значка.** Координаты кнопки зависят от браузера: нужен снимок (`spectacle` внутри частного сеанса работает) и поиск своего значка по снимку.
10. **Значок на панели.** Обе панели по умолчанию прячут значок экстеншена в меню. Chrome: закрепление через настройки профиля стенда. Firefox: `action.default_area` или настройка профиля. Проверить вживую. Если для этого нужно поле манифеста — объяснить, что меняется у обычного пользователя.
11. **Размер экрана.** На 1280x720 родное меню Chromium уже не влезает и прокручивается. Мышиным сценариям нужен экран побольше.
12. **Сценарий `entries`:** матрица «вход × страница» до кадра в рендере. В этой сессии вход один — кнопка.

## Тесты

- `node:test`: опрос без передачи, выбранное видео, устаревшая ссылка, отказ чужому отправителю, тексты всех исходов, порядок «передача идёт, попап закрылся».
- Стенд, Chromium и Firefox: настоящий клик по значку × `mse-fmp4`, `mse-webm`, `video-src`, `iframe-cross-origin`, `shadow-dom` → **кадр в рендере**.
- Клик после начала проигрывания → играет с текущей секунды, начало потока не пропущено.
- Выбор другого видео в попапе на `banner-with-main` или `ad-beside-film` → в плеере именно оно.
- Отказы текстом: `no_video` на странице без видео, `protected` на `drm-clearkey`, `not_supported_yet` на `native-hls`, вопрос на `video-src-local`.
