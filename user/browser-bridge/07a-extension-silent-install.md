# Сессия 07a: плеер сам ставит экстеншен

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 07a плана `user/browser-bridge/`: разведай вживую и сделай установку экстеншена Fastiplayer Bridge самим плеером там, где браузер это позволяет, — так, чтобы человеку оставалось минимум действий. Учитывай будущую Windows. Сначала прочитай `user/browser-bridge/README.md` (решения 157–161), `results/06.md`, `results/07.md`.

## Зачем

Решение владельца 161 (сессия 06): «Хотелось бы, чтобы плеер сам всё ставил, что надо, минимизируя действия пользователя». Если тихая установка будет работать хорошо, владелец готов вообще отказаться от публикации в магазинах (сессия 24). Это решение принимается **по фактам этой сессии**, а не заранее.

В 06 плеер уже ставит посредника и файлы подключения кнопкой «Connect» (crate `browser-bridge-install`). Его каталог браузеров знает семейство, упаковку (пакет / Flatpak / Snap) и app ID. Установщик экстеншена встаёт рядом, на тот же каталог.

## Что известно на момент 06 (документация производителей, 2.11.2026)

- **Chrome и Chromium на Linux:** внешняя установка — «файл предпочтений» `<ID>.json` в системной папке (`/opt/google/chrome/extensions/`, `/usr/share/google-chrome/extensions/`; у Chromium — своя). Можно указать магазин (`external_update_url`), свой сервер обновлений или локальный `.crx` (`external_crx` + `external_version`). На Linux браузер ставит такой экстеншен **без вопроса** человеку. Папки системные — нужен пароль администратора (pkexec).
- **Chrome на Windows и macOS:** внешняя установка разрешена **только для экстеншенов из Chrome Web Store**. Без публикации в CWS тихой установки в Chrome на Windows не будет.
- **Chrome из Flatpak:** системные папки внутри образа приложения, только для чтения. Пользовательской папки для внешних экстеншенов в документации нет — проверить вживую, есть ли обход.
- **Свой `.crx` подписывается своим закрытым ключом.** В 05 закрытый ключ разработки сознательно не хранится (решение 154: магазин подписывает сам). Самостоятельная раздача `.crx` = хранить ключ и, вероятно, новый ID → пересмотр решения 154 и `extension_identity`.
- **Firefox:** вне режима разработчика ставит только экстеншены, подписанные Mozilla. Подпись без публичной страницы («unlisted», автоматическая проверка) возможна, аккаунт AMO нужен. Есть пользовательская папка для `.xpi`; при следующем запуске Firefox **спрашивает** человека, включать ли такой экстеншен. Поведение в текущих версиях подтвердить вживую.
- **Обычный путь без ограничений:** плеер открывает страницу экстеншена в магазине в нужном браузере (`flatpak run <id> <ссылка>` для Flatpak), человек жмёт «Add». Firefox так же открывает наш подписанный `.xpi` своим окном установки.

## Что сделать

1. **Разведка вживую** (основной ПК; Windows — по готовности стенда, иначе по документации с пометкой): для каждого браузера каталога 06 — какие способы реально работают, нужен ли пароль, что видит человек (вопрос браузера, плашка «управляется организацией», ничего), переживает ли установка обновление браузера и как удаляется. Отдельно — Chrome из Flatpak.
2. **На решение владельцу** — таблица «браузер × способ × действия человека» и последствия для магазинов, ключа (решение 154) и Windows. Без этого кода не писать.
3. **Реализация** по выбранному: установщик экстеншена в `browser-bridge-install` рядом с установщиком посредника (тот же каталог, свой шов под Windows), кнопка и статус «Extension: installed / not installed / install in browser» в разделе «Browser integration». Удаление убирает только своё.
4. **Тесты:** фейковый `HOME` и фейковые системные папки (файлы на месте, повтор без дубликатов, удаление только своего), отказ pkexec — понятный статус, а не падение; живая проверка — экстеншен из 07 установлен плеером и доходит до плеера.
