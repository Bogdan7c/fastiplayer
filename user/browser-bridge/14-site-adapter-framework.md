# Сессия 14: каркас адаптеров сайтов — серии, озвучки, качества

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 14 плана `user/browser-bridge/`: контракт адаптера сайта в экстеншене (распознать страницу, отдать список серий, озвучек и качеств, по запросу плеера добыть поток выбранного варианта) и его поддержку в протоколе и плеере: серии → очередь, озвучки → меню ♪ с переключением на той же секунде и памятью для сериала, качества → наше меню. Первый адаптер — для страницы сериала тестового стенда. Сначала прочитай `user/browser-bridge/README.md`, `results/00.md` (где на сайтах живут серии и озвучки), `results/13.md`.

## Зачем

Решения 16, 17, 19 — озвучки критичны. На сериальных сайтах выбор озвучки, серии и качества живёт в плеере страницы, и каждая озвучка — отдельный поток. Без адаптеров этого не достать.

## Что сделать

1. **Контракт адаптера** (TS, `src/adapters/`):
   - `matches(url, frames)`;
   - `describe()` → сериал / сезон / серия, список серий (ссылки на страницы серий), озвучки (идентификатор + название), качества;
   - `resolve(variant)` → поток выбранной серии, озвучки и качества (через управление плеером страницы или прямой запрос, как делает сам сайт).

   Адаптер не имеет доступа к портам и правам сверх общего ядра. Ошибка адаптера — не ошибка экстеншена: откат на обычное обнаружение 09.
2. **Протокол** (расширение 01 с версией):
   - `Handoff` несёт описание вариантов;
   - плеер может запросить `ResolveVariant` (смена озвучки или качества, следующая серия);
   - экстеншен отвечает `FreshMaterial`.

   Если вкладки уже нет — экстеншен открывает её в фоне и закрывает после (спросить владельца, допустимо ли).
3. **Плеер:**
   - озвучки адаптера — как web-версии звука в меню ♪ (`web_versions`, `web_version_switch`): переключение = переоткрытие на той же секунде через существующий same-item candidate switch;
   - память выбора озвучки — «для этого сериала» (ключ — нормализованный ID сериала от адаптера), новая запись в `track-memory` со схемой и миграцией;
   - серии → строки очереди с ленивым разрешением потока (поток просится, когда до строки дошла очередь или предзагрузка);
   - качества адаптера — в меню качества.
4. **Ведение адаптеров:** у каждого — фикстуры страниц (сохранённый DOM / JSON **без** личных данных) и модульные тесты; версия адаптера в журнале отладки.

## Тесты

- Стенд «сериал»: передача серии 2 → в очереди серии 2…N, играет 2; смена озвучки → другой поток на той же секунде ± 1 с, **кадр в рендере**; следующая серия в той же озвучке; память озвучки пережила перезапуск плеера.
- Адаптер падает → обычное обнаружение, плеер играет.
- Модульные на `describe` / `resolve` по фикстурам.
