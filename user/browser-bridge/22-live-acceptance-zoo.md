# Сессия 22: живая приёмка зоопарка

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 22 плана `user/browser-bridge/`: полная живая приёмка — 3 машины (основная, T480s, T410) × 3 стола + Xwayland (KDE Wayland; KDE Wayland с браузером через Xwayland вместо KDE X11 — решение 73; GNOME Wayland временно на T480s, Xfce X11 временно на T410) × браузеры (Google Chrome из Flatpak, Firefox, Chromium) × эталонные сайты × режимы 1, 2, 3 и PiP. После — удаление временных столов и проверка KDE. Сначала прочитай `user/browser-bridge/README.md`, `results/00b.md` (как ставили и удаляли столы), `results/21c.md`.

## Зачем

Решения 23 и 35: в конце — полный шмон всего. Автотесты не видят то, что видит человек: мигание окна, ложный автозапуск, неудобство.

## Что сделать

1. **План прогона — владельцу до начала:** порядок машин и столов, длительность каждого блока, когда нужна его рука (вход в сеанс, логин на сайтах). Машины — только когда владелец их отдал.
2. **Установка «как у пользователя»:** чистый профиль браузера, экстеншен из собранного пакета (Chrome — «Load unpacked» или из магазина, если уже опубликован; Firefox — подписанный `.xpi`), подключение кнопкой в настройках плеера, Flatpak по инструкции (решение 22).
3. **Сценарии на каждой клетке** (сокращённо там, где клетка повторяет соседнюю):
   - режим 1 всеми входами;
   - режим 2 с заглушкой и возвратом;
   - серии с автопереходом, озвучка, Next, память выбора;
   - субтитры; качество; «GLES2 → H.264» на T410;
   - режим 3 и PiP — по вердикту;
   - 15 минут обычного сёрфинга с режимом 2 — ложные запуски.
4. **Временные столы** ставятся и удаляются по протоколу 00b, KDE проверяется после.
5. **Найденное** — чинится по корневой причине отдельными коммитами или уходит в бэклог решением владельца.
