# Сессия 16b3c3: родной HLS застревает в перемотке на старте

Отделена решениями 389–390 (16b3c2). Идёт до [16b4](16b4-feed-live-acceptance.md). Это починка плеера, без изменения стенда (кроме строки повтора, если понадобится).

> Выполни сессию 16b3c3 плана `user/browser-bridge/`: найди корень редкого зависания родного HLS на старте и почини. Сначала прочитай `user/browser-bridge/README.md`, этот файл, `results/16b3c2.md` (раздел «Находка: зависание HLS») и общий бэклог п. 70.

## Что известно

- Строка стенда `capture chromium m3u8-in-src` (родной HLS VOD в `<video src>`): 1 раз из ~20 под нагрузкой (release-плеер, 8 частей стенда сразу).
- Поколение показано с `start_ms=1245`, плеер принял `Accurate`-перемотку на 1245 мс, HLS-демуксер дал `final_receipt` с якорем 80 мс, окно показало первый кадр — и 60 с `state=seeking`, `presented_frames=23`, `position_ms=0`, звука нет.
- Выдержка журнала и журнал части — в отчёте 16b3c2.

## Что сделать

1. **Поймать.** Повтор строки под нагрузкой (`--jobs 8`, несколько десятков раз) с подробным журналом плеера (`FASTIPLAYER_BENCH_PLAYER_LOG=info,player_core=debug,web_media_hls=debug`). Длительность замера называется владельцу заранее.
2. **Корень, а не следствие.** Кто не завершает перемотку: ответ демуксера после `final_receipt`, установка поколения против перемотки по показу (`seek_when_shown`, 03e), смена дорожек `TracksChanged` в момент перемотки.
3. **Тест до кадра.** Процессный тест браузерного режима, который воспроизводит порядок событий и падает на коде до починки; кадры после перемотки доходят до рендера.

4. **Остаток полного прогона 16b3c2 (решение 390).** `series-memory-restart` в Firefox красный в обоих полных прогонах стенда частями, а отдельно и рядом с нагрузкой проходит («the memory holds 0 series»: смена озвучки на странице не записана). Причина не установлена: выбор теперь делается через ~2 с после передачи, а экстеншен признаёт смену на странице выбором человека лишь при условиях `session-choice-memory.ts` (решения 284, 15a). Сначала вывести заметки памяти в журнал стенда и увидеть, какое условие не выполнилось; потом — решение владельца.

## Тесты

- Новый процессный тест падает до починки и проходит после.
- Стенд: быстрый набор и задетое по таблице `crates/browser-bridge-bench/README.md` (плеер `browser_session/hls_bridge/`, `session_media/`); строка `m3u8-in-src` — серия повторов без сбоя.
