## Главный механизм (подтверждён владельцем)

«Сортировщик»:

1. Куски каждого SourceBuffer склеиваются в **целые коробки**. Для fMP4 это init-сегмент (`ftyp`+`moov`) и медиасегмент (`moof`+`mdat`, вместе с `styp`/`sidx`/`emsg` перед ним). Для WebM — init (EBML-заголовок, `Segment`, всё до первого `Cluster`) и `Cluster`. Сканер читает только заголовки коробок и не разбирает видео.
2. Целые коробки кормят **существующие демуксеры** (`symphonia-demux` для fMP4 и WebM, `mpeg-ts-demux` для TS) через реестр `demux-api` в фоновом демуксере `ProgressiveDemuxer`.
3. **Эпизод** — один демуксер на одном init-сегменте. Новый эпизод начинается, когда:
   - пришёл новый init-сегмент с другими байтами (смена качества);
   - вызван `changeType` (смена кодека);
   - сменился `timestampOffset`.

   Так уже делают живые HLS и DASH. Плеер получает `TracksChanged` только при настоящей смене дорожек.
4. `abort()` выбрасывает недособранную коробку. В демуксер попадают только целые коробки.
5. Поколение (новый `MediaSource`) — новый источник целиком: сторож поколений уже стоит в сервере 02.

## Кто чем владеет

| Часть | Модуль | Что делает |
|---|---|---|
| Контейнер по MIME | `container` | `video/mp4` / `audio/mp4` → fMP4, `video/webm` / `audio/webm` → WebM, `video/mp2t` → TS; остальное — честный отказ |
| Сканер коробок | `framing/` | целые коробки из кусков любой нарезки; ошибки формы — типизированные |
| Защита | `protection` | `encv`/`enca` в `stsd`, `ContentEncryption` WebM → отказ «защищённое видео» |
| Труба эпизода | `pipe` | ограниченная очередь байтов → `Read` для демуксера на его потоке |
| Эпизод | `episode` | init + смещение + труба + фоновый демуксер |
| SourceBuffer | `source_buffer` | приём кусков, текущий init, смещение, очередь эпизодов, сдвиг времени пакетов, стабильные ID дорожек |
| Поток | `stream` | несколько SourceBuffer одного поколения → один `Demuxer` для плеера (`CompositeAvDemuxer` для раздельных звука и видео) |
| Пределы | `policy` | все числа с объяснением «почему так», без скрытых литералов |

## Инварианты

- Страница — враг: каждая коробка проверяется на форму и предел размера. Битые байты — ошибка одного потока, а не паника процесса.
- Время для плеера: `pts`/`dts` + `timestampOffset`. Кадр с отрицательным временем выбрасывается (как `appendWindowStart = 0` в MSE).
- `next_event` плеера никогда не блокируется: ждём байтов — `TemporarilyUnavailable`.
- Конец потока (`endOfStream`) — обычный EOF после доигрыша всех эпизодов.

## Тесты 03a

- Сквозной: записанный поток из фикстур протокола (fMP4 H.264 + AAC, два SourceBuffer, разрезы посреди боксов) → источник → `PlayerSession` → **кадры доходят до показа**, звук пишется в выход, A/V синхронны.
- WebM VP9 + Opus в одном SourceBuffer и MPEG-TS — так же.
- Смена качества (новый init с другим разрешением) и `changeType` (H.264 → VP9) без остановки потока.
- `timestampOffset`, `abort()` посреди коробки, отказ DRM, битые байты, предел размера коробки.

## Не входит (03b, 03c)

Перемотка, «буферизовано до», «полон», переходник протокола и единая очередь сообщений и байтов в процессе браузерного режима, живой прогон — 03b. `<video src>` и «буфер доигран» — 03c.
