# Сессия 01: архитектура и протокол моста

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 01 плана `user/browser-bridge/`: утверди с владельцем архитектуру моста (README, раздел «Архитектура») с поправками по итогам 00/00a и создай нейтральный crate `browser-bridge-protocol` — сообщения экстеншен ↔ посредник ↔ плеер, версия протокола, лимиты, `Debug` без секретов, общие JSON-фикстуры для Rust и TS. Сначала прочитай `user/browser-bridge/README.md`, `results/00.md`, `results/00a.md`.

## Зачем

Протокол — шов между тремя программами на двух языках. Если его форма поплывёт позже, придётся менять всех троих сразу.

## Что сделать

1. **Архитектура — владельцу.** Короткое описание простым языком: кто чем владеет, какие границы, какие инварианты. Поправки по 00/00a (Flatpak-путь, Firefox MV2/MV3, требования режима 3). Решения владельца — в README.
2. **Crate `browser-bridge-protocol`** (только типы, `serde`; никаких I/O, D-Bus, HTTP):
   - **Конверт:** версия протокола, ID запроса, тип сообщения. Несовместимая версия — типизированный отказ `ProtocolVersionUnsupported { supported }`.
   - **Запросы экстеншена:**
     - `Handoff` — что открыть: ссылка на страницу; пойманные кандидаты (тип — progressive / HLS / DASH; URL; контекст запроса — заголовки и куки строго для origin кандидата); субтитры; подсказки (длительность, позиция, заголовок, признак рекламы); намерение (играть сейчас / в очередь); флаг инкогнито;
     - `Ping` / `Hello` — версия, возможности сторон;
     - `FreshMaterial` — ответ на запрос плеера о свежем потоке;
     - место под геометрию режима 3 (по 00a), пока типом-заготовкой без реализации.
   - **События плеера:** `Accepted` / `Rejected(reason)`, позиция, «закрыт на секунде N», «пользователь нажал Вернуть», «нужен свежий материал для страницы X».
   - **Лимиты:** число кандидатов, длина URL, размер заголовков и кук, общий размер — согласовать с лимитами пересылки второго запуска (`admission.rs`). Предел 1 МБ native messaging от хоста к браузеру — учесть.
   - **Секреты:** значения кук и заголовков — в обёртке с `Debug`/`Display` без значения (по образцу `HttpHeader::Debug`). Сериализация есть, логирование — нет.
   - **Причины отказа** — перечисление, а не строка: нет плеера, DRM, не поддерживается протокол, лимит, инкогнито запрещено настройкой, занят и т. д.
3. **Общие фикстуры** `crates/browser-bridge-protocol/fixtures/*.json`: валидные и невалидные сообщения. Rust-тесты разбирают их сейчас, TS-тесты экстеншена (07) — те же файлы. Одна правда на двоих.
4. Guardrail: crate не зависит ни от одного crate-а плеера (`scripts/check-refactor-guardrails.py`).
5. Швы Windows: в протоколе нет ничего про D-Bus. Транспорт — забота 02/05.
6. **Идемпотентность и поколения** (инвариант 5a README):
   - у каждого запроса — ключ идемпотентности. Повтор с тем же ключом даёт тот же ответ, а не второе действие;
   - у каждого запроса плеера к экстеншену (`FreshMaterial`, `ResolveVariant`) — поколение строки очереди. Ответ с чужим поколением отбрасывается с причиной `Superseded`;
   - сколько живёт память ключей у получателя — ограничено по числу и времени;
   - описать владельцу простым языком.
7. **Контекст запроса из 00 (п. 9):** UA браузера, `partitionKey` для кук iframe, хранилище кук контейнера — поля в протоколе, если разведка показала, что они нужны.

## Тесты

- Каждая фикстура разбирается в ожидаемое значение и обратно байт-в-байт (round-trip).
- Каждый лимит: на границе принимается, за границей — точная причина отказа.
- Неизвестная версия, неизвестный тип, лишнее поле (политика строгая, `deny_unknown_fields` — или нет; решить и обосновать ради совместимости версий).
- `Debug` любого сообщения с куками не содержит значения куки (тест ищет значение в строке).
- **Property-тесты** (proptest или аналог из дерева): случайное валидное сообщение → сериализация → разбор = исходное; случайные байты и обрезки валидных → только типизированная ошибка, без паники и без зависания.
- Повтор с тем же ключом идемпотентности; ответ со старым поколением → `Superseded`.
- Строки с юникодом, эмодзи, RTL, управляющими символами, нулевым байтом — по правилам допуска.
