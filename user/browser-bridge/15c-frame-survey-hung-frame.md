# Сессия 15c: опрос вкладки не ждёт зависший фрейм (klonua в Chromium)

Часть сессии 15 ([общий замысел](15-reference-site-adapters.md)), решения 297, 298, общий бэклог п. 46. Зависит от 15b.

> Выполни сессию 15c плана `user/browser-bridge/`: на klonua в Chromium передача видео не начинается — опрос вкладки кончается `survey_timed_out`. Докажи корень, опрашивай фреймы по одному со сроком на каждый, закрепи страницей стенда с зависшим фреймом и живьём на klonua в Chromium и Firefox. Второе — подсказка зрителю, когда страница не выполнила выбор из нашего меню (решение 298). Сначала прочитай `user/browser-bridge/README.md`, этот файл, `results/15b.md`, `results/09c.md`, `results/10b.md`, п. 46 общего бэклога.

## Что известно (15b, 10 ноября 2026)

- **Симптом.** Фильм и сериал на klonua (плеер Ashdi в теневом DOM `<player-control>`, много рекламных iframe), невидимый Chromium 156: каждая попытка передачи — `survey_timed_out`. Firefox на тех же страницах и Chromium на uakino (тот же Ashdi, iframe прямо на странице) передают.
- **Не регрессия 15b:** сборка экстеншена до адаптера PlayerJS падает так же.
- **Гипотеза.** `surveyTabVideos` (`extensions/browser/src/background/handoff/frame-survey.ts`) зовёт `scripting.executeScript` сразу во все фреймы. Chromium отвечает, только когда ответили все. Один фрейм, который не отвечает (грузится вечно, без контент-скрипта, `about:blank` рекламы), держит весь ответ до `SURVEY_TIMEOUT_MS` = 5 с. Проба стенда с тем же видом вызова (`live_handoff --playerjs-report-every`) на klonua в Chromium зависла, на uakino — ответила.

## Что сделать

1. **Доказать корень:** какой фрейм не отвечает и почему (`webNavigation.getAllFrames`, вызов по одному фрейму, время ответа каждого). Если корень другой — сначала обсудить с владельцем.
2. **Опрос по одному фрейму:** список фреймов, `executeScript` с `frameIds` на каждый, срок на фрейм, собрать ответивших. Сохранить прежние исходы: «вкладка закрыта для экстеншена», «скрипт не встал» (поздний вход 10d), ограничение числа кандидатов. Тот же вид вызова есть в других местах (проверить и `link-entry.ts`, и пробы стенда).
3. **Стенд:** страница с фреймом, который никогда не отвечает, — передача главного видео проходит; focused-тесты опроса (молчащий фрейм, отказ фрейма, все молчат, учёт кандидатов).
4. **Подсказка при отказе выбора (решение 298):** протокол — сообщение «исход выбора» от страницы к плееру (версия протокола по правилам 86); исходы адаптера `no_such_variant` (у новой озвучки нет этой серии, решение 295), `person_only` (сайт принимает только настоящую мышь), `failed`. Плеер показывает причину вместо тишины; тост «Audio: …» до исхода не должен обещать смену. Фон уже знает исход (`variant-mirror.ts`, `command`), до плеера он не доходит.
5. **Живьём:** klonua в Chromium (фильм — озвучка из нашего меню, сериал — три нажатия) и Firefox без регрессий.
