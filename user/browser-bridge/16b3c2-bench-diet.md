# Сессия 16b3c2: стенд на диете и проверка только задетого

Отделена решением 386 (16b3c). Идёт до [16b3d](16b3d-shadow-dom-and-loop.md). Это инфраструктура стенда, без изменения поведения моста.

> Выполни сессию 16b3c2 плана `user/browser-bridge/`: быстрый набор стенда и протокол «проверяем только задетое». Сначала прочитай `user/browser-bridge/README.md`, этот файл, решение 386 и `results/16b3c.md` (раздел «Регресс-прогон» — времена строк).

## Что сделать

1. **Замер, где уходит время.** По журналам прогона 16b3c: время на строку, сколько из него — ожидание сводки плеера (`BROWSER_PLAYBACK_SUMMARY_INTERVAL`, 10 с), запуск браузера и KWin, сборка. Цифры — в отчёт.
2. **Короткая сводка для стенда.** Тестовая переменная процесса плеера (как `FASTIPLAYER_TEST_BROWSER_VIDEO`), обычный плеер — прежние 10 с. Судьи «кадры выросли на N между сводками» — на «выросли за T секунд», без привязки к шагу сводки.
3. **Параллельный запуск строк.** Каждая строка уже в своей песочнице (временный HOME, частная шина, свой невидимый KWin). Ключ `--jobs N`, по умолчанию по числу ядер с запасом. Плеер для стенда — сборка с оптимизацией, чтобы под нагрузкой не плыли строки, чувствительные ко времени. Доказать: быстрый набор 3 раза подряд без сбоев.
4. **Быстрый набор** (`scripts/browser-bridge-bench.sh quick`): главные строки сайтов с контентом — MSE как у YouTube (смена качества, реклама → фильм, перемотка), `<video src>`, HLS, следующая серия и память выбора, перезагрузка страницы, возврат вкладки, режим 2; ленты — по одной строке на устройство (много элементов, пул, один элемент). Цель — несколько минут на оба браузера. Список строк — на утверждение владельцу.
5. **Протокол «только задетое».** Таблица в README стенда: какие пути кода (экстеншен: `page/shadow`, `background/handoff`, `feed/`, адаптеры; плеер: `browser_session`, `pushed-media-source`, кадр окна) → какие команды и страницы стенда гонять. Правило сессий плана: перед коммитом — быстрый набор + задетое по таблице; полный прогон — только перед вехой. Записать в «Общие правила сессий» README плана.

## Тесты

- Юнит-тесты судей после перехода на время, а не на сводки: каждый падает, если судью сломать.
- Быстрый набор — PASS в Chromium и Firefox 3 раза подряд; полный прогон один раз в конце — те же итоги, что в 16b3c.
