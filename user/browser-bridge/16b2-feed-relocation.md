# Сессия 16b2: окно идёт за лентой

Часть [16b](16b-short-video-feeds.md), решение 345. Разведка — [results/16b0.md](results/16b0.md). Звук HE-AAC — [16b1](16b1-he-aac-decoder.md).

> Выполни сессию 16b2 плана `user/browser-bridge/`: человек передал ролик ленты и крутит страницу, окно само переходит на следующий ролик. Сначала прочитай `user/browser-bridge/README.md` (решения 201, 204, 226, 227, 259), этот файл, `results/16b0.md`, `09c2-preroll-element-hop.md`, `results/09c2.md`, `results/16a.md`.

## Зачем

Без этого после первого перелистывания окно стоит на старом ролике или закрывается (4009), и ценность моста на лентах нулевая.

## Три устройства лент (разведка, Firefox)

- **Много элементов (Instagram).** Свой `<video>` и свой `MediaSource` у каждого ролика. Старый встаёт на паузу вне экрана, адрес меняется, новый стартует; сыгранный удаляется через ~6 с.
- **Один элемент (Shorts).** Страница переносит элемент и даёт ему новый `MediaSource`. По коду это уже новое поколение — проверить.
- **Пул из двух (TikTok).** Элементы чередуются, следующий загружен заранее, адрес не меняется.

## Сначала проверить (в разведке не сделано)

1. Прогнать через мост Shorts (вход не нужен; помощник `live_handoff`, свежий профиль). Работает ли смена поколения на переносимом элементе.
2. Досмотреть ролик до конца на каждом сайте: что делает страница (перемотка на 0 и `play()` или следующий ролик). Shorts переключает `loop`, у тени для `loop` кода нет. Не уйдёт ли окно в «Waiting for the next episode…» и 4011.
3. Как `classifySurvey` и `mayBeAd` судят ролики по 8–15 с. Если как рекламу — на рилсы лягут плашка и запрет перемотки (205–206).
4. Сторож следующего видео не берёт элементы с `loop` (`#loopKeepsAway`).
5. Как перехват классифицирует звуковой буфер TikTok, объявленный `video/mp4; codecs="mp4a.40.29"`.
6. Путь паузы и причина 4009 — подтвердить наблюдением с мостом (сейчас выведены из кода).

## Механизм — подтвердить с владельцем до кода

Переданное видео ушло с экрана (видимая площадь 0 или элемент вне документа), а другое видео на странице стало видимым и заиграло по воле страницы. Тогда сеанс переезжает на него в том же окне. Решает фон экстеншена, плеер про ленту не знает. Превью по наведению не считается: при нём наше видео остаётся на экране.

Открытые вопросы для владельца:
- что делать с паузой страницы на ушедшем с экрана элементе, пока не ясно, придёт ли следующий ролик (пауза в окне или ждём);
- сколько ждать следующий ролик, прежде чем признать конец.

Правило одно на все ленты. Адаптер сайта — только если общего не хватило.

## Стенд

- Страница «лента» с тремя строками по устройству: много элементов (порядок Instagram: пауза → `pushState` → play → удаление через ~6 с), один переносимый элемент, пул из двух.
- Прокрутка настоящим колесом: в `desktop_input` колеса нет, добавить `Mouse::scroll_at` (`axis` в `org_kde_kwin_fake_input`).
- **Судья доказывает, что в окне следующий ролик, а не старый.** Рост `presented_frames` этого не отличает. Ролики должны быть различимы, например разной длины (длина по MPRIS) или с выжженной меткой. Плюс `loads` и кадры после маркера прокрутки.
- Строка «много элементов» падает на текущем коде.
- Страница с превью по наведению рядом с главным видео: сеанс никуда не уходит. Тест падает, если убрать строгость правила.
