# Сессия 09: перехват байтов и виртуальный видеоэлемент

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 09 плана `user/browser-bridge/`: production-версия того, что доказал прототип 00c — перехват MSE (главный поток и, где можно, воркер), байты `<video src>` через сеть браузера, виртуальный видеоэлемент (страница думает, что играет, браузер не декодирует), все фреймы включая чужие iframe, отсев рекламы, DRM не трогаем, угадывание главного видео. Время, буфер и перемотку виртуальному элементу диктует плеер через мост. Проверь на стенде 08. Сначала прочитай `user/browser-bridge/README.md` (инварианты), `results/00c.md`, `results/08.md`.

## Зачем

Решения 8, 37, 39. Это двигатель всей фичи.

## Что сделать

1. **Модель вкладки** в фоне: найденные видеоэлементы (фрейм, размер, видимость, играет ли), их MediaSource и `SourceBuffer` (кодеки), признаки (реклама, DRM, MSE в воркере). Хранится в `storage.session` (service worker засыпает).
2. **Перехват MSE** на `document_start` во всех фреймах (MAIN-мир): `addSourceBuffer`, `appendBuffer`, `remove`, `abort`, `changeType`, `timestampOffset`, `endOfStream`, `duration`. Пока сеанс не открыт — только наблюдение, без копирования байтов. Открыт — байты идут в поток протокола со своим поколением.
3. **`<video src>`:** по способу 00c (Firefox — чтение ответа; Chrome — `fetch` из контекста страницы с `Range` по запросу плеера). Свой `<video>` страницы перестаёт качать: источник снят, элемент виртуальный.
4. **Виртуальный видеоэлемент** (вариант 00c): свойства и события элемента отдаются из состояния, которое присылает плеер — время, пауза, скорость, `buffered` из обратного давления (03), `readyState`, размеры, `getVideoPlaybackQuality`. Команды страницы (play, pause, seek) уходят плееру событиями. Перемотка из нашего плеера → `seeking` / `seeked` и `currentTime` для страницы → плеер страницы качает новые куски.
5. **Подмена кодеков** (решение 43): `MediaSource.isTypeSupported`, `HTMLMediaElement.canPlayType`, `navigator.mediaCapabilities` отвечают «нет» на AV1/VP9, когда плеер сказал «дёшев только H.264» или так выставлено в настройке. До первой загрузки плеера страницы — иначе он уже выбрал.
6. **DRM:** `requestMediaKeySystemAccess` вызван → вкладка помечена, перехват выключен, ничего не подменяется (инвариант 4).
7. **Реклама и мусор:** отдельный элемент рекламы (IMA SDK) не передаётся. Вшитая в поток реклама играет у нас (честное ограничение). Беззвучные баннеры, превью, короткие ролики — отсев (данные, а не код).
8. **Главное видео** (решение 8): играет сейчас > самое большое видимое > самое длинное > не реклама. Список всего найденного — для попапа (10).
9. **Страница — враг** (инвариант 1): лимиты на размер и частоту сегментов и событий, проверка формы. Мусор от страницы ломает только этот сеанс.
10. **Известные ограничения:** MSE в воркере, если 00c не нашла способ; плееры, которые не поверили виртуальному элементу. Такие сайты в попапе честно помечены «not supported yet».

## Тесты

- Модульные (TS) на модели вкладки, отсеве, угадывании, подмене кодеков, состоянии виртуального элемента — на записанных последовательностях событий стенда.
- **Стенд, оба браузера:** каждая MSE-страница и `<video src>` → **кадр в рендере** в браузерном режиме; браузер не декодирует (счётчик `getVideoPlaybackQuality` настоящего элемента не растёт / нет процесса декодера — способ из 00c); перемотка из плеера → страница докачивает → играет с T; ABR сменил качество → играет дальше; «зависло → перезагрузка плеера» на стенде не срабатывает.
- DRM-страница не трогается; реклама отдельным элементом не уходит в плеер.
- Подмена кодеков: стенд с выбором AV1 / VP9 / H.264 → при «только H.264» страница выбирает H.264.
- **Атака страницы:** гигантские сегменты, тысячи событий в секунду, мусор вместо fMP4 → сеанс закрывается с причиной, экстеншен и плеер живы.

## Поправки по итогам 00 (29.10.2026, решения 61–72)

- **Воркеры (решение 63):** обёртка `Worker`/`SharedWorker` в MAIN-мире внедряет хук в воркер (Twitch). Firefox MSE в воркере не поддерживает.
- **HLS (решение 64):** `canPlayType`/`isTypeSupported` для HLS → `""` в Chrome.
- **DRM (решение 65):** элемент с `setMediaKeys`/`encrypted` не трогаем; опрос ключевых систем — не признак.
- **Реклама (решение 66):** отдельный рекламный `<video>` не перехватывается. Смена MediaSource — новое поколение.
- **Сосуществование (решение 72):** хук корректен, если блокировщик или другой экстеншен подменил `MediaSource`/`SourceBuffer`/`URL.createObjectURL` раньше или позже нас. Тесты на оба порядка.

## Поправки по итогам 00c (29.10.2026, решения 81–84)

- **Муляж — «тень»** (решение 81). Устройство и ловушки — в `results/00c.md`:
  - свойства и методы `HTMLMediaElement` переопределяются на прототипе;
  - события настоящего элемента гасятся перехватом на `window` в фазе захвата;
  - подделываются `getVideoPlaybackQuality`, `requestVideoFrameCallback` и Chrome-счётчики `webkit*Decoded*`.
- **Обязательно:** настоящий элемент держать рядом с позицией муляжа (раз в 15 с, если отстал больше чем на 20 с). Иначе Chrome не может чистить буфер позади → `QuotaExceededError` у YouTube через ~7 минут фона. Альтернатива без декода — свой скрытый `remove()`.
- Перемотку муляжа ограничивать длительностью, на конце — `ended`.
- Синтетические события имеют `isTrusted = false` — следить в шмоне 21a.
- **`<video src>` качает background** с `Range`: из страницы и контент-скрипта чужой CDN без CORS не отдаётся.
- **m3u8 в `src` после нашего «не поддерживаю»** — экстеншен сам качает плейлист и сегменты через сеть браузера из background (решение 83). DW ушёл в MSE, такие сайты на эталоне не встретились; сделать по образцу простого HLS без DRM.
- **DRM:** Vimeo — `setMediaKeys` с ключами без события `encrypted`. Признак `setMediaKeys` обязателен.
- **Остаток браузера в муляже — цель экономии.** На 780M браузер в «тени» тратит 9–11 % ядра на YouTube (обычное проигрывание — 14–18 %). Fastiplayer рядом стоит ~4 %, так что остаток браузера решает, выиграет ли мост на машинах с аппаратным декодом (прикидка — в поправках 23). Что урезать и мерить до и после:
  - `timeupdate` и прочие синтетические события — не чаще, чем нужно плееру страницы;
  - тики часов — по изменениям, а не 4 раза в секунду всегда;
  - отчёты и журнал экстеншена — выключены в продукте;
  - передача байтов — без лишних копий: Firefox шлёт буфер как есть, Chromium — base64 только между контент-скриптом и background (решение 82);
  - перестановку настоящего элемента делать не чаще, чем нужно для чистки буфера.
