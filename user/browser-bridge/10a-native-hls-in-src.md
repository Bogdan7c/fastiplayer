# Сессия 10a: нативный HLS в `<video src>`

Добавлена 3 ноября 2026 в сессии 09b по решению владельца 185. Идёт после вехи M1 (сессия 10) и её не задерживает.

> Выполни сессию 10a плана `user/browser-bridge/`. Научи мост страницам, которые кладут плейлист m3u8 прямо в `<video src>`, хотя мы ответили «HLS не поддерживаю» (решения 64, 83). Фон экстеншена сам качает плейлист и сегменты через сеть браузера, плеер играет. Проверь на стенде 08 до кадра в рендере. Сначала прочитай `user/browser-bridge/README.md` (решения 37, 64, 83, 100–104, 185), этот файл, `results/09b.md`, `mem:browser-bridge/core`.

## Зачем

Решение 64: экстеншен отвечает `""` на `canPlayType` и `isTypeSupported` для HLS. Тогда плеер страницы уходит в MSE (hls.js), а MSE мы уже перехватываем. Но часть страниц кладёт m3u8 в `src`, не спрашивая браузер. Chrome 156 такой поток играет сам, и передать его нечем.

На эталоне такое не встретилось: DW ушёл в MSE (00c). Поэтому это не блокер вехи M1. С 09b такая страница получает честное «not supported yet», и видео остаётся в браузере.

## Что уже есть

- Плеер умеет HLS сам: `media-services`, нативный HLS VOD и live (`mem:media-services/native-hls-vod-n07-2026-09-01`, `mem:media-services/native-hls-live-n08-2026-09-01`). Это разбор плейлиста, выбор варианта, сегменты MPEG-TS и fMP4, перемотка.
- Мост умеет «байты по запросу» для `<video src>` (03c, 09b): плеер просит `fetch_range`, фон качает через сеть браузера с куками страницы.
- Фон экстеншена уже качает файл по адресу, который знает только экстеншен. Адрес в протокол не попадает.

## Развилка — решает владелец в начале сессии

1. **Плеер ведёт HLS, браузер только качает.** Наш HLS-движок плеера разбирает плейлист и просит каждый адрес (плейлист, сегмент, ключ) у экстеншена новым запросом протокола «дай этот ресурс». Фон качает его через сеть браузера.
   - Плюсы: переиспользуется готовый HLS-движок плеера: варианты, live, перемотка.
   - Цена: адреса сегментов идут через протокол, а не остаются только в экстеншене. Нужно правило «фон качает только адреса из плейлиста этого сеанса» (инвариант 1: страница — враг).
2. **Экстеншен ведёт HLS.** Фон разбирает плейлист, качает сегменты и шлёт их плееру потоком.
   - Цена: MPEG-TS не формат «сортировщика» (03a принимает fMP4 и WebM). Понадобится переупаковка или новый путь в источнике. Второй разборщик HLS — на TS.

Агент приносит факты (объём, риски) по обоим путям. Механизм подтверждается владельцем до кода (урок плана: пересказать главный механизм простыми словами и получить «да»).

## Стенд

- Страница `m3u8-in-src` из 09b: сейчас у неё честное «not supported yet». После 10a — кадр в рендере в Chromium. Firefox на Linux нативный HLS не играет: там остаётся `unsupported`.
- HLS live и HLS fMP4 — по возможностям генератора медиа стенда.
