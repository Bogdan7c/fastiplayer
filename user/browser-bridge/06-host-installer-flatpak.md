# Сессия 06: установка посредника, Flatpak и кнопка в настройках

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 06 плана `user/browser-bridge/`: плеер сам находит браузеры (пакеты системы и Flatpak), ставит посредника и файлы подключения, показывает статус в настройках («Connect to browsers») и предлагает подключение при первом запуске. Для Flatpak — путь и инструкция из `results/00.md`, для Snap — честное сообщение. Сначала прочитай `user/browser-bridge/README.md`, `results/00.md`, `results/05.md`.

## Зачем

Решения 21, 22, 26. Без простой установки фича мертва: обычный человек не будет руками класть JSON в скрытые папки.

## Что сделать

1. **Модуль установки** (новый, вне `app-egui`, например в `desktop-integration`; с владельцем — отдельный crate или нет):
   - каталог браузеров: имя, путь файла подключения (из 00), признак «найден» (есть папка профиля / бинарь / Flatpak-приложение);
   - установка: бинарь хоста в постоянное место (`~/.local/share/fastiplayer/browser-host/`), файл подключения с путём и ID экстеншенов, `.service`-файл D-Bus activation браузерного режима (02); атомарная запись (`atomic-file-store`); удаление;
   - статус по каждому браузеру: подключён / не подключён / нужен Flatseal / Snap не поддерживается / файл устарел (версия хоста не совпадает с плеером);
   - обновление: при новом плеере хост и файлы переписываются (версия в имени или в файле).
2. **Flatpak** (решение 22): файлы подключения в `~/.var/app/<id>/…` по итогам 00, хост — в папке, доступной песочнице. Статус «нужен Flatseal» определяется проверкой прав (`flatpak info --show-permissions`), а не догадкой.
   - Инструкция `docs/browser-bridge/flatpak.md`: 3 шага, скриншоты словами, без костылей.
   - Если Flatseal не хватает и нужен обход — стоп, владельцу на решение.
3. **Snap:** браузер распознан → статус «Snap browsers are not supported» и ссылка на справку. Ничего не ставим.
4. **Настройки:** раздел «Browser integration» — список браузеров со статусами, кнопки «Connect» / «Disconnect», ссылки на страницы экстеншенов в магазинах (пока заглушки до 24). Строится на существующей инфраструктуре настроек (`settings-core`), без раздувания `app-egui`.
5. **Первый запуск:** если найден хотя бы один браузер и мост не подключён — одно ненавязчивое предложение (уведомление с кнопкой). Отказ запоминается в config.
6. **Config:** новая секция `[browser_bridge]` — миграция схемы по существующим правилам (золотая фикстура, тест миграции).

## Тесты

- Установщик на фейковом `HOME`: правильные файлы в правильных местах для каждого браузера каталога; повторная установка не плодит дубликаты; удаление убирает только своё; битый существующий файл → перезапись с предупреждением.
- Flatpak-статусы на фейковом выводе `flatpak info`; Snap распознаётся по признакам и ничего не пишется.
- **Сквозной:** после установки в фейковый `HOME` запуск хоста по пути из файла подключения, как это делает браузер, → `OpenSession` + записанный поток стенда → кадры до рендера.
- Миграция config.
- **Хаос установки:**
  - домашняя папка с пробелами, кириллицей и кавычками в пути — файл подключения валидный JSON и браузер запускает хост;
  - профиля браузера ещё нет (браузер ни разу не запускали);
  - папка конфига — симлинк или доступна только на чтение → понятный статус, а не падение;
  - чужой файл подключения с нашим именем;
  - плеер перенесли или удалили — файл подключения указывает в пустоту → экстеншен показывает «not connected», а не висит;
  - две сборки плеера (dev и установленная) — кто владеет файлами и именем на шине, правило записать.

## Поправки по итогам 00 (29.10.2026, решения 61–72)

- **Firefox:** файл подключения — `~/.mozilla/native-messaging-hosts/`, Firefox 147+ читает только его (bug 2005167). Дополнительно пишется `$XDG_CONFIG_HOME/mozilla/native-messaging-hosts/` на будущее. Проверено: создание `~/.mozilla` не переключает корень профиля.
- **Flatpak (решение 69), проверено на Chrome 156:**
  - хост в `~/.var/app/<id>/…`, файл подключения в `~/.var/app/<id>/config/<браузер>/NativeMessagingHosts/`;
  - Flatseal: `talk-name=io.github.Bogdan7c.Fastiplayer.*` (маска покрывает и базовое имя, и под-имена; точное имя — только себя);
  - D-Bus activation `.service` в `~/.local/share/dbus-1/services/` поднимает плеер **снаружи** песочницы (systemd-юнит хоста), fd передаётся.
  - У многих пользователей Flatseal уже открывает полную шину — проверять и этот вариант.
- **Firefox Flatpak / Snap:** Firefox 157+ умеет `xdg-native-messaging-proxy` (Snap включает автоопределение), Flatpak-сборка Firefox — ещё нет (bug 2078349). Проверить на выпуске к моменту сессии.
- Распознавание Snap: `/proc/<pid>/cgroup` содержит `snap.<имя>.<app>-….scope`.

## Поправки по итогам 02 (29.10.2026, решения 87–89)

- `.service`-файл D-Bus activation собирает `desktop_integration::browser_session_activation_service_file(путь)`. Путь пишется в одинарных кавычках. Пути с апострофом, обратной косой чертой или управляющими символами отвергаются: dbus-daemon и dbus-broker толкуют их по-разному, а файл с `'\''` dbus-daemon молча пропускает. Установщик показывает человеку понятную причину.
- `scripts/install-desktop-entry.sh` уже ставит этот файл в `~/.local/share/dbus-1/services/`; `--uninstall` его убирает. Кнопка «Connect to browsers» делает то же из плеера.
- **Проверено вживую в 02 (dbus-broker, KDE):** новый `.service` dbus-broker сам НЕ подхватывает — звонок отвечает `ServiceUnknown`. После `ReloadConfig` на `org.freedesktop.DBus` активация работает. Установщик обязан вызвать `ReloadConfig` сам — `scripts/install-desktop-entry.sh` уже так делает (через `busctl`), кнопка «Connect to browsers» делает то же через zbus. На GNOME и Xfce проверить заново; путь с пробелом на dbus-broker тоже.
- Живая проверка активации на настоящей шине — ручной тест `live_session_bus_wakes_the_installed_browser_session` (`crates/app-egui/tests/browser_session_process.rs`, `--ignored`).

## Поправки по итогам 05 (2.11.2026, решения 153–156)

- Имя посредника и файла подключения — `browser_bridge_protocol::extension_identity::NATIVE_HOST_NAME` (`io.github.bogdan7c.fastiplayer.bridge`, файл `<имя>.json`). Разрешённые ID — оттуда же (`ALLOWED_EXTENSIONS`): установщик пишет `allowed_origins` (`chrome-extension://<ID>/`) и `allowed_extensions` из того же списка, а не из своих констант.
- Бинарь посредника — `fastiplayer-browser-host` (crate `browser-bridge-host`). Релизный — 4 МБ, только `libc` и `libgcc_s`, требует GLIBC 2.39 (рантайм Chrome 156 — 2.42). Для Flatpak-браузера сборку проверить под glibc рантайма.
- Во Flatpak в `path` файла подключения должен стоять сам бинарь внутри папки песочницы: скрипт-обёртка стенда 05 там не работает.
- Если Flatpak-сборка посредника упрётся в размер или библиотеки, клиент двери выносится из `desktop-integration` в свой crate (решение 155).
- Живая проверка Flatpak-Chrome — здесь: `talk-name=io.github.Bogdan7c.Fastiplayer.*`, экстеншен через CDP `Extensions.loadUnpacked`. Мини-экстеншен 05 для этого годится, но он вне репозитория — при необходимости собирается заново по описанию в `results/05.md`.
