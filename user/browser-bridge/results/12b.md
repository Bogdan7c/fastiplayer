# Результат сессии 12b: режим 2 — «Ask», правила в попапе и веха M2

## Статус

**DONE, веха M2 принята.** 8 ноября 2026. Вердикт владельца после своего круга: «я принимаю, проблем не обнаружил». Больше всего ему понравилось предложение «Play this video in Fastiplayer?» поверх видео.

Как это выглядит для человека:
1. **«Ask».** Сайт помечен «Ask» (или в настройке выбрано «Ask first» для новых сайтов). Человек нажал Play на видео, и видео замирает. Поверх него вопрос «Play this video in Fastiplayer?» и четыре кнопки: «Play in Fastiplayer», «Play here», «Always for this site», «Never for this site».
   - «Always» и «Never» записывают правило сайта и сразу выполняют его.
   - Предложение висит, пока человек не выберет. Повторный запуск самой страницей ничего не решает. Ушёл со страницы — предложение пропало.
   - После «Play here» то же видео на этой странице больше не спрашивает, пока страницу не перезагрузят или не откроют другое видео.
2. **Попап.** Правило текущего сайта: Default / Always / Never / Ask.
3. **Страница настроек.**
   - Свой стоп-лист (добавить, убрать).
   - Список своих правил сайтов.
   - Встроенный стоп-лист, только для чтения.
   - Раздел «Video filters» — появился по просьбам владельца во время вехи.
4. **Кто «запустил видео».** Видео уходит в плеер, только если человек кликнул мышью по самому видео и оно заиграло в пределах секунды. Так же, как раньше, уходит фильм после рекламы, по которой человек кликнул. Видео, которое страница запустила сама, и клик рядом (лайк, соседний пост) не считаются. Клавиши тоже не считаются.
5. **Фильтры видео.** По умолчанию в плеер уходит и беззвучное, и короткое, и зацикленное видео. У каждого из трёх фильтров есть галочка «On every site» и свой список сайтов, где он действует, даже если галочка снята.

Поправка к вопросу 258. В вопросе было сказано, что встроенный стоп-лист сильнее правил. Это неверно: своё «Always» сильнее встроенного списка (порядок 12a). Записано в решении 258.

Решения, принятые по ходу работы (владелец их не выбирал, они следуют из устройства):
- На вкладке живёт одно предложение. Новое предложение снимает прежнее.
- Если слой страницы не встал (не HTML-документ, нет `popover`), панель сама отвечает «Play here»: видео не должно висеть замершим без вопроса.
- Фон принимает выбор, если помнит предложение или если сайт вкладки сейчас помечен «Ask». Служебный процесс экстеншена (MV3) может уснуть между вопросом и кликом.
- Ключ сайта фон берёт только у отправителя сообщения (вкладка, фрейм), а не из полей сообщения.

## Как устроено

```
 страница (MAIN-мир)                     изолированный мир                   фон
 клик по видео → play()  ─►  сторож: охрана? клик по ЭТОМУ видео ≤ 1 с?
                             общие фильтры звука/цикла?
                             тень → донесение viewer_play ───────────────►  политика сайта + фильтры
                                                                            по адресу вкладки
                                                                            ├ hand_off → handOffTab
                                                                            ├ ask_viewer ─┐
                                                                            └ release      │
 видео замирает под тенью ◄── hold_for_viewer_offer ◄──── ответ ask_viewer ◄──────────────┘
 панель «Play this video…» (теневой слой изолированного мира, isTrusted-клик)
        выбор ─────────────────────────► viewer_offer_choice ─────────────►  правило сайта (Always/Never)
                                                                            + действие: в плеер / здесь
```

- **Предложение.**
  - Сторож получил третий исход задержки: держать видео под предложением (`holdForViewerOffer`).
  - Видео стоит ровно на паузе, страница видит «играю», как под тенью.
  - Снятие предложения возвращает видео странице, но отказ не запоминается: новый клик по видео — новый вопрос.
  - Модули: `page/viewer-offer-anchor.ts`, `content/viewer-offer-{relay,listener}.ts`, `content/page-ui/viewer-offer-{view,controller}.ts`, `background/auto-handoff/viewer-offer{s,-listener}.ts`, договор `shared/viewer-offer-contract.ts`.
- **Правки настройки** — чистые функции «настройка + намерение → новая настройка или отказ» (`shared/auto-handoff-settings-edits.ts`). Ими пишут фон (выбор на предложении), попап и страница настроек.
- **Фильтры видео** (`shared/video-filter-settings.ts`, фон — `background/auto-handoff/video-filters.ts`).
  - Охрана страницы знает только общие галочки звука и цикла.
  - Списки сайтов судит фон по адресу вкладки: изолированный мир адреса не знает, фрейм может быть чужим плеером.
  - Беззвучное короткое видео общий классификатор сам считает «украшением». Поэтому там, где фильтр звука не действует, фон судит задержанное видео как звучащее. Сам классификатор для кнопки и передачи вкладки не тронут.
- **Клик по видео** (`page/auto-handoff/viewer-activation.ts`, `viewer-play-watch.ts`).
  - Запоминается последнее доверенное нажатие основной кнопкой мыши с точкой на экране.
  - Запуск засчитывается, если точка внутри прямоугольника видео и нажатию не больше секунды.
  - Браузерная «временная активация» больше не читается.

## Находки

### Firefox: клик по нашей панели уходил кнопке «Картинка в картинке»

На стенде «Never for this site» в Firefox не нажималась: 6 прогонов из 6.

Корень: Firefox на каждый `mousedown` ищет видео под курсором (`PictureInPictureChild`, `nodesFromRect` с порогом видимости 1.0). Перекрытием он считает только **непрозрачный** слой. Панель была полупрозрачной, поэтому Firefox «видел» сквозь неё видео и отдавал клик своей кнопке у правого края видео.

Исправлено в корне: у панели сплошной фон. После этого 10 из 10. Ловушка записана в память: она касается любых наших контролов поверх видео, в том числе режима 3.

### Живой круг владельца на X

1. Много роликов в ленте короче 60 с и без звука, а владелец хочет отправлять их в плеер. Отсюда решения 260 и 261: фильтры выключаются, по умолчанию выключены, у каждого свой список сайтов.
2. После решения 261 часть роликов уходила в плеер «сама», как будто от наведения курсора, без закономерности.
   - Корень: запуском человека считался любой клик или клавиша на странице за последние ~5 с (решение 247).
   - Пока фильтр звука отсекал беззвучное, этого не было видно. Когда фильтр выключили, ролик, который лента запустила сама через долю секунды после лайка, стал «запуском человека».
   - Исправлено в корне (решение 262): засчитывается только клик по самому видео. Ряд стенда `click-beside-feed` повторяет случай: клик по «Like» под видео, лента сама запускает беззвучный ролик, ролик остаётся у браузера.
3. «Плеер всегда на полный экран» — не дефект. Окно моста помнит свой размер (решения 137–138). В настройках был записан 1920×1046, то есть экран без панели KDE. Скорее всего, этот размер появился, когда во время круга агента окно развернул скрипт KWin.

## Известные ограничения

- `page/shadow/shadow-session.ts` — 799 строк. Следующая правка тени должна выносить код в отдельный модуль.
- Если кнопка Play стоит вне видео (под ним), видео само не уйдёт: останется кнопка поверх видео (следствие 262).
- Если видео запускается после клика в другом месте страницы, оно само тоже не уйдёт. Например, YouTube после клика по превью запускает видео в браузере, а в плеер оно уходит по клику на Play на самом видео. Владелец этого и хотел.
- Бывает, что сайт кладёт свою кнопку Play в родительской странице поверх чужого iframe с плеером. Тогда клик достаётся родительской странице, а не фрейму с видео, и такой запуск не засчитается. Рабочий путь — кнопка поверх видео.
- Сайт в списке фильтра при выключенной галочке: охрана сначала задерживает видео, фон через мгновение отпускает. Видна короткая запинка.
- Для переезда сеанса (`next_video`) охрана по-прежнему не берёт зацикленные видео. Фильтр цикла касается только режима 2.
