## Находка 2: заголовок окна раньше, чем страница признана ушедшей

**Корень.** Заголовок вкладки уходил в окно сразу по `tabs.onUpdated`. Адрес и заголовок одной навигации браузер сообщает отдельными событиями и в любом порядке. Судить «новый ролик или уход страницы» можно только по обоим.

**Починка (экстеншен, `handoff/episode-change/page-title-gate.ts`).**
- Новый заголовок ждёт адрес той же навигации 1 с.
- Адрес с начала видео тот же — заголовок уходит в окно.
- Адрес сменился — заголовок ждёт нового видео. Если страница признана ушедшей, заголовок выброшен, окно досматривает ролик под прежним названием.
- Ждёт не дольше 8 с: новое видео могло начаться раньше смены адреса. Связь с допуском ухода страницы (5 с) закреплена тестом.

**Проверка.** Тесты на оба порядка «заголовок / адрес», на «видео началось раньше адреса» и на уход на главную; без починки они падают. Строка стенда `spa-away` требует, чтобы заголовок не пришёл. Живьём: см. таблицу ниже.

## Находка 3: после конца серии плеер играет её начало

**Что закрыто в 16a3 (не корень живого случая).** Команды страницы (перемотка, `play`) для источника, который страница уже поставила, но ещё не назвала, уходили в старую серию. Теперь они ждут первого события нового источника (`page/coming-source-commands.ts`). Тесты падают без починки. Строка стенда `episodes/instant-next` сторожит результат, но без починки тоже проходит, поэтому доказательством не считается.

**Живой корень (пойман 12 ноября, klonua / Ashdi, подробный журнал ядра).**
- 15:11:58.057 — серия 8 доиграла, ядро в `Ended`.
- +133 мс — ядру пришла команда `Seek(0)` для доигравшей серии. Ядро ушло в перемотку.
- +0,3 мс — пришла `Play` и переписала намерение перемотки на «играть». Серия 8 пошла с начала со звуком.
- +0,94 с — загружена серия 9.

Пара «перемотка на 0 + `play`» — то, что тень шлёт, когда страница зовёт `play()` у доигравшего элемента: для тени это повтор. Правило 16a2 («`play` после конца только запоминает волю») её не видит: к моменту `play` ядро уже не в `Ended`, а в перемотке. Отличить «повтор» от «страница ставит следующую серию» до объявления нового поколения плеер не может.

Длительность вспышки равна времени, за которое страница приносит следующую серию: 0,4 с на Tortuga (16a2), 0,5–0,9 с на klonua, 5,2 с в одном прогоне klonua (серия 6 → 7). Тот же перезапуск есть и в журнале 16a2 на klonua (13:17:36, 13:18:51); тогда его не заметили. На Tortuga в 16a3 переход серии 1 → 2 прошёл чисто (один прогон): сработало правило 16a2.

Порядок событий на самой странице (зовёт ли плеер сайта `play()` до смены источника) ещё не снят. Это следующий шаг, его можно сделать без машины владельца.

## Находка 1: YouTube в долго скрытой вкладке не переходит к следующему ролику

Не воспроизводится в нынешней сборке: 3 прогона из 3 под мостом чистые. Корень случая 16a2 не найден.

| Прогон | Итог |
|---|---|
| Без моста, звук выключен, вкладка скрыта 97 с | следующий ролик через 1,1 с после конца |
| Под мостом, вкладка скрыта 90 с (с датчиком) | следующий ролик через 1,5 с |
| Под мостом, вкладка скрыта 7 мин (с датчиком) | следующий ролик через 1,3 с |
| Под мостом, без датчика, ролик с начала, вкладка скрыта 7 мин 45 с (форма 16a2) | конец 14:50:49,8 → надпись ожидания через 2,1 с → новое поколение через 3,8 с |

Датчик — временный экстеншен владельца на время прогона: журнал таймеров, видимости и событий элемента страницы на `127.0.0.1`. Последний прогон сделан без него, чтобы датчик сам не будил вкладку. Первую попытку прогона без моста пришлось повторить: у YouTube был выключен автопереход; его включили.

Chrome (Flatpak): проверка отложена — в профиле Chrome нет экстеншена моста.
