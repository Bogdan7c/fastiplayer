# Итог сессии 10a: нативный HLS в `<video src>`

## Статус

**DONE на стенде, 7 ноября 2026.** Страница, которая кладёт плейлист m3u8 прямо в `<video src>`, передаёт видео в Fastiplayer и как запись (VOD), и как эфир (live). Браузер под тенью ничего не качает и не декодирует, каждый файл качает фон экстеншена сетью браузера по запросу плеера. Работа шла в три сессии:
- [10a1](10a1.md) — плеер и протокол;
- [10a2](10a2.md) — экстеншен, номерки и VOD;
- [10a3](10a3.md) — эфир.

## Выбранный путь и почему

**«Плеер ведёт HLS, браузер качает по номеркам»** (решение 228).

```
 страница <video src=…m3u8> ──► фон экстеншена: корень плейлиста → номерок №0
 плеер: готовый HLS-движок ── «дай ресурс №N» ──► фон качает сетью браузера (куки, Referer,
        ▲                                         заслон локальных адресов)
        └── плейлист с адресами-номерками ◄── переписчик (белый список тегов)
```

- **Переиспользуется готовый HLS-движок плеера** (`web-media-hls`): варианты, эфир, перемотка, MPEG-TS и fMP4, AES-128. Второй движок на TypeScript не нужен, два движка со временем вели бы себя по-разному.
- **Адресов плеер не видит.** Фон переписывает каждый плейлист: все адреса заменяются на номерки, а в плеер уходят только знакомые теги знакомого вида. Качает фон только по номеркам, которые выдал сам.
- **Сервер видит настоящий браузер:** куки, Referer, антибот — забота браузера, как везде в мосте (решение 37).
- Отклонены:
  - «экстеншен ведёт HLS» — второй разборщик и новый путь для TS в источнике;
  - «настоящие адреса в протоколе» — фону пришлось бы сверять каждый адрес плеера с плейлистами.

Эфир (решения 230–232) добавил одно новое понятие — **сопоставление часов**. У плеера в эфире свои часы, у страницы свои. Тень один раз считает разницу и дальше показывает странице «часы плеера + разница». Окно перемотки присылает сам плеер сообщением протокола 1.2, поэтому страница предлагает только ту перемотку, которую плеер правда может сделать. Эфир возвращается на страницу с игрой (решение 234): загруженный на паузе эфир встроенный HLS Chromium 156 потом часто не запускает — это ошибка самого браузера, проверено без экстеншена.

## Протокол

- **1.1** (10a1) — HLS-поколение: `hls_source_added`, `fetch_resource`, `resource_fetch_finished`, адрес-заглушка номерка.
- **1.2** (10a3) — эфир: `live_window`.

Новые сообщения уходят только собеседнику, который их знает. При старой общей версии страница получает прежнее честное «not supported yet».

## Стенд до кадра в рендере (Chromium 156)

| что | сценарий | итог |
|---|---|---|
| VOD MPEG-TS | `capture m3u8-in-src` | PASS, 242 кадра |
| VOD fMP4, мастер на 2 варианта | `capture hls-fmp4-abr` | PASS, 237 кадров |
| VOD TS + AES-128 | `capture hls-aes128` | PASS, 242 кадра, ключ скачан фоном |
| Команды VOD (пауза, play, перемотка, возврат на T) | `player-commands hls-vod-long` | PASS |
| Локальные сегменты со страницы из интернета | `local-address hls-local-segments-are-not-fetched` | PASS, 0 запросов фона к локальным |
| Эфир со скользящим окном | `hls-live` | PASS: 250 кадров под тенью, фон дошёл до сегмента 18 при начальном окне до 4, страница видит `Infinity` и окно, уехавшее на 30 с, возврат на эфир с игрой; 10 прогонов из 10 |

По каждой HLS-странице журнал сервера показывает три вещи:
- до передачи элемент запрашивал плейлист;
- под тенью элемент сделал 0 запросов;
- плейлисты, сегменты и ключи качал фон (`Sec-Fetch-Dest: empty`).

## Честные ограничения

- **Firefox на Linux** нативный HLS не играет: там видео нет, передавать нечего. Стенд считает это законным `unsupported`.
- **SAMPLE-AES и DRM не трогаем.** Ключ с чужой схемой получает номерок «отказ», плеер честно кончает.
- **Эфир возвращается с игрой**, даже если в плеере стоял на паузе: обход ошибки Chromium (решение 234). Пауза эфира на самой странице потом тоже иногда роняет движок Chromium — это поведение браузера на любой странице.
- **Эфир:** назад можно отмотать только то, что плеер скачал после передачи. После возврата шкала страницы начинается заново: это следствие возврата на эфир, а не на старую секунду.
- **Неизвестные теги плейлиста выбрасываются.** Если живой поток окажется без нужного тега, таблицы белого списка нужно расширить.
- **Живые сайты** с m3u8 прямо в `src` на эталоне не встречались: сайты на hls.js уходят в MSE, потому что экстеншен отвечает «HLS не поддерживаю». Проверено только на стенде.
- Подробности и мелкие ограничения — в отчётах 10a1, 10a2 и 10a3, открытые вопросы — общий бэклог, пп. 38–41.
