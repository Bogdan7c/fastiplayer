# Результат сессии 14b1: каркас адаптеров, две руки, меню и команды

**Статус:** DONE 9 ноября 2026. Коммиты `d90522ce`, `03820f6c`, `33359e9b`, `f062168d`.

## Что получил человек

Пока — на своей странице стенда «сериал»; адаптеры настоящих сайтов придут в 15. На этой странице уже работает вся цепочка:

- **Меню ♪ показывает озвучки сайта**, кнопка качества — его качества, кнопка Next появляется, когда у сайта есть следующая серия.
- **Выбор в нашем меню нажимает кнопку на странице.** Сайт сам качает новый поток, плеер возвращается на ту же секунду. На стенде выбор был на 6,0 с, плеер встал на 6,0–6,1 с.
- **Next открывает следующую серию в той же озвучке.**
- **Сломанный адаптер ничего не ломает:** видео играет обычным перехватом, меню просто нет.

## Решения владельца

- **284.** Выбор на самой странице тоже запоминается. Исключения: смена, которую сделала сама память, и стартовое «по умолчанию» серии. Делается в 14b2.
- **285.** В инкогнито память читается, но не пишется. Делается в 14b2.
- **286.** Сессия 14b разделена на 14b1 (каркас, руки, меню, стенд) и 14b2 (память, настройки, перезапуск браузера, инкогнито).

Полный текст — в [decisions.md](../decisions.md).

## Что сделано

**Переезд без смены поведения (отдельный коммит, правило 8):**
- `src/adapters/` разложен так:
  - `sites/<сайт>/` — паспорт, селекторы и способности одного сайта;
  - `capabilities/<способность>/` — общие контракты;
  - `registry/` — два реестра, по одному на мир страницы.
- Реклама 09d и именование субтитров 13b2 переехали туда же. Каждый бандл тянет только свой код: проверено по сборке.
- Смысл старых тестов не менялся, менялись только пути импорта.

**Каркас вариантов:**
- **Контракт** `VariantAdapter`:
  - `describe` → ключ сериала и серии (в плеер не уходят), озвучки, качества, «следующая серия есть»;
  - `select(kind, id)` и `next` → `done | no_such_variant | person_only | failed`.
- **Две руки (решение 282):**
  - **клик** — DOM фрейма в изолированном мире;
  - **рука-функция** — вызов функций плеера сайта в MAIN-мире по личному порту. Изолированный мир называет только имя действия из белого списка адаптера. MAIN-мир копирует результат в простые данные с лимитами глубины, узлов и длины строк. Пограничник проверяет ответ строго, у ответов свой бюджет, у вызова свой срок.
- **Наблюдатель во фрейме** `variant-watch.ts`:
  - включается арендой от фона: до передачи страница и фон молчат (решение 198);
  - чтения сливаются, не чаще раза в 250 мс; донесений не больше 4 в секунду; на каждом продлении — пульс;
  - сбой адаптера → «меню нет».
- **Фон** `variant-mirror.ts`:
  - главнее фрейм с видео сеанса;
  - подписи чистятся и режутся до лимитов протокола, негодные id и повторы выбрасываются;
  - `variant_menu_changed` и `page_navigation` (только плееру ≥ 1.7) уходят только при изменении;
  - `select_variant` уходит только для пункта из последнего меню и только во фрейм, приславший меню;
  - исход команды и паспорт адаптера (`bench-series@1`) пишутся в журнал разработчика.
- **Фасад** `session-site-adapters.ts` — одна точка, через которую сеанс говорит с рекламой и вариантами. `handoff-session.ts` остался ровно 800 строк.

**Протокол экстеншена:**
- `sanitizeVariantLabel` — та же чистка, что у заголовка страницы, предел 256 байт;
- `isValidVariantId` — правило id протокола: base64url, 1–64 байта.

**Стенд:**
- адаптер `bench-series` (живым сайтам не отвечает: только локальный хост и метка стенда);
- страница `series-variants`;
- сценарий `series`;
- тестовая переменная плеера принимает список выборов по очереди.

## Доказательства

- **Экстеншен:** 2845 тестов. Новые — на реестры, договор руки, клиент руки (флуд, мусор, загрязнение прототипа, срок), исполнитель (белый список, ловушки страницы, вечное обещание), мост MAIN-мира, наблюдатель, адаптер стенда на фикстуре с обеими настоящими руками, нормализацию (всё проходит кодек протокола), сеанс.
- **Проверка проверок:** код ломали нарочно 14 раз, каждую поломку поймал тест. Одна нашла слабый тест приоритета фрейма: видео стояло во фрейме 0, и правило «наименьший номер» совпадало случайно. Тест переделан.
- **Стенд `series`, Chromium и Firefox — 4 из 4 PASS:**
  - меню у плеера;
  - 720p из нашего меню → окно показало 720p;
  - Dub B → страница начала с нуля, плеер встал на 6,0–6,1 с, кадры растут;
  - Next → серия 2 в Dub B, кадры растут;
  - сломанный адаптер → кадры есть, меню нет.
- **Регресс стенда — 18 из 18 PASS** (обе стороны общей проводки рекламы и сеанса): `capture` (`series`, `ad-skip`, `ad-skip-never`, `ad-skip-trusted`), `quality`, `page-subtitles`.
- **Ворота:** `npm run check`, `cargo fmt`, `clippy --workspace -D warnings`, ограничители размера и границ — чистые.

## Известные ограничения

- **Живых сайтов ещё нет:** адаптеры YouTube, Twitch и украинских сайтов — сессия 15.
- **`person_only`** пока только строка в журнале. Подсказку зрителю даст сессия 15 вместе с YouTube.
- **id варианта** у адаптера настоящего сайта должен быть в алфавите base64url. Подпись на кириллице идёт в `label`, ключом может быть номер пункта.
- **Адаптер стенда едет в продуктовой сборке** — он маленький и честный: отвечает только локальному хосту с меткой стенда.
- **`subtitle_choice` от плеера** экстеншен пока пропускает: память выбора — 14b2.
- **На пределе:** `handoff-session.ts` — 800 строк. Новое подключение — только через фасад `session-site-adapters.ts`.
