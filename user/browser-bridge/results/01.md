## Решения владельца (29.10.2026; в README — 85–86)

1. **Посредник — только «звонок в дверь»** (решение 85). Он будит плеер и выдаёт порт с одноразовым пропуском. Всё живое идёт напрямую по WebSocket из background экстеншена в процесс браузерного режима: байты, MSE-события, часы, команды, события страницы, позже геометрия режима 3.

   По дороге владелец спросил: почему не связать браузер с плеером напрямую или не сделать посредником сам плеер? Ответ:
   - экстеншен не умеет запускать программы, единственная дверь наружу — native messaging;
   - всё, что запускает браузер из Flatpak, живёт в его песочнице, а полный плеер там не работает: другие библиотеки, нет нормального доступа к GPU и звуку, другая домашняя папка;
   - поэтому посредник — крошечная программа, которая лишь будит настоящий плеер снаружи.
2. **Версии — «договорились, значит строго»** (решение 86):
   - в `hello` стороны договариваются о `major.minor`;
   - более новая сторона говорит на языке общей версии;
   - получатель отвергает незнакомое с точной причиной, молча ничего не теряется.

## Архитектура простыми словами

```
 экстеншен ── native messaging ──► посредник ── D-Bus ──► плеер
     «вход»: hello → hello_accepted;  open_session → session_granted (порт + пропуск) | refused

 background экстеншена ════ WebSocket 127.0.0.1 ════► процесс браузерного режима
     «сеанс»: attach(пропуск) → attached; дальше текстовые рамки (JSON) и двоичные (куски байтов)
```

- **Экстеншен** — единственный источник правды о странице: что делает плеер страницы с MSE, где позиция, что в меню озвучек.
- **Посредник** понимает только два сообщения «входа». Он может умереть посреди фильма — сеанс продолжится (инвариант 3).
- **Плеер** ведёт часы (`clock` 4 раза в секунду) и командует страницей: play, пауза, перемотка, скорость, «вернуть», вариант меню, Next, «дай байты X–Y» для `<video src>`.
- **Протокол** ничего не знает о D-Bus, stdio и сокетах — это шов под Windows. Транспорт делают сессии 02 и 05.

## Схема сообщений

Все JSON-сообщения — объекты с полем `type` в snake_case. Варианты внутри сообщений помечены полем `kind`. Время — целые микросекунды, скорость — тысячные доли (1000 = 1×).

**«Вход», экстеншен → плеер** (`ExtensionControlMessage`):

| `type` | Что |
|---|---|
| `hello` | версия протокола, версия программы, метки возможностей |
| `open_session` | номер запроса, ключ сеанса, домен и заголовок, намерение (`window` / `picture_in_picture` / `in_page`), подсказки (длительность: `unknown` / `finite` / `live`, позиция) |

**«Вход», плеер → экстеншен** (`PlayerControlMessage`):

| `type` | Что |
|---|---|
| `hello_accepted` | общая версия и `hello` плеера; метки `cheap_codec.*` — дешёвые кодеки для решения 43 |
| `session_granted` | порт, пропуск, итог: `started` / `reused_existing` / `replaced_previous` |
| `refused` | на что отказ и причина: плеер недоступен, не отвечает, завершается, DRM, версия (кого обновить), кодек, битое сообщение (точный вид), `hello` не было |

**«Сеанс», экстеншен → плеер** (`PageSessionMessage`):
- `attach`;
- MSE: `generation_started`, `source_buffer_added` (MIME с кодеками), `source_buffer_type_changed` (`changeType`), `timestamp_offset_changed`, `source_buffer_removed` (`remove`, конец `at` или `end_of_timeline`), `source_buffer_aborted` (`abort`), `duration_changed`, `end_of_stream`;
- `seek_started` — кто перематывает (плеер с номером или страница) и куда;
- `page_playback` — страница сама вызвала play / pause / скорость;
- `variant_menu_changed` — меню адаптера: озвучки, качества, субтитры;
- `range_fetch_finished` — итог запроса байтов `<video src>`;
- `tab_gone`.

**«Сеанс», плеер → экстеншен** (`PlayerSessionMessage`): `attached`, `clock`, `buffer_state` (обратное давление `accepting` / `full`), `play`, `pause`, `seek`, `set_rate`, `return_to_page` (позиция + играть/пауза), `select_variant`, `next_episode`, `fetch_range`, `stream_rejected` (DRM в init-сегменте, кодек, нечитаемые байты).

**Закрытие сеанса** — код WebSocket 4000–4008:

| Код | Причина |
|---|---|
| 4000 | человек закрыл плеер |
| 4001 | заменён видео из другой вкладки |
| 4002 | вкладка ушла |
| 4003 | нарушение протокола |
| 4004 | чужой пропуск |
| 4005 | нет такого сеанса |
| 4006 | плеер завершается |
| 4007 | `attach` не пришёл вовремя |
| 4008 | к сеансу уже подключено другое соединение |

## Поток данных

Двоичная рамка WebSocket — 24 байта заголовка little-endian + 1 байт … 1 МиБ груза. Base64 нет.

| Смещение | Вид 1: байты SourceBuffer | Вид 2: байты `<video src>` |
|---|---|---|
| 0 | вид рамки | вид рамки |
| 1–3 | флаги и резерв = 0 | флаги и резерв = 0 |
| 4 | поколение (u32, от 1) | номер запроса (u32) |
| 8 | индекс SourceBuffer (u16, 0–7), резерв | смещение в файле (u64, ≤ 2⁵³ − 1) |
| 16 | порядковый номер (u64) | резерв = 0 |

Правила (сторож `StreamGate`, инвариант 6):
- **Поколение** — новый `MediaSource`: реклама, ролик, серия, озвучка. Первое — 1, дальше ровно +1, объявляется до своих сообщений.
  - Старшее поколение — молча выбросить.
  - Необъявленное — нарушение протокола.
- **SourceBuffer** объявляется до своих байтов и только один раз.
- **Порядковые номера** идут подряд с 0 для каждого SourceBuffer поколения. Пропуск — нарушение: кусок потерян.
- **Перемотка — событие, а не поколение, и байты она не выбрасывает.** Это уточнение инварианта 6, найденное при проектировании сторожа:
  - сначала я пометил каждую рамку номером перемотки и выбрасывал «старые»;
  - у Twitch `MediaSource` живёт в воркере, а перемотка случается на элементе в главном потоке, и кусок сразу после перемотки воркер может пометить старым номером, хотя он уже новый;
  - поэтому разрыв времени приёмник видит по меткам времени в байтах — так же, как MSE в самом браузере;
  - сброс разбора — отдельное `source_buffer_aborted`.

  Совпадает с находкой 00c: «разрыв внутри поколения — метка».
- Поколение куска определено точно: каждый SourceBuffer принадлежит одному `MediaSource`.

## Версии и совместимость

- `CURRENT_PROTOCOL_VERSION = 1.0`. Внутри `major` новая `minor` только добавляет сообщения, поля и значения.
- `negotiate_protocol_version(player, extension)`:
  - тот же `major` — меньшая `minor`;
  - разные `major` — `IncompatibleVersion { update: extension | player }`.
- Форма `hello` и отказа по версии не меняется никогда: иначе стороны не договорятся о том, что они разные.
- Разбор строгий:
  - лишнее поле, незнакомый `type` или значение, повтор поля, массив вместо объекта, дробь вместо целого — каждое со своим видом причины (`MessageErrorKind`);
  - незнакомые метки возможностей в `hello` пропускаются — это единственное исключение.
- Резервные байты рамки обязаны быть нулями: будущая `minor` займёт их, но старой стороне такие рамки не пошлют.

## Лимиты

| Что | Лимит | Почему |
|---|---|---|
| JSON-сообщение | 128 КиБ | худшее меню 256 × 256 байт ≈ 80 КиБ; в 8 раз меньше предела native messaging от хоста (1 МиБ) |
| Груз рамки | 1 МиБ | большой `appendBuffer` экстеншен режет сам, плееру границы кусков не важны; память приёмника предсказуема |
| SourceBuffer в поколении | 8 | на эталоне 1–2 |
| Заголовок страницы | 1024 байта UTF-8 | только для подписи окна |
| Домен | 253 байта | предел DNS |
| MIME | 256 байт | реальные короче 64 |
| Ключ сеанса, ID варианта | 64 байта base64url | |
| Пропуск | 32–128 байт base64url | ≥ 192 бит случайности |
| Вариантов в меню | 256 | 24 дорожки YouTube, десятки озвучек |
| Меток возможностей | 64 по 64 байта | |
| Запрос `<video src>` | 16 МиБ за раз | несколько секунд даже 4K |
| Целые в JSON | ≤ 2⁵³ − 1 | точные целые JavaScript |
| Скорость | 0,063×–16× | диапазон браузеров |

Сколько буфера держать (около 2 минут), решает плеер своими настройками в 03, а не протокол.

**Строки** — отдельные типы, обойти проверку нельзя:
- текст для человека — любой Unicode: эмодзи, кириллица, арабский, иврит, CJK, метки направления U+200E/F, соединитель U+200D;
- в нём запрещены управляющие символы (включая нулевой байт, табуляцию, перевод строки), U+2028/2029 и символы переворота направления U+202A–202E, U+2066–2069 — ими подделывают надписи;
- машинные строки — узкий ASCII.

Пропуск не печатается в журнал отладки и сверяется за постоянное время (`SessionToken::matches`).

## Известные ограничения

- **Геометрия режима 3 — заготовка.** Зарезервирована метка возможности `feature.page_geometry`. Сообщения (прямоугольник видео, область страницы, зум, калибровка, видимость, оверлеи, хоткеи, PiP, опознание окна браузера — список в `results/00a.md`) появятся в 17–19 как `minor` 1.1. Замораживать их форму до прототипа на настоящем рендере рано.
- **`mode = "sequence"` и `appendWindowStart/End` SourceBuffer не передаются.** На эталоне не встречались. Если появятся — новое сообщение в `minor`.
- **TS-половины ещё нет** — сессия 07. Фикстуры готовы для неё.
- Вид отказа «лишнее / недостающее / повторное поле» восстанавливается по началу текста ошибки serde: типизированного вида serde не даёт. Формулировки стабильны много лет, а смену сразу поймают фикстуры — на каждый вид есть своя.
- `SessionToken` сравним и через `==` (нужно для тестов сообщений). Плеер обязан сверять пропуск только `matches`.
- Протокол проверен тестами, но не на живом браузере: транспорт и экстеншен — 02, 05, 07.
