## Решения владельца (29.10.2026, эта сессия; в README — 73–75)

1. **KDE X11 из зоопарка убран.** Plasma 6.8 работает только на Wayland: сеанса X11 и пакета `kwin-x11` больше нет. Путь X11 проверен здесь через Xwayland, настоящий X11 — Xfce на T410 в 00b.
2. **«Наклейка» = окно размером с видимую часть родного плеера страницы.** Человек должен ощущать, будто плеер сайта подменили. Окно меняет форму по видимой области плеера: картинка обрезается, а не сжимается, и каждый пиксель видео остаётся там, где был бы на странице. Это **фича плеера**, а не трюк с окном. Работать она должна везде, а не только в KWin; переносимость — задача 17.
3. **Экстеншен — единственный источник геометрии**, плеер исполняет. Ставить окно в точку экрана будет тонкий бэкенд размещения под стол. Окно остаётся на winit: на Wayland клиент не может сам выбрать своё место на экране, и это правило протокола, а не ограничение winit.

## Как устроен прототип

Одноразовый код в scratchpad, в репозиторий не попал. Цепочка:

```
страница (тестовый стенд: видео 960×540 с голубыми маркерами по краям, автопрокрутка)
  → экстеншен MV3: прямоугольник видео каждый кадр, пока страница движется, иначе раз в 0,5 с
  → посредник native messaging (Python)
  → Unix-сокет → окно-заглушка (winit + softbuffer, тестовый узор с зелёной рамкой по краям видео)
       ├─ само считает видимую часть, обрезку и свой размер
       └─ KDE Wayland: публикует цель по D-Bus, KWin-скрипт долгим опросом забирает её и ставит окно
          X11: ставит себя само (`set_outer_position`)
```

Отставание мерилось двумя способами:
- **скриншоты при постоянной скорости прокрутки** — расстояние между голубым маркером страницы и зелёной рамкой нашего окна, 4 px = 1 кадр при 240 px/с;
- **метки времени** на каждом звене цепочки.

## Находки (уроки для боевого кода)

1. **KWin `callDBus` передаёт числа JS как `int32`.** Метод с сигнатурой `t` (u64) D-Bus отклоняет, а обратный вызов скрипта при ошибке **не вызывается вовсе**: скрипт молча зависает. Контракт «скрипт ↔ плеер» должен идти строками, плюс сторожевой таймер в скрипте.
2. **`Script.run` после повторной загрузки скрипта в KWin 6.8 ничего не делает.** Работает `org.kde.kwin.Scripting.start`.
3. **В KWin 6 у `workspace` нет сигнала `stackingOrderChanged`**, он есть только у окна. Держать наше окно над браузером приходится через сигналы окна браузера и `raiseWindow`.
4. **Начало области страницы внутри окна браузера нельзя вычислить по `outer`/`inner`:** формула ошиблась на 16 px. Точный источник — любое событие мыши над страницей: `screenX − clientX − window.screenX` (и так же по Y). Нативный Wayland-Chromium считает координаты от края своей поверхности **вместе с тенью CSD**, поэтому в KWin нужен `bufferGeometry`, а не `clientGeometry`. С калибровкой мышью совпадение — пиксель в пиксель на обоих путях.
5. **winit 0.30 на Wayland не умеет `set_visible`:** вызов ничего не делает. Прятать окно должен композитор (свернуть) или само окно — пересозданием.
6. **KWin активирует новое окно**, и наше окно забирает фокус клавиатуры у страницы. Окно «Наклейки» обязано не принимать фокус и не попадать в Alt+Tab и панель задач.
7. **Браузер владельца может работать через Xwayland.** Chromium из-за личного конфига флагов шёл под X11 внутри Wayland-сеанса. Мост не может считать, что браузер нативный: бэкенд размещения обязан различать окна Wayland и X11 (у KWin это свойство окна).
8. **Фоновая вкладка ненадёжно сообщает, что её спрятали:** таймеры и rAF там заморожены. Видимость вкладки должен вести service worker экстеншена (`tabs.onActivated`, `windows.onFocusChanged`), а не только сама страница.
9. **Позиция и картинка нашего окна обновляются в разных кадрах.** KWin двигает окно сразу, а новую картинку с обрезкой окно показывает кадром позже. Отсюда 1–3 кадра против 0–1 на X11, где окно двигает себя само и рисует в том же цикле. `layer-shell` это подтвердил: одним commit — стабильно 1 кадр.
10. **Панели браузера сдвигают область страницы внутри окна, и страница этого «не видит» как своё движение.** Это панель закладок, полоса загрузок, инфобары, поиск по странице, боковая панель. Прямоугольник видео относительно области страницы не меняется, меняется только её начало в окне. Калибровка мышью это ловит, но лишь когда мышь пройдёт над страницей. До этого окно стоит со сдвигом на высоту панели. Признак «калибровка устарела» есть: событие `resize` у страницы при неизменном `outer`. Тогда окно надо прятать до новой калибровки или сдвигать по разнице `inner`; второе однозначно только для панелей сверху.

11. **`layer-shell` висит над всеми обычными окнами.** Для «Наклейки» это значит: прятать слой или вырезать из него область, когда браузер перекрыт чужим окном. Знает об этом только композитор (у KWin — порядок окон и их геометрия).
12. **В «Театре» фокус решает выход.** Если фокус у браузера, клавиши уходят странице. Значит, либо окно «Театра» берёт фокус само (это основная поверхность), либо экстеншен пересылает клавиши плееру. А чтобы при выходе снять страницу с паузы, нужна обратная команда «плеер → страница».

## Требования режима 3 к протоколу (вход для 01)

- **Геометрия главного видео:**
  - прямоугольник в CSS-пикселях относительно области страницы (может выходить за край);
  - размер области страницы, `devicePixelRatio`/зум, `visualViewport`, фуллскрин страницы;
  - `seq` и метки времени.
- **Частота:** каждый кадр, пока страница движется (около 57 сообщений/с), иначе редкий пульс. Канал «страница → плеер» стоит меньше 1 мс.
- **Калибровка начала области страницы в окне** по событию мыши, с состоянием «откалибровано / ещё нет / устарела». «Устарела» — это `resize` области страницы при неизменном `outer` (панель браузера, находка 10), смена зума. Калибруется на каждом движении мыши, а не только на первом.
- **Видимость вкладки и окна от service worker:** вкладку сменили, окно браузера свернули, другой рабочий стол.
- **Событие «страница показала своё меню или оверлей над видео».** Иначе меню качества и озвучек сайта будет скрыто нашим окном. Альтернатива — адаптеры (14).
- **Хоткеи:** фокус остаётся у страницы, экстеншен пересылает пробел, стрелки и F плееру (решения 6, 58).
- **Запросы режима:** PiP (обычный и `documentPictureInPicture`), «Театр», фуллскрин.
- **Обратный канал «плеер → страница»:** пауза и продолжение при входе и выходе из «Театра», возврат.
- **Опознание окна браузера** для бэкенда размещения: pid процесса браузера (родитель посредника) плюс заголовок вкладки. Риск: у браузера из Flatpak посредник в песочнице, и pid родителя — из чужого пространства имён процессов.

## Требования к управлению окном (вход для 17)

- **Фича плеера «окно = видимая часть родного плеера»** (решение 74): обрезка без масштаба, размер окна по видимой области, без зависимости от стола.
- **Нейтральный бэкенд размещения** с операциями:
  - поставить окно в абсолютную точку;
  - держать над окном браузера, но не над всеми;
  - спрятать и показать без пересоздания окна;
  - «поверх всех» для PiP;
  - геометрия от композитора для «Театра»: плеер принимает размер, а не навязывает свой.
- **Окно «Наклейки» без фокуса, без Alt+Tab и панели задач**; окно PiP — по решению 17.
- **Бэкенд KWin:** скрипт с долгим опросом по D-Bus (строковый контракт, сторожевой таймер, `Scripting.start`), `bufferGeometry` для CSD-браузеров, порядок окон через сигналы окна браузера, возврат фокуса.
- **Бэкенд X11:** окно ставит себя само по `screenX/Y` плюс калибровка, `AlwaysOnTop` для PiP.
- **Атомарность:** на KWin-пути позиция и картинка расходятся на кадр (1–3 кадра). `layer-shell` даёт стабильно 1 кадр, но висит над всеми окнами. Это кандидат в основной бэкенд на KDE только вместе с правилом «прятать, когда браузер перекрыт» (по данным KWin-скрипта). Выбор — вердикт 00b.
- **«Театр»:** размер даёт композитор; окно берёт фокус или экстеншен пересылает клавиши; Esc и наши контролы — выход.
- GNOME — вердикт 00b.

## Известные ограничения разведки

- Отставание «Наклейки» мерилось на автопрокрутке страницы (`scrollTo` каждый кадр). Прокрутку колесом скриншоты не поймали: снимок занимает около 0,5 с, а анимация колеса короче. В покое после колеса окно совпадает.
- Скриншоты сняты на 60 Гц; на 144 Гц и с VRR не проверялось.
- Ресайз окна браузера проверен по шагам через KWin-скрипт: результат виден после каждого шага, а промежуточные кадры живого перетаскивания края мышью не сняты.
- Анализ отставания по скриншотам проверен вручную по шести снимкам. Перед отставанием стояла постоянная ошибка калибровки 16 px, и её отделили замером в покое.
- Прототип iframe (same-origin) собран, но не запускался.
- «Показать рабочий стол» не проверено: вызов KWin `showDesktop` по D-Bus окна не спрятал.
- Пауза видео страницы при входе в «Театр» поставлена экстеншеном, но глазами не проверена: страницу закрывает наше окно.
- Перетаскивание и ресайз окна браузера делались KWin-скриптом по шагам, а не живым перетаскиванием мышью.
