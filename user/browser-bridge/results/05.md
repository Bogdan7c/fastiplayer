# Результат сессии 05: посредник `fastiplayer-browser-host`

## Статус

**DONE.** 2 ноября 2026. Посредник native messaging — «звонок в дверь» (решение 85) — готов и проверен живьём. Браузер запускает его, посредник:
1. проверяет, что позвал наш экстеншен;
2. передаёт `hello` и `open_session` в дверь D-Bus браузерного режима (плеер просыпается сам);
3. возвращает браузеру порт и пропуск WebSocket;
4. выходит, когда браузер закрывает порт.

Видео, команды и события сеанса идут мимо посредника, напрямую по WebSocket. Посредник можно убить посреди фильма, и плеер доиграет: это проверено тестом.

Живая проверка на экране владельца (KDE Wayland, основной компьютер). Тестовый мини-экстеншен через настоящего посредника будил плеер и гнал в него записанный 20-секундный ролик со счётчиком кадров:

|---|---|
| Chromium 156, временный профиль | ✅ окно плеера, видео (владелец видел); 500 из 500 кадров на показе, звук 20 с; посредник вышел с кодом 0 после закрытия браузера, сирот 0 |
| Firefox 158 | ✅ то же: окно и видео (владелец видел), 500 из 500 кадров, посредник вышел сам, файл подключения после проверки удалён |

## Решения владельца (2.11.2026; в README — 153–156)

1. **Механизм подтверждён до кода (153):** браузер запускает посредника → тот проверяет ID экстеншена → передаёт `hello` / `open_session` в дверь D-Bus (будит плеер) → возвращает порт и пропуск → выходит по закрытию входа. Видео и команды идут мимо него.
2. **Список «наших» экстеншенов фиксируется сейчас и вшит в код (154).** Для Chrome создан ключ разработки: его публичная часть пойдёт в поле `key` манифеста экстеншена (07), и ID всегда будет `mcikhhmaenodlfkafgehbkikilmpnpji`. Закрытый ключ не нужен (магазин подписывает сам) и не хранится. Для Firefox выбран ID `fastiplayer-bridge@bogdan7c.github.io`, он же пойдёт в AMO. ID из Chrome Web Store добавится в 24. Вариант «список в файле установщика» отклонён: посредник не доверяет файлам на диске.
3. **Клиент двери D-Bus берётся из `desktop-integration` как есть (155).** Граница не меняется. Лишнего мало: zbus и маленький `media-core`, без egui и wgpu. Если Flatpak-сборка (06) упрётся в размер или библиотеки, клиент вынесем отдельной правкой.
4. **Живая проверка — мини-экстеншен и записанный ролик (156).** Прототип 00c и робот стенда 03b жили вне репозитория и пропали вместе с временной папкой. Мини-экстеншен проверяет именно посредника во всех браузерах; перехват YouTube — работа 07 и 09.

Решения агента (владелец получил их до кода и не возражал):
- ответ плеера `refused{hello_required}` после его перезапуска посредник передаёт экстеншену как есть, а `hello` сам не повторяет — посредник остаётся тонким;
- имя посредника для браузеров — `io.github.bogdan7c.fastiplayer.bridge`: Chrome разрешает в нём только строчные буквы.

## Что сделано

| Что | Где |
|---|---|
| «Кто наш экстеншен»: имя посредника, ID Chrome и Firefox, проверка «разрешён ли ID в этом семействе браузеров» | `browser-bridge-protocol/src/extension_identity.rs`, фикстура `fixtures/extension-identity.json` (публичный ключ Chrome) |
| Новый crate посредника, бинарь `fastiplayer-browser-host` | `crates/browser-bridge-host` |
| `caller` — кто позвал: Chrome `chrome-extension://ID/` (на Windows ещё `--parent-window=`), Firefox `[путь файла подключения, ID]`; чужой → выход до шины | `src/caller.rs` |
| `framing` — рамки «4 байта длины в порядке машины + JSON»: от браузера ≤ 128 КиБ (больше → закрыть порт, тело не читается), к браузеру ≤ 1 МиБ | `src/framing.rs` |
| `door` — шов к плееру (trait `PlayerDoor`); Linux — клиент D-Bus, соединение открывается при первом звонке и одно на все звонки; другие ОС — `UnsupportedPlatform` | `src/door.rs` |
| `relay` — строгий разбор `hello` / `open_session`, исходный JSON в дверь, строгая проверка ответа плеера, свои отказы с точной причиной | `src/relay.rs` |
| `host` и `log` — цикл до закрытия входа, коды выхода, журнал в stderr только из видов, размеров и причин; закрытый stderr посредника не роняет | `src/host.rs`, `src/log.rs` |
| Сторож зависимостей: посреднику можно только протокол, `desktop-integration` и `thiserror` | `scripts/check-refactor-guardrails.py` + тест, `scripts/ci-checks.sh` |

Свои отказы посредника:

| Что случилось | Браузер получает |
|---|---|
| Не JSON, чужой тип, лишнее поле, пустая рамка | `refused{in_reply_to: unparsed_message, reason: malformed_message{вид}}`, порт жив |
| Плеер не установлен, не запустился, шины нет, имя держит чужой пользователь | `refused{player_unavailable}` |
| Плеер не ответил за 8 с | `refused{player_not_responding}` |
| Плеер завершается | `refused{player_shutting_down}` |
| Плеер ответил непонятным | `refused{player_unavailable}`, подробность — в stderr |

Коды выхода: 0 — браузер закрыл вход; 2 — чужой экстеншен; 3 — битая рамка; 4 — ответ не записан; 5 — внутренняя ошибка.

Пункты исходного плана 05, снятые решениями 82 и 85, не делались: данные в fd, обратное давление, «порт закрыт → вкладка ушла плееру», «плеер закрылся → событие в браузер». Всё это идёт по WebSocket мимо посредника.

## Доказательства

**Модульные тесты** (`cargo test -p browser-bridge-host`, 46):
- рамки: склейка, разрез по байту, нулевая длина, ровно предел и на байт больше, `u32::MAX` без чтения тела, обрыв в префиксе и в теле, прерывание сигналом, ошибка ОС, ответ ровно 1 МиБ и больше;
- кто позвал: свои ID обоих браузеров, чужие, ID Firefox внутри origin Chrome, кривой origin, лишние и не-UTF-8 аргументы;
- перевод каждой ошибки клиента D-Bus в свой отказ; шины нет → «недоступен» и повтор без кэша мёртвого соединения;
- `relay`: что уходит в дверь (ровно исходный JSON), мусор не доходит до двери, битый ответ плеера не доходит до браузера.

**Fuzz** (`tests/property.rs`, свой xorshift, 2 × 3000 прогонов): случайные рамки, длины, разрезы, прерывания и ответы двери. Каждый прогон:
- кончается предсказанным типизированным выходом;
- даёт ровно один валидный ответ на каждую целую рамку;
- не читает вход дальше нужного;
- звонит в дверь только строго валидными сообщениями.

Мутация (временно снят предел длины) → тест падает.

**Настоящий бинарь без плеера** (`tests/binary.rs`, 5). Вместо шины — слушающий сокет, по нему видно, подключался ли посредник. Проверено:
- чужой экстеншен → код 2, к шине не подключался;
- браузер сразу закрыл порт → код 0, к шине не подключался;
- плеера нет → `player_unavailable`;
- закрытый stderr не меняет ответ;
- объявленные 64 МиБ → код 3 по одному префиксу.

**Сквозные тесты с настоящим плеером** (`app-egui/tests/browser_session_process/native_host.rs`, 6). Частная шина будит `fastiplayer --browser-session`, тест играет роль браузера:
- посредник выдал пропуск и вышел по EOF; сеанс по пропуску играет записанный поток — `presented_frames = 10`, откатов позиции 0;
- посредник убит `SIGKILL` посреди потока — плеер доигрывает до конца, 10 кадров;
- два посредника сразу (Chromium и Firefox): вторая вкладка заменяет первую (код 4001), ответы не путаются (`request_id` 1 и 2, разные пропуски);
- плеер ушёл между звонками → тот же посредник честно отдаёт `hello_required`, после нового `hello` снова выдаёт пропуск;
- чужой экстеншен → код 2, плеер не просыпался;
- мусор → отказ `unknown_type`, порт жив, `hello` после него принимается.

Мутация (посредник выходит сразу после проверки вызывающего) → падают 5 из 6. Шестой (чужой экстеншен) отсекается раньше этой точки и падать не должен.

**Договор ID** (`browser-bridge-protocol/tests/extension_identity.rs`): ID Chrome выводится из публичного ключа фикстуры (SHA-256 → буквы a–p); формула сверена с независимым расчётом; константы совпадают с фикстурой.

**Живые прогоны.** Стенд: мини-экстеншен, один манифест на оба браузера (`scripts/browser-bridge-live-check/`, перенесён в репозиторий по просьбе владельца). Он гонит 20-секундный ролик H.264 + AAC (854×480, 25 к/с, номер кадра на картинке): 59 кусков, разрезанных посреди боксов, два SourceBuffer, как у YouTube.

## Известные ограничения

- **Chrome из Flatpak вживую не проверялся** — это работа 06. Нужны `talk-name=io.github.Bogdan7c.Fastiplayer.*`, бинарь посредника внутри папки песочницы (обёртка-скрипт там не годится) и загрузка экстеншена через CDP `Extensions.loadUnpacked`. Совместимость glibc проверена.
- **`kill -9` браузера вживую не проверялся.** Закрытие браузера (`SIGTERM`) проверено: посредник получает EOF и выходит. EOF после `kill -9` браузера для посредника выглядит так же; это закрыто тестами с закрытием входа.
- **Безоконный тестовый режим плеера** в одном прогоне без браузера показал 497 из 500 кадров (в окне — 500 из 500). Это тестовая обвязка `FASTIPLAYER_TEST_BROWSER_VIDEO=headless`, к посреднику отношения не имеет; не расследовалось.
- **Стенд живой проверки — `scripts/browser-bridge-live-check/`** (просьба владельца после сессии: прошлые стенды пропадали вместе с временной папкой). Ролик (ffmpeg, побайтно повторяемый) и манифест (ключ и ID — из `extension-identity.json`) генерируются при запуске в `target/browser-bridge-live-check/`; в git только исходники. Запуск и критерии PASS — в README стенда. Постоянный стенд с автопрогоном — сессия 08.
- Билет активации окна на Wayland через посредника (решение 139) в 05 не делался: экстеншена ещё нет, разведка — в 10.
