# Результат сессии 06: установка посредника, Flatpak и кнопка в настройках

## Статус

**DONE.** 2 ноября 2026. Плеер сам подключает браузеры:
1. находит установленные браузеры: пакеты, Flatpak, Snap;
2. по кнопке «Connect» копирует посредника в постоянную папку;
3. пишет файл подключения и файл D-Bus «как разбудить плеер»;
4. показывает честный статус каждого браузера.

Flatpak-браузеру без доступа к шине право даёт кнопка «Allow». Snap получает честное «не поддерживается». При первом запуске плеер один раз предлагает подключить браузеры.

Живая проверка на основном компьютере (KDE Wayland). Плеер нажатиями мыши подключил Firefox (пакет) и Google Chrome (Flatpak, через «Allow»). Мини-экстеншен из 05 в обоих браузерах через установленные плеером файлы разбудил плеер и доиграл ролик до конца.

## Решения владельца (2.11.2026; в README — 157–161)

1. **Механизм подтверждён до кода (157):**
   - плеер находит браузеры, по «Connect» копирует посредника, пишет файл подключения и файл D-Bus, просит шину перечитать службы;
   - статус — сравнение «на диске то же, что записал бы этот плеер»;
   - права Flatpak читаются командой `flatpak`, а не угадываются;
   - файлами владеет копия плеера, последней нажавшая «Connect»;
   - всё — в новом crate `browser-bridge-install`.
2. **Кнопка «Allow» для Flatpak (158).** По явному клику плеер выполняет официальную `flatpak override --user --talk-name=io.github.Bogdan7c.Fastiplayer.* <id>`. Инструкция Flatseal — для тех, кто хочет руками.
3. **Предложение при первом запуске открывает раздел настроек (159)**, а не подключает всё молча.
4. **Каталог широкий (160):** Firefox, Chromium, Google Chrome, Brave, Vivaldi, Edge, LibreWolf, Waterfox — пакетами и Flatpak. Вживую проверены три, остальные помечены «not verified».
5. **Плеер должен ставить и сам экстеншен (161).** Слова владельца: «По возможности делаем тихую установку (учитываем винда в будущем). Если это будет работать хорошо, то я вообще откажусь от публикации в магазин». Факты производителей показали ограничения (ниже), поэтому это новая сессия **07a** после каркаса экстеншена. Решение по магазинам — по её итогам.

Решения агента (владелец получил их до кода, возражений не было):
- **«Браузер найден» = стоит программа или Flatpak-приложение.** Одна папка профиля не признак: на основном компьютере много пустых папок от удалённых браузеров (Edge, LibreWolf, Waterfox, Firefox из Flatpak, Brave, Vivaldi).
- **«Disconnect» работает и без посредника рядом с плеером.** Удаление своих файлов источника не требует. Проблема источника блокирует только «Connect» и «Allow».
- **Пустые свои папки после «Disconnect» убираются**, но только наши и только если пусты; симлинки не трогаются.

**Куда что пишется:**
- посредник для браузеров из пакетов — `~/.local/share/fastiplayer/browser-host/`, одна копия на все;
- посредник для Flatpak-браузера — `~/.var/app/<id>/data/fastiplayer/browser-host/`: песочница видит свою папку по тому же пути;
- файл подключения:
  - Chromium-семейство — `<профиль>/NativeMessagingHosts/`;
  - Firefox — `~/.mozilla/native-messaging-hosts/` и XDG-путь на будущее;
- служба D-Bus — `~/.local/share/dbus-1/services/`.

**Порядок «выключатель последним».** Сначала посредник, потом служба, файл подключения — последним. Браузер никогда не видит файл, который указывает на несуществующего посредника. Посредник пишется во временный файл, получает право на запуск и только потом подменяет старый. Так уже подключённый браузер не поймает «неисполняемого» посредника.

**Статусы:**

| Статус | Когда |
|---|---|
| Connected | файлы на диске совпадают с тем, что записал бы этот плеер |
| Connected to another Fastiplayer copy | файлы наши, но служба будит другой бинарь — например, dev-сборку |
| … that no longer exists | тот бинарь удалён |
| Not connected | файла подключения нет |
| Outdated — reconnect | посредник или файл отличаются (обновили плеер), посредник не исполняемый, пропала служба |
| Needs Flatpak permission | файлы на месте, но песочнице не разрешено наше имя на шине |
| Another program uses this connection file | файл с нашим именем, но не наш; «Connect» перезапишет с предупреждением, «Disconnect» не тронет |
| Firefox from Flatpak is not supported yet | Flatpak-сборка Firefox ещё не умеет `xdg-native-messaging-proxy` (bug 2078349) |
| Snap browsers are not supported | решение 22; ничего не пишется |

**Две сборки плеера** (dev и установленная). Файлами владеет копия, последней нажавшая «Connect». Посредник и файл подключения у обеих одинаковые, различается только служба D-Bus — какой бинарь будить. Другая копия видит «Connected to another Fastiplayer copy» и кнопку «Reconnect to this copy».

## Известные ограничения

- **Firefox из Flatpak не поддержан.** Нужен `xdg-native-messaging-proxy` на стороне Flatpak-сборки (bug 2078349); на основном компьютере такого браузера нет — проверить в 21b / 22.
- **Brave, Vivaldi, Edge, LibreWolf, Waterfox и Flatpak-сборки Chromium вживую не проверялись.** Пути — по документации производителей, в UI и справке пометка «not verified».
- **Посредник внутри песочницы проверен только на рантайме Chrome** (glibc 2.42 ≥ нужных 2.39). Статус «Connected» не запускает посредника внутри песочницы, поэтому рантайм со старой glibc покажет «Connected», а не поднимет посредника. Проверка запуском — кандидат в 21b.
- **«Disconnect» не отзывает право Flatpak**, выданное «Allow»: мы не знаем, давал ли его человек сам. Как отозвать руками — в `docs/browser-bridge/flatpak.md`.
- Если папка конфигурации не читается, браузер показывается как «Unavailable» с причиной.
- **Подписи разделов настроек.** Соседний раздел `browser_mode` и группа `offer` показываются сырыми id — это визуальная доводка UI (auto-memory владельца «UI polish deferred»).
- **Экстеншена ещё нет (07),** поэтому из UI его не поставить — сессия 07a.
