# Итог разведки 16b: ленты коротких видео

**Статус:** DONE 18 ноября 2026 — разведка и деление. Кода нет. Решения 344–346: свой декодер HE-AAC, деление на 16b1–16b4, без замера T410.

## Что сделано

Сессия 16b началась с разведки трёх лент, как требует её файл: Instagram Reels, YouTube Shorts и TikTok. Нужно было узнать, как устроена каждая лента и какой звук она отдаёт. Файл сессии требовал до начала сверить с владельцем звук рилсов: в журнале круга M1 был отказ `UnsupportedAudioCodec`.

Сначала два read-only помощника разметили код экстеншена (переезд сеанса, путь паузы, закрытие 4009) и стенда (страницы, судья, ввод). Потом агент смотрел живые ленты в отдельном Firefox 160 под управлением Marionette. На страницу ставился наблюдатель: элементы `<video>`, их события, вставки и удаления в DOM, смена адреса, строки типов `addSourceBuffer`. Instagram и Shorts — с входом владельца, TikTok — без входа. Моста в этом браузере не было.

## Устройство лент (Firefox, 18 ноября 2026)

| | Instagram Reels | YouTube Shorts | TikTok |
|---|---|---|---|
| Элементов `<video>` | ~11 одновременно, у каждого свой `MediaSource` | один на всю ленту (второй пустой) | пул из двух, по очереди |
| Что при прокрутке | старый встаёт на паузу (уже вне экрана), адрес меняется (`pushState`), новый стартует через 80–400 мс | страница переносит тот же элемент в новый ролик и даёт ему новый `MediaSource`; паузы нет | старый удаляется из DOM и встаёт на паузу, заранее загруженный новый стартует со звуком |
| Что позади | сыгранный элемент удаляется через ~2 ролика (~6 с после паузы) | — | освободившийся элемент перезаряжается следующим роликом |
| Адрес | меняется на каждом ролике | меняется на каждом ролике | не меняется |
| `loop` | нет | у первого ролика есть, потом снят | нет |
| Звук / видео | `mp4a.40.5` (HE-AAC v1) / H.264 | Opus / AV1 | `mp4a.40.29` (HE-AAC v2) / HEVC |

Ещё замечено:
- TikTok без входа после ~3 роликов показывает окно выбора интересов, оно закрывается ×.
- Звуковой буфер TikTok объявлен как `video/mp4; codecs="mp4a.40.29"`, с типом `video`.
- Instagram в браузере без жеста человека запускает ролики без звука.

## Что из этого следует

**Звук.** Наш AAC-декодер — патч Symphonia `symphonia-codec-aac-patch`. HE-AAC он отвергает прямо: `aac: aac too complex` при `sbr_present` или типе объекта не LC. Значит, Instagram и TikTok через мост сейчас играют без звука. Это и есть отказ из круга M1. Shorts звучит (Opus). Владелец выбрал свой декодер SBR и PS (решение 344) первой частью, 16b1.

**Три устройства лент.** Общий механизм переезда такой: переданное видео ушло с экрана, а на его месте заиграло другое. Тогда сеанс переезжает на новое видео в том же окне. Превью по наведению не считается, потому что при нём наше видео остаётся на экране. Для Shorts переезд элемента не нужен: новый `MediaSource` того же элемента мост уже считает новым поколением. Это прочитано в коде, но через мост не проверено.

**Почему окно вставало на паузу на Instagram.** По коду пауза страницы на элементе с тенью уходит в плеер без проверки, на экране ли элемент (`shadow-session.ts` → `page-event-translator.ts`). Закрытие 4009, по коду, — элемент тени вне документа дольше 1 с (`DetachedElementWatch`), а Instagram удаляет сыгранный элемент через ~6 с. Обе причины выведены из кода и наблюдения без моста, прямо они не доказаны.

## Что не проверено (уходит в 16b2)

- Через мост не прогнан ни один сайт ленты: ни Shorts, ни путь паузы, ни 4009.
- Ни один ролик не досмотрен до конца. Неизвестно, что страница делает после конца (перемотка на 0 и `play()` или следующий ролик). Shorts переключает `loop`, а у тени нет кода для `loop`.
- Ролики длиной 8–15 с: как их судят `classifySurvey` и признак «может быть реклама» (`mayBeAd`). Если как рекламу, на рилсы лягут плашка рекламы и запрет перемотки.
- Сторож следующего видео не берёт элементы с `loop` (`#loopKeepsAway`).
- Кодеки сняты только в Firefox, без подмены кодеков моста, TikTok — без входа, Instagram — без звука. В Chrome сайты могут отдавать другое.
- Как перехват классифицирует звуковой буфер TikTok с типом `video/mp4`.

## Урок разведки

Первая попытка взять вход владельца была копией его профиля Firefox. Профиль был подключён к Firefox Sync, и копия разослала правку в его настоящий браузер: из настоящего Firefox пропали дополнения. Агент заметил это сам через несколько минут. С согласия владельца он поставил дополнения обратно мышью со страниц магазина и восстановил прежние вкл/выкл и тему. Закладки, история и формы не пострадали. Настройки внутри дополнений Firefox при удалении стирает. Правило на будущее: для живых проверок с входом — только свежий профиль, в который переносятся одни cookies нужных сайтов, без входа в синхронизацию.
