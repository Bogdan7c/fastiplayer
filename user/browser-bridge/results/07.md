# Результат сессии 07: каркас экстеншена Fastiplayer Bridge

## Статус

**DONE.** 2 ноября 2026. В репозитории появился экстеншен Fastiplayer Bridge на TypeScript (`extensions/browser/`):
- одна кодовая база на оба браузера, два собранных варианта — `dist/chrome/` и `dist/firefox/`;
- протокол моста на TypeScript разбирает те же общие фикстуры, что и Rust, байт в байт;
- фон экстеншена — единственный, кто говорит с плеером: при старте браузера только проверяет, есть ли посредник, а плеер будит, лишь когда связь действительно нужна;
- попап показывает «Connected to Fastiplayer 0.2.0» или честное «Fastiplayer is not connected» с инструкцией;
- сборка и тесты экстеншена — в CI.

Перехвата видео ещё нет: это сессия 09. Скрипты в странице сейчас — пустые каркасы.

Попутно сверка TS с Rust нашла три места, где Rust-разбор протокола мягче решения 86 («договорились, значит строго»). Они закрыты в Rust, на них добавлены 35 фикстур (было 97 случаев, стало 132).

Живая проверка на невидимом экране — Chromium 156 и Firefox 158, настоящие посредник и плеер — прошла все сценарии.

## Решения владельца (2.11.2026; в README — 162–164)

1. **Механизм связи с плеером подтверждён до кода (162):**
   - с плеером говорит только фон экстеншена;
   - при старте браузера фон лишь проверяет «посредник установлен?»: открывает порт посредника, ничего не посылает и закрывает его, плеер не будится;
   - открыт попап или передаётся видео — фон шлёт `hello`, плеер просыпается и отвечает своей версией;
   - нет ответа — у значка «!», попап «Fastiplayer is not connected» со ссылкой на Settings › Browser integration;
   - если посредник упал, фон повторяет попытки с паузами 0,5 → 1 → 2 → 4 … до 30 с, но только пока связь нужна.

   Вариант «будить плеер при каждом старте браузера» отклонён: процесс плеера поднимался бы секунд на 30 каждый раз, а главная идея проекта — старое железо.
2. **Сборщик — esbuild (163).** Скрипты в странице не умеют подключать другие файлы, а без сборщика общий код (протокол, лимиты) лежал бы копией в каждом из них. Типы проверяет `tsc`, сборщик их только стирает.
3. **web-ext — как в плане (164):** только для разработки, хотя он тянет сотни пакетов npm.

Решения агента (владельцу — в итоге сессии):
- **Строгость формы протокола — обе стороны.** Rust был мягче решения 86 в трёх местах:
  - номер вместо имени варианта (`"kind":0` serde читал как «вариант № 0»);
  - массив вместо вложенного объекта (`"protocol":[1,0]`);
  - внешняя форма перечисления (`{"closed":null}`).

  Исправлено в Rust, проверено фикстурами (подробности ниже). Новых видов причин нет: всё это `wrong_value_type` — «значение не того типа».
- **Минимальные версии браузеров:**
  - Chrome 116 — с этой версии WebSocket продлевает жизнь фона экстеншена (документация Chrome);
  - Firefox 140 (ESR) — с этой версии понимается обязательный для AMO ключ `data_collection_permissions`; `world: "MAIN"` есть с 128 (MDN).
- **Заголовок страницы перед отправкой:** перевод строки и табуляция становятся одним пробелом, а не выбрасываются. Иначе «Серія 3⏎Озвучка» склеилась бы в «Серія 3Озвучка».
- **Порт посредника закрывается через 30 с простоя.** Открытый порт держит фон экстеншена и процесс посредника, вечно держать его нельзя. Сеансу видео он не нужен: тот идёт по WebSocket (решение 85), а WebSocket сам держит фон в Chrome 116+.

### Связь с посредником — машина состояний

| Состояние | Что значит | Выход |
|---|---|---|
| `idle` | порта нет | проба, нужда или запрос |
| `probing` | порт открыт без сообщений (1 с) | разрыв в окне → `host_missing`, иначе порт закрыт, статус без значка |
| `handshaking` | ушёл `hello`, ждём ответ ≤ 8 с (посредник ждёт плеер ≤ 5 с) | `hello_accepted` → `ready`; отказ или таймаут → статус и повтор |
| `ready` | плеер ответил, можно слать `open_session` | разрыв или простой 30 с |
| `backoff` | пауза перед повтором | только пока есть нужда |

- **`host_missing` или `player_unavailable`.** Если порт закрылся раньше чем через 1 с и не сказал ни слова — посредник не запустился (`host_missing`): настоящий посредник всегда отвечает хотя бы отказом. Позже или после ответа — посредник работал, но плеера нет.
- **Несовместимая версия** — без повторов: тут нужно обновление, а не ожидание.
- **Плеер перезапустился между звонками (`hello_required`)** — фон сам повторяет `hello` и тот же `open_session`, один раз (решение 153).
- **Запрос на разорванном порту** не висит: он получает явный исход «нет ответа».

### Строгость формы протокола (Rust)

**Корень.** Производный разбор serde рассчитан на любые форматы, поэтому принимает одни и те же данные в нескольких формах. Сообщения протокола помечены полем `type`, и serde читает их в два прохода через свой внутренний буфер, а читатель буфера ещё терпимее. Строгость нельзя навесить снаружи: её должен нести каждый тип.

**Исправление.** Типы протокола объявлены с `#[serde(remote = "Self")]`, а настоящий разбор пишут макросы `strict_object!` и `strict_label!`. Они сначала проверяют форму (объект или строка), потом отдают данные производному разбору. Затронуто 23 типа-объекта и 13 типов-меток, запись не изменилась.

**Доказательство.** 35 фикстур `shape-*`: от 6 до 13 на каждую из четырёх схем, все три класса, плюс незнакомый ключ во внешней форме. Без исправления 26 из них в Rust не сходятся (25 приняты молча). Старые 97 фикстур и все тесты потребителей зелёные.

**Живая проверка** (невидимый экран kwin_wayland, частная шина D-Bus и частные профили; экран и профили владельца не тронуты). Chromium 156.0.8078.47 и Firefox 158.0.1, плеер 0.2.0:

| Сценарий | Chromium | Firefox |
|---|---|---|
| A. Посредник и плеер на месте, открыт попап | PASS: «Connected to Fastiplayer 0.2.0»; посредник `caller accepted` → `hello_accepted`; плеер проснулся и сам вышел через ~30 с простоя; посредник `rc=0`, сирот 0 | PASS, то же |
| B. Посредника нет | PASS: «Fastiplayer is not connected» + инструкция, значок «!», плеер не запускался | PASS, то же |
| C. Старт браузера без попапа | PASS: посредник открыт на пробу и закрыт без единого сообщения, плеер не просыпался | PASS, то же |

Firefox на стенде управлялся через Marionette: WebDriver BiDi не пускает на страницы `moz-extension://`.

**Независимое ревью** (отдельный агент, без моих выводов) нашло и закрыло:
- плеер перезапустился, а в полёте два `open_session`: повтор после `hello_required` получал только первый, второй сразу уходил отказом. Теперь оба уходят заново после одного нового `hello`;
- попап открыли, пока запрос ждал ответа: лишний `hello` своим таймаутом мог оборвать исправный запрос. Теперь при запросе в полёте `hello` не шлётся;
- пробуждение фона стирало значок «!» от прошлой проверки. Теперь начальный «unknown» значок не трогает.

На оба первых случая есть тесты-регрессии; без исправления они падают (проверено временным откатом). Права «на вырост» (`contextMenus`, `storage`, `scripting`, все сайты), которые пока не используются, оставлены сознательно: решение 47 — доступ ко всем сайтам с самой установки.

## Известные ограничения

- Chrome из Flatpak и Snap вживую не проверялись в этой сессии (посредник для Flatpak проверен в 06).
- Значок «!» проверен через API (`action.getBadgeText`), а не глазами на панели. Попап открывался как вкладка, а не кликом по кнопке.
- Если посредник сам падает в первую секунду (например, отказ чужому экстеншену), это тоже покажется как «посредник не найден». Для человека текст один и тот же.
- `web-ext lint` предупреждает: `data_collection_permissions` на Firefox для Android требует 142. Android не поддерживается: native messaging там нет.
- Внешний вид попапа — набросок. Доводка — на финальной полировке UI.
- В Rust у каждого типа протокола осталась нестрогая функция `T::deserialize`. Явный вызов по имени типа обходит проверку формы. Это описано в `strict_shape.rs`, таких вызовов в коде нет.
