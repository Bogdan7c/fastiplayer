# Сессия 05: посредник `fastiplayer-browser-host`

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 05 плана `user/browser-bridge/`: создай бинарник `fastiplayer-browser-host` — тонкий посредник native messaging. Он разбирает рамки stdio, проверяет отправителя, переводит управляющие сообщения в D-Bus-интерфейс браузерного режима (02), а байты потока пишет в fd, полученный от плеера; события плеера возвращает в браузер. Плеер запускается через D-Bus activation. Медиа посредник не понимает. Сначала прочитай `user/browser-bridge/README.md`, `results/00.md` (как браузеры запускают хост), `results/00c.md` (выбранный канал данных), `results/01.md`, `results/02.md`.

## Зачем

Браузер умеет говорить с внешним миром только через такую программу. Чем она тоньше, тем меньше в ней ошибок и тем легче ревью в магазинах.

## Что сделать

1. **Рамки native messaging:** 4 байта длины (порядок байт машины) + JSON. Лимиты: от браузера — свой разумный предел, к браузеру — меньше 1 МБ. Битая рамка или превышение → закрыть порт с записью причины в stderr (браузер пишет его в свой лог), без паники.
2. **Проверка отправителя:** ID экстеншена из аргументов (Chrome — origin, Firefox — ID) сверяется со списком, вшитым при сборке и установке. Чужой → выход.
3. **Управление:** сообщения протокола → D-Bus `BrowserSession1` → ответ обратно; подписка на сигнал событий плеера → сообщения в браузер. Плеер не запущен → вызов будит его через D-Bus activation (02). Таймауты и понятный отказ «плеер не стартовал» — по образцу UX13.
4. **Данные:** сегменты из браузера (как выбрано в 00c: base64 в native messaging или свой локальный канал) → проверка формы и лимитов → запись в fd от плеера. Обратное давление: fd полон → посредник перестаёт читать stdin, а не копит в памяти.
5. **Жизненный цикл:** порт закрыт → «вкладка ушла» плееру → выход. Плеер закрылся → событие «закрыт» в браузер. Состояния, которое нельзя потерять, у посредника нет.
6. **Размер и зависимости:** маленький бинарь (`zbus` и `serde_json` уже в дереве), без async-рантайма, если блокирующего zbus хватает (Context7). Сборка с минимумом библиотек — важно для Flatpak (00).
7. **Логи:** только в stderr и только безопасные поля (тип сообщения, размер, причина). Никаких заголовков страниц, доменов в отладочных логах по умолчанию.
8. **Швы Windows:** транспорт к плееру за trait-ом. Linux — D-Bus + fd, у остальных ОС — `UnsupportedPlatform`.

## Тесты

- Рамки: склейка и разрез по байтам, нулевая длина, длина больше лимита, обрыв посреди сообщения, мусор вместо JSON — для каждого точное поведение.
- **Fuzz рамок и потока:** случайные байты, длины и разрезы (`cargo fuzz` или property-тест) → только типизированный выход, без паники, без чтения за лимит, без зависания.
- Чужой ID экстеншена → выход без обращения к шине.
- **Сквозной:** тест запускает хост как дочерний процесс (как браузер), пишет `OpenSession` и записанный поток стенда в stdin, на частной шине поднят настоящий процесс браузерного режима (02–04) → **кадры доходят до рендера**; событие позиции приходит в stdout хоста.
- Обратное давление: плеер не читает → память посредника не растёт.
- Плеер умер посреди сеанса → хост не падает, браузер получает «закрыт».
- Несколько хостов одновременно (два профиля Firefox и Chrome сразу) → последний сеанс заменяет предыдущий (решение 40), события не путаются.
- Браузер убит `kill -9` → stdin закрыт → хост выходит, плеер получает «вкладка ушла», сирот не остаётся.
