# Сессия 05: посредник `fastiplayer-browser-host`

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 05 плана `user/browser-bridge/`: создай бинарник `fastiplayer-browser-host` — тонкий посредник native messaging (рамки stdio, проверка отправителя, перевод сообщений протокола в D-Bus-интерфейс моста из 02 и событий плеера обратно, запуск плеера через D-Bus activation). Он не понимает медиа и не принимает решений. Сначала прочитай `user/browser-bridge/README.md`, `results/00.md` (как браузеры запускают хост), `results/01.md`, `results/02.md`.

## Зачем

Браузер умеет говорить с внешним миром только через такую программу. Чем она тоньше, тем меньше в ней ошибок и тем легче ревью в магазинах.

## Что сделать

1. **Рамки native messaging:** 4 байта длины (порядок байт машины) + JSON. Лимиты: от браузера — свой разумный предел (не 4 ГиБ), к браузеру — меньше 1 МБ. Битая рамка или превышение → закрыть порт с записью причины в stderr (браузер пишет его в свой лог), без паники.
2. **Проверка отправителя:** ID экстеншена из аргументов (Chrome — origin, Firefox — ID) сверяется со списком, вшитым при сборке и установке. Чужой → выход.
3. **Мост:** запрос протокола → вызов D-Bus `BrowserBridge1` → ответ обратно. Подписка на сигнал событий плеера → сообщения в браузер. Если плеер не запущен, вызов будит его через D-Bus activation (02). Время ожидания и понятный отказ «плеер не стартовал» — по образцу таймаутов UX13.
4. **Жизненный цикл:** порт закрыт → хост выходит; плеер закрылся → событие «закрыт» в браузер, хост живёт, пока жив порт. Хост не держит состояние, которое нельзя потерять.
5. **Размер и зависимости:** маленький бинарь (`zbus` и `serde_json` уже в дереве), без async-рантайма, если блокирующего zbus хватает (Context7). Сборка статическая или с минимумом библиотек — важно для Flatpak (00).
6. **Логи:** только в stderr и только безопасные поля (тип сообщения, размер, причина). Никаких URL, кук и заголовков.
7. **Швы Windows:** транспорт к плееру за trait-ом. Linux — D-Bus, у остальных ОС — `UnsupportedPlatform`.

## Тесты

- Рамки: склейка и разрез по байтам, нулевая длина, длина больше лимита, обрыв посреди сообщения, мусор вместо JSON — для каждого точное поведение.
- Чужой ID экстеншена → выход без обращения к шине.
- **Сквозной:** тест запускает хост как дочерний процесс (как это делает браузер), пишет `Handoff` в stdin, на частной шине поднят настоящий приёмник 02 + путь 03 → **кадры доходят до рендера**; событие позиции приходит в stdout хоста.
- Плеер умер посреди сеанса → хост не падает, браузер получает «закрыт».
- В stderr хоста за весь тест нет значения куки.
- **Fuzz рамок:** случайные байты, длины и разрезы потока (`cargo fuzz` или property-тест на разборщике) → только типизированный выход, без паники, без чтения за лимит, без зависания.
- Несколько хостов одновременно (два профиля Firefox и Chrome сразу) → каждый получает только свои события.
- Браузер убит `kill -9` → stdin закрыт → хост выходит, сирот не остаётся.
