# Сессия 13a: метка кодеков по рендеру окна и первый вопрос после установки

Часть сессии 13 ([общий замысел](13-tracks-quality-codec-policy.md)), решения 263–266.

> Выполни сессию 13a плана `user/browser-bridge/`: метка «дешёвых» кодеков в `hello` строится по рендеру, на который встанет окно (Auto без аппаратного Vulkan → GLES2 → только H.264), а экстеншен получает метку сразу после установки, не дожидаясь первой передачи. Сначала прочитай `user/browser-bridge/README.md`, `results/09b.md`.

## Зачем

После 09b оставались две дыры политики «H.264 для старого железа» (решение 43):
- профиль рендера `Auto`, который на машине без аппаратного Vulkan встаёт на GLES2, метки не давал: сайт отдавал AV1/VP9;
- метка приходила только с первой передачей, поэтому самое первое видео после установки шло без политики.

Автоопределение по железу владелец отложил (решение 264).

## Что сделать

1. **Прогноз рендера окна.** Модуль `render_backend::forecast`: та же чистая выборка `select_renderer` с теми же пробами каталога и меткой незавершённого старта (только чтение), без окна. Метка `codec_label` строится по прогнозу; безоконный тестовый процесс — по профилю.
2. **Первый вопрос.** Экстеншен: `background/codec-policy/first-label-request.ts`. Пока метка неизвестна, на `onInstalled` и `onStartup` он берёт нужду в связи, ждёт `hello_accepted` до 30 с и отпускает. Пустая метка тоже пишется в кэш.

## Тесты

- Прогноз на подставных пробах: Auto без Vulkan, Auto с меткой падения Vulkan, явный негодный профиль, «ничего не годно».
- Метка по пути рендера.
- Экстеншен в сборе (связь + сервис политики + первый вопрос): hello без попапа → курьер H.264; пустая метка запоминается; известная метка не будит плеер; срок без ответа; два события подряд.
- Стенд `codecs`: Auto с меткой «Vulkan упал» → H.264; первая страница после установки без попапа → H.264.
