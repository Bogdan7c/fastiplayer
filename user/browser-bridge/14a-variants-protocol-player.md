# Сессия 14a: варианты страницы — протокол 1.7 и плеер

Часть сессии 14 ([общий замысел](14-site-adapter-framework.md)), решения 17, 19, 44, 67, 279–283.

> Выполни сессию 14a плана `user/browser-bridge/`: протокол 1.7 (Rust и TS) — `page_navigation`, `subtitle_preference`, `subtitle_choice` — и плеер: меню вариантов страницы `variant_menu_changed` (есть с 1.0) — озвучки в меню ♪, качества в кнопке качества; команды `select_variant` и `next_episode` (есть с 1.0); кнопка Next в транспорте браузерного режима; возврат на ту же секунду после смены варианта (решение 280); подсказка и отчёт выбора субтитров для памяти экстеншена. Сначала прочитай `user/browser-bridge/README.md`, `14-site-adapter-framework.md`, этот файл целиком.

## Что уже есть (разведка 14)

- **С протокола 1.0** лежат, но никем не шлются и не читаются:
  - страница → плеер `variant_menu_changed{menu}`, меню `VariantMenu{kind: audio|quality|subtitles, options: [{id, label, selection: selected|available}]}`, до 256 пунктов, подпись до 256 байт, id уникальны, `selected` не больше одного (`browser-bridge-protocol::session::variants`);
  - плеер → страница `select_variant{kind, variant_id}` и `next_episode{}`.
- Плеер сейчас считает `variant_menu_changed` «пропущенным» (`app-egui::browser_session::translator`), экстеншен отвечает `ignore` на `select_variant` и `next_episode`.
- Меню ♪ браузерного режима сейчас показывает встроенные дорожки потока: обычно одна, кнопки нет.
- Кнопка Next, Prev, Shuffle, Repeat в браузерном режиме скрыты (`WindowViewProfile::offers_queue_navigation`). Next и клавиша N сейчас работают как «пропустить рекламу» (09d).
- Перемотка страницы по просьбе плеера уже есть: `seek{seek_id, target_us}` и ответ `seek_started{player_seek}`. Ворота нового поколения тоже: `generation_placement::aim_for_viewer`.

## Договор протокола 1.7

**Страница → плеер:**
- **`page_navigation{next_episode}`** — `available | unavailable`. Вне поколений, последнее слово главнее. До первого сообщения — `unavailable`.
- **`subtitle_preference{choice}`** — запомненный экстеншеном выбор субтитров для этой серии:
  - `{kind: "page_track", track}` — дорожка страницы с этим номером (как в `subtitle_track_offered`);
  - `{kind: "off"}` — субтитры выключены.

  Последнее слово главнее, действует на текущее и следующие поколения, пока зритель сам не выберет иначе.

**Плеер → страница:**
- **`subtitle_choice{choice}`** — та же форма. Шлётся только по действию зрителя (меню CC, клавиши C/V), не по автовыбору и не по подсказке. Свой файл или встроенная дорожка не шлются: экстеншену нечего запомнить.

**Существующие сообщения 1.0 — правила 14a:**
- `variant_menu_changed` с `kind = subtitles` плеер пропускает со счётчиком: субтитры приходят дорожками 13b.
- `select_variant` плеер шлёт только для пункта из последнего меню этого вида. Ящик «один на вид»: новый выбор вытесняет неотправленный старый.
- `next_episode` шлётся, только если `page_navigation` сказал `available`. С экстеншеном старше 1.7 кнопки Next нет.

## Плеер

**Кто чем владеет:**
- **Склад вариантов страницы** — новый модуль в `browser_session/` рядом с `page_subtitles/`. Хранит последнее меню каждого вида, «следующая серия есть», подсказку субтитров. Владелец — `SessionMedia`. Наружу — снимок фактов в `CoreStep`, как `page_quality`.
- **Перевод входящих** — новый подмодуль `translator/` (`translator.rs` на пределе 800 строк).
- **Исходящие** — новый подмодуль `outbound/` с intent-методами: выбрать вариант, следующая серия, сообщить выбор субтитров. Типизированный исход: нет меню, устаревший пункт, протокол стар, страницы нет, в очереди.
- **Возврат на секунду (решение 280)** — свой модуль в `session_media/`. При выборе озвучки или качества запоминается позиция T. Первое новое поколение фильма, пришедшее, когда на экране нет рекламы, ставится на T через `aim_for_viewer(T)`, страница получает одну просьбу перемотки. Самовольный старт страницы с нуля этого не перебивает (так же борется с самоволием `viewer_click_claim`). Запомненное снимается:
  - когда применено;
  - когда зритель сам перемотал, выбрал другой вариант или нажал Next;
  - когда смена прошла в том же поколении (YouTube меняет звук внутри одного `SourceBuffer`, позиция и так та же — эстафета 03d);
  - по сроку из настроек (`[browser_session]`, по умолчанию 120 с — с запасом на рекламу Ashdi ~35 с после смены озвучки).
- **Окно:**
  - меню ♪ — озвучки страницы заменяют встроенные дорожки, одна отметка «играет», B ходит по кругу (решение 283);
  - кнопка качества — список качеств страницы с отметкой выбранного над пунктом «Change quality on the page»; подпись кнопки по-прежнему по картинке (13c);
  - кнопка Next — на своём месте в транспорте, только когда «следующая серия есть»;
  - Next, клавиша N, MPRIS Next: реклама на экране → пропуск рекламы, как в 09d; иначе следующая серия; иначе как сейчас;
  - в рекламе выбор озвучки и качества заблокирован тем же тостом, что перемотка (решения 206, 283);
  - тосты: «Audio: <label>», «Quality: <label>», «Next episode».
- **Субтитры:** у владельца субтитров intent «подсказка страницы». Порядок силы: действие зрителя в этом сеансе > подсказка страницы > `page_display = showing` > наш автовыбор. Подсказка ждёт, пока дорожка с этим номером придёт.
- **Подписи страницы** — текст страницы (инвариант 1): проверены протоколом, перед показом убираются управляющие символы и знаки смены направления, длинные обрезаются в UI.
- На диск ничего не пишется (инвариант 7): выбор зрителя запоминает экстеншен.

**Инварианты, которые нельзя нарушить:**
- без меню нет пунктов; меню одного вида не трогает другой вид;
- устаревший пункт (меню сменилось после открытия нашего меню) не уходит странице;
- реклама главнее следующей серии;
- возврат на секунду не срабатывает на рекламное поколение и не переживает срок;
- старый экстеншен (общая версия ниже 1.7) — меню вариантов работает (оно из 1.0), Next и подсказка субтитров нет.

## Тесты

- **Протокол:** фикстуры на каждое новое сообщение (валидные, лишнее поле, чужой вид выбора, номер дорожки 0), 1.6 их не включает. Rust и TS — общие фикстуры.
- **Плеер, модульные:**
  - склад: нет меню, замена меню, вид `subtitles` пропущен, чужой вид не задет;
  - исходящие: нет меню, устаревший пункт, протокол 1.6 без Next, ящик «один на вид»;
  - возврат на секунду: рекламное поколение пропущено, применено на фильм, снято перемоткой зрителя, снято сроком, снято сменой в том же поколении;
  - меню ♪ с озвучками страницы, B по кругу; кнопка качества со списком; Next виден и скрыт; N в рекламе пропускает рекламу;
  - субтитры: подсказка сильнее `showing`, зритель сильнее подсказки, отчёт выбора только по действию зрителя.
- **Сквозные тесты процесса (кадр в рендере):**
  - смена озвучки: поколение 1 играет на T → выбор в ♪ → странице ушёл `select_variant` → поколение 2 начинается с 0 → плеер просит перемотку на T → данные на T → кадры показаны, позиция T ± 1 с;
  - выбор качества → `select_variant{quality}`;
  - Next: без `page_navigation` кнопки нет, после `available` — `next_episode`;
  - подсказка субтитров → дорожка страницы включена, пиксели субтитров; выбор зрителя → `subtitle_choice`.
